# Most Recent Run Outcome in Health

## User Story

As an owner-operator, I want the status region to tell me how my last run ended, so that I can see acquisition is failing without opening the Runs screen.

## Description

Completes `GET /api/health` by populating `most_recent_run`, the one field CAP-001-E1-S6 left `null`.

Module: `ingestion-api`. Deliberately small and separate: it is the seam where E7's run records complete the payload E1 delivers, and it is the last dependency the status region needs.

Together with E1's four fields this satisfies AC-18 in full: the owner can determine both whether the product is running and whether its most recent run failed, without inspecting the data store.

Source: `component-design-ingestion-api.md` section 11; system design 4.2.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-18] Given health, When it is called, Then the owner can tell whether the most recent acquisition run failed, without inspecting the data store.
- [DAC-E7-8] Given `GET /api/health`, When it responds, Then `most_recent_run` reports the most recent run's outcome, completing the payload whose other fields E1 delivers.

### Derived

- [DAC-E7-S3-1] Given no run has ever been recorded, When health responds, Then `most_recent_run` is `null`, which the status region renders as no run recorded rather than as a failure. (traces to: DAC-E1-17, AC-17)
- [DAC-E7-S3-2] Given a run in a non-terminal state, When health responds, Then that run is reported with its current state rather than skipped in favour of an older terminal one. (traces to: AC-18)
- [DAC-E7-S3-3] Given the most recent run, When it is reported, Then it carries its id, state and end timestamp, enough for the status region without a second request. (traces to: DAC-E7-8)
- [DAC-E7-S3-4] Given health is polled every 30 seconds from every screen, When this query runs, Then it is indexed so the poll is cheap. (traces to: DAC-E1-13)

## Technical Details

### API Contract

`GET /api/health` response gains:

```json
"most_recent_run": {
  "run_id": "...",
  "state": "partial",
  "ended_at": "2026-09-05T22:14:03Z"
}
```

`null` when no run has ever been recorded.

### Testing

- `pytest` with FastAPI's test client and `testcontainers[postgres]`, marked `postgres`.
- An empty run table yields `null`.
- A terminal run yields its state and end timestamp.
- A `running` run is reported as running rather than skipped for an older terminal run.
- The query plan uses an index, asserted by `EXPLAIN` in the test.

### Validation

`uv run pytest -m postgres`, `uv run ruff check .`, `uv run mypy src`.

### Dependencies

- **CAP-001-E1-S6**, the health endpoint this completes.
- **CAP-001-E5-S1**, `acquisition_run`.
- **CAP-001-E1-S5**, the status region consuming this field.
