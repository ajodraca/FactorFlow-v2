# Run Detail Screen

## User Story

As an owner-operator whose run failed, I want to open it and see which instrument and data type was affected and why, so that I can correct the cause and run again.

## Description

Delivers `web/src/screens/runs/detail`, the child route under Runs.

Module: `owner-web-app`. Renders inside the shell from CAP-001-E1-S4. This is the screen the capability's third user flow ends at.

Progressive disclosure carries the volume: 3000 instruments collapse to one row each and expand to four data types. Re-run is named as the recovery action, which is what makes AC-6's re-run safety visible to the owner as a remedy rather than a risk.

Source: `ux-design.md` section 1.5; `component-design-owner-web-app.md` section 2.3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-10] Given a failed or partial run, When it is opened, Then per-instrument, per-data-type reasons are shown.
- [AC-11] Given an unrecognised instrument, When it renders, Then it is distinguished from other failures.
- [AC-19] Given a running run, When it is open, Then a cancel action is available and the `cancelling` state is shown.
- [AC-26] Given a queued run, When it is open, Then cancelling it shows its own confirmation copy and an immediate cancelled state with no started time.
- [DAC-E7-9] Given 3000 instruments, When the screen renders, Then it collapses to one row per instrument and expands to four data types.
- [DAC-E7-11] Given every status, When it renders, Then it carries a text label plus icon or shape.
- [DAC-E7-2] Given a not-found outcome, When it renders, Then it is distinguishable from a failed outcome, since the owner's remedy differs.

### Derived

- [DAC-E7-S4-1] Given an abandoned run, When it is opened, Then a written explanation states that the run's process stopped and the run was reclaimed, with the path to starting a new run. (traces to: DAC-E5-17)
- [DAC-E7-S4-2] Given a failed or partial run, When it is opened, Then re-run is offered as the named recovery action. (traces to: AC-6)
- [DAC-E7-S4-3] Given a cancel that races completion, When `409` returns, Then the screen states the run completed rather than showing a cancellation that did not happen. (traces to: DAC-E5-9)
- [DAC-E7-S4-4] Given per-instrument outcomes, When they render, Then `not_found` uses a warning tier distinct from `failed`, since the owner's remedy differs. (traces to: AC-11)
- [DAC-E7-S4-5] Given a reason, When it renders, Then it shows the data type and the provider request id, and never any credential. (traces to: DAC-E7-3, DAC-E7-4)
- [DAC-E7-S4-6] Given a run in a non-terminal state, When the screen is open, Then it polls every 10 seconds and stops once the run is terminal. (traces to: AC-19)
- [DAC-E7-S4-7] Given an outcome filter, When it is applied, Then only matching instruments render, and results page rather than loading 3000 rows at once. (traces to: DAC-E7-10)

## Technical Details

### Implementation

- React 18, TypeScript, Tailwind, shadcn/ui.
- `data-table` `expandable` for instruments expanding to four data types; `badge` with `status-*` variants; `button` `secondary` plus `dialog` `confirm` for cancel; `button` `default` for re-run.
- Endpoints: `GET /api/acquisition-runs/{id}`, `POST /api/acquisition-runs/{id}/cancel`, `POST /api/acquisition-runs` for re-run.

### Testing

- `vitest` with React Testing Library; `@playwright/test` for open-run-then-cancel and for expanding an instrument to its data types.
- An abandoned run renders its explanation and the new-run path.
- `not_found` and `failed` render distinguishable tiers.
- A `409` on cancel renders the completed message.
- Polling stops when the run reaches a terminal state.
- The outcome filter narrows the list and paging works across pages.
- A reason containing a credential-like value is asserted never rendered.

### Validation

`npm run test`, `npm run test:e2e`, `npm run lint`, `npx tsc --noEmit`.

### Dependencies

- **CAP-001-E1-S4**, the shell and the run detail child route.
- **CAP-001-E5-S5**, the run endpoints.
- **CAP-001-E7-S1**, the per-instrument result queries behind run detail.

### Open Question

The indeterminate progress indicator for an active run remains an unresolved component-spec gap (`ux-design.md` section 3). This screen renders the progress region without it until the gap is closed.
