# Instrument and Settings API Endpoints

## User Story

As an owner-operator using the interface, I want endpoints to manage my instrument list and history depth, so that the screens have a contract to call.

## Description

Delivers `src/factorflow/api/routes/instruments.py` and `src/factorflow/api/routes/settings.py`, with their Pydantic models.

Module: `ingestion-api`. Thin HTTP surface over CAP-001-E2-S1 and CAP-001-E2-S2; the domain logic lives there and is not duplicated here.

Source: `component-design-ingestion-api.md` sections 2.4, 11.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] Given the endpoints, When the owner adds, lists or retires instruments, Then no configuration file or direct store access is needed.
- [DAC-E2-4] Given `POST /api/instruments`, When at least one symbol is added or reactivated, Then it returns `201`; when all are duplicates, `409`; when all are malformed, `422`.
- [DAC-E2-5] Given `DELETE /api/instruments/{symbol}`, When the symbol is unknown, Then `404`; when already retired, `409`.
- [DAC-E2-8] Given `PUT /api/settings/history-depth`, When the value is not a positive integer, Then `422`.
- [DAC-E2-10] Given `GET /api/instruments`, When it is called, Then it supports a symbol prefix filter, a lifecycle filter, a limit and a cursor, and reports active and retired counts.

### Derived

- [DAC-E2-S3-1] Given a mixed batch, When it returns `201`, Then the body reports `added`, `reactivated` and `rejected` separately, each rejected entry carrying a reason. (traces to: DAC-E2-4)
- [DAC-E2-S3-2] Given `GET /api/settings/history-depth` with no depth set, When it responds, Then `years` is `null`, distinct from zero. (traces to: DAC-E2-7)
- [DAC-E2-S3-3] Given any non-2xx response from these routes, When it is returned, Then it carries the shared error envelope with a stable snake_case code, owner-facing message, resource and request id. (traces to: DAC-E7-5)
- [DAC-E2-S3-4] Given a `limit` beyond the canonical bound, When it is supplied, Then it is rejected with `422` rather than silently clamped. (traces to: DAC-E2-10)
- [DAC-E2-S3-5] Given a cursor from a previous page, When it is supplied, Then the next page continues from it and the ordering is stable across requests. (traces to: DAC-E2-10)

## Technical Details

### API Contract

| Method | Path | Success | Errors |
|---|---|---|---|
| `GET` | `/api/instruments` | `200` instruments, `active_count`, `retired_count`, `next_cursor` | `422` bad bounds |
| `POST` | `/api/instruments` | `201` `{added, reactivated, rejected[]}` | `409` all duplicate; `422` all malformed |
| `DELETE` | `/api/instruments/{symbol}` | `200` `{lifecycle: "retired", retired_at}` | `404` unknown; `409` already retired |
| `GET` | `/api/settings/history-depth` | `200` `{years|null, updated_at}` | none |
| `PUT` | `/api/settings/history-depth` | `200` `{years, updated_at}` | `422` not a positive integer |

Auth: none on every route, loopback only.

Request for `POST /api/instruments`:
```json
{ "symbols": ["AAPL", "MSFT"] }
```

### Testing

- `pytest` with FastAPI's test client and `testcontainers[postgres]`, marked `postgres`.
- Each status code in the table is exercised, including the all-duplicate `409` and all-malformed `422` distinction.
- A mixed batch returns `201` with all three result groups populated.
- Depth `null` versus `0` asserted distinct in the response body.
- An over-limit `limit` returns `422`.

### Validation

`uv run pytest -m postgres`, `uv run ruff check .`, `uv run mypy src`.
