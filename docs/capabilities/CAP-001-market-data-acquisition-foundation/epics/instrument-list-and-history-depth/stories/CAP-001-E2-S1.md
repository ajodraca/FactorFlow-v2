# Instrument List Service: Add, Retire, Reactivate and Normalise

## User Story

As an owner-operator, I want to name the instruments I care about and retire ones I no longer follow, so that acquisition covers exactly what I choose without losing what was already observed.

## Description

Delivers `src/factorflow/instruments/service.py` and `src/factorflow/instruments/symbols.py`.

Module: `instrument-list-service`. This is the domain logic behind the instrument endpoints; the HTTP surface is CAP-001-E2-S3.

Retirement is a lifecycle transition, never a delete. This follows from C5: point-in-time history cannot be re-acquired as observed, so a delete is unrecoverable, and an instrument dropped today may be one a later backtest needs.

Source: `component-design-instrument-list-service.md` sections 2.2, 2.3, 2.4.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] Given the acquisition list, When the owner adds, removes or lists instruments, Then it happens without editing configuration files or the data store directly.
- [AC-21] Given an instrument being retired, When retirement completes, Then further acquisition stops for it and every observation already recorded is retained.
- [DAC-E2-1] Given a symbol on entry, When it is normalised, Then the same instrument named two ways becomes one row.
- [DAC-E2-2] Given a symbol already present and active, When it is added, Then it is reported a duplicate; given one present and retired, Then it is reactivated.
- [DAC-E2-5] Given retirement, When it is applied, Then it is a lifecycle transition and never a delete.

### Derived

- [DAC-E2-S1-1] Given a symbol with surrounding whitespace or lowercase letters, When it is normalised, Then it is trimmed and uppercased before any lookup or insert. (traces to: DAC-E2-1)
- [DAC-E2-S1-2] Given a symbol that does not match `^[A-Z][A-Z0-9.-]{0,15}$` after normalisation, When it is added, Then it is rejected as malformed and no row is written. (traces to: DAC-E2-1)
- [DAC-E2-S1-3] Given a retired instrument, When the same symbol is added again, Then the existing row's lifecycle returns to `active` and `retired_at` is cleared, rather than a second row being created. (traces to: DAC-E2-2)
- [DAC-E2-S1-4] Given a batch containing valid, duplicate and malformed symbols, When it is added, Then each symbol is classified independently and rejected entries never discard accepted ones. (traces to: DAC-E2-3)
- [DAC-E2-S1-5] Given retirement of a symbol that is unknown, When it is attempted, Then it is reported as unknown and distinguished from one already retired. (traces to: DAC-E2-5)
- [DAC-E2-S1-6] Given retirement, When it completes, Then no observation, coverage segment or run result for that instrument is modified or removed. (traces to: AC-21)
- [DAC-E2-S1-7] Given the list read, When it is called, Then it supports a symbol prefix filter, a lifecycle filter, and cursor paging, and reports active and retired counts. (traces to: DAC-E2-10)

## Technical Details

### Implementation

- `symbols.py`, normalisation (trim, uppercase) and shape validation matching the `instrument_symbol_shape` check constraint, so application and database agree.
- `service.py`, `add_many`, `retire`, `list`, each a function over a `psycopg` connection. No ORM.
- Adds use a single statement per batch where possible, classifying results by returned rows.

### Data Changes

None. Operates on `instrument` from CAP-001-E1-S1.

No index is added here. Symbol uniqueness is already enforced by `idx_instrument_symbol`, created in migration `0001` per `component-design-market-data-store.md` section 2.3. This story owns *reactivation semantics* — a retired symbol becoming active again by returning the existing row to `active` rather than inserting a second row (DAC-E2-S1-3) — which that index supports rather than conflicts with. Adding a second unique index on `symbol` would duplicate it, and migration `0001` is applied and therefore never edited.

### Testing

- `pytest` with `testcontainers[postgres]`, marked `postgres`.
- Normalisation: `" aapl "` and `"AAPL"` resolve to one row.
- Malformed symbols rejected: lowercase-only after trim is fine, but `"1AAPL"`, a 17-character symbol, and an empty string are rejected.
- Reactivation returns the original `instrument_id`.
- A mixed batch returns added, reactivated and rejected classifications with reasons.
- Retiring then reading coverage still shows the instrument's observations.

### Validation

`uv run pytest -m postgres`, `uv run ruff check .`, `uv run mypy src`.

### Dependencies

- **CAP-001-E1-S1**, the `instrument` table.
