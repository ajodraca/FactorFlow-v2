# Instruments and Settings Screens

## User Story

As an owner-operator, I want screens to manage my instrument list and state my history depth, so that I can set up acquisition without touching a config file.

## Description

Delivers `web/src/screens/instruments/` and `web/src/screens/settings/`.

Module: `owner-web-app`. Renders inside the shell from CAP-001-E1-S4.

Bulk entry is what makes AC-4's 3000 instruments reachable; one at a time is not a usable path to that number. The `textarea` component was added to the design system at `status: beta` with a `list` variant specifically for this.

Retirement is confirmed as retirement, using `dialog` `confirm` rather than `destructive`, because it is not destructive: observations are retained.

Source: `ux-design.md` sections 1.2, 1.3; `component-design-owner-web-app.md` section 2.3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] Given the Instruments screen, When the owner adds or retires instruments, Then the current list is visible and no config file is involved.
- [AC-2] Given the Settings screen, When the owner states a history depth, Then it is recorded and shown.
- [AC-25] Given a retire confirmation, When it is shown, Then it states that a run already under way still finishes with the instrument included.
- [DAC-E2-3] Given bulk entry, When symbols are pasted, Then newline, comma, tab and semicolon separators are accepted and what was recognised is reported before anything is added.
- [DAC-E2-9] Given no history depth set, When the Start action renders, Then it renders `blocked` with its reason stated rather than disabled or absent.
- [DAC-E2-10] Given 3000 instruments, When the list renders, Then search and filter remain usable.

### Derived

- [DAC-E2-S4-1] Given a bulk paste containing rejected entries, When the preview is shown, Then rejected entries are listed with reasons and the accepted ones remain available to add. (traces to: DAC-E2-3)
- [DAC-E2-S4-2] Given the retire confirmation, When it renders, Then it uses `dialog` `confirm` and not `destructive`, and its copy says retirement rather than deletion. (traces to: AC-21)
- [DAC-E2-S4-3] Given a control that cannot be used, When it renders, Then it uses `button` `blocked` with the reason visible, never a bare disabled control, because a disabled control hides its reason from keyboard and screen-reader users. (traces to: DAC-E2-9)
- [DAC-E2-S4-4] Given the instrument table, When it renders, Then active and retired instruments are distinguishable and retired ones are not omitted. (traces to: AC-21)
- [DAC-E2-S4-5] Given the depth input, When a non-positive or non-integer value is entered, Then the error names the operation, the resource and the reason per STD-UI-19. (traces to: DAC-E2-8)
- [DAC-E2-S4-6] Given the list has never been populated, When the screen renders, Then it states that no instruments are named, distinct from a filter matching nothing. (traces to: AC-17)
- [DAC-E2-S4-7] Given every status shown, When it renders, Then it carries a text label plus icon or shape and is readable in greyscale. (traces to: AC-1)

## Technical Details

### Implementation

- React 18, TypeScript, Tailwind, shadcn/ui on Radix.
- Instruments: `form` `inline` + `input` `text` for single add; `textarea` `list` for Add many; `data-table` `expandable`; `dialog` `confirm` for retire.
- Settings: `form` `stacked` + `input` `numeric` for depth; `card` `summary` + `badge` for credential presence, which is read from health and never rendered as a value.
- Endpoints consumed: `GET/POST/DELETE /api/instruments`, `GET/PUT /api/settings/history-depth`.

### Testing

- `vitest` with React Testing Library; `@playwright/test` for the add-then-retire path end to end.
- Bulk entry parses all four separators.
- A rejected entry does not discard accepted ones.
- The retire dialog's copy mentions the in-flight run behaviour.
- The Start action renders `blocked` with a reason when depth is unset.
- Never-populated and nothing-found render distinct copy.

### Validation

`npm run test`, `npm run test:e2e`, `npm run lint`, `npx tsc --noEmit`.

### Dependencies

- **CAP-001-E1-S4**, the shell.
- **CAP-001-E2-S3**, the endpoints consumed.
