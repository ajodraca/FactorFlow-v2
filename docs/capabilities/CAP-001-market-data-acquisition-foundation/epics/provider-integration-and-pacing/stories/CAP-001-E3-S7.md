# Test-Only Ingestion Entry Point for the Loopback Provider Stub (Clause 2a)

## User Story

As the owner-operator running the E2E acquisition journeys, I want the ingestion process in the E2E stack to reach the local Massive stub over loopback `http`, using a test credential generated for each run, through an entry point the release artifact never contains, so that the acquisition stack exercises the real runner while no production credential, and no production build, can ever use plain HTTP.

## Technical Details

### API Contract

No HTTP endpoint changes. In-process contract:

```python
# src/factorflow/ingestion_main.py (acquisition-runner 2.1)
def main(
    *,
    settings_factory: Callable[[], Settings] = Settings,
    credential_reader: Callable[[], SecretStr] = read_provider_credential,
) -> int: ...
```

- `settings_factory` replaces the direct `Settings()` call at start.
- `credential_reader` replaces the direct `read_provider_credential()` call in the claim path.
- A parameter is not configuration. No environment variable, flag or constant selects them.

### Data Changes

None.

### Implementation

- `src/factorflow/ingestion_main.py`: add the two keyword-only parameters and route the start load and the claim-time credential read through them. Behaviour with the defaults is unchanged.
- `tests/e2e/support/ingestion_e2e_main.py` (new): a settings subclass or wrapper of `MassiveSettings` that accepts `http` only for a host in `_LOOPBACK_HOSTS` (imported from `factorflow.config.settings`, not copied) and otherwise applies every 2.2c clause unchanged. A start-time `socket.getaddrinfo` check for `localhost` uses `ipaddress.ip_address(...).is_loopback`. A checking reader wraps `read_provider_credential` with `re.fullmatch(r"TEST-ONLY-[0-9a-f]{32,}", value)`. The module ends with `sys.exit(main(settings_factory=..., credential_reader=...))`.
- `scripts/run-e2e-server.sh`: the item 5 edit, around today's lines 90, 138 and 145.
