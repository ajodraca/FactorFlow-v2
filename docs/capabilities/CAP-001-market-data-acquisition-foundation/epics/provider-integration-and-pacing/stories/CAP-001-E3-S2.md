# Provider Response Models in the Product's Vocabulary

## User Story

As a maintainer, I want provider responses parsed into models named in our vocabulary, so that wire field names never leak into the rest of the codebase.

## Description

Delivers `src/factorflow/ingestion/massive/models.py`, Pydantic models for the four response shapes.

Module: `massive-client`. The non-abstraction decision permits this component to use Massive's shapes internally, but not to let `t`, `o`, `h`, `l`, `c` reach callers.

Source: `component-design-massive-client.md` sections 2.3, 2.5.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [DAC-E3-12] Given a provider response, When it is parsed, Then wire field names stay inside this component and models name fields in the product's vocabulary.
- [AC-5] Given a fundamental record, When it is modelled, Then the provider's filing date is available as a descriptive attribute but is not the as-of date.

### Derived

- [DAC-E3-S2-1] Given a daily bar, When it is parsed, Then `t`, `o`, `h`, `l`, `c`, `v`, `vw` and `n` map to named fields for timestamp, open, high, low, close, volume, volume-weighted average price and transaction count. (traces to: DAC-E3-12)
- [DAC-E3-S2-2] Given a bar timestamp in Unix milliseconds, When it is parsed, Then it converts to a session date without timezone ambiguity. (traces to: DAC-E3-12)
- [DAC-E3-S2-3] Given a monetary or ratio value, When it is parsed, Then it is held as `Decimal` rather than `float`, so no binary rounding enters recorded history. (traces to: AC-5)
- [DAC-E3-S2-4] Given a response missing a field the model requires, When it is parsed, Then validation fails and the failure is classified `ProviderContractViolation` by CAP-001-E3-S3 rather than passing a partial record on. (traces to: DAC-E3-5)
- [DAC-E3-S2-5] Given an optional field absent, When it is parsed, Then the model records its absence rather than substituting a zero, because absent and zero are different facts. (traces to: AC-5)

## Technical Details

### Implementation

- Pydantic v2 models, one per data type, with `Decimal` for every price, ratio and monetary quantity.
- Field aliases map wire names to product names; the alias is the only place a wire name appears.
- `filing_date` is modelled as a plain attribute with a docstring stating it must never serve as the observation date, because it conflates restatements of the same period.

### Testing

- `pytest`, marked `not postgres`.
- A recorded fixture per data type parses into the model with product-named fields.
- A test asserts no model field is typed `float` for a monetary or ratio value.
- A missing required field raises a validation error.
- An absent optional field is distinguishable from a zero value.

### Validation

`uv run pytest -m 'not postgres'`, `uv run ruff check .`, `uv run mypy src`.

### Dependencies

None. CAP-001-E3-S1 consumes these models.
