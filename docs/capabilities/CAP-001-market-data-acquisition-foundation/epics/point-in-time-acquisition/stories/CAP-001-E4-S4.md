# Range Planning: Fetch Only What Is Missing

## User Story

As an owner-operator, I want a run to fetch only the ranges it does not already hold, so that deepening my history depth backfills the earlier years without re-downloading what I have.

## Description

Delivers `src/factorflow/ingestion/plan.py`.

Module: `acquisition-runner`. This is what makes AC-6, AC-22 and the capability's fifth flow work without re-fetching.

`depth_start` is computed from the depth **snapshotted onto the run row at request time**, not from the current setting, so a depth changed while a run sits queued does not redefine a run already requested.

Re-fetching the trailing range on every run is deliberate and cheap: the last covered day may have been a partial session, and the writer's idempotence means re-fetching a day already held writes nothing.

Source: `component-design-acquisition-runner.md` section 2.3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-22] Given a raised history depth, When the next run plans, Then it fetches the missing earlier range for each active instrument falling short, without re-acquiring what is covered.
- [AC-6] Given a period already acquired, When planning runs, Then the plan does not re-request it except for the trailing range.
- [DAC-E4-6] Given an instrument and data type, When planning runs, Then it yields only the sub-ranges of the requested depth not already covered.
- [DAC-E4-7] Given an instrument covered from later than the depth start, When planning runs, Then the earlier gap is yielded.
- [DAC-E4-8] Given a run row, When `depth_start` is computed, Then it derives from the depth snapshotted at request time, not the current setting.

### Derived

- [DAC-E4-S4-1] Given an instrument with no coverage, When planning runs, Then the whole range from `depth_start` to today is yielded as one fetch range. (traces to: DAC-E4-6)
- [DAC-E4-S4-2] Given an instrument covering the whole requested range, When planning runs, Then only the trailing range since `covered_to` is yielded. (traces to: DAC-E4-9)
- [DAC-E4-S4-3] Given coverage with an interior gap, When planning runs, Then each missing sub-range is yielded separately rather than as one span covering held data. (traces to: DAC-E4-6)
- [DAC-E4-S4-4] Given a depth changed while a run is queued, When that run is claimed and plans, Then it uses its own snapshotted depth, so its scope is explainable from its own record. (traces to: DAC-E4-8)
- [DAC-E4-S4-5] Given planning per data type, When it runs, Then reference, prices, fundamentals and corporate actions are planned independently, since their coverage can differ. (traces to: AC-3)
- [DAC-E4-S4-6] Given `depth_start` later than today, When it is computed, Then the plan is empty rather than yielding an inverted range. (traces to: DAC-E4-6)

## Technical Details

### Interface

```python
@dataclass(frozen=True)
class FetchRange:
    data_type: str
    start: date
    end: date

def plan_fetches(
    covered: list[tuple[date, date]],
    depth_start: date,
    today: date,
) -> list[FetchRange]:
    """The sub-ranges of [depth_start, today] not already covered."""
```

`depth_start` is `today` minus the run's `history_depth_years`.

### Testing

- `pytest`, marked `not postgres`. Pure function, table-driven.
- No coverage yields the whole range.
- Full coverage yields only the trailing range.
- Coverage starting later than `depth_start` yields the earlier gap, which is AC-22's backfill.
- An interior gap yields two ranges, not one spanning held data.
- An inverted or empty window yields an empty plan.
- A property test asserts no yielded range overlaps any covered range except the deliberate trailing re-fetch.

### Validation

`uv run pytest -m 'not postgres'`, `uv run ruff check .`, `uv run mypy src`.
