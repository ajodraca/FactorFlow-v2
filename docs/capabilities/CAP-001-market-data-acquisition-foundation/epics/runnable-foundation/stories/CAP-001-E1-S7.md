# Host and Origin Checks on the API

## User Story

As an owner-operator, I want the API to refuse requests that name a foreign host or come from a foreign web page, so that a page my browser happens to load cannot drive or read my unauthenticated, plain-HTTP product.

## Description

Adds one HTTP middleware to `src/factorflow/api/app.py`, registered before every route and the static mount, that makes the two checks of `component-design-ingestion-api.md` section 2.5a. The API serves plain HTTP on loopback with no authentication (AC-14), so CONST-SEC 1.3 condition H9 of the `SEC-ENC-001 host-local loopback exception` requires a `Host` check (against DNS rebinding) and an `Origin` check on state-changing requests (against cross-site requests). The deployment's reliance on that exception is recorded in `component-design-runtime-config.md` section 2.8.1 and DEC-0050.

Module: `ingestion-api`. No route, response model or schema changes; the two new error codes use the existing error envelope.

The 15 test modules that build a `TestClient` rely on its default `Host: testserver`, which the new check refuses. Each passes `base_url="http://127.0.0.1:8000"` instead:

- `tests/integration/`: `test_api_coverage.py`, `test_api_health.py`, `test_api_instruments.py`, `test_api_pagination.py`, `test_api_runs.py`, `test_api_settings.py`, `test_api_static_mount.py`
- `tests/unit/`: `test_api_coverage_routes.py`, `test_api_errors.py`, `test_api_instruments_error_mapping.py`, `test_api_instruments_query_mapping.py`, `test_api_no_secrets.py`, `test_api_request_id.py`, `test_api_request_id_redaction_composition.py`, `test_api_runs_routes.py`

The E2E stacks need no change: each API's port comes from `FACTORFLOW_API_PORT`, and the Playwright pages and request contexts use those same loopback origins (section 2.5a).

Source: `component-design-ingestion-api.md` sections 2.5a and 7; `component-design-runtime-config.md` section 2.8.1 (H9 row); CONST-SEC 1.3 SEC-ENC-001 host-local loopback exception, condition H9 and check (p).

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-14] Given the API bound to loopback with no authentication, When a request arrives, Then the interface stays reachable only from the owner's own machine and only on its own loopback names.
- [DAC-E1-18] Given any request to the API, When its `Host` header is missing or is not one of the API's loopback hosts, Then it is answered `400` `host_not_allowed`; and When a state-changing request carries an `Origin` that is not the API's own loopback origin, Then it is answered `403` `origin_not_allowed`.

### Derived

- [DAC-E1-S7-1] Given `ApiSettings.port` is `<port>`, When a request's `Host` is exactly `127.0.0.1:<port>`, `localhost:<port>` or `[::1]:<port>`, Then the host check passes; `Host: evil.example:8000`, `Host: 127.0.0.1:9999` and a request with no `Host` header each return `400` with the error envelope and code `host_not_allowed`, on an `/api/` path and on `/`, before any route handler or the static mount runs. (traces to: DAC-E1-18)
- [DAC-E1-S7-2] Given a request whose method is not `GET`, `HEAD` or `OPTIONS`, When it carries an `Origin` header that is not exactly `http://127.0.0.1:<port>`, `http://localhost:<port>` or `http://[::1]:<port>`, Then it returns `403` with code `origin_not_allowed` and the handler does not run. This holds for each of the five state-changing routes: `POST /api/acquisition-runs`, `POST /api/acquisition-runs/{run_id}/cancel`, `PUT /api/settings/history-depth`, `POST /api/instruments`, `DELETE /api/instruments/{symbol}`, and for `Origin: null`. (traces to: DAC-E1-18)
- [DAC-E1-S7-3] Given a state-changing request with no `Origin` header, or with one of the three loopback origins, When it arrives, Then the origin check does not refuse it; and Given a `GET` with a foreign `Origin`, When it arrives, Then the origin check does not refuse it. (traces to: DAC-E1-18)
- [DAC-E1-S7-4] Given a refused request, When the middleware answers it, Then a `warning` structured log record carries the request id and the rejected header's value, and no credential or request body is read or logged. (traces to: DAC-E1-18, DAC-E1-11)
- [DAC-E1-S7-5] Given a refused `POST /api/acquisition-runs`, When the response is returned, Then no run is created. (traces to: DAC-E1-18)
- [DAC-E1-S7-6] Given the release-source guard `tests/unit/test_release_excludes_test_paths.py::test_release_source_accepts_no_http_scheme` (TC-COMP-364, DAC-E3-S6-17 (c), SEC-NDG-001), When it scans `src/factorflow`, Then it exempts only the loopback origin forms of this story's allow-list in `src/factorflow/api/app.py` (string parts exactly `http://127.0.0.1:`, `http://localhost:` and `http://[::1]:`, completed with `ApiSettings.port`), and still fails on any other `http://` constant, any comparison with or listing of the `http` scheme anywhere, and any of those three forms in another module. A new case in the same test module asserts that the exemption is that narrow: the three forms placed in another module, or a fourth `http://` form in `api/app.py`, fail the guard. (traces to: DAC-E1-18; SEC-NDG-001)

## Technical Details

### API Contract

Applies to every endpoint and to the static mount:

- `400 Bad Request`, body `{"error": {"code": "host_not_allowed", ...}}` in the existing error envelope (`src/factorflow/api/errors.py`), when `Host` is missing or foreign.
- `403 Forbidden`, body with code `origin_not_allowed`, when a non-`GET`/`HEAD`/`OPTIONS` request carries a foreign `Origin`.

The host check runs first. No other response changes.

### Implementation Notes

- One `@app.middleware("http")` function (or a Starlette middleware class) in `src/factorflow/api/app.py`, added in the application factory so it wraps every route and the `/` static mount. A refusal carries the request id like every other error response (DAC-E1-S7-4); the ordering relative to the existing request-id middleware is the implementation plan's to fix.
- The allowed sets are derived from `ApiSettings.port` at factory time; no new setting is added.
- Comparison is exact on the header value (host and port, case-insensitive host); no suffix or prefix matching.

### Data Changes

None.

### Testing

- **Release-source guard (DAC-E1-S7-6).** The origin allow-list is an `http://` string constant, which the existing guard rejects as written. The guard exists so that no `http` provider base URL can reach the release build (E3-S6, SEC-NDG-001). An origin allow-list compared against an incoming request header sends nothing anywhere, so the guard is narrowed to the exact exemption above rather than weakened, and DAC-E3-S6-17 (c) is superseded for these three forms in `api/app.py` only, on the authority of ingestion-api v8 section 2.5a (approved after E3-S6). The narrowing is not done by hiding the scheme behind an indirection. `$test-design` updates TC-COMP-364 to match.
- New `tests/unit/test_api_host_origin.py` (no container, runs under `-m 'not postgres'`), covering DAC-E1-S7-1 to S7-5 with `TestClient` and explicit headers, parametrised over the five state-changing routes and `Origin: null`. Route handlers or their services are stubbed so the test asserts the handler is not reached on refusal.
- The 15 modules listed in the Description pass `base_url="http://127.0.0.1:8000"`; their assertions do not change.
- `uv run pytest` (full suite, PostgreSQL-marked tests included) and `npm run test:e2e` stay green, the latter confirming the E2E origins pass.
