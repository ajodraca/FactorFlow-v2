# Schema Foundation: Instruments, Settings and Applied Migrations

## User Story

As an owner-operator, I want the product to create its first database schema on start, so that instruments and settings have somewhere durable to live and later migrations have a recorded baseline.

## Description

Delivers migration `0001_extensions_owner_state.sql` and the `applied_migrations` table it is recorded in. This is the first of the four numbered migration files and the foundation every later story writes against.

Module: `market-data-store` and `schema-migrator` (schema half only). The migrator's application logic is CAP-001-E1-S2; this story delivers the SQL and the `applied_migrations` definition the migrator reads.

`applied_migrations` is created by the migrator before the first migration file runs, not by a migration file, because the migrator has to read it to decide what to apply. Its definition belongs to `market-data-store` and is reproduced in that component design so the two cannot drift.

Per the tech stack there is **no ORM**: tables are defined in SQL, and access uses `psycopg` 3 with bound parameters.

Source: `component-design-market-data-store.md` sections 2.2, 2.3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-15] Given an existing store, When a newer build applies migrations, Then previously acquired history is neither lost nor rewritten.
- [DAC-E1-1] Given the capability's state, When it is persisted, Then all of it lives in one PostgreSQL database with no part split across another store.
- [DAC-E1-2] Given a database with no `applied_migrations` table, When the migrator starts, Then it creates that table before running the first migration file.

### Derived

- [DAC-E1-S1-1] Given migration `0001`, When it is applied, Then the `btree_gist` extension is created, since `coverage_segment`'s exclusion constraint in a later migration depends on it. (traces to: DAC-E1-1)
- [DAC-E1-S1-2] Given the `instrument` table, When a row is inserted, Then `symbol` must be uppercase and match `^[A-Z][A-Z0-9.-]{0,15}$`, enforced by check constraints rather than by application code. (traces to: AC-1)
- [DAC-E1-S1-3] Given the `instrument` table, When `lifecycle` is written, Then it must be `active` or `retired`, and `retired_at` must be non-null if and only if `lifecycle` is `retired`. (traces to: AC-21)
- [DAC-E1-S1-4] Given `owner_setting`, When the history depth is stored, Then it is held as a `jsonb` value keyed by `setting_key`, so a later setting needs no schema change. (traces to: AC-2)
- [DAC-E1-S1-5] Given `applied_migrations`, When a migration is recorded, Then the row carries `version` as primary key, `name`, `checksum` and `applied_at`. (traces to: DAC-E1-3)
- [DAC-E1-S1-6] Given migration `0001` applied twice, When the second application is attempted, Then it is skipped because its version is already recorded, and no statement runs. (traces to: AC-15)

## Technical Details

### Data Changes

`migrations/0001_extensions_owner_state.sql`:

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;

CREATE TABLE instrument (
    instrument_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    symbol        text        NOT NULL,
    lifecycle     text        NOT NULL,
    added_at      timestamptz NOT NULL DEFAULT now(),
    retired_at    timestamptz,
    CONSTRAINT instrument_symbol_uppercase CHECK (symbol = upper(symbol)),
    CONSTRAINT instrument_symbol_shape     CHECK (symbol ~ '^[A-Z][A-Z0-9.-]{0,15}$'),
    CONSTRAINT instrument_lifecycle_known  CHECK (lifecycle IN ('active', 'retired')),
    CONSTRAINT instrument_retired_at_agrees
        CHECK ((lifecycle = 'retired') = (retired_at IS NOT NULL))
);

CREATE TABLE owner_setting (
    setting_key   text        PRIMARY KEY,
    setting_value jsonb       NOT NULL,
    updated_at    timestamptz NOT NULL DEFAULT now()
);
```

`applied_migrations`, created by the migrator rather than by a file:

```sql
CREATE TABLE IF NOT EXISTS applied_migrations (
    version     integer     PRIMARY KEY,
    name        text        NOT NULL,
    checksum    text        NOT NULL,
    applied_at  timestamptz NOT NULL DEFAULT now()
);
```

A unique index on `symbol` is deliberately **not** added here: symbol uniqueness across lifecycle states is settled in CAP-001-E2-S1, which owns reactivation semantics.

### Testing

- `pytest` with `testcontainers[postgres]`, marked `postgres`.
- Applying `0001` to an empty database creates both tables and the extension.
- Each check constraint rejects its violating case: lowercase symbol, symbol over 16 characters, unknown lifecycle, `retired` without `retired_at`, `active` with `retired_at`.
- Applying `0001` twice records one row in `applied_migrations`.

`uv run pytest -m postgres`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`.
