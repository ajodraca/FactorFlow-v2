# Database URL Confinement and Migrations Packaged in the Distribution

## User Story

As an owner-operator, I want every process to refuse a database connection that would leave my machine unencrypted, and the installed product to carry its own migrations, so that the plaintext database channel stays on the host and a deployed image actually brings my store forward.

## Description

Two changes that every later deployment step needs, both in the Python package:

1. **H7 database URL confinement.** `DatabaseSettings` in `src/factorflow/config/settings.py` gains the validator of `component-design-runtime-config.md` section 2.3, *Database URL confinement (H7)*: a plaintext channel only to loopback, every libpq route to another address refused, `sslmode=verify-full` required for any other host. `src/factorflow/db/migrate_main.py` stops reading `FACTORFLOW_DATABASE_URL` from `os.environ` and loads it through `DatabaseSettings()` before connecting (`component-design-schema-migrator.md` section 2.5), so the first client on the channel is confined too. `app_main`'s pool (`src/factorflow/api/app.py`) and `ingestion_main` already load through `DatabaseSettings` and gain the check with no change. This is condition H7 of the CONST-SEC 1.3 `SEC-ENC-001 host-local loopback exception`, relied on for channels (b) and (c) through runtime-config section 2.8.1 and DEC-0050.
2. **Migrations as package data (release blocker B1).** The four migration files and their `README.md` move from the repository-root `migrations/` to `src/factorflow/db/migrations/`. `migrate_main` exposes `MIGRATIONS_DIR = Path(__file__).resolve().parent / "migrations"`, and `pyproject.toml` `[tool.setuptools.package-data]` adds `"db/migrations/*.sql"`, so the installed distribution carries them (schema-migrator section 2.1). No file's content changes, so no recorded checksum changes.

Module: `runtime-config` and `schema-migrator`. Both live in this repository; one story because the migrator's change touches the same entry point for both reasons, and neither part is useful to deploy without the other.

**Files the move touches** (schema-migrator section 2.1): `src/factorflow/db/migrate_main.py`; `tests/conftest.py`; the test modules that compute `parents[N] / "migrations"` and import `MIGRATIONS_DIR` instead: `tests/integration/test_api_coverage.py`, `test_api_health.py`, `test_api_pagination.py`, `test_api_runs.py`, `test_instrument_constraints.py`, `test_migration_0001.py`, `test_migration_idempotence.py`, `test_migrator_empty.py`, `test_observation_append.py`, `test_owner_setting.py`; `tests/unit/test_migration_0001_matches_design.py`, `test_migration_filenames.py`, `test_migrator_discover.py`, `test_runs_queries.py`, `test_schema_migrations_match_design.py`, `test_sql_is_append_only.py`; `tests/unit/test_no_committed_secrets.py`'s scanned prefixes; the comments citing `migrations/000N_*.sql` in `src/factorflow/api/models.py`, `src/factorflow/runs/queries.py`, `web/src/api/types.ts` (two), `tests/e2e/support/acquisition.ts` and the two SQL fixtures; and the README. The `Dockerfile` line copying `migrations/` is removed by CAP-001-E1-S9, which rewrites the file. `tests/fixtures/migrations_ok/` stays where it is.

**Test placeholder URLs** (specification review v13 FINDING-53). Runtime-config section 2.3 says no test changes under the validator, but 15 test modules set `FACTORFLOW_DATABASE_URL=postgresql://unused/unused`, whose host `unused` the validator refuses. Each changes to a loopback placeholder such as `postgresql://unused@127.0.0.1/unused`: `tests/integration/test_api_binding.py`, `test_api_static_mount.py`; `tests/unit/test_api_coverage_routes.py`, `test_api_errors.py`, `test_api_instruments_error_mapping.py`, `test_api_instruments_query_mapping.py`, `test_api_isolation.py`, `test_api_no_secrets.py`, `test_api_request_id.py`, `test_api_request_id_redaction_composition.py`, `test_api_runs_routes.py`, `test_ingestion_e2e_main.py`, `test_ingestion_main.py`, `test_massive_tls.py`, `test_settings_base_url.py`. Where a test asserts an exact `Settings()` error message (`test_settings_base_url.py`), the expected text is unchanged once the placeholder is loopback.

## Technical Details

### Configuration Surface

No new variable. `FACTORFLOW_DATABASE_URL` gains the confinement rule above; the compose definition (CAP-001-E1-S9) names `127.0.0.1`.

### Implementation Notes

- The validator is a `model_validator(mode="after")` on `DatabaseSettings`, raising through the existing `_EnvNamedSettings` path so the message names the variable and never the value. The checked host must be the one libpq would connect to, so the URL is parsed the way libpq parses it (for example with `psycopg.conninfo.conninfo_to_dict`), not with a generic URL parser alone.
- `migrate_main.main()` constructs `DatabaseSettings()` inside the same try path that today handles a missing variable, maps `ConfigurationError` to exit 1, and passes `settings.url.get_secret_value()` to `run_migrations`. Its module docstring's deferral note is removed.
- The redaction filter in `configure_logging()` keeps reading the raw variable to mask it (runtime-config section 2.5); no other code under `src/` reads it.

### Data Changes

None. Files move; content and checksums are unchanged.
