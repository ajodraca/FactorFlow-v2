# Status Region and Unreachable State

## User Story

As an owner-operator, I want to see from any screen whether the product is answering, so that I can tell a healthy system from one that is failing without opening the database.

## Description

Delivers `web/src/app/status-region.tsx`, the persistent region pinned to the bottom of the navigation rail, and the unreachable state the shell renders when the API cannot be reached.

Module: `owner-web-app`. The region reports two facts; this story delivers the liveness fact and the frame for the second. The most recent run's outcome is supplied by CAP-001-E7-S3, and until that story lands the region renders its run line as not yet available rather than as a failure.

The unreachable state is what a refused start surfaces as. When the migrator exits non-zero the API never binds, so the interface cannot reach it, and AC-16 requires that to be legible rather than blank.

Source: `component-design-owner-web-app.md` sections 2.2, 2.3; `ux-design.md` sections 0, 2.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-18] Given any screen, When it renders, Then the owner can tell whether the product is answering without inspecting the data store.
- [AC-16] Given a store that could not be brought forward, When the owner opens the interface, Then a named unreachable state states the likely cause and where to look.
- [DAC-E1-13] Given the status region, When it is mounted, Then it polls health every 30 seconds and shows its last-updated time.
- [DAC-E1-14] Given the status region, When it is laid out, Then it is sized to take a third line later without restructuring.
- [DAC-E1-15] Given a failure to reach the API, When it occurs, Then a named unreachable state renders rather than a raw transport error.
- [DAC-E1-17] Given no run has ever existed, When the region renders, Then it renders correctly rather than erroring or showing a false failure.

### Derived

- [DAC-E1-S5-1] Given a successful health response, When it renders, Then the region shows the product as answering with a text label plus icon or shape, readable in greyscale. (traces to: AC-18)
- [DAC-E1-S5-2] Given the last-updated time, When it renders, Then it uses ISO-8601 and the America/Chicago timezone for timestamps. (traces to: DAC-E1-13)
- [DAC-E1-S5-3] Given a health request that fails, When the failure is a transport error, Then the unreachable state names the likely cause, that the application container may not have started, and where to look, the container log. (traces to: DAC-E1-15)
- [DAC-E1-S5-4] Given the run-outcome line before CAP-001-E7-S3 lands, When the region renders, Then it states that no run has been recorded rather than presenting an empty successful state. (traces to: DAC-E1-17)
- [DAC-E1-S5-5] Given the polling interval, When the component unmounts, Then the interval is cleared so no request continues after navigation. (traces to: DAC-E1-13)
- [DAC-E1-S5-6] Given `credential_present` is false in the health response, When the region renders, Then it distinguishes a missing credential from a health check that did not answer. (traces to: AC-13)

## Technical Details

### API Contract Consumed

`GET /api/health` (delivered by CAP-001-E1-S6):

```json
{
  "status": "ok",
  "database": "reachable",
  "credential_present": true,
  "schema_version": 4,
  "most_recent_run": null
}
```

`most_recent_run` is `null` until CAP-001-E7-S3 populates it, and `null` renders as "no run recorded", never as a failure.

### Testing

- `vitest` with React Testing Library; fetch stubbed.
- A successful response renders the answering state with text plus icon.
- A rejected fetch renders the named unreachable state containing the cause and where to look.
- `most_recent_run: null` renders "no run recorded".
- `credential_present: false` renders distinctly from an unanswered check.
- Unmounting clears the interval; asserted by advancing fake timers and observing no further calls.

### Validation

`npm run test`, `npm run lint`, `npx tsc --noEmit`.

### Dependencies

- **CAP-001-E1-S4**, the shell providing the region's slot.
- **CAP-001-E1-S6**, the health endpoint. Developable in parallel against the contract above.
