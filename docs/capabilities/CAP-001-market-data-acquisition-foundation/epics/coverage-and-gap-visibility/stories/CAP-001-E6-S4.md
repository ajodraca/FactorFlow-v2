# Coverage Screen

## User Story

As an owner-operator, I want one screen answering whether my data is fit to rely on, so that I can tell which instruments have complete coverage over the range I need without inspecting the data.

## Description

Delivers `web/src/screens/coverage/`.

Module: `owner-web-app`. Renders inside the shell from CAP-001-E1-S4. This is the screen the capability's second user flow is entirely about.

Coverage does not auto-poll and shows a last-updated time, because deriving coverage is the most expensive read in the product.

The unavailable state matters as much as the data. When fewer than two instruments hold data, the screen must say detection is unavailable rather than show a reassuring zero.

Source: `ux-design.md` section 1.1; `component-design-owner-web-app.md` section 2.3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-7] Given the Coverage screen, When it renders, Then each instrument shows data-type presence, covered range and last-acquired.
- [AC-8] Given gaps, When they render, Then a count shows in the row and specific dates behind expansion.
- [AC-17] Given nothing acquired, When it renders, Then it states no data has been acquired rather than appearing empty and healthy.
- [AC-21] Given retired instruments, When they render, Then their retained coverage is shown and marked distinctly.
- [AC-22] Given an instrument short of the stated depth, When it renders, Then it shows as short by a stated number of years.
- [DAC-E6-4] Given gap detection unavailable, When it renders, Then the reason is shown rather than a zero count.
- [DAC-E6-13] Given the screen, When it is open, Then it does not auto-poll and shows a last-updated time.

### Derived

- [DAC-E6-S4-1] Given an absent value, When it renders, Then an em dash is shown; a measured zero renders as zero; an inapplicable cell renders blank. These three are visually distinct. (traces to: AC-7)
- [DAC-E6-S4-2] Given dates, When they render, Then they use ISO-8601, with session dates left unconverted and timestamps in America/Chicago. (traces to: AC-7)
- [DAC-E6-S4-3] Given per-data-type presence, When it renders, Then present, absent and unknown use distinct badge variants, each carrying text plus icon or shape. (traces to: DAC-E6-11)
- [DAC-E6-S4-4] Given never-acquired, When it renders, Then its copy differs from a filter matching nothing, and the never-acquired state offers the run action. (traces to: AC-17)
- [DAC-E6-S4-5] Given 3000 instruments, When the screen renders, Then search and filter remain usable and the table scrolls within its own container rather than the page. (traces to: DAC-E6-10)
- [DAC-E6-S4-6] Given a uniform depth shortfall across all instruments, When it renders, Then it reads as a plan limit rather than as a provider data gap. (traces to: DAC-E6-12)
- [DAC-E6-S4-7] Given the screen in greyscale, When it renders, Then every status remains distinguishable. (traces to: AC-7)

## Technical Details

### Implementation

- React 18, TypeScript, Tailwind, shadcn/ui.
- `data-table` `expandable`; `badge` `coverage-present` / `coverage-absent` / `coverage-unknown`; `badge` `status-warning` for depth shortfall; `badge` `secondary` for retired.
- Endpoint: `GET /api/coverage`. Manual refresh only, with last-updated shown.

### Testing

- `vitest` with React Testing Library; `@playwright/test` for expansion to gap dates.
- Absent, zero and inapplicable render distinctly, asserted directly.
- `gap_detection.available: false` renders the reason and no zero count.
- Never-acquired and nothing-found render different copy.
- No polling occurs, asserted with fake timers over an extended interval.
- A retired instrument renders with its marker and its coverage.

### Validation

`npm run test`, `npm run test:e2e`, `npm run lint`, `npx tsc --noEmit`.

### Dependencies

- **CAP-001-E1-S4**, the shell.
- **CAP-001-E6-S3**, the endpoint consumed.

### Open Questions

- Density tier is unselected (OQ-UI-4); this screen inherits the current default and selects no tier.
- `data-table` offers pagination rather than the virtualisation STD-UI-30 requires at this volume, so the component does not discharge that rule alone.
