# Coverage API Endpoint

## User Story

As an owner-operator using the interface, I want one endpoint returning per-instrument coverage, gaps and their availability, so that the Coverage screen has a single contract to call.

## Description

Delivers `src/factorflow/api/routes/coverage.py`.

Module: `ingestion-api`. Thin surface over `coverage-service`. Deriving coverage is the most expensive read in the product, which is why the screen does not auto-poll.

Source: `component-design-ingestion-api.md` section 11.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-7] Given `GET /api/coverage`, When it is called, Then it reports per-instrument data-type presence, covered ranges and last-acquired.
- [AC-8] Given the response, When gaps are included, Then gap counts and gap-detection availability with a reason are present.
- [AC-17] Given nothing acquired, When it is called, Then `never_acquired` is true.
- [DAC-E6-10] Given the endpoint, When it is called, Then it supports symbol filter, lifecycle filter, `from`, `to`, `limit` and `cursor`.

### Derived

- [DAC-E6-S3-1] Given gap detection unavailable, When the response is built, Then `gap_detection` reports unavailable together with the reason, and gap counts are absent rather than zero. (traces to: DAC-E6-4)
- [DAC-E6-S3-2] Given specific gap dates, When they are requested, Then they are available through expansion rather than included in every collapsed row, keeping the default response bounded at 3000 instruments. (traces to: DAC-E6-14)
- [DAC-E6-S3-3] Given a `limit` beyond the canonical bound, When it is supplied, Then `422` is returned rather than silently clamping. (traces to: DAC-E6-10)
- [DAC-E6-S3-4] Given a lifecycle filter, When it is applied, Then retired instruments can be included or excluded explicitly, and the default includes them so retained history is not hidden. (traces to: AC-21)
- [DAC-E6-S3-5] Given `from` later than `to`, When supplied, Then `422` is returned. (traces to: DAC-E6-10)

## Technical Details

### API Contract

- Endpoint: `GET /api/coverage`
- Auth: none, loopback only
- Query: `symbol`, `lifecycle`, `from`, `to`, `limit`, `cursor`
- Response `200`:
  ```json
  {
    "instruments": [{
      "symbol": "AAPL", "lifecycle": "active",
      "data_types": {"reference": "present", "prices": "present",
                     "fundamentals": "absent", "corporate_actions": "present"},
      "covered_from": "2021-09-06", "covered_to": "2026-09-05",
      "last_acquired_at": "2026-09-05T22:14:03Z",
      "gap_count": 2, "depth_short_by_years": 0
    }],
    "never_acquired": false,
    "gap_detection": {"available": true, "reason": null},
    "next_cursor": null
  }
  ```
- Errors: `422` for bad bounds or an inverted date range.

### Testing

- `pytest` with FastAPI's test client and `testcontainers[postgres]`, marked `postgres`.
- A populated store returns presence, ranges, last-acquired and gap counts.
- A single-instrument store returns `gap_detection.available` false with a reason and no gap counts.
- An empty store returns `never_acquired` true.
- Over-limit and inverted range return `422`.
- The default lifecycle filter includes retired instruments.
