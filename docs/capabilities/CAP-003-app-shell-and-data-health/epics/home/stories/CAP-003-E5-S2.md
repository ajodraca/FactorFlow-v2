# The Data Tile: Verdict Badge, Hero Count, As-Of Lines, Lag Badge and the First-Download-Running State

## User Story
As an owner-operator, I want one tile that says how many followed stocks are current and whether the data can be trusted, in the same words Data health uses, so that Home never reads better than Data health.

## Description
Creates `web/src/screens/home/data-tile.tsx`: a `card` `metric` whose whole surface is one link to `/data`, titled *Data*, per home-ui 2.4. Badge from `dataTileBadge` over `worstDataTier(problems.stock_count, followed_count, latest_terminal_download.state)` and `tierOf` over the summary's score state; hero line *{current} of {followed} stocks current* with both figures from the summary's `stocks_current`, attention's `followed_count` and an em dash with hidden *not determinable* only while the summary is not served or carries no `stocks_current`; *Scores {time}* from `set.ended_at` (em dash while not served, *No scores yet* when `never_classified`); *Prices {YYYY-MM-DD}* from `prices_as_of`; the scope sentence; the lag badge `status-warning` *Not reflecting the latest download* when `set.not_current` or `later` building or failed. While `latest_terminal_download` is null the tile renders the first-download-running state: *Your first download, started {time}, is running.* from `started_at` or `requested_at`, at most a `status-active` *Downloading* badge while `running`, no verdict word, no hero count, no as-of lines, no lag badge, no progress (DEC-0210 as amended). Skeleton while attention loads; *Couldn't read the data summary: {reason}.* with **Try again** while it fails; a summary error other than `404` the same way inside the tile. No request to `/api/data-health`. Writes `data-tile.test.tsx`.

Source: component-design-home-ui.md 2.2, 2.4, 7; component-design-ui-components.md 2.4; epic CAP-003-E5 DAC-E5-2 to DAC-E5-5, DAC-E5-11.
