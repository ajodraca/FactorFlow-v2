# The Data Tile

## User Story

As an owner-operator, I want one tile that says how many followed stocks are current out of how many are followed, when scores and prices are from, and whether scores lag the latest download, so that I know how far to trust what I see without opening Data health.

## Description

Logical component: `home-ui`. Creates `web/src/screens/home/data-tile.tsx`, a `card` `metric` whose whole surface is one link to `/data`, as `component-design-home-ui.md` §2.4 specifies. The badge is E1-S3's `dataTileBadge` over `worstDataTier(problems.stock_count, followed_count, latest_terminal_download.state)` and `tierOf` over the summary's score state (DEC-0210, DEC-0217 as amended, PROVISIONAL). The hero line takes both figures from the summary's `stocks_current`; only while the summary is not served is `followed` attention's `followed_count` and the current count an em dash. While `latest_terminal_download` is null and `latest_download` is not, the tile renders the first-download-running state with no verdict word. The lag badge renders when `set.not_current` is true or `later` is building or failed. While attention fails the tile renders the error state; a summary error other than `404` renders inside the tile the same way.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-8] Home MUST show how many followed stocks are current out of how many are followed, and the as-of time of scores and of prices, and MUST say when scores do not reflect the latest download.
- [AC-11] The tile's verdict tier MUST be the same composition Data health's verdict uses.
- [AC-21] Until a download has ended, the tile MUST give no verdict and never *Yes*.
- [AC-20] The tile's badge MUST render through `StatusBadge` with label and shape.
- [DAC-E5-2] While `latest_terminal_download` is null and `latest_download` is not, the tile MUST render the first-download-running state: title *Data*, body *Your first download, started {YYYY-MM-DD HH:MM zone}, is running.* from `started_at` (or `requested_at` while queued), at most a `status-active` *Downloading* badge shown only while `latest_download.state` is `running`, and no verdict word, hero count, as-of line, lag badge or progress. (traces to: AC-21, AC-8)
- [DAC-E5-3] Once `latest_terminal_download` is set, the tile badge MUST be `dataTileBadge` over the verdict from attention's `problems.stock_count`, `followed_count` and `latest_terminal_download.state` and the summary's score state; no request to `/api/data-health` MUST be made. (traces to: AC-8, AC-11)
- [DAC-E5-4] The hero line MUST take `current_count` and `followed_count` both from the summary's `stocks_current` whenever the summary is served; only while the summary is not served or carries no `stocks_current` MUST `followed` be attention's `followed_count` and the current count an em dash with hidden *not determinable*; the scores as-of MUST be the summary's `set.ended_at`, an em dash while not served and *No scores yet* when `never_classified`; the prices as-of MUST be attention's `prices_as_of` as a session date, unconverted. (traces to: AC-8)
- [DAC-E5-5] The lag badge `status-warning` *Not reflecting the latest download* MUST render when the summary's `set.not_current` is true or its `later` block reports a newer set building or failed, and never otherwise. (traces to: AC-8)
