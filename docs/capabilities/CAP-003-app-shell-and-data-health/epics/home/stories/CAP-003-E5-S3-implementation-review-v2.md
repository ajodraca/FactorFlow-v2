### IR-001 — Row identity is unpinned: a middle item leaving moves focus under a constant key

- **Severity**: MEDIUM
- **Scope**: late
- **Status**: OPEN
- **Acceptance criteria**: DAC-E5-9, DAC-E5-S3-2, AC-25 (home-ui §10 *Accessibility*: "A changed count is announced politely … and focus never moves")
- **Tasks**: T003; T016
- **Files**: `web/src/screens/home/needs-you-card.tsx:60` (`key={item.kind}`); `web/src/screens/home/needs-you-card.test.tsx:321-349`
- **Claim challenged**: T003 proves that focus never moves when an item leaves.
- **Observed evidence**: The mutant `review2-key-constant` (`key={item.kind}` → `key="row"`) passes every home test, `token-literals.test.ts` and `tsc`. T003 focuses the middle row and removes `data_problems`, which is the last row. Under positional reconciliation, the rows before the removed one keep their nodes, so the test cannot tell the keys apart. Probe P1 focuses the last row's link and removes the middle row instead. It passes on HEAD. Under the mutant, React updates the middle `li` in place with the last row's props and deletes the last `li`, so `document.activeElement` becomes `<body>`.
- **Expected evidence/behavior**: Plan T016: "`<ul>` of `NeedsYouItemRow`s, one per item, `key={item.kind}`". DAC-E5-9 and DAC-E5-S3-2: an item leaves "without `document.activeElement` changing". Items are unique per kind (data-health-reader item rules: "Each kind present exactly while its cause holds"), so `kind` is a stable identity.
- **Impact**: The production code is correct today. A refactor to an index or constant key would pass the suite. A keyboard user resting on a later row would then lose focus to the page whenever an earlier item resolves, which is the exact failure DAC-E5-9 forbids. The scope is `late` because neither line changed since v1, so this finding cannot block.
- **Required remediation**: Optional, non-blocking. In T003, add a case that focuses a row after the one that leaves (for example the *Fix data…* link, with `download_not_complete` removed). Assert that `document.activeElement` is still that link, that the link is connected, and that it still carries its own name. `review2-key-constant` must then fail.

### IR-002 — Substring class assertions leave the row's `grid` and the root's `flex` unpinned

- **Severity**: MEDIUM
- **Scope**: late
- **Status**: OPEN
- **Acceptance criteria**: DAC-E5-10, AC-26 (home-ui §10 *Layout*: "regions `--space-5` apart … the summary row, a three-column grid with the data tile in the first column"; story Description: "the three-column summary row with the tile in the first column")
- **Tasks**: T006; T014; T017
- **Files**: `web/src/screens/home/index.tsx:48`, `:54`; `web/src/screens/home/home.test.tsx:385`, `:614-616`
- **Claim challenged**: T006 pins the summary row's `grid-cols-3` grid, and T014 pins the root's `w-full`, `flex`, `flex-col` and `gap-5`.
- **Observed evidence**: Both tests use `className).toContain(name)`, which is a substring match. `"grid-cols-3"` contains `grid`, and `"flex-col"` contains `flex`. So both of these pass every home test, `token-literals.test.ts` and `tsc`:
  - `review2-row-no-grid`: `className="grid grid-cols-3 gap-5"` → `className="grid-cols-3 gap-5"`;
  - `review2-root-no-flex`: `className="flex w-full flex-col gap-5"` → `className="w-full flex-col gap-5"`.

  Probes P2 and P3 use `classList.contains`. They pass on HEAD, and each fails on its mutant. The cycle-5 assertions already use `classList.contains` for exactly this reason.
- **Expected evidence/behavior**: Plan T017: root `<div className="flex w-full flex-col gap-5" …>` and `<div data-testid="home-summary-row" className="grid grid-cols-3 gap-5">`. Plan T014: "classes `w-full`, `flex`, `flex-col` and `gap-5`".
- **Impact**: Both effects are visual. Without `grid`, `grid-cols-3` does nothing. The row is a block, and the tile spans the full content width instead of the first of three columns. Without `flex`, `flex-col` and `gap-5` do nothing, so the header, the summary row and the card lose their `--space-5` separation. Per skill E.9, a visual-only effect is recorded here and never lowers severity. Scope `late` caps it at MEDIUM.
- **Required remediation**: Optional, non-blocking. In T006 and T014, assert the classes with `classList.contains` (whole class names), as cycle 5 does. `review2-row-no-grid` and `review2-root-no-flex` must then fail.
