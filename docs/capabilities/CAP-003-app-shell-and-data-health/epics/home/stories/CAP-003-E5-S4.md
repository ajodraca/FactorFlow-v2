# Home Journey End to End: a Partial Download Puts a Data Item on Home and the Chip in the Rail

## User Story
As an owner-operator, I want Home proven against the running product, so that a download that left stocks failed shows up as an item and as a count, and leaves when fixed.

## Description
Writes `tests/e2e/home-needs-you.spec.ts` (home-ui 2.1, 7): a partial download leaving three stocks failed shows the data item on Home and the Data health chip in the rail; **Fix data** navigates to `/data` (the Data health screen itself is registered and proven by E6; this spec asserts the URL, backlog review v2 FINDING-2); after a clean download the item leaves. It also carries the Home assertions the setup journey (E4-S5) deferred: with no download `/home` shows *No data has been downloaded yet.* with **Start setup**, and after the first download is started `/` lands on Home with the first-download item. The summary precondition is fixed: `GET /api/classifications/summary` answers `404` in this clone (CAP-002 not merged), so the tile's hero count renders not determinable and the first-download item follows DEC-0216 (backlog review v2 FINDING-11).

Scheduled after the E5 closing story CAP-003-E5-S5, which registers `/home` and the Home destination (DEC-0223 answer A).

Source: component-design-home-ui.md 7; capability flow 3.
