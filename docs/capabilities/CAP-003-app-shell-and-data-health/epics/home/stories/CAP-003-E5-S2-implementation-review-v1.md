### IR-001 — The lag badge's *later building* cause is never isolated, so dropping it passes

- **Severity**: HIGH
- **Scope**: initial
- **Status**: OPEN
- **Acceptance criteria**: DAC-E5-5, AC-8
- **Tasks**: T005 (TC-COMP-129)
- **Files**: `web/src/screens/home/data-tile.tsx:212`; `web/src/screens/home/data-tile.test.tsx:113-121` (`BUILDING`), `:450-476`
- **Claim challenged**: T005 proves the lag badge "renders when `set.not_current` is true or `later` reports building or failed, and never otherwise".
- **Observed evidence**: Replacing `summary.later !== null` with `summary.later?.state === "failed"` passes all 183 home tests. The only building fixture, `BUILDING`, also sets `set.not_current: true`, so the `not_current` cause alone keeps its badge. The plan's kill list names only "removing the `later !== null` cause (NEVER_FAILED loses it)", which covers failed and not building. Probe P1 renders `never_classified: true`, `set: null` and `later.state: "building"`. HEAD shows *Not reflecting the latest download*, and the mutant shows nothing.
- **Expected evidence/behavior**: DAC-E5-5: "MUST render when … its `later` block reports a newer set building or failed". The plan's Resolved Conflict 6 reads `later` literally, with or without a set, and TC-COMP-129 step 2 says "Render with `later.state` `building`". CAP-002 serves this exact state: "`later` carries a building or failed set in both states" (`classification-types.ts:73-77`). UX design 1.3's *first scores* item is keyed on "summary `later` building, while summary `never_classified` is true".
- **Impact**: A regression would hide the lag badge while the first scores are produced. That is a real state on every new install, right after its first download ends. The tile would then show a verdict and *No scores yet* with no lag warning.
- **Required remediation**: Add a T005 case that isolates the building cause, for example `served(NEVER_BUILDING)`: `never_classified: true`, `set: null`, `stocks_current: null`, and a building `later`. It must expect the `status-warning` lag badge, so that `review-lag-later-failed-only` fails.
