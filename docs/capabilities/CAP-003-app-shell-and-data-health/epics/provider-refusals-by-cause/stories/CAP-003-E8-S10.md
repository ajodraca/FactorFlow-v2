# The Download Detail States Each Failed Data Type's Fix by Its Cause

## User Story
As an owner-operator, I want each failed data type on a download's detail to say what fixes it, by the cause its reason records, so that the detail and *Needs fixing* tell me the same thing.

## Description
Adds the fix line to the download detail's expanded data types (owner-web-app v2 §2.1, §2.3 *A failure's fix*; UX design v2 §1.8 *Fix by cause*; system design §3.6 note 7, §4.2, the delivered run-detail interface reused unchanged). In `web/src/screens/runs/detail/instrument-roster.tsx` (taken over by CAP-003-E7-S5): `fixText(row)` as owner-web-app §2.3 gives it, `failureRecovery(row.outcome, failureCause(row.reason))` from `ui-components`, rendered after the reason sentence of each expanded data type whose outcome is `failed`:

- `provider_plan` (reason begins `[not_entitled] `): `PLAN_FIX_TEXT`, no text *Download again*;
- `download_later` (reason begins `[rate_limited] `): `RATE_LIMIT_FIX_TEXT`;
- `download_again` (any other prefix, or none): this screen's constant `DOWNLOAD_AGAIN_FIX`, *Download again; data already stored is never duplicated or overwritten.* (UX design 1.8);
- `stop_following` (outcome `not_found`): nothing added; E7-S5's *Not found* sentence and **Open Data health** render as they do.

The cause is read from the delivered `GET /api/acquisition-runs/{id}` row's `reason`, so the request, the response model and the client are unchanged. The reason sentence and the summary card, including its download recovery for a `failed` or `partial` download, stay as E7-S5 delivers them (owner-web-app §14 question 3, the owner's).

**Ownership (backlog review v5 FINDING-1).** CAP-003-E7-S5 takes the detail over without any per-failure fix line: its Description and criteria render the reason sentence and the *Not found* diagnosis only, and the delivered `instrument-roster.tsx` renders none either. This story owns the whole fix line, all four kinds, including the `download_again` sentence that owner-web-app v2 §2.3 calls delivered but that neither the delivered screen nor E7-S5 renders. E7-S5 is not refined. This story adds rows to `web/src/screens/runs/run-detail.test.tsx`; where an E7-S5 assertion reads a failed row's full text content, the story extends it with the fix line and names it in its task plan.

Source: component-design-owner-web-app.md 1 (item 9), 2.1, 2.3, 7 (*Fix by cause on the detail*), 8 criteria 8, 9, 14 question 3; component-design-ui-components.md 2.7a; UX design v2 §1.8; epic CAP-003-E8 DAC-E8-15, DAC-E8-16, DAC-E8-18, DAC-E8-19.
