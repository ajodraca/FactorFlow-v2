# A Real 429 Is Throttling, Not an Attempt, and Each Stock Starts Its Own Budget

## User Story
As an owner-operator, I want a rate limit from the provider waited out instead of spent as a failed attempt, and the wait bounded per stock, so that a download on a busy plan finishes with data instead of failing within seconds.

## Description
Lifts the governor classifier out of `MassiveClient._through_governor` into a module-level `classify_for_governor(exc) -> Outcome` in `src/factorflow/ingestion/massive/client.py` and adds `MassiveClient.start_instrument()` (massive-client CAP-003 §2.3, §2.6; system design §3.6 notes 2, 3, §4.2 *Throttle classification*, *Stock boundary*). The rules, first match winning:

1. a `urllib3.exceptions.MaxRetryError` whose `reason` is a `ResponseError` and `str(reason) == ResponseError.SPECIFIC_ERROR.format(status_code=429)` (the module constant `_THROTTLED_RETRY_REASON`, never a hand-typed copy) is `THROTTLED`;
2. any other non-`BadResponse` exception is `RETRYABLE`: every other `MaxRetryError` (the other forcelisted statuses `413`, `499`, `500`, `502`, `503`, `504`, a refused redirect whose reason is "too many redirects", a connection error), as delivered;
3. a `BadResponse` that `is_rate_limited_body` recognises is `THROTTLED` (kept for an SDK without `429` in its forcelist);
4. any other `BadResponse` is `FATAL` unless `classify_error_body` gives a `ProviderUnavailable`, which stays `RETRYABLE`.

`_through_governor` passes `classify_for_governor` to `self._governor.execute` and keeps the delivered `except BadResponse` re-raise. `start_instrument()` calls `self._governor.start_throttle_budget()` once and sends nothing. The SDK construction (`retries=0`, the forcelist, the redirect refusal, `pagination=False`, `trace=False`, `base=`) is unchanged, so the redirect and proxy controls of DEC-0038, DEC-0041 and DEC-0042 are untouched.

Replaces the delivered TC-INT-025 test in `tests/unit/test_massive_retry.py`, which patched `RESTClient` to raise a `BadResponse` for a `429` that the real SDK cannot raise under `retries=0`, with the real-transport rows below, keeping its marker; the TC-INT-026 timeout row is kept.

**Lands and releases with CAP-003-E8-S4 (owner decision, Alvaro de Jodra, 2026-11-08; backlog review v6 FINDING-13).** This story and CAP-003-E8-S4 land in one pull request or, if merged separately, ship in one release: no release is built from a commit that holds this story without CAP-003-E8-S4. The runner's per-stock call to `start_instrument()` is E8-S4's, and without it the budget starts when the client is built (rate-limit-governor §3); because `CredentialAwareClientFactory.get_or_rebuild` caches one client per credential across downloads, that budget would span the ingestion process, not one stock. Heartbeats would stay bounded, but once 300 s of throttling were spent every later throttled request in any download would be recorded `[rate_limited]` after a single send, where release 0.2.0 still retried a `429` twice with backoff.

## Technical Details

### API Contract
- No HTTP surface. In process (massive-client §11): `classify_for_governor(exc) -> Outcome` (new, module level); `MassiveClient.start_instrument() -> None` (new); `MassiveClient.fetch_*` may now raise `ProviderRateLimited` when a stock's budget is spent.
- Provider endpoints: unchanged; no request is added.

### Data Changes
- None.

### Implementation
- Python 3.12, `massive` 2.8.0, `urllib3` 2.7.0, pytest (tech stack v7).
- Files: `src/factorflow/ingestion/massive/client.py`; `tests/unit/test_massive_retry.py` (TC-INT-025's patched test replaced, rows added), `tests/unit/test_massive_client_governor_integration.py` (row added).
- A urllib3 or SDK version bump re-runs these rows, which fail if either side changes how a `429` arrives (assumption 10). Rollback: redeploy the previous image; no data step.

### Validation
`uv run pytest` (or `uv run pytest -m 'not postgres'` when no container runtime is available, reported as an exclusion), `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src` (tech stack v7 validation commands).

### Dependencies
- **CAP-003-E8-S2**, `RateLimitGovernor.start_throttle_budget()`, the per-stock budget checked before each wait and `ProviderRateLimited` with its `rate_limited` kind, which rows DAC-E8-S3-2 to DAC-E8-S3-4 exercise.
- **CAP-003-E8-S1**, `ProviderNotEntitled` and its real-transport rows, which DAC-E8-S3-7 keeps passing through the lifted classifier.
- No E1 to E7 story (owner decision, Alvaro de Jodra, 2026-11-07: provider side first, recorded in `backlog.md` *Sequencing*).
