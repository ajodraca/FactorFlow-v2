# The Shell's Problem Failure Type Carries Its Cause

## User Story
As an owner-operator, I want the shell's typed problem rows to carry each failure's cause as the API serves it, so that Data health can name the provider plan as a plan refusal's fix.

## Description
Adds owner-shell v2's one change (owner-shell v2 §2.1, §2.3; system design §4.1 `owner-shell` row). In `web/src/app/shell-types.ts` (CAP-003-E3-S1's file): `import type { FailureCause } from "../components/patterns/failure-recovery";` and, in the failure type of `ProblemPage`'s rows, which `DataHealth.problems.rows` shares, the required field `cause: FailureCause | null`. The import is type-only, so it makes no runtime cycle with `ui-components`' type imports from this file. `web/src/app/shell-client.ts` (E3-S1's file) passes the served `cause` through on `fetchDataHealth()` and `fetchProblems(cursor, limit)`, `null` included; with the field required, `npx tsc --noEmit` refuses any mapping that drops it. Writes `web/src/app/shell-types.test.ts` (new, type-level). The shell reads `cause` nowhere itself.

**Ownership (backlog review v5 FINDING-1).** CAP-003-E3-S1 builds `shell-types.ts` and `shell-client.ts` without `cause`, as its Description lists the types; E3-S1 depends on nothing in CAP-003 (DEC-0223 answer A); it could import `FailureCause` once CAP-003-E8-S5 lands, but owning the field would add an edge from E3-S1 to E8-S5, against EPIC order and ahead of E1-S8, so the field is this story's whichever lands first (`backlog.md` ownership table; backlog review v6 FINDING-1). This story owns the field and its type proof. E3-S1 is not refined: its DAC-E3-S1-4 (no field added or renamed from the wire shape) holds both before and after this story.

**Fixtures this story changes.** Making `cause` required turns every test fixture typed as a `ProblemPage` or `DataHealth` failure that exists when this story lands into a `tsc` error until it carries `cause`. This story adds `cause` to each, `null` unless the test exercises a cause, and changes no assertion. Expected files, confirmed by `npx tsc --noEmit` when the story is planned: `web/src/app/shell-client.test.ts` (CAP-003-E3-S1) and any `web/src/app/*.test.ts(x)` or `web/src/screens/data-health/*.test.tsx` (CAP-003-E3-S3, E6-S1, E6-S3, E6-S5) already landed. A story landing after this one writes its fixtures with `cause` from the start.

Source: component-design-owner-shell.md 2.1, 2.3 (*`cause` on a problem failure*), 7 (*Failure cause type*), 8 criterion 9; component-design-ui-components.md 2.7a, 11; epic CAP-003-E8 DAC-E8-14.
