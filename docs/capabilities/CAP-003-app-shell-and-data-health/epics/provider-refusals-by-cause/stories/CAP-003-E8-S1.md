# A Plan Refusal Is Sent Once and Recorded as not_entitled

## User Story
As an owner-operator, I want a request my Massive plan is not entitled to sent once and recorded under its own reason, so that a refusal no download can fix stops costing three requests and stops reading as an ordinary failure.

## Description
Adds the plan refusal to `massive-client`'s error taxonomy and has the runner record it per data type (massive-client CAP-003 §2.4, §2.5; acquisition-runner CAP-003 §2.3; system design §3.6 notes 1, 5). In `src/factorflow/ingestion/massive/errors.py`: `ProviderNotEntitled(MassiveError)` with the design's docstring; the `_NOT_ENTITLED_MARKER` constant and `_mentions_not_entitled`, which searches `error` and `message` each on its own, case-insensitively; the entitlement rule in `classify_error_body` after the delivered not-found and credential rules and before the default, building `ProviderNotEntitled("The provider plan is not entitled to this data.", provider_request_id=request_id)`; the `_ERROR_KIND_BY_TYPE` row `not_entitled` with the fixed `_NOT_ENTITLED_DESCRIPTION`, selected by `type(error) is ProviderNotEntitled` and never passed to `redact`; `__all__`; the `CredentialRejected` docstring loses "(401/403)". `src/factorflow/ingestion/massive/__init__.py` re-exports `ProviderNotEntitled`. In `src/factorflow/ingestion/outcomes.py`, `classify_provider_error` maps `ProviderNotEntitled` to `failed` with the composed reason unchanged, and its docstring and `TypeError` text name the accepted types.

**Why the outcome mapping is in this story.** The delivered classifier closure in `MassiveClient._through_governor` already treats a `BadResponse` whose typed error is not a `ProviderUnavailable` as `FATAL` and re-raises it as `classify_error_body(...)` (`client.py` lines 288-300). So once `classify_error_body` returns `ProviderNotEntitled`, the refused request is sent once through the delivered code, and the runner receives a type the delivered `classify_provider_error` rejects with `TypeError` (`outcomes.py` lines 112-159). Carrying the one-line mapping here keeps every landed state of the branch releasable: a `403` "not entitled" is recorded `failed` with kind `not_entitled`, never a crashed download. The rest of the runner's change, the stock boundary, is CAP-003-E8-S4's.

Unchanged: `classify_for_governor` and the `429` rule (CAP-003-E8-S3), `ProviderRateLimited` and its kind (CAP-003-E8-S2), the SDK construction (`retries=0`, `pagination=False`, `trace=False`, `base=`), every endpoint path, `models.py`, `paging.py`, `is_fatal_for_governor`, `_safe_fields`.

Source: component-design-massive-client.md 2.1, 2.4, 2.5, 3, 4, 7, 8 criteria 1, 5, 7, 8; component-design-acquisition-runner.md 2.1, 2.3, 7 (first row); system design §3.6 notes 1, 5, constraint 16 (a), (c), (d), assumption 9; epic CAP-003-E8 DAC-E8-1, DAC-E8-3, DAC-E8-4, DAC-E8-8, DAC-E8-20.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-29] When the provider refuses a data type because the owner's plan is not entitled to it, the product MUST send that request once and MUST record the refusal under its own reason.
- [DAC-E8-1] A provider error body whose `error` or `message` field contains `not entitled`, in any case, MUST classify as `ProviderNotEntitled` carrying the body's `request_id`; the rule MUST sit after the not-found and credential rules and before the default; `ProviderNotEntitled` MUST be `FATAL` for the governor, so a refused data type sends exactly one request and takes no wait. (traces to: AC-29)
- [DAC-E8-3] An error envelope matching none of the not-found, credential or entitlement rules, and a body that is not JSON, MUST stay `ProviderUnavailable` and `RETRYABLE`, retried to `max_attempts` (3) and recorded with kind `unavailable`, pinned by a real-transport test. (traces to: AC-29)
- [DAC-E8-4] `compose_failure_reason` MUST choose a reason's kind by the error's exact class from a closed table, MUST begin every reason with `[<kind>] ` and MUST raise `TypeError` for an unlisted `MassiveError` subclass; a plan refusal MUST compose exactly `[not_entitled] symbol=<symbol> data_type=<type> request_id=<id>: the provider plan is not entitled to this data`, never the provider's text, and without the credential's value. This story delivers the `not_entitled` row; the `rate_limited` row is CAP-003-E8-S2's. (traces to: AC-29)
- [DAC-E8-8] `classify_provider_error` MUST record `ProviderNotEntitled` as outcome `failed` with the composed reason unreworded; no outcome value, column, timing value or migration MUST be added. (traces to: AC-29)
- [DAC-E8-20] Every test of a `403` MUST run through the real SDK and `urllib3` path of `tests/unit/massive_transport_fakes.py` with production `MassiveSettings` and one `FakeClock` passed as both `monotonic` and `now`. (traces to: AC-29)

## Technical Details

### API Contract
- No HTTP surface. In process: `classify_error_body(body)` may now return `ProviderNotEntitled`; `MassiveClient.fetch_*` may raise it; `compose_failure_reason(error, *, symbol, data_type, redact)` accepts it; `classify_provider_error(error, *, data_type, reason)` accepts it (massive-client §11; acquisition-runner §11).
- Provider endpoints: unchanged (CAP-001 massive-client v15 §2.5); no request is added.

### Data Changes
- None: the outcome `failed` already exists and the kind is reason text in `run_instrument_result.reason` (constraint 16 (d)). No migration.

### Implementation
- Python 3.12, the locked `massive` 2.8.0 and `urllib3` 2.7.0, pytest (tech stack v7).
- Files: `src/factorflow/ingestion/massive/errors.py`, `src/factorflow/ingestion/massive/__init__.py`, `src/factorflow/ingestion/outcomes.py`; `tests/unit/test_massive_error_classification.py`, `tests/unit/test_massive_failure_reasons.py`, `tests/unit/test_massive_retry.py`, `tests/unit/test_outcomes.py` (rows added; delivered rows kept).
- Rollback: redeploy the previous image; no data step (OPS-MIG-003). Rows written with `[not_entitled]` stay readable as reason text.

### Validation
`uv run pytest` (or `uv run pytest -m 'not postgres'` when no container runtime is available, reported as an exclusion), `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src` (tech stack v7 validation commands).

### Dependencies
- None inside CAP-003. This is the first provider-side story and depends on no E1 to E7 story (owner decision, Alvaro de Jodra, 2026-11-07: provider side first, recorded in `backlog.md` *Sequencing*): it edits CAP-001's delivered code in `src/factorflow/ingestion/` and can be planned and coded now.
- Cross-capability: CAP-001's delivered `massive-client`, `rate-limit-governor` and `acquisition-runner` code and the harness `tests/unit/massive_transport_fakes.py`, `tests/unit/governor_fakes.py` (`requires-runtime`, delivered). CAP-001's approved designs are not edited (AGT-SCOPE-002).
- Developable in parallel against the stored reason's leading kind (massive-client §2.5, a read contract): CAP-003-E8-S6, which reads `[not_entitled] ` from stored reasons.
