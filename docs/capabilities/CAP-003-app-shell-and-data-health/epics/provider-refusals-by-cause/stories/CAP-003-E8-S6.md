# data-health-reader Reads Each Failure's Cause and Stops a Plan Refusal Making Its Row Retryable

## User Story
As an owner-operator, I want each failure's cause read from the reason the store already holds, and a plan refusal kept in every count but never counted as fixable by a download, so that Data health tells me what fixes a problem without hiding it.

## Description
Adds data-health-reader v2's cause to the reader CAP-003-E2-S1 creates (data-health-reader v2 §2.1, §2.2, §2.4; system design §3.4 note 9, §3.6 note 6, assumption 8). In `src/factorflow/data_health/models.py`: the `FailureCause` `Literal` of the six kinds and the field `cause: FailureCause | None` on the failure dataclass, with the `retryable` comment updated. In `src/factorflow/data_health/reader.py`: `_CAUSE_PREFIX` (`re.compile(r"\[(not_found|credential_rejected|unavailable|contract_violation|not_entitled|rate_limited)\] ")`), `cause_of(reason)` matching at position 0 and returning `None` for a null reason or no match, `read_problems` setting each failure's `cause = cause_of(reason)`, and `_retryable(failures)` returning `any(f.outcome == "failed" and f.cause != "not_entitled" for f in failures)`, replacing E2-S1's any-`failed` rule.

**Ownership (backlog review v5 FINDING-1).** CAP-003-E2-S1 builds the reader in data-health-reader's version 1 shape: no `cause`, and `retryable` true when any failure is `failed`, as its Description states. This story owns every version 2 change to the reader: `FailureCause`, the `cause` field, `cause_of` and the `retryable` rule. It edits E2-S1's files; E2-S1 is not refined. Of E2-S1's tests, DAC-E2-S1-3's `failed` case keeps passing under the new rule as long as its fixture's reason does not begin `[not_entitled] `; if it does, this story changes that fixture's reason to one beginning `[unavailable] ` and says so in its task plan. No other E2-S1, E2-S2 or E2-S3 assertion changes: the problem set, `affected_count`, the attention `problems` block, the Company financials check's `problem_count` and the verdict's inputs are unchanged (§3.6 note 6).

**Fixtures this story changes (backlog review v6 FINDING-11).** `cause` is a required field with no default, placed after `outcome` (data-health-reader v2 §2.2), so every failure dataclass a test constructs when this story lands fails with `TypeError` until it carries `cause`. This story adds `cause` to each, `None` unless the test exercises a cause, and changes no assertion. Expected files, confirmed by `uv run pytest` when the story is planned, are those of the following stories that have already landed: CAP-003-E2-S4's `tests/unit/test_api_data_health_models.py` and `tests/unit/test_api_data_health_routes.py`, which double the reader's dataclasses, and CAP-003-E2-S5's `stub_reader_functions` in `tests/unit/test_api_no_secrets.py`, which returns populated reader values (ingestion-api §2.3). A story landing after this one constructs the failure with `cause` from the start.

No SQL changes: `queries.py` is untouched and the cause is read in Python from the `reason` each problem row already fetches, so E2-S7's volume bound on `GET /api/data-health` is unaffected (AC-28). Results recorded before the ingestion change keep `[unavailable]` and read with cause `unavailable`, or `None` when the reason predates the format, both ordinary failures (constraint 17 (c)).

Source: component-design-data-health-reader.md 2.1, 2.2, 2.4 (*Cause and retryable*), 3, 4, 6, 7 (*Cause from the prefix*, *Retryable by cause*, *Plan refusal stays a problem*, *Rate limit is retryable*), 8 criteria 10 to 12; epic CAP-003-E8 DAC-E8-11, DAC-E8-12, DAC-E8-19.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-29] A plan refusal's *Needs fixing* row MUST NOT offer a download as its fix.
- [AC-14] A row whose failures are all `not_found` MUST stay non-retryable.
- [AC-16] A plan refusal and a rate limit MUST stay in the one problem set the *Needs fixing* header and the Data health rail chip count.
- [DAC-E8-11] `data-health-reader` MUST read each failure's `cause` with a match anchored at the start of the stored reason against `[<kind>] ` for the six kinds, returning `None` for a null reason, a reason without a prefix, an unknown kind such as `[foo]`, a kind without its following space, and a kind not at the start; `retryable` MUST be true exactly when some failure is `failed` with a cause other than `not_entitled`, so a row whose failures are all plan refusals, all *Not found*, or a mix of the two is never retryable, and a `rate_limited` or unknown-cause failure makes its row retryable. (traces to: AC-29, AC-14, AC-30)
- [DAC-E8-12] A plan refusal MUST stay in the problem set: in `affected_count`, attention's `problems.stock_count`, the problem rows and the Company financials check's `problem_count`; the cause MUST change only the fix. (traces to: AC-29, AC-16)
- [DAC-E8-19] Results recorded before the upgrade MUST keep `[unavailable]` and MUST NOT be rewritten, so they read as ordinary failures. (traces to: AC-29, AC-30)

## Technical Details

### API Contract
- None served. The reader's Python interface gains `cause_of(reason) -> FailureCause | None` and the failure dataclass's `cause` field; `read_problems`, `read_data_health` and `read_attention` keep their signatures (data-health-reader §11). `data-health-api` serialises the field in CAP-003-E8-S7.

### Data Changes
- None: no schema, migration, index or SQL change (data-health-reader §2.4).

### Implementation
- Python 3.12, `psycopg` 3, frozen dataclasses with full type hints, `re` from the standard library (tech stack v7; SA-TYPE-001).
- Files: `src/factorflow/data_health/models.py`, `src/factorflow/data_health/reader.py` (edited); `tests/unit/test_data_health_cause.py` (new); `tests/integration/test_data_health_problems.py` (rows added); fixtures of DAC-E8-S6-7.
- Rollback: redeploy the previous image; no data step.

### Validation
`uv run pytest` (or `uv run pytest -m 'not postgres'` when no container runtime is available, reported as an exclusion), `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src` (tech stack v7 validation commands).

### Dependencies
- **CAP-003-E2-S1**, `models.py`, `reader.py`, `read_problems` and `tests/integration/test_data_health_problems.py`, which this story edits.
- **CAP-003-E2-S2**, `read_attention`, whose `problems.stock_count` DAC-E8-S6-3 asserts.
- **CAP-003-E2-S3**, `read_data_health` and the Company financials check, whose `affected_count` and `problem_count` DAC-E8-S6-3 asserts.
- Developable in parallel against the stored reason's leading kind (massive-client §2.5): CAP-003-E8-S1 and CAP-003-E8-S2, which write `[not_entitled]` and `[rate_limited]`; the tests seed reason strings and need neither.
