# Register the Setup Screen at `/setup`

## User Story

As an owner-operator, I want setup reachable at `/setup` inside the shell with its title, so that an empty install opens on it and I can return to it from Settings.

## Description

Logical component: `owner-shell`. Registers `setup-ui`'s `SetupScreen` (E4-S2) in the shell: the `/setup` route in `web/src/app/routes.tsx` (`React.lazy`), the *Setup* title in `titles.ts`, and the `routes.test.tsx` and `shell.test.tsx` cases that visit it. Setup has no rail destination (`component-design-owner-shell.md` §2.6), so `destinations.ts` is unchanged. This is the owner-shell registration story the epics backlog review v1 FINDING-2 asked for, sequenced after the screen's first story (DEC-0223); with it the root redirect of E3-S3 lands on a real screen.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-2] Until the first download has been started, `/` MUST open setup.
- [AC-17] Screens MUST open in the same shell, titled in the top bar.
- [DAC-E3-1] `/` MUST `Navigate replace` to `/setup` when `health.most_recent_run` is null. (traces to: AC-2, AC-21)
- [DAC-E3-9] Top-bar titles MUST come from the static route-to-title table. (traces to: AC-17)

- [DAC-E3-S7-2] Given `most_recent_run` null, When `/` renders, Then the location becomes `/setup` and the setup screen is in the document. (traces to: DAC-E3-1)
- [DAC-E3-S7-3] Given `DESTINATIONS` after this story, When read, Then it has no setup entry. (traces to: AC-1)
