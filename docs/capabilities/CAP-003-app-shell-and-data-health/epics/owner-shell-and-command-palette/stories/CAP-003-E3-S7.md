# Completion Toast: One Toast per Terminal Transition, None Where the Outcome Is Already Visible

## User Story
As an owner-operator, I want to be told once when a download ends while I am elsewhere, so that I learn of a failure without watching the Downloads screen.

## Description
Creates `web/src/app/download-toast.ts`, the watcher of owner-shell 2.9: when `latest_download.state` was non-terminal in the previous attention answer and is terminal in this one, raise one `toast` (`success` for *Complete*, `warning` for *Partial* and *Interrupted*, `error` for *Failed*, none for *Cancelled by you*), naming the download by its start time (`formatDownloadName`) and linking to `/data/downloads/{id}`, and none when the current route is `/data/downloads/{that id}`, `/data/downloads` or `/data`. `error` and `warning` toasts persist until dismissed; none takes focus. Mounted from `shell.tsx` beside the `Toaster`. Writes `download-toast.test.tsx`.

Source: component-design-owner-shell.md 2.9, 7; epic CAP-003-E3 DAC-E3-13.
