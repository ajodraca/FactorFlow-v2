### IR-001 — The rule for a rejection that is not an API error has no test (T010)

- **Severity**: HIGH
- **Scope**: initial
- **Status**: OPEN
- **Acceptance criteria**: DAC-E3-S2-2 (the failure path the rule belongs to); TEST-TDD-006
- **Tasks**: T010 (the rule), T004/T005 (where its test belongs)

- **Claim challenged**: T010 is marked complete, and the TDD evidence records no surviving mutant for cycle 2.
- **Observed evidence**: Two mutants survive with all 83 focused tests and `tsc` green. `manual:review:1` replaces `throw error;` with `return;`, so a rejection that is neither `ApiError` nor `ApiUnreachableError` is silently swallowed. `manual:review:2` moves the scheduling out of `finally`, so a throwing `onSettled` ends the poll permanently. - **Expected evidence/behavior**: T010: "Any other value is rethrown after the next read is scheduled, so a programming error surfaces instead of rendering as a stale read", and "Then, in a `finally`, it clears `inFlight` and … sets `timer`". T010 ties these rules to DAC-E3-S2-2 and TC-COMP-070. TEST-TDD-006: "A task must not be marked complete while any changed-line mutant survives".
- **Impact**: A later change could make a programming error disappear silently, or could stop every shell poll after one malformed answer, and the suite would stay green. CAP-003-E3-S3 builds the attention and score reads on this hook, so one bad answer would freeze the rail chips and Home with no error shown.
- **Required remediation**: Add tests that kill `manual:review:1` and `:2`. Drive a rejection with a non-API value, such as `new TypeError("x")`. Assert that the state does not become an `error` carrying it, that the rejection surfaces, and that the next read still fires at the interval. If the "surfaces" half cannot be observed under Vitest without disabling its unhandled-rejection reporting, record that part as an exception under TEST-TDD-006 instead. The "next read still fires" half is observable and must be tested.

### IR-002 — Stopping on unmount is not pinned: the cleared timer and the `stopped` guard (TC-COMP-069 edge case)

- **Severity**: HIGH
- **Scope**: initial
- **Status**: OPEN
- **Acceptance criteria**: DAC-E3-S2-1, DAC-E3-5 (through TC-COMP-069); TEST-TDD-006
- **Tasks**: T003, T010
- **Files**: `web/src/app/use-polled-read.ts:37` (`if (stopped || inFlight)`), `:80-85` (`stop`); `web/src/app/use-polled-read.test.ts:120-163`
- **Claim challenged**: T003 says it implements TC-COMP-069, including its edge case. Its kill list includes "negate-boolean on the stopped guard ((d) reads after unmount)".
- **Observed evidence**: The two guards hide each other. `manual:review:3` deletes `clearTimeout(timer)` from `stop`, so the pending timer still fires after unmount, and `run` then returns at `stopped`.
