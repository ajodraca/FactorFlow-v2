# Shell Journeys End to End: Navigation by Keyboard, Old Bookmarks, Stop and Recover, and the Palette

## User Story
As an owner-operator, I want the shell proven against the running product, so that the rail, the redirects, the unreachable state and the palette work the way the designs say before any new screen lands on them.

## Description
Writes the four new Playwright specs of owner-shell 2.1 and command-palette 2.1: `tests/e2e/shell-navigation.spec.ts`, `tests/e2e/legacy-redirects.spec.ts`, `tests/e2e/unreachable-recovery.spec.ts` and `tests/e2e/command-palette.spec.ts`, limited to what is registered at this story (backlog review v2 FINDING-2): `/` redirects by URL; the rail's registered items (Settings, and Research when CAP-002 has merged) and the palette's Pages group (Coverage, Followed stocks, Downloads, Settings) reach their screens by keyboard alone; the four legacy paths arrive with the query kept; stopping the application container shows the unreachable state with *Last answered* and restarting it returns the same screen with no reload; from two screens `Ctrl+K`, a typed symbol and `Enter` land on `/data/coverage?symbol=…`, and from a text field the shortcut types instead. The Home and Data health landings are added to `shell-navigation.spec.ts` by E5-S5 and E6-S7 when they register those destinations.

Source: component-design-owner-shell.md 7; component-design-command-palette.md 7; epic CAP-003-E3 NFR *Accessibility*.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-1] Every screen MUST render inside one shell; every rail item MUST reach its screen.
- [AC-18] Each path CAP-001 shipped MUST take the owner to the same screen at its new path.
- [AC-22] The palette MUST open from the keyboard and the top bar on every screen and find followed stocks and pages.
- [AC-23] Stopping the application MUST show the unreachable state; restarting MUST return the screen without a reload.
- [AC-25] Every operation MUST be completable by keyboard.

### Derived
- [DAC-E3-S8-1] Given `unreachable-recovery.spec.ts`, When the container is stopped and restarted through `tests/e2e/support`, Then the rail and top bar remain throughout, the *Last answered* line carries the last success, and recovery keeps the URL and the page's JavaScript context (no `load` event). (traces to: AC-23)
- [DAC-E3-S8-2] Given `shell-navigation.spec.ts`, When it runs at this story, Then it asserts only the Settings and `/data` sub-page landings and the `/` redirect target URL, and exposes one helper the E5 and E6 closing stories extend with the Home and Data health landings. (traces to: AC-1)
- [DAC-E3-S8-3] Given `command-palette.spec.ts` with one followed stock seeded, When *K* is typed, Then the Stocks group lists it from the server and `Enter` opens `/data/coverage?symbol={symbol}` (research routes unregistered in this clone). (traces to: AC-22)
