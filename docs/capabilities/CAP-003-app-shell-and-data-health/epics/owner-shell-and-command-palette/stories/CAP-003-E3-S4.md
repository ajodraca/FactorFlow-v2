# Command Palette Dialog: Stocks, Universes and Pages

## User Story

As an owner-operator, I want a palette that finds followed stocks, universes and pages and only ever navigates, so that I can jump anywhere from any screen without a control that could place or stop trading.

## Description

Logical component: `command-palette`. Creates `web/src/app/command-palette/` as `component-design-command-palette.md` §2.1 specifies: `index.tsx` (`<CommandPalette open onOpenChange />` on E1-S8's `command` `dialog`, labelled *Search FactorFlow*, `loop` set), `use-stock-search.ts` (the delivered `listInstruments({ symbol: prefix, lifecycle: "active", limit: 8 })`, debounced 250 ms, aborted with `AbortController` on new text), `universes.ts` (`fetchActiveUniverses()` over `GET /api/universes?lifecycle=active` through the delivered `requestJson`, once per open, only while `RESEARCH_REGISTERED`), `pages.ts` (the shipped `DESTINATIONS` plus *Coverage*, *Followed stocks*, *Downloads*), `targets.ts` (`stockTarget`, `universeTarget`; DEC-0207 PROVISIONAL) and `copy.ts`. The shell owns the shortcut and the opener (E3-S5); this story owns the dialog and its contents. The e2e keyboard journey `tests/e2e/command-palette.spec.ts` needs the shell's listener and is listed in E3-S5.

Carries AC-19 and AC-20 for this surface (review v1 FINDING-4): every string is in `copy.ts` and in the display vocabulary; statuses do not appear in the palette.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-22] The owner MUST be able to find followed stocks, universes and pages from the palette; it MUST NOT offer any action that places or stops trading.
- [AC-24] The palette's eight states MUST render as designed or record why one does not apply.
- [AC-27] A stock or universe item MUST open CAP-002's routes when they are registered.
- [AC-19] Every user-visible label MUST use the display label STD-UI-1 defines.
- [DAC-E3-11] The palette MUST show Stocks (followed stocks whose symbol starts with the typed text, from `GET /api/instruments?symbol=prefix&lifecycle=active&limit=8`, debounced 250 ms, aborted on new text), Universes (from `GET /api/universes?lifecycle=active` once per open, filtered locally, only while research routes are registered) and Pages, in that order, with no Actions group; a stock MUST open `/research/stocks/{symbol}` when research routes are registered and `/data/coverage?symbol={symbol}` otherwise. (traces to: AC-22, AC-27)
- [DAC-E3-12] The palette MUST render an `aria-disabled` hint row before typing, `CommandEmpty` *No stocks or pages match "{text}".*, a *Showing the first 8. Keep typing to narrow.* row when the response's `next_cursor` is set, and per-group errors (*Couldn't search followed stocks: {reason}.*, *Couldn't read universes: {reason}.*) that leave the other groups usable; while health is unreachable the palette still opens and Pages stays usable. (traces to: AC-24)

### Derived

- [DAC-E3-S4-1] Given the palette open and *KO* typed, When 249 ms pass, Then no request is sent; When 250 ms pass, Then one `GET /api/instruments?symbol=KO&lifecycle=active&limit=8` is sent; When the text changes to *KOF* before it answers, Then the first request is aborted and only the second's rows render. (traces to: DAC-E3-11)
- [DAC-E3-S4-2] Given `RESEARCH_REGISTERED` false, When the palette opens, Then no Universes group and no universes request exist and a stock item navigates to `/data/coverage?symbol=KO`; given it true, Then one universes request is made per open and a stock navigates to `/research/stocks/KO`. (traces to: DAC-E3-11)
- [DAC-E3-S4-3] Given every item rendered, When their accessible names are collected, Then none contains *trade*, *order*, *buy*, *sell* or *stop trading*, and every item's activation calls `navigate` and nothing else. (traces to: AC-22)
- [DAC-E3-S4-4] Given a stock search failing with `ApiUnreachableError`, When rendered, Then the Stocks group reads *Couldn't search followed stocks: {reason}.* and the Pages items remain selectable. (traces to: DAC-E3-12)
- [DAC-E3-S4-5] Given a Pages item for Coverage, When rendered, Then its primary text is *Coverage* and its hint *Data health › Coverage*; no palette string contains *instrument*, *acquisition* or *run* as a whole word. (traces to: AC-19)
- [DAC-E3-S4-6] Given the dialog open, When `Escape` is pressed, Then `onOpenChange(false)` is called and nothing typed is retained for the next open. (traces to: AC-22)

## Technical Details

### API Contract

Consumes `GET /api/instruments` (delivered, `symbol`, `lifecycle=active`, `limit=8`; rows and `next_cursor`) and `GET /api/universes?lifecycle=active` (`classification-api`, as published; names and ids). Exposes `CommandPalette({ open, onOpenChange })`.

### Implementation

- New: `web/src/app/command-palette/index.tsx`, `use-stock-search.ts`, `universes.ts`, `pages.ts`, `targets.ts`, `copy.ts`, `command-palette.test.tsx`, `use-stock-search.test.ts`.
- Typed text reaches the server only as the `symbol` query parameter (SEC-INP-001); no storage.

### Data Changes

None.

### Validation

`npm run lint`, `npm run format`, `npx tsc --noEmit`, `npm run test`.

### Dependencies

- **CAP-003-E3-S3**, `DESTINATIONS` and `RESEARCH_REGISTERED`.
- **CAP-003-E1-S8**, the `command` component.
- **CAP-003-E7-S1** (a later epic, deliberately), the `requestJson` export `universes.ts` uses (DEC-0223).
