# Shell Types, the One Fetch Module and the requestJson Export

## User Story
As an owner-operator, I want one typed mapping from the three data-health reads and the summary to the shell, so that every screen reads the same shapes from one place.

## Description
Creates `web/src/app/shell-types.ts` (`ReadState<T>`, `ScoreState`, `Attention` mirroring `data-health-api`'s `AttentionResponse` field for field, `DataHealth`, `ProblemPage`, `ScoreSummary` mirroring `classification-api`'s published `ClassificationSummaryResponse`, neither redefined) and `web/src/app/shell-client.ts` (`fetchAttention()`, `fetchScoreSummary()` mapping a `404` to `not_served`, `fetchDataHealth()`, `fetchProblems(cursor, limit)`), the one fetch module for `data-health-api`'s three routes and the summary (owner-shell 2.1, 2.3; DAC-E3-18). It depends on nothing in CAP-003, so E1's `needs-you.ts` story can import its types (DEC-0223 answer A).

**The `requestJson` export.** `shell-client.ts` and the palette's `universes.ts` call the delivered `requestJson` in `web/src/api/client.ts`, which is declared at line 154 without `export` (backlog review v3, *Repository facts*). This story adds the `export` keyword, the one-word edit, unless CAP-002-E4-S1 has already added it when this story is implemented, which is the condition DAC-E7-12 states; the owner placed the export here deliberately, in the first story that imports it, citing CAP-002's equivalent move (DEC-0223; backlog review v3 BR-5 note). `web/src/api/client.ts` is otherwise owner-web-app's file (owner-web-app 2.1), and E7-S6 confirms the export exists. Everything else in `client.ts` and its tests is unchanged.

Source: component-design-owner-shell.md 1, 2.1, 2.3; component-design-command-palette.md 2.3; component-design-owner-web-app.md 2.1; epic CAP-003-E3 DAC-E3-18; epic CAP-003-E7 DAC-E7-12.

## Technical Details

### API Contract
- Consumes `GET /api/attention`, `GET /api/data-health`, `GET /api/data-health/problems` (data-health-api 2.3) and `GET /api/classifications/summary` as CAP-002 publishes it; same origin, no auth (DEC-0208).

### Data Changes
- None: no schema, migration, index or browser storage.

### Implementation
- TypeScript, React 18 (tech stack v7). Files: `web/src/app/shell-types.ts`, `web/src/app/shell-client.ts`, `web/src/app/shell-client.test.ts` (doubled `fetch`); `web/src/api/client.ts` (the `export` keyword only, conditionally).
- Snake_case wire fields are kept as published (DAC-E3-18: mirrored field for field).

### Validation
`npm run test`, `npm run lint`, `npm run format`, `npx tsc --noEmit`, `npm run build` (tech stack v7 validation commands).

### Dependencies
- None inside CAP-003: this story depends on nothing, so E1-S8, E3-S2 and E3-S5 can build on it (DEC-0223 answer A).
- Cross-capability: the delivered `requestJson`, `ApiError`, `ApiUnreachableError` in `web/src/api/client.ts` (CAP-001); the summary shape as CAP-002 publishes it.
