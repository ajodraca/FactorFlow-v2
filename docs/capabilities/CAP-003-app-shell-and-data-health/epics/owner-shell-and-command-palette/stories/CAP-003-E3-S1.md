# Shell Types, the One Fetch Module and the Layout-Constants Module

## User Story

As an owner-operator, I want the shell's wire types, its one fetch module and the approved layout dimensions defined once, so that every screen reads the same shapes and the same widths and no file restates them.

## Description

Logical component: `owner-shell`. Creates the three pure modules `component-design-owner-shell.md` §2.1 and §2.3 specify, with no screen or provider: `web/src/app/shell-types.ts` (`ReadState<T>`, `ScoreState`, `Attention` mirroring `data-health-api`'s `AttentionResponse` field for field, `DataHealth`, `ProblemPage`, `ScoreSummary` mirroring `classification-api`'s published `ClassificationSummaryResponse`, neither redefined); `web/src/app/shell-client.ts` (`fetchAttention()`, `fetchScoreSummary()` mapping a `404` to `not_served`, `fetchDataHealth()`, `fetchProblems(cursor, limit)`) over the delivered `requestJson`, `ApiError` and `ApiUnreachableError`; and `web/src/app/layout.ts` with the `LAYOUT` constant of §2.1 (`railWidth` 208 px, `contentMaxWidth` 1180 px, `sideColumnMin` 260 px, `sideColumnMax` 300 px, `markerSize` 28 px, `railIconSize` 16 px, `explanationMeasure` 70ch), the approved-specification values of AC-26 (owner decision 2026-10-25).

This story comes first in E3 because E1-S4's `needs-you.ts` imports `Attention` and `ScoreState` from `shell-types.ts` and `LAYOUT.markerSize` (epics backlog review v1 FINDING-1; DEC-0223). It depends on E7-S1 for the `requestJson` export the fetch module needs. Carries the automated check for DAC-E3-16's single-writer rule that review FINDING-5 found missing: a Vitest test rejecting the seven layout values as literals in any file under `web/src/` other than `layout.ts` and `design-system/theme.css`.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-26] The approved-specification layout dimensions MUST be held in one layout-constants module.
- [AC-8] The shell MUST read `followed_count` and `prices_as_of` for Home's data tile; `Attention` carries them.
- [AC-16] The shell MUST read `problems.stock_count` for the Data health chip; `Attention` carries it.
- [DAC-E3-16] `web/src/app/layout.ts` MUST hold `railWidth` 208 px, `contentMaxWidth` 1180 px, `sideColumnMin` 260 px, `sideColumnMax` 300 px, `markerSize` 28 px, `railIconSize` 16 px and `explanationMeasure` 70ch as approved-specification values, and no other file MUST write these values. (traces to: AC-26)
- [DAC-E3-18] `Attention` MUST mirror `data-health-api`'s `AttentionResponse` field for field and `ScoreSummary` MUST mirror `classification-api`'s published summary, neither redefined; `shell-client.ts` MUST be the one fetch module for `data-health-api`'s three routes and the summary. (traces to: AC-8, AC-16)

### Derived

- [DAC-E3-S1-1] Given `shell-types.ts`, When compared field by field with system design §4.2's `GET /api/attention`, `GET /api/data-health` and `GET /api/data-health/problems` shapes and `classification-api`'s summary, Then every field is present with the same name and nullability and none is added or renamed. (traces to: DAC-E3-18)
- [DAC-E3-S1-2] Given `fetchScoreSummary()` against a `404 not_found` envelope, When it resolves, Then it returns `{ kind: "not_served" }` rather than throwing; given any other `ApiError`, Then it throws it unchanged. (traces to: DAC-E3-18)
- [DAC-E3-S1-3] Given `fetchProblems("KO", 50)`, When called, Then it requests `GET /api/data-health/problems?cursor=KO&limit=50` once through `requestJson` and returns the typed page. (traces to: DAC-E3-18)
- [DAC-E3-S1-4] Given a new Vitest test `web/src/app/layout.test.ts`, When it scans every `.ts`, `.tsx` and `.css` file under `web/src/` except `layout.ts`, Then it fails on a literal `208px`, `1180px`, `260px`, `300px`, `28px`, `16px` or `70ch`. (traces to: DAC-E3-16)
- [DAC-E3-S1-5] Given `LAYOUT`, When imported, Then it is `as const` and each value is a CSS length string, so a consumer sets it through a style or a CSS variable rather than retyping it. (traces to: DAC-E3-16)

## Technical Details

### API Contract

Consumes, through the delivered `requestJson`: `GET /api/attention` (200 `AttentionResponse`), `GET /api/classifications/summary` (200 or 404), `GET /api/data-health` (200 `DataHealthResponse`), `GET /api/data-health/problems?cursor&limit` (200 `ProblemPageResponse`, 422). Exposes none.

### Implementation

- New: `web/src/app/shell-types.ts`, `web/src/app/shell-client.ts`, `web/src/app/layout.ts`, `web/src/app/shell-client.test.ts`, `web/src/app/layout.test.ts`.
- Edits nothing delivered.

### Data Changes

None.

### Validation

`npm run lint`, `npm run format`, `npx tsc --noEmit`, `npm run test`.

### Dependencies

- **CAP-003-E7-S1** (a later epic, deliberately), the `requestJson` export from `web/src/api/client.ts` that `shell-client.ts` imports (DEC-0223). Developable in parallel against E2's response shapes, which system design §4.2 fixes.
