# Register Data Health with Its Destination and Chip, and the Shell Navigation Journey

## User Story

As an owner-operator, I want Data health in the rail with the number of followed stocks with problems, and the whole shell proven reachable by keyboard, so that the rail is complete for M1 and every destination can be reached without a mouse.

## Description

Logical component: `owner-shell`. Registers `data-health-ui`'s `DataHealthScreen` (E6-S1): the `/data` route in `routes.tsx`, the *Data health* title in `titles.ts` (already the ancestor crumb of the `/data/*` screens from E3-S3), and the destination `{ group: "data", label: "Data health", to: "/data", count: "problems" }` ahead of Settings in `DESTINATIONS` (`component-design-owner-shell.md` §2.6). The Data health chip renders `attention.problems.stock_count` live (DAC-E3-7; AC-16). With all M1 destinations present, adds `tests/e2e/shell-navigation.spec.ts` (§7): an empty install opens setup; after a download is requested `/` opens Home; every rail item and the palette reach their screens by keyboard alone.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] The rail MUST list Home, (Research,) Data health and Settings in two groups and nothing else.
- [AC-16] The Data health destination MUST carry the number of followed stocks with problems, absent when zero.
- [AC-22] The palette MUST be reachable on every screen.
- [AC-25] Every operation MUST be completable by keyboard.
- [DAC-E3-2] A destination enters `DESTINATIONS` only in the change that registers its screen. (traces to: AC-1, AC-27)
- [DAC-E3-7] The Data health chip MUST equal `attention.problems.stock_count`; a zero count MUST render no chip; while the attention read fails the chip keeps its last value and its name gains *, as of {time}*. (traces to: AC-16, AC-25)

### Derived

- [DAC-E3-S9-1] Given `problems.stock_count` 3, When the rail renders, Then the Data health item is named *Data health, 3 stocks with problems*; given the next attention read failing, Then the chip still reads *3* and the name gains *, as of {time}*. (traces to: DAC-E3-7)
- [DAC-E3-S9-2] Given `DESTINATIONS` after this story, When read, Then the data group is Data health then Settings and the whole list is Home, (Research,) Data health, Settings. (traces to: DAC-E3-2)
- [DAC-E3-S9-3] Given a real stack with no download, When `shell-navigation.spec.ts` runs, Then `/` opens setup; after a download is requested `/` opens Home; `Tab` and `Enter` alone reach Home, Data health, Settings and the palette, and `Ctrl+K` then a page name lands on that page. (traces to: AC-1, AC-2, AC-22, AC-25)
