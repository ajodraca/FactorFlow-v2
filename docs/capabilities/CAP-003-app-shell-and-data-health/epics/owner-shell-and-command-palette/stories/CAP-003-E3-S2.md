# layout.ts, usePolledRead and the Health Provider with lastAnsweredAt and the Hidden-Page Pause

## User Story
As an owner-operator, I want the shell's polling rules and layout dimensions held in one place each, so that no screen opens an interval of its own and no file writes a layout value of its own.

## Description
Creates `web/src/app/layout.ts` (the `LAYOUT` constant of owner-shell 2.1: `railWidth` 208 px, `contentMaxWidth` 1180 px, `sideColumnMin` 260 px, `sideColumnMax` 300 px, `markerSize` 28 px, `railIconSize` 16 px, `explanationMeasure` 70ch, approved-specification values, not tokens; DAC-E3-16), `web/src/app/use-polled-read.ts` (`usePolledRead(read, intervalMs)`: reads on mount, schedules the next read with `setTimeout` from the interval the last answer implies, clears it on `visibilitychange` to hidden, reads at once on visible, never overlaps two reads of one kind, keeps the last value in `error.last` on failure; owner-shell 2.4; DAC-E3-5) and `web/src/app/health.tsx` (`HealthProvider`, `useHealth`, `formatTimestamp`, `UNREACHABLE_MESSAGE` moved from the delivered `status-region.tsx`, keeping the delivered `unknown`, `answering`, `unreachable` states and 30 s cadence, gaining `lastAnsweredAt` and the visibility rule; DEC-0212). `status-region.tsx` itself is deleted by E3-S6 with the shell rewrite; this story copies, so both exist until then. Writes `health.test.tsx` with the delivered polling, unknown-state and cleanup cases moved from `status-region.test.tsx`, and `use-polled-read.test.ts`.

**AC-26 scan, layout rule.** Extends `web/src/components/token-literals.test.ts` (E1-S1) with DAC-E3-16's single-writer rule: the seven layout values appear in no `.ts` or `.tsx` source under `web/src/` other than `layout.ts`.

Source: component-design-owner-shell.md 2.1, 2.4, 7; epic CAP-003-E3 DAC-E3-5, DAC-E3-16; backlog review v3 FINDING-5.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-25] Every region updated by polling MUST show its last-updated time; this story delivers `checkedAt` on every read.
- [AC-26] The approved-specification layout dimensions MUST be held in one layout-constants module.
- [DAC-E3-5] `usePolledRead` MUST read on mount, schedule from the interval the last answer implies, clear on hidden, read at once on visible, and never overlap two reads of one kind; `HealthProvider` MUST keep its delivered states and 30 s cadence and gain `lastAnsweredAt` and the same visibility rule. (traces to: AC-25)
- [DAC-E3-16] `web/src/app/layout.ts` MUST hold the seven values as approved-specification values, and no other file MUST write these values. (traces to: AC-26)

### Derived
- [DAC-E3-S2-1] Given a read whose last answer implies 10 s, When the page is hidden, Then no read fires until it is visible again, when one fires at once and the schedule resumes; given a read in flight, When its interval elapses, Then no second read of the same kind starts. (traces to: DAC-E3-5)
- [DAC-E3-S2-2] Given a failed read after a successful one, When the state is read, Then it is `{ kind: "error", error, last: { data, checkedAt } }` with the previous value kept. (traces to: AC-24)
- [DAC-E3-S2-3] Given `HealthProvider`, When a health read succeeds, Then `lastAnsweredAt` is that instant and the delivered `formatTimestamp` still renders *America/Chicago* for the delivered tests (system design assumption 5). (traces to: AC-23)
- [DAC-E3-S2-4] Given `token-literals.test.ts`, When the layout rule runs over `web/src/`, Then `208px`, `1180px`, `260px`, `300px`, `28px`, `16px` and `70ch` occur in no non-test source other than `web/src/app/layout.ts`. (traces to: DAC-E3-16)
