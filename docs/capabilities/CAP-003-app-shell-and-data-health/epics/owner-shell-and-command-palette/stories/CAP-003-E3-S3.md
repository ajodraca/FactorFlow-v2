# ShellProvider, useShell and the On-Demand useDataHealth Hook

## User Story
As an owner-operator, I want the attention and summary reads shared with every screen from one context at recorded cadences, so that three intervals serve the whole interface and a screen can re-read once after an action.

## Description
Creates `web/src/app/shell-context.tsx` (`ShellProvider`, `useShell()` exposing `health`, `attention`, `scores`, `refresh(kind)` and `setTitleDetail(text)`; owner-shell 2.3) and `web/src/app/use-data-health.ts` (`useDataHealth()`: one read of `GET /api/data-health` on mount, on `retry()` and once when the context's attention read shows `latest_download` turning terminal, never on an interval; used by `data-health-ui` alone, DEC-0219 withdrawn; DAC-E3-19). Cadences per owner-shell 2.4: attention and summary every 60 s, every 10 s while `latest_download.state` is `requested`, `running` or `cancelling` or the summary's `later.state` is `building`; a summary `404` is `not_served`, not an error, re-read on the 60 s cadence; any other summary error keeps `last` (DAC-E3-6). `refresh` re-reads at once and keeps the cadence. Writes `shell-context.test.tsx` and `use-data-health.test.tsx`.

Source: component-design-owner-shell.md 2.3, 2.4, 3, 7; epic CAP-003-E3 NFR *Cadences*, DAC-E3-6, DAC-E3-18, DAC-E3-19.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-25] Every region updated by polling MUST show its last-updated time, from the cadences this context records.
- [AC-28] `GET /api/data-health` MUST be read on demand only.
- [AC-8] Home MUST read the summary through this context.
- [DAC-E3-6] A summary `404` MUST yield `scores: not_served`, not an error; a failed attention or summary read MUST keep the last value in `error.last`. (traces to: AC-24, AC-8)
- [DAC-E3-18] The `Shell context` MUST expose `health`, `attention`, `scores`, `refresh(kind)` and `setTitleDetail`. (traces to: AC-8, AC-16)
- [DAC-E3-19] `useDataHealth()` MUST read once on mount, on `retry()` and once when the attention read shows `latest_download` turning terminal, never on an interval. (traces to: AC-28)

### Derived
- [DAC-E3-S3-1] Given an idle store, When the context polls, Then attention and summary read every 60 s; given `latest_download.state` `running`, Then every 10 s; given the download turned terminal, Then back to 60 s after the next answer (system design constraint 8). (traces to: AC-25)
- [DAC-E3-S3-2] Given `refresh("attention")`, When called by a screen after an action, Then one attention read fires at once, the scheduled read is rescheduled from it, and no second read overlaps. (traces to: DAC-E3-5)
- [DAC-E3-S3-3] Given `setTitleDetail("Download 2026-10-15 09:30 CDT")`, When called, Then the context holds that text until `setTitleDetail(null)`; given the calling screen unmounts, Then the detail is cleared (DEC-0214). (traces to: AC-17)
- [DAC-E3-S3-4] Given `credential_present` in the health answer, When exposed, Then the context passes the boolean only and no value field exists on any context type (AC-4). (traces to: AC-4)
