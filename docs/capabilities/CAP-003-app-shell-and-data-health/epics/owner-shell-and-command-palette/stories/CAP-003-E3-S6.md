# The Shell Frame: Rail with Count Chips, Top Bar with the Palette Opener, Unreachable State and the Retired Status Region

## User Story
As an owner-operator, I want every screen inside one frame whose rail lists only shipped destinations with their attention counts and whose main region alone changes when the product stops answering, so that the product reads as one product.

## Description
Rewrites `web/src/app/shell.tsx` per owner-shell 2.2 and 2.7: `HealthProvider` outside `ShellProvider`, the rail (`LAYOUT.railWidth`, the *FactorFlow* brand mark, the primary group, a flexible gap, the data-and-system group pinned to the bottom, `NavLink` items with a 16 px `lucide-react` stroke icon and `aria-current="page"`, the `nav` labelled *Main*), the sticky top bar (the title or breadcrumb from `titles.ts`, the *Search* opener `button` `outline` named *Open the command palette* showing *⌘K* on a Mac and *Ctrl+K* otherwise, nothing between them), the main region (the unreachable state while health is unreachable, else `AppRoutes`), the `Toaster`, the palette mount and the one `keydown` listener on `document`. Creates `count-chip.tsx` (`badge` `status-warning` at `--text-xs`; Home's count `deriveNeedsYou(attention, scores).length`, Data health's `attention.problems.stock_count`; absent at zero; named in words; stale name *, as of {time}* while attention fails; one polite live region) and `unreachable-state.tsx` (owner-shell 2.8). Focus moves to the routed screen's `h1` on route change. Deletes `status-region.tsx`, `status-region.test.tsx`, `status-region.a11y.test.tsx`, `status-region.integration.test.tsx` and `shell.status-region.test.tsx` (DEC-0204, DEC-0211); rewrites `shell.test.tsx`, `shell.a11y.test.tsx`, `shell.layout.test.tsx` and `shell.unreachable.test.tsx` as owner-shell 2.10 lists; `shell.tokens.test.tsx` and `build-output.test.tsx` unchanged. Rewrites `tests/e2e/startup-health.spec.ts` and `startup-refusal.spec.ts` only for what exists at this story: the frame, the unreachable state's text and *Last answered* line, and the `/` redirect by URL; the setup and Home landing assertions and §2.10's latest-outcome assertion are added by E4-S6 and E5-S5 (backlog review v2 FINDING-2).

`SetupDraftProvider` is not mounted here: under DEC-0223 answer A the E4 closing story (CAP-003-E4-S6) mounts it inside `ShellProvider` and outside the route map, delivering E3's AC-3 clause and DAC-E3-14 across the epic boundary, so E3 never depends on E4. The Home and Data health chips render once their destinations are registered (E5-S5, E6-S7); `count-chip.tsx` is tested directly here with both counts. Icons per destination are unspecified by the UX design (epic E3 Open Questions); the implementing story's review chooses the `lucide-react` icons.

Source: component-design-owner-shell.md 2.2, 2.7, 2.8, 2.10, 3, 4, 7; epic CAP-003-E3 DAC-E3-7, DAC-E3-8, DAC-E3-10, DAC-E3-15, DAC-E3-17; DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-1] Every owner-interface screen MUST render inside one shell whose navigation groups the primary destinations apart from Data health and Settings, in order, with an unshipped destination absent rather than disabled.
- [AC-16] The two counts MUST be absent when zero.
- [AC-22] The owner MUST be able to open the palette from the keyboard and from the top bar on every screen.
- [AC-23] When the product stops answering, the main region MUST be replaced by the unreachable state while the rail and top bar remain; when it answers again the screen MUST return without a reload.
- [AC-25] Every operation MUST be completable by keyboard.
- [AC-26] The shell MUST be built from `ui-components` and consume theme tokens only, with the layout dimensions from `layout.ts`.
- [DAC-E3-7] The chip values, names, stale name and polite announcement MUST be as stated. (traces to: AC-16, AC-25)
- [DAC-E3-8] The unreachable state MUST be a `card` holding a `section` `role="status"` with the three texts, announced once on entry and once on recovery, and on recovery the routed screen MUST mount again at the same URL and refetch. (traces to: AC-23)
- [DAC-E3-10] One `keydown` listener MUST open the palette on `⌘K` or `Ctrl+K` and ignore text-field targets; the opener MUST show the platform shortcut and be named *Open the command palette*. (traces to: AC-22, AC-25)
- [DAC-E3-15] The delivered status-region files MUST be deleted and the delivered shell tests and startup specs rewritten as owner-shell 2.10 lists; `shell.tokens.test.tsx` and `build-output.test.tsx` MUST stay unchanged. (traces to: AC-23, AC-1)
- [DAC-E3-17] The top bar MUST leave the place of the environment region and the kill switch empty rather than reserving a disabled control. (traces to: AC-1; the epic cites AC-10, which backlog review v3 FINDING-7 asks to retrace to AC-1 and system design constraint 14)
