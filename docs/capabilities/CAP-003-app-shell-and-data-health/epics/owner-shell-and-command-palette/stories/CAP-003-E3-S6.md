# Download Completion Toast

## User Story

As an owner-operator, I want one notice when a download ends while I am on another screen, so that I learn a download finished, was partial, interrupted or failed without a notice repeating what the screen already shows.

## Description

Logical component: `owner-shell`. Creates `web/src/app/download-toast.ts`, the watcher of `component-design-owner-shell.md` §2.9, mounted by the frame (E3-S5): it compares consecutive attention answers and raises one `toast` when `latest_download.state` turns from non-terminal to terminal, `success` for *Complete*, `warning` for *Partial* and *Interrupted*, `error` for *Failed*, none for *Cancelled by you*, naming the download by `formatDownloadName` and linking to `/data/downloads/{run_id}`; none when the current route is `/data/downloads/{that id}`, `/data/downloads` or `/data`. `error` and `warning` toasts persist until dismissed and none takes focus (E1-S8).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-12] No screen MUST present a partial or interrupted download as complete: the toast's variant and label follow the recorded state.
- [AC-25] Toasts MUST never take focus.
- [DAC-E3-13] `download-toast.ts` MUST raise one toast when `latest_download.state` turns from non-terminal to terminal between two attention answers (`success` for *Complete*, `warning` for *Partial* and *Interrupted*, `error` for *Failed*, none for *Cancelled by you*), naming the download by its start time and linking to its detail, and none when the current route is `/data/downloads/{that id}`, `/data/downloads` or `/data`. (traces to: AC-12)

### Derived

- [DAC-E3-S6-1] Given consecutive answers `running` then `partial` on `/home`, When the second arrives, Then exactly one `warning` toast reads *Download {start time}: Partial* with a link to `/data/downloads/{run_id}`; given `running` then `succeeded`, Then one `success` toast; given `running` then `failed`, Then one `error` toast; given `cancelling` then `cancelled`, Then none. (traces to: DAC-E3-13)
- [DAC-E3-S6-2] Given the same transition while on `/data/downloads/{that id}`, `/data/downloads` or `/data`, When it arrives, Then no toast is raised; given a transition for a different run while on another download's detail, Then the toast is raised. (traces to: DAC-E3-13)
- [DAC-E3-S6-3] Given two answers both `partial`, When the second arrives, Then no toast is raised (no transition); given the first answer after mount already terminal, Then none. (traces to: DAC-E3-13)
- [DAC-E3-S6-4] Given an `error` toast raised while focus is in a form field, When it appears, Then focus stays in the field and the toast persists until dismissed. (traces to: AC-25)
