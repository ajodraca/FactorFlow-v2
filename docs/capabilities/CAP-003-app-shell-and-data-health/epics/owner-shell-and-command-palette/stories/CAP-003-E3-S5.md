# Shell Frame: Rail, Count Chips, Top Bar, Unreachable State and the Palette Opener

## User Story

As an owner-operator, I want every screen inside one frame with a rail of shipped destinations, a top bar with the title and the palette, and a designed state when the product stops answering, so that I am never stranded and the product looks like one thing.

## Description

Logical component: `owner-shell`. Rewrites `web/src/app/shell.tsx` to the composition of `component-design-owner-shell.md` §2.2 and §2.7: `HealthProvider` outside `ShellProvider`, `setup-ui`'s `SetupDraftProvider` (E4-S1) inside `ShellProvider` and outside the main region's route map (DEC-0202 as amended), the rail (brand mark, primary group, gap, data-and-system group, `nav` labelled *Main*, `NavLink` `aria-current="page"`, 16 px `lucide-react` icons at `LAYOUT.railIconSize`, 208 px at `LAYOUT.railWidth`), the sticky top bar (title or breadcrumb from E3-S3's `titles.ts`, the **Search** opener naming *Open the command palette* with *⌘K* or *Ctrl+K*), the main region that renders E3-S3's route map or the unreachable state, the `Toaster`, the palette mount with one `keydown` listener on `document`, and focus to the routed screen's `h1` on route change. Creates `web/src/app/count-chip.tsx` (DAC-E3-7's chip, driven by a destination's `count` kind) and `web/src/app/unreachable-state.tsx` (§2.8). Leaves the top bar's environment and kill-switch place empty (DAC-E3-17).

Deletes `status-region.tsx` and its four test files (DEC-0204, DEC-0211) and rewrites the delivered `shell.test.tsx`, `shell.a11y.test.tsx`, `shell.layout.test.tsx`, `shell.unreachable.test.tsx`, `tests/e2e/startup-health.spec.ts` and `startup-refusal.spec.ts` as §2.10 lists; `shell.tokens.test.tsx` and `build-output.test.tsx` stay unchanged. Adds `tests/e2e/unreachable-recovery.spec.ts` and the palette's `tests/e2e/command-palette.spec.ts` (E3-S4). The Home and Data health chips go live when their destinations enter in E3-S8 and E3-S9; this story's chip tests drive the chip with a test destination list. Below 768 px the rail stacks above the content (E3 NFR Layout).

Carries AC-19 and AC-20 for the shell (review v1 FINDING-4): rail labels, titles and state copy use the display vocabulary; the chip is a `badge` from `ui-components`.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] Every owner-interface screen MUST render inside one shell whose navigation groups Home, Research, Strategies and Portfolio apart from Data health and Settings, in that order, and an unshipped destination MUST be absent rather than disabled.
- [AC-3] The shell MUST mount `setup-ui`'s `SetupDraftProvider` above the `/setup` route so the drafts outlive route changes.
- [AC-10] Before paper trading ships, no unshipped destination MUST render, even disabled.
- [AC-16] Each count MUST be absent when it is zero.
- [AC-22] The owner MUST be able to open the command palette from the keyboard and from the top bar on every screen.
- [AC-23] When the product stops answering, the main region MUST be replaced by the unreachable state while the rail and top bar remain; when it answers again the screen MUST return without a reload.
- [AC-24] The shell's own states (loading, unreachable, not found, setup incomplete) MUST render as designed.
- [AC-25] Every operation MUST be completable by keyboard.
- [AC-26] The shell MUST be built from `ui-components` and consume theme tokens only, with the layout dimensions read from `layout.ts`.
- [AC-19] Every user-visible label MUST use the display label STD-UI-1 defines.
- [DAC-E3-7] The Home chip MUST equal `deriveNeedsYou(attention, scores).length` and the Data health chip `attention.problems.stock_count`; a zero count MUST render no chip; each item's accessible name MUST include the count in words; while the attention read fails the chip keeps its last value and its name gains *, as of {time}*; a changed count MUST be announced through one polite live region. (traces to: AC-16, AC-25)
- [DAC-E3-8] The unreachable state MUST be a `card` holding a `section` `role="status"` with *FactorFlow is not answering.*, the delivered cause paragraph and *Last answered {YYYY-MM-DD HH:MM:SS zone}* from `lastAnsweredAt` or *Not yet answered since this page opened*, announced once on entry and once on recovery; on recovery the routed screen MUST mount again at the same URL and refetch. (traces to: AC-23)
- [DAC-E3-10] One `keydown` listener on `document` MUST open the palette on `⌘K` or `Ctrl+K` and ignore the event when its target is a text field; the opener MUST show *⌘K* on a Mac and *Ctrl+K* otherwise and be named *Open the command palette*; the palette MUST restore focus to the opener or the previously focused element on close. (traces to: AC-22, AC-25)
- [DAC-E3-14] `shell.tsx` MUST mount `SetupDraftProvider` inside `ShellProvider` and outside the main region's route map. (traces to: AC-3)
- [DAC-E3-15] The delivered `status-region.tsx` and its four test files MUST be deleted, with the delivered shell tests and the two startup e2e specs rewritten as owner-shell §2.10 lists; `shell.tokens.test.tsx` and `build-output.test.tsx` MUST stay unchanged. (traces to: AC-23, AC-1)
- [DAC-E3-17] The top bar MUST leave the place of the environment region and the kill switch empty rather than reserving a disabled control. (traces to: AC-10)

### Derived

- [DAC-E3-S5-1] Given the frame on any route, When rendered, Then the document holds one `nav` named *Main*, one `banner` whose first text is the title, one `main`, and no element whose text or role names *Strategies*, *Portfolio*, *Stop all trading* or an environment. (traces to: AC-1, DAC-E3-17)
- [DAC-E3-S5-2] Given a test destination with `count: "problems"` and `attention.problems.stock_count` 3, When rendered, Then the item's accessible name is *Data health, 3 stocks with problems* and a `badge` `status-warning` reads *3*; given 0, Then no chip renders and the name is *Data health*. (traces to: DAC-E3-7)
- [DAC-E3-S5-3] Given health turning unreachable while on `/data/coverage`, When rendered, Then only the main region changes, the `section` `role="status"` reads *FactorFlow is not answering.* with *Last answered {time}* from the last `200`; When health answers again, Then Coverage mounts at `/data/coverage` and its fetch runs again, with no `location.reload`. (traces to: DAC-E3-8)
- [DAC-E3-S5-4] Given focus in an `input`, When `Ctrl+K` is pressed, Then the palette does not open and the input receives the keystroke; given focus on the body, Then it opens; When it closes, Then focus returns to the opener. (traces to: DAC-E3-10)
- [DAC-E3-S5-5] Given a route change, When the new screen renders, Then focus is on its `h1` (`tabIndex={-1}`) and not on the rail. (traces to: AC-25)
- [DAC-E3-S5-6] Given the rewritten `startup-health.spec.ts`, When it runs against a real stack, Then `/` lands on setup on an empty install and on Home after a download is requested, with no `liveness-state` or `run-outcome` test id; given `startup-refusal.spec.ts`, Then it asserts the unreachable text and its *Last answered* line. (traces to: DAC-E3-15)
- [DAC-E3-S5-7] Given the frame's styles, When the token scan and `layout.test.ts` run, Then no width, size or colour literal is found outside `layout.ts` and the theme. (traces to: AC-26)
