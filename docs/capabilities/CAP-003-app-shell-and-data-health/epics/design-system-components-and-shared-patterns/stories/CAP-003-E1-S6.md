# `AsOfLine` Taken Over from CAP-002 and Generalised

## User Story

As an owner-operator, I want the as-of line built once, so that Home's header, Data health's verdict line and CAP-002's Research line render their times the same way.

## Description

Logical component: `ui-components`. Takes over `web/src/components/patterns/as-of-line.tsx`, which CAP-002 delivers specialised to the Research as-of line (DEC-0073), and generalises it to `AsOfLine`: parts joined by *·* at `--text-xs` `--muted-foreground`, as `component-design-ui-components.md` §2.1 specifies. CAP-002's Research line is rewritten to compose `AsOfLine`, rendering what it rendered before, so CAP-002's `as-of-line.test.tsx` cases for that line keep passing. It is the one delivered pattern file this epic edits rather than creates.

Sequencing: the owner fixed CAP-002 to land first (capability OQ-2). This clone does not yet hold `as-of-line.tsx`, so this story is implementable only after CAP-002's `classification-ui` has merged; that is a cross-capability sequencing, not a dependency on a CAP-003 story, and nothing else in E1 waits on it. If `classification-ui` has not merged when this story is scheduled, the story stops and reports rather than creating the file first (E1 open question 2).

Breakdown and ordering: DEC-0223.
