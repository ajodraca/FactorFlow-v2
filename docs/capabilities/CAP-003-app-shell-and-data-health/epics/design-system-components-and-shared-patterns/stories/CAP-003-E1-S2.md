# The One Tier Function, `StatusBadge`, Presence Renderings and America/Chicago Formatters

## User Story

As an owner-operator, I want every status, absent value and time on every screen to come from one mapping and one set of formatters, so that a download outcome reads the same word and tier everywhere and a dash never hides as a zero.

## Description

Logical component: `ui-components`. Creates `web/src/components/patterns/tiers.ts` (`Tier`, `Status`, `tierOf`, `labelOf`), `status-badge.tsx` (`StatusBadge`), `presence.tsx` (`Absent`, `NotDeterminable`) and `format.ts` (`formatInstant`, `formatClock`, `formatSessionDate`, `formatCount`, `formatDownloadName`), as `component-design-ui-components.md` §2.3 and §2.5 specify, with one test file per pattern. `tierOf` and `labelOf` implement UX brief §12.2 verbatim; `StatusBadge` renders the `badge` `status-<tier>` variant from E1-S1 with the label as text and the tier shape as an `aria-hidden` `lucide-react` icon. Not determinable is not a tier: it renders through `NotDeterminable` only.

`formatDownloadName` renders *Download {YYYY-MM-DD HH:MM zone}* from `started_at`, else `requested_at`, the naming the owner confirmed as permanent (capability OQ-1). The delivered `formatTimestamp` in the shell's health module is left as it is for the delivered tests that assert it (§2.5).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-19] Every user-visible label MUST use the display label STD-UI-1 defines and MUST NOT show the domain term beside it; `labelOf` is the one source of status labels.
- [AC-20] Every download outcome, check result and stock state MUST render as the single severity tier the blueprint's status map assigns it, with its label and its tier shape, never colour alone.
- [AC-12] No screen MUST present a partial or interrupted download as complete; `partial` is warning and `abandoned` serious in the one tier function.
- [AC-24] Every data-bearing region MUST NOT collapse never-populated into nothing-found; `Absent` and `NotDeterminable` keep present, absent and not determinable apart.
- [DAC-E1-1] `tierOf` and `labelOf` MUST implement every row of UX brief §12.2 verbatim; `partial` MUST never map to good and `cancelled` never to critical. (traces to: AC-20, AC-12)
- [DAC-E1-2] `StatusBadge` MUST render the `badge` `status-<tier>` variant with the label as text and the tier shape as an `aria-hidden` icon, so no information is carried by colour alone. (traces to: AC-20)
- [DAC-E1-8] `Absent` MUST render an em dash in `--value-missing` with visually hidden text naming what is absent, never `0` and never blank; `NotDeterminable` MUST render `badge` `coverage-unknown` with *Not determinable* (or a caller's label), `--pattern-indeterminate` and its reason. (traces to: AC-24, AC-8)
- [DAC-E1-9] `formatInstant` MUST render `YYYY-MM-DD HH:MM zone` (or with seconds when asked) in America/Chicago with *CDT* or *CST*, built from `Intl.DateTimeFormat` parts; `formatClock` renders `HH:MM:SS zone`; `formatSessionDate` renders a session date unconverted; `formatCount` renders thousands separators; `formatDownloadName` renders *Download {YYYY-MM-DD HH:MM zone}* from `started_at`, else `requested_at`. (traces to: AC-25)

### Derived

- [DAC-E1-S2-1] Given each of the twenty-one `Status` inputs of UX brief §12.2 (eight download states, two result outcomes, five score states, two check statuses, two credential values, and the `item` kinds), When `tierOf` and `labelOf` run, Then each returns exactly the table's tier and label, asserted row by row in `tiers.test.ts`. (traces to: DAC-E1-1)
- [DAC-E1-S2-2] Given `StatusBadge` for each of the six tiers, When rendered, Then the accessible name is the label alone, the shape element is `aria-hidden`, and the six shapes are distinct elements (hollow circle, ringed dot, filled circle, triangle, diamond, square). (traces to: DAC-E1-2)
- [DAC-E1-S2-3] Given `Absent` with `what="scores as-of"`, When rendered, Then the visible text is an em dash and the accessible text names *scores as-of* and *not determinable* or *absent* as the caller states, and `0` appears nowhere. (traces to: DAC-E1-8)
- [DAC-E1-S2-4] Given `NotDeterminable` with a reason, When rendered, Then the badge reads *Not determinable*, the reason is in the accessible description, and no `status-*` class is applied. (traces to: DAC-E1-8)
- [DAC-E1-S2-5] Given an instant in October and one in January, When `formatInstant` runs, Then the zone reads *CDT* and *CST* respectively; given a session date `2026-10-15`, When `formatSessionDate` runs in a browser zone other than America/Chicago, Then it still renders `2026-10-15`. (traces to: DAC-E1-9)
- [DAC-E1-S2-6] Given a run with `started_at` null and `requested_at` set, When `formatDownloadName` runs, Then it names the download by `requested_at`. (traces to: DAC-E1-9)

## Technical Details

### API Contract

N/A: pure functions and presentational components. `tierOf(status: Status): Tier`; `labelOf(status: Status): string`; `StatusBadge({ status }: { status: Status })`; `Absent({ what }: { what: string })`; `NotDeterminable({ reason, label? })`; `formatInstant(date: Date | string, opts?: { seconds?: boolean }): string`; `formatClock(date): string`; `formatSessionDate(date: string): string`; `formatCount(n: number): string`; `formatDownloadName(run: { started_at: string | null; requested_at: string }): string`.
