# `worstDataTier` and `dataTileBadge`

## User Story

As an owner-operator, I want the data verdict composed by one function that Data health's verdict and Home's data tile both call, so that the tile never reads better than the verdict and never says *Yes* before a download has ended.

## Description

Logical component: `ui-components`. Creates `web/src/components/patterns/worst-data-tier.ts` with `worstDataTier` and `dataTileBadge` exactly as `component-design-ui-components.md` §2.4 specifies (DEC-0210 and DEC-0217 as the owner amended them on 2026-10-25, PROVISIONAL). The inputs are the problem set (`affectedCount`, `followedCount`) and the latest terminal download's recorded state; the checks' tiers do not feed it. The tier order is the one `sortAttention` uses: critical, serious, warning, good, neutral, with active alongside good.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-11] The Data health verdict MUST name how many followed stocks need attention with its severity tier; this story delivers the one function that composes it.
- [AC-8] Home's data tile badge MUST be the worse of the verdict tier and the score-state tier.
- [DAC-E1-3] `worstDataTier` MUST return `null` whenever `latestTerminalDownload` is null, for `affectedCount` 0 and above 0 alike, and `dataTileBadge` MUST return `null` whenever the verdict is `null`, whatever the score state. (traces to: AC-21, AC-11)
- [DAC-E1-4] Otherwise `worstDataTier` MUST answer good *Yes* when `affectedCount` is 0, warning *Mostly yes* when it is above 0 and below `followedCount`, critical *No* when `affectedCount` ≥ `followedCount` > 0, critical *No* with the clause *, and the last download failed.* when the latest terminal download is `failed`, and serious *Mostly yes* with *, and the last download was interrupted.* when it is `abandoned`; the worst input wins by the one order, and the download clause is returned whenever the latest terminal download failed or was interrupted. (traces to: AC-11)
- [DAC-E1-5] `dataTileBadge` MUST return the worse of the verdict tier and the score-state tier by the same order with the label of whichever wins, a tie going to the verdict, and a null or neutral or active score state MUST never worsen or displace the answer. (traces to: AC-8)

### Derived

- [DAC-E1-S3-1] Given `latestTerminalDownload` `succeeded` and `affectedCount` 0 of 10, When `worstDataTier` runs, Then it answers `{ tier: "good", word: "Yes", downloadClause: null }`. (traces to: DAC-E1-4)
- [DAC-E1-S3-2] Given `latestTerminalDownload` `abandoned` and `affectedCount` 10 of 10, When `worstDataTier` runs, Then the tier is critical (every stock affected wins over serious), the word is *No*, and `downloadClause` is `"interrupted"`. (traces to: DAC-E1-4)
- [DAC-E1-S3-3] Given `latestTerminalDownload` `succeeded` and `affectedCount` 0, and a score state `failed`, When `dataTileBadge` runs, Then it returns the critical tier with the label *Score update failed* and `from: "scores"`; given the score state `not_current` against a warning verdict, Then the verdict wins the tie with its own word. (traces to: DAC-E1-5)
- [DAC-E1-S3-4] Given `latestTerminalDownload` `partial` or `cancelled`, When `worstDataTier` runs, Then the download contributes no tier and no clause and the answer follows the problem set alone. (traces to: DAC-E1-4)
- [DAC-E1-S3-5] Given `verdict` null and every score state including `failed` and `not_current`, When `dataTileBadge` runs, Then it returns `null`. (traces to: DAC-E1-3)

## Technical Details

### API Contract

N/A: pure functions. `worstDataTier(inputs: { affectedCount: number; followedCount: number; latestTerminalDownload: RunState | null }): DataAnswer | null`; `dataTileBadge(verdict: DataAnswer | null, scores: Extract<Status, { of: "scores" }> | null): { tier: Tier; label: string; from: "verdict" | "scores" } | null`, with `DataAnswer = { tier: "good" | "warning" | "serious" | "critical"; word: "Yes" | "Mostly yes" | "No"; downloadClause: "failed" | "interrupted" | null }`.
