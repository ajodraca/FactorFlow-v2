# Needs You Derivation and Sort: needs-you.ts and the Item Row

## User Story
As an owner-operator, I want the Needs you list derived and ordered in one place, so that Home's list and the rail's Home count are always the same array.

## Description
Creates `web/src/components/patterns/needs-you.ts` exporting `NeedsYouKind`, `NeedsYouItem`, `deriveNeedsYou(attention, scores)` and `sortAttention(items)` per ui-components 2.6 (DEC-0203, DEC-0216, both upheld) and `web/src/components/patterns/needs-you-item.tsx`, the blueprint §4.1 row (severity tile, tag badge, title, body, one action slot) that `home-ui` fills with its copy. `deriveNeedsYou` produces the six kinds exactly while their causes hold: `data_problems`, `download_not_complete`, `credential_missing` from attention's items; `first_scores` and `score_failed` from a served summary; `first_download` under a served `never_classified` summary while `latest_download` is non-terminal, or under a `404` summary only while `latest_terminal_download` is null. It returns no user-visible string. `sortAttention` orders by `TIER_ORDER` then `recordedAt` newest first, stable for equal keys.

**Deliberate later-epic dependency (DEC-0223 answer A; backlog review v3 FINDING-1).** `deriveNeedsYou` takes `Attention` and `ScoreState`, which `owner-shell` defines in `web/src/app/shell-types.ts` and this layer imports as types only (ui-components §11; owner-shell 2.1, 2.3). That file is CAP-003-E3-S1, so this E1 story hard-depends on an E3 story. The edge is stated here and in `dependencies.yaml`; nothing else in E1 waits on E3.

Source: component-design-ui-components.md 2.6, 7, 11; component-design-owner-shell.md 2.3; epic CAP-003-E1 DAC-E1-6, DAC-E1-7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-9] Items MUST be ordered by severity tier then recency, and an item MUST leave the list only when its cause is resolved. This story delivers the derivation and sort both callers use.
- [AC-16] The Home destination MUST carry the number of *Needs you* items: the length of this derivation.
- [AC-7] Home MUST show the first download's progress until scores exist: the `first_download` item variant.
- [DAC-E1-6] `deriveNeedsYou` MUST produce each of the six kinds exactly while its cause holds, with the `first_download` variant under a `404` summary only while `latest_terminal_download` is null, and MUST return no user-visible string. (traces to: AC-9, AC-7)
- [DAC-E1-7] `sortAttention` MUST order by tier then `recordedAt` newest first, stable for equal keys; the length of `sortAttention(deriveNeedsYou(...))` is the one value both `owner-shell` and `home-ui` use. (traces to: AC-9, AC-16)

### Derived
- [DAC-E1-S8-1] Given each kind, When `deriveNeedsYou` runs, Then the item's `target` is `/data` for `data_problems` and `score_failed`, `/data/downloads/{runId}` for `download_not_complete`, `first_download` and `first_scores`, and `/settings` for `credential_missing`, with `runId` set only for the three download-bound kinds. (traces to: AC-9)
- [DAC-E1-S8-2] Given a summary in `error` state, When `deriveNeedsYou` runs, Then no score-derived item is produced and the three server items still are; given a served summary with `later.state` `building` and `never_classified` true, Then `first_scores` is present and `first_download` is not. (traces to: DAC-E1-6)
- [DAC-E1-S8-3] Given `needs-you-item.tsx`, When rendered, Then the severity tile is `aria-hidden`, the tag badge carries the tier in words through `StatusBadge`, and the single action slot renders one link styled `button` `outline`. (traces to: AC-9, AC-20)
