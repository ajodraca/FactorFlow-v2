# `stepper`, `progress`, `toast` and `command`

## User Story

As an owner-operator, I want the stepper, progress bar, toast and command palette components vendored with their accessibility contracts, so that setup's steps, a running download's progress, completion notices and the palette behave the same everywhere.

## Description

Logical component: `ui-components`. Vendors `web/src/components/ui/stepper.tsx` (`vertical`, bespoke, a native `ol` with `aria-current="step"`), `progress.tsx` (`determinate`, `indeterminate`, Radix Progress), `toast.tsx` (`Toaster` and `toast()` with `success`, `warning`, `error`, on `sonner`) and `command.tsx` (`Command`, `CommandDialog`, `CommandInput`, `CommandList`, `CommandEmpty`, `CommandGroup`, `CommandItem`, `CommandSeparator`, `CommandLoading`, on `cmdk` inside Radix Dialog), per `component-design-ui-components.md` §2.1. Adds `cmdk`, `sonner` and `@radix-ui/react-progress`, each with its licence verified when added (tech stack v7 OQ-TS-10; DEC-0205; SEC-DEP-003). The `command` dialog's 560 px width is shadcn/ui's own, not a call-site literal (UX design 1.1), and is the one named exemption added to E1-S1's token scan.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-25] Every operation MUST be completable by keyboard; cmdk supplies the combobox and listbox contracts, the stepper is a native `ol`.
- [AC-26] Every surface MUST be built from the product's design-system components and consume its theme tokens.
- [DAC-E1-14] `stepper` MUST set `aria-current="step"`; `progress` MUST expose `progressbar` labelled by its visible text; `command` MUST loop and restore focus on close. (traces to: AC-25)
- [DAC-E1-12] No vendored component MAY contain a spacing, size or colour literal outside the theme, and no `package.json` dependency MAY be added beyond the confirmed packages, each with its licence recorded when added. (traces to: AC-26)

### Derived

- [DAC-E1-S8-1] Given `stepper` `vertical` with four steps, one current and one done, When rendered, Then it is an `ol`, the current `li` carries `aria-current="step"`, the done step's text includes *done* and renders as a link when given a target, and the step dot's size reads a value passed by the caller rather than a literal. (traces to: DAC-E1-14)
- [DAC-E1-S8-2] Given `progress` `determinate` with value 120 of 300 and the visible text *120 of 300 stocks*, When rendered, Then the element has `role="progressbar"`, `aria-valuenow` 120, `aria-valuemax` 300 and is labelled by the visible text; given `indeterminate`, Then it has no `aria-valuenow` and its label still renders. (traces to: DAC-E1-14)
- [DAC-E1-S8-3] Given `toast("error", ...)` and `toast("warning", ...)`, When raised, Then each persists until dismissed and takes no focus; given `toast("success", ...)`, Then it auto-dismisses and takes no focus. (traces to: AC-25)
- [DAC-E1-S8-4] Given `CommandDialog` with `loop` set and three items, When `ArrowDown` is pressed on the last item, Then the first becomes active; When `Escape` is pressed, Then the dialog closes and focus returns to the element that opened it. (traces to: DAC-E1-14)
- [DAC-E1-S8-5] Given the token scan test, When it runs over the four new files, Then the only exemption is `command.tsx`'s dialog width. (traces to: DAC-E1-12)
