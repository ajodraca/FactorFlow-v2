# StateRegion: STD-UI-23's Eight States Around a Body

## User Story
As an owner-operator, I want every data-bearing region to render each of the eight states as designed, so that a never-populated region is never shown as nothing found and an error always offers a way back.

## Description
Creates `web/src/components/patterns/state-region.tsx` exporting `StateRegion<T>`, which takes the delivered `ScreenState<T>` union from `web/src/api/types.ts` (unchanged) and one renderer per state, refusing at the type level a call that omits a state without `{ notApplicable: "reason" }`; it renders the loading skeleton, the two empty states as distinct copy, the error with its three parts and **Try again**, and leaves the unreachable kind to the shell (ui-components 2.7; DAC-E1-10; STD-UI-23).

Source: component-design-ui-components.md 2.7, 7; epic CAP-003-E1 DAC-E1-10.

## Acceptance Criteria (Given/When/Then)

- [DAC-E1-10] `StateRegion` MUST take the delivered `ScreenState` union unchanged, refuse to type-check a call that omits a state without a reason, render the two empty states as distinct copy and the error with **Try again**, and leave the unreachable kind to the shell. (traces to: AC-24)

### Derived

(traces to: DAC-E1-10)
- [DAC-E1-S9-2] Given a call omitting a renderer and its `notApplicable` reason, When `npx tsc --noEmit` runs, Then it fails on that call (asserted with a `// @ts-expect-error` case in the test file). (traces to: DAC-E1-10)
