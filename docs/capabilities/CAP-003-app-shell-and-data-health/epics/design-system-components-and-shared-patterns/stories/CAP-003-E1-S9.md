# `data-table` Variants with CAP-001's Windowing

## User Story

As an owner-operator, I want one data table with compact, history, virtualised and expandable variants, so that Recent downloads, Coverage, Followed stocks, Downloads and the download roster are the same table and the 3000-stock lists stay bounded in the DOM.

## Description

Logical component: `ui-components`. Vendors `web/src/components/ui/data-table.tsx` on `@tanstack/react-table` with the four variants `component-design-ui-components.md` §2.1 names: `compact`, `history`, `virtualised` and `expandable`. The `virtualised` variant reuses the hand-built windowed rendering over keyset pages that CAP-001 delivered in `web/src/screens/coverage/coverage-table.tsx`, moved into the vendored component; no virtualisation library is added (DEC-0215; §3). The delivered `coverage-table.tsx` keeps working until E7-S2 rebuilds Coverage on this variant, so this story copies the windowing logic rather than removing it. Adds `@tanstack/react-table` with its licence verified when added (tech stack v7 OQ-TS-10; SEC-DEP-003).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-26] Every surface MUST be built from the product's design-system components and consume its theme tokens.
- [AC-25] Every operation MUST be completable by keyboard; the table's expanders and sortable headers are focusable controls.
- [DAC-E1-12] No vendored component MAY contain a spacing, size or colour literal outside the theme, and no `package.json` dependency MAY be added beyond the confirmed packages, each with its licence recorded when added. (traces to: AC-26)

### Derived

- [DAC-E1-S9-1] Given `data-table` `virtualised` with 3000 rows, When rendered in a viewport, Then the number of row elements in the DOM is bounded by the window size plus overscan and does not grow with the row count, asserted by the test that CAP-001's `coverage-table.test.tsx` windowing case establishes. (traces to: AC-26)
- [DAC-E1-S9-2] Given `data-table` `expandable` with a row expander, When the expander is activated by keyboard, Then the row's detail renders, the expander is named for its row (*Expand AAPL*) and `aria-expanded` follows. (traces to: AC-25)
- [DAC-E1-S9-3] Given `data-table` `history` with the first column marked as the row header, When rendered, Then each row's first cell is a `th` with `scope="row"` and sortable columns expose `aria-sort`. (traces to: AC-25)
- [DAC-E1-S9-4] Given `data-table` `compact`, When rendered, Then row height resolves to `--row-height-compact` and cell padding to `--cell-padding-x` and `--cell-padding-y`, with no literal. (traces to: DAC-E1-12)
- [DAC-E1-S9-5] Given a filter change through the table toolbar, When the row set changes, Then focus stays on the filter control and the new count is announced through a polite live region. (traces to: AC-25)
