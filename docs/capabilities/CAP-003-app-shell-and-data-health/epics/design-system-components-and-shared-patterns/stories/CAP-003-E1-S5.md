# The One Tier Function: tiers.ts and StatusBadge

## User Story
As an owner-operator, I want every download state, result outcome, score state, check result and credential presence mapped to one severity tier with its display label and shape in one place, so that no two screens ever disagree about what a status means.

## Description
Creates `web/src/components/patterns/tiers.ts` exporting `Tier`, `Status`, `tierOf(status)` and `labelOf(status)`, implementing UX brief §12.2 verbatim as DAC-E1-1 restates it, and `web/src/components/patterns/status-badge.tsx` exporting `StatusBadge`, which renders `badge` `status-<tier>` with the label as text and the tier shape as an `aria-hidden` icon (neutral hollow circle, active ringed dot, good filled circle, warning triangle, serious diamond, critical square) (ui-components 2.3; blueprint §8; STD-UI-8). Not determinable is not a tier and never passes through `tierOf` (ui-components 2.5). The `item` status kind carries DEC-0203's tag tiers for E1-S8.

Source: component-design-ui-components.md 2.3, 7; UX brief §12.2; epic CAP-003-E1 DAC-E1-1, DAC-E1-2.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-19] Every user-visible label MUST use the display label STD-UI-1 defines and MUST NOT show the domain term beside it. This story delivers `labelOf`, the one source of status labels.
- [AC-20] Every download outcome, check result and stock state MUST render as the single severity tier the blueprint's status map assigns it, with its label and its tier shape, never colour alone.
- [AC-12] No screen MUST present a partial or interrupted download as complete: `partial` is warning and `abandoned` serious.
- [DAC-E1-1] `tierOf` and `labelOf` MUST implement every row of UX brief §12.2 verbatim; `partial` MUST never map to good and `cancelled` never to critical. (traces to: AC-20, AC-12)
- [DAC-E1-2] `StatusBadge` MUST render the label as text and the tier shape as an `aria-hidden` icon, so greyscale rendering keeps every tier distinguishable. (traces to: AC-20)

### Derived
- [DAC-E1-S5-1] Given the `Status` union, When a new kind or state is added without a row, Then `tierOf` and `labelOf` fail to type-check (exhaustive `switch` with a `never` default), so a status can never render without a tier. (traces to: AC-20)
- [DAC-E1-S5-2] Given `web/src/components/patterns/tiers.test.ts`, When it runs, Then it asserts every row of DAC-E1-1 by input, label and tier, including check `ok` labelled *No missing prices or gaps* or *All financials present* by the caller's check, and credential present or missing as *Found* or *Missing*. (traces to: DAC-E1-1)
- [DAC-E1-S5-3] Given `status-badge.test.tsx`, When each tier renders, Then the label is in the accessible name, the shape is `aria-hidden`, and no two tiers share a shape. (traces to: DAC-E1-2)
