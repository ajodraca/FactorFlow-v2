# `StateRegion`: STD-UI-23's Eight States Around a Body

## User Story

As an owner-operator, I want every data-bearing region to render each of the eight states as designed, so that a region that has never been populated never looks like one where nothing matched and a failed read always offers a retry.

## Description

Logical component: `ui-components`. Creates `web/src/components/patterns/state-region.tsx` as `component-design-ui-components.md` §2.7 specifies: `StateRegion<T>` takes the delivered `ScreenState<T>` union from `web/src/api/types.ts` (unchanged) and one renderer per state kind, refusing at the type level a call that omits a kind without `{ notApplicable: "reason" }`. It renders the loading skeleton, the two empty states as distinct copy, the error with its three parts and **Try again**, and leaves the `unreachable` kind to the shell, which replaces the main region (AC-23).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-24] Every data-bearing region MUST render each of STD-UI-23's eight states as designed, or record why one does not apply, and MUST NOT collapse never-populated into nothing-found.
- [DAC-E1-10] `StateRegion` MUST take the delivered `ScreenState` union unchanged and one renderer per state, MUST refuse to type-check a call that omits a state without `{ notApplicable: "reason" }`, MUST render the two empty states as distinct copy and the error with its three parts and **Try again**, and MUST leave the unreachable kind to the shell. (traces to: AC-24)

### Derived

- [DAC-E1-S5-1] Given a `ScreenState` of each of the eight kinds, When `StateRegion` renders with a renderer per kind, Then exactly that kind's renderer output is in the document. (traces to: DAC-E1-10)
- [DAC-E1-S5-2] Given a call whose props omit `stale` without `{ notApplicable }`, When `npx tsc --noEmit` runs over a fixture file, Then it fails, asserted with Vitest's `expectTypeOf` or an `// @ts-expect-error` fixture. (traces to: DAC-E1-10)
- [DAC-E1-S5-3] Given the `error` kind with `operation`, `reason` and a `retry` callback, When rendered, Then the body reads *Couldn't {operation}: {reason}.* with a **Try again** `button` `outline` that calls `retry` once per activation and never moves focus elsewhere. (traces to: DAC-E1-10)
- [DAC-E1-S5-4] Given the `empty-never-populated` and `empty-no-match` kinds with their own copy, When rendered, Then each shows only its own copy and neither renders the other's reset control. (traces to: AC-24)
- [DAC-E1-S5-5] Given the `unreachable` kind, When rendered, Then `StateRegion` renders nothing of its own. (traces to: DAC-E1-10)
