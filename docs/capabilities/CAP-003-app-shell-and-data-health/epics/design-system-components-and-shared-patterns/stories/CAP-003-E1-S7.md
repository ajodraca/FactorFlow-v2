# worstDataTier and dataTileBadge: the One Data Verdict

## User Story
As an owner-operator, I want the data verdict composed once from the problem set and the latest terminal download, so that Data health's answer and Home's data tile can never disagree.

## Description
Creates `web/src/components/patterns/worst-data-tier.ts` exporting `DataAnswer`, `worstDataTier({ affectedCount, followedCount, latestTerminalDownload })` and `dataTileBadge(verdict, scores)` per ui-components 2.4 (DEC-0210, DEC-0217 as the owner amended them, both upheld). `worstDataTier` returns `null` while `latestTerminalDownload` is null (no verdict, never *Yes*); otherwise the worst of the problem-set tier and the download tier by the one order critical, serious, warning, good, neutral, with active ranked alongside good, the word following the winning tier and the download clause returned whenever the latest terminal download failed or was interrupted. `dataTileBadge` returns the worse of the verdict tier and the score-state tier (`tierOf` over the summary's state), a tie going to the verdict, a null score state contributing no tier, and `null` whenever the verdict is `null`.

Source: component-design-ui-components.md 2.4, 7; epic CAP-003-E1 DAC-E1-3, DAC-E1-4, DAC-E1-5.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-11] The Data health verdict MUST name how many followed stocks need attention with its severity tier. This story delivers the one function that composes it.
- [AC-8] Home's tile badge MUST be the worse of the verdict tier and the score-state tier.
- [AC-21] Before any download has ended, no surface MUST present a verdict.
- [DAC-E1-3] `worstDataTier` MUST return `null` whenever `latestTerminalDownload` is null, and `dataTileBadge` MUST return `null` whenever the verdict is `null`, whatever the score state. (traces to: AC-21, AC-11)
- [DAC-E1-4] Otherwise `worstDataTier` MUST answer as the DAC-E1-4 table states, with the download clause returned whenever the latest terminal download failed or was interrupted. (traces to: AC-11)
- [DAC-E1-5] `dataTileBadge` MUST return the worse of the verdict and the score-state tier with the label of whichever wins, a tie going to the verdict, and a null, neutral or active score state never worsening the answer. (traces to: AC-8)

### Derived
- [DAC-E1-S7-1] Given `web/src/components/patterns/worst-data-tier.test.ts`, When it runs, Then it covers each row of the DAC-E1-4 table, the `affectedCount >= followedCount > 0` critical case, a `cancelled` or `partial` latest terminal download contributing no tier, and `dataTileBadge` over a `null` verdict returning `null` for `failed` and `not_current` score states alike. (traces to: DAC-E1-3, DAC-E1-4)
- [DAC-E1-S7-2] Given the tier order, When it is defined, Then it is one exported constant `TIER_ORDER` that `sortAttention` (E1-S8) imports, so the verdict and the sort cannot drift apart (DEC-0217). (traces to: AC-11)
