# Form Controls: `dialog` `confirm`, `form`, `input`, `textarea`, `select`, `checkbox` and `radio-group`

## User Story

As an owner-operator, I want the dialog, form and field components vendored with their keyboard and focus contracts, so that setup, Data health and the taken-over screens confirm and edit through the same controls.

## Description

Logical component: `ui-components`. Vendors `web/src/components/ui/dialog.tsx` (`confirm`, Radix AlertDialog), `form.tsx` (`stacked`, `inline`, on `react-hook-form` with the `zod` resolver), `input.tsx` (`text`, `numeric` with suffix), `textarea.tsx` (`list`), `select.tsx` (`inline`), `checkbox.tsx` (`default`) and `radio-group.tsx` (`cards`), as shadcn/ui ships them with relative imports, per `component-design-ui-components.md` §2.1. Adds the packages these import, each with its licence verified when added: `@radix-ui/react-dialog`, `@radix-ui/react-alert-dialog`, `@radix-ui/react-radio-group`, `@radix-ui/react-select`, `@radix-ui/react-checkbox`, `@radix-ui/react-label`, `react-hook-form`, `zod`, `@hookform/resolvers` (tech stack v7 OQ-TS-10; DEC-0215; SEC-DEP-003). `dialog` `destructive` is not vendored: nothing in M1 deletes (STD-UI-2).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-25] Every operation MUST be completable by keyboard; Radix supplies the dialog, radio, select and checkbox keyboard contracts.
- [AC-26] Every surface MUST be built from the product's design-system components and consume its theme tokens.
- [DAC-E1-14] `dialog` `confirm` (Radix AlertDialog) MUST put **Cancel** first and focus it. (traces to: AC-25)
- [DAC-E1-15] `dialog` `destructive` MUST NOT be used for stopping following or cancelling a download, because nothing is deleted (STD-UI-2). (traces to: AC-25)
- [DAC-E1-12] No vendored component MAY contain a spacing, size or colour literal outside the theme, and no `package.json` dependency MAY be added beyond the ten confirmed packages and the `@radix-ui/react-*` primitives, each with its licence recorded when added. (traces to: AC-26)

### Derived

- [DAC-E1-S7-1] Given `dialog` `confirm` opened from a trigger, When it opens, Then it has `role="alertdialog"` with `aria-modal`, focus is on **Cancel**, which is the first action, `Tab` cycles inside the dialog, and `Escape` or **Cancel** closes it and returns focus to the trigger. (traces to: DAC-E1-14)
- [DAC-E1-S7-2] Given `form` `stacked` with a `zod` schema and `input` `numeric` with the suffix *years*, When a value fails the schema on submit, Then the field renders its error text linked by `aria-describedby`, the typed value is kept, and the input's accessible name includes the suffix. (traces to: AC-25)
- [DAC-E1-S7-3] Given `radio-group` `cards`, When focused, Then the group is one tab stop, arrow keys move the selection, and the selected card carries a 1 px `--foreground` ring from a token, not a literal. (traces to: AC-25)
- [DAC-E1-S7-4] Given `select` `inline`, When opened by keyboard, Then options are navigable with arrow keys and `Enter` selects; given `checkbox` `default`, When `Space` is pressed, Then it toggles. (traces to: AC-25)
- [DAC-E1-S7-5] Given `textarea` `list` with a description, When rendered, Then the description is linked by `aria-describedby` and the control accepts multi-line paste without transformation. (traces to: AC-25)
- [DAC-E1-S7-6] Given the token scan test from E1-S1, When it runs over the seven new files, Then it passes with no new exemption. (traces to: DAC-E1-12)
