# Vendor data-table: compact, history, virtualised and expandable Variants on TanStack Table

## User Story
As an owner-operator, I want one table component whose virtualised variant keeps the 3000-stock lists responsive, so that Coverage, Followed stocks, Downloads, the download detail and Recent downloads share one table with one set of semantics.

## Description
Vendors `data-table` into `web/src/components/ui/data-table.tsx` on `@tanstack/react-table` with four variants: `compact`, `history` (row header on the first column), `virtualised` (windowed rendering over keyset pages) and `expandable` (per-row expansion) (ui-components 2.1; UX design §3). The `virtualised` variant reuses the hand-built windowed rendering CAP-001 delivered in `web/src/screens/coverage/coverage-table.tsx`, re-implemented inside the vendored component without editing that file; no virtualisation library is added (DEC-0215; STD-UI-30). E7 later switches Coverage and Followed stocks to it and removes the hand-built copy (owner-web-app 2.3). Adds `@tanstack/react-table` with its licence.

Source: component-design-ui-components.md 2.1, 3, 5, 7; epic CAP-003-E1 NFR *Performance*, *Volume*; CAP-001 AC-4.

- [DAC-E1-S4-2] Given any variant, When rendered, Then column headers are programmatic (`columnheader`, `aria-sort` on a sorted column), the `history` variant's first cell is the row header, and the `expandable` variant's expander is a button named for its row and toggles `aria-expanded`. (traces to: AC-25)
- [DAC-E1-S4-3] Given the component, When `token-literals.test.ts` runs, Then it passes, row height resolves to `--row-height` and `package.json` gains only `@tanstack/react-table` with its licence. (traces to: DAC-E1-12)
