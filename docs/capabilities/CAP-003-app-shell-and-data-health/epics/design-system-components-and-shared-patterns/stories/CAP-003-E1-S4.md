# *Needs You* Derivation, Sort and Item Row

## User Story

As an owner-operator, I want the *Needs you* list derived and ordered by one function, so that Home's list and the rail's Home count are the same array and an item leaves only when its cause is gone.

## Description

Logical component: `ui-components`. Creates `web/src/components/patterns/needs-you.ts` (`NeedsYouKind`, `NeedsYouItem`, `deriveNeedsYou`, `sortAttention`) and `needs-you-item.tsx` (the blueprint §4.1 row: 28 px severity tile `aria-hidden`, tag badge, title, body, one action), as `component-design-ui-components.md` §2.6 specifies (DEC-0203, DEC-0216, PROVISIONAL). `deriveNeedsYou` reads `Attention` and `ScoreState`, the types `owner-shell` defines in `web/src/app/shell-types.ts` and this module imports as types only (§11), which is why this story depends on CAP-003-E3-S1 in the later epic E3: the epics backlog review v1 FINDING-1 interleaving, resolved by DEC-0223. It returns no user-visible string; the copy is `home-ui`'s (E5-S3). The item row's 28 px tile size reads `LAYOUT.markerSize` from `web/src/app/layout.ts` (E3-S1), not a literal.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-9] Every item on Home MUST have exactly one action, items MUST be ordered by severity tier then recency, and an item MUST leave the list only when its cause is resolved, never because it was viewed.
- [AC-16] The Home destination MUST carry the number of *Needs you* items; this story delivers the derivation whose length is that count.
- [AC-7] Home MUST show the first download's progress until scores exist; this story delivers the `first_download` variant that exists before the score read is served (DEC-0216).
- [DAC-E1-6] `deriveNeedsYou` MUST produce each of the six kinds exactly while its cause holds in the latest attention and summary reads, with the `first_download` variant present under a `404` summary only while `latest_terminal_download` is null, and the `first_scores` and `score_failed` kinds absent under a `404`; it MUST return no user-visible string. (traces to: AC-9, AC-7)
- [DAC-E1-7] `sortAttention` MUST order by tier (critical, serious, warning, good, neutral, with active sorting with good), then by `recordedAt` newest first, and MUST be stable for equal keys; the length of `sortAttention(deriveNeedsYou(...))` is the one value both `owner-shell` and `home-ui` use. (traces to: AC-9, AC-16)

### Derived

- [DAC-E1-S4-1] Given attention `items` carrying `data_problems`, `download_not_complete` (with `run_id`) and `credential_missing`, When `deriveNeedsYou` runs with any score state, Then each becomes an item with its target (`/data`, `/data/downloads/{runId}`, `/settings`), tier (warning; critical for `failed` and serious for `abandoned`; critical) and `recordedAt` from the item's `recorded_at`. (traces to: DAC-E1-6)
- [DAC-E1-S4-2] Given a served summary with `later.state` `building` and `never_classified` true, When derived, Then one `first_scores` item (active) is present; given `later.state` `failed`, Then one `score_failed` item (critical, `recordedAt` its `ended_at`, target `/data`) is present. (traces to: DAC-E1-6)
- [DAC-E1-S4-3] Given the score state `not_served` and `latest_download` non-terminal with `latest_terminal_download` null, When derived, Then one `first_download` item (active, target the download's detail) is present; given `latest_terminal_download` set, Then no score-derived item is present. (traces to: DAC-E1-6)
- [DAC-E1-S4-4] Given items with equal tier and equal `recordedAt`, When sorted twice, Then their relative order is the input order both times. (traces to: DAC-E1-7)
- [DAC-E1-S4-5] Given `NeedsYouItemRow` with a tier, tag, title, body and one action, When rendered, Then it is an `li` whose severity tile is `aria-hidden`, whose tag badge carries the tier word, and whose only interactive element is the action link. (traces to: AC-9, AC-25)
