# Vendoring Foundation: `cn`, Tailwind Token Keys, `badge`, `button` and `card`

## User Story

As an owner-operator, I want the first design-system components vendored into the repository over the existing theme tokens, so that every later surface is assembled from the same badge, button and card and no surface carries a colour or size literal of its own.

## Description

Logical component: `ui-components`. Creates `web/src/components/ui/utils.ts` (`cn()` from `clsx` and `tailwind-merge`), `web/src/components/ui/badge.tsx` (`status-<tier>`, `coverage-present`, `coverage-absent`, `coverage-unknown`, `secondary`), `web/src/components/ui/button.tsx` (`default`, `secondary`, `outline`, `ghost`, `blocked`, with `asChild` for links) and `web/src/components/ui/card.tsx` (`default`, `metric`, `summary`), copied as shadcn/ui ships them with `@/` imports rewritten to relative paths, as `component-design-ui-components.md` §2.1 specifies. No `tsconfig.json` or `vite.config.ts` alias is added (DEC-0211).

Extends the delivered `tailwind.config.js` with exactly the keys §2.2 lists (`primary`, `primary-foreground`, `accent`, `accent-foreground`, `popover`, `popover-foreground`, `muted`, `ring`, `destructive`, `destructive-foreground`, `status-foreground`, `seq-1`, `borderRadius.DEFAULT`, `ringWidth.DEFAULT`), each in the delivered `hsl(var(--token) / <alpha-value>)` form resolving to a token `design-system/theme.css` already defines; no token is added. Adds to `package.json` only the packages these three components import, `clsx`, `tailwind-merge`, `class-variance-authority`, `lucide-react` and `@radix-ui/react-slot`, each with its licence verified against the package's `LICENSE` file when added (tech stack v7 OQ-TS-10; SEC-DEP-003). Widens the delivered `web/src/api/render.test.tsx` glob to `web/src/components/` (§4).

Carries the automated check for AC-26's literal ban that epics backlog review v1 FINDING-5 found missing: a Vitest test over `web/src/components/**` rejecting `px`, `rem` and hex colour literals (DAC-E1-S1-5). The 560 px inside the vendored `command` dialog is shadcn/ui's own and is exempted by name when E1-S8 vendors it (UX design 1.1).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-26] Every surface MUST be built from the product's design-system components and consume its theme tokens, with no spacing, size or colour literal outside the theme.
- [AC-25] Every operation MUST be completable by keyboard; this story delivers the `button` contract every screen relies on.
- [DAC-E1-11] `tailwind.config.js` MUST gain only the keys the vendored components reference, each in the delivered `hsl(var(--token) / <alpha-value>)` form resolving to a token `theme.css` already defines; the delivered `web/src/app/shell.tokens.test.tsx` MUST keep passing. (traces to: AC-26)
- [DAC-E1-12] No vendored component or pattern MAY contain a spacing, size or colour literal outside the theme, and no `package.json` dependency MAY be added beyond the ten packages tech stack v7 confirms and the `@radix-ui/react-*` primitives, each with its licence recorded when added. (traces to: AC-26)
- [DAC-E1-14] `button` `blocked` MUST remain focusable and be described by its reason. (traces to: AC-25)
- [DAC-E1-15] `button` `disabled` MUST NOT be used where a precondition gates an action. (traces to: AC-25)

### Derived

- [DAC-E1-S1-1] Given the three vendored sources, When `npx tsc --noEmit` and `npm run lint` run, Then both pass with no `@/` import and no alias in `tsconfig.json` or `vite.config.ts`. (traces to: DAC-E1-12)
- [DAC-E1-S1-2] Given `badge`, When each of the `status-neutral`, `status-active`, `status-good`, `status-warning`, `status-serious`, `status-critical`, `coverage-present`, `coverage-absent`, `coverage-unknown` and `secondary` variants renders, Then its classes resolve only to `--status-<tier>`, `--status-<tier>-muted`, the presence pairs or `--secondary` custom properties and to no literal colour. (traces to: AC-26)
- [DAC-E1-S1-3] Given `button` `blocked` with a reason, When it is rendered and tabbed to, Then it receives focus, is `aria-disabled`, is described by the reason through `aria-describedby`, and activating it calls no handler. (traces to: DAC-E1-14)
- [DAC-E1-S1-4] Given `button` with `asChild`, When it wraps a router `Link`, Then one anchor renders with the button's classes and no nested interactive element. (traces to: AC-25)
- [DAC-E1-S1-5] Given a new Vitest test `web/src/components/tokens.test.ts`, When it scans every `.ts` and `.tsx` file under `web/src/components/`, Then it fails on any `px`, `rem` or `#rrggbb` literal outside a named exemption list, and the list is empty in this story. (traces to: DAC-E1-12)
- [DAC-E1-S1-6] Given `package.json` after this story, When its dependencies are listed, Then the only additions are `clsx`, `tailwind-merge`, `class-variance-authority`, `lucide-react` and `@radix-ui/react-slot`, and the story's commit records each licence (MIT, MIT, Apache-2.0, ISC, MIT, verified against the package). (traces to: DAC-E1-12)
- [DAC-E1-S1-7] Given the widened `render.test.tsx`, When it runs, Then it asserts no `dangerouslySetInnerHTML` under `web/src/components/`. (traces to: AC-26)
