# Design-System Components and Shared Patterns

**EPIC ID:** CAP-003-E1
**Capability:** CAP-003
**Summary:** Build the owner interface's building-block layer once, so that every surface this capability delivers or takes over, and every later capability's screen, is assembled from the same components and the same rules. It vendors the design-system components as shadcn/ui ships them into `web/src/components/ui/` and builds the blueprint's shared patterns in `web/src/components/patterns/`: the one status-to-tier function with its label and shape, `worstDataTier` behind both the Data health verdict and Home's data tile badge, the *Needs you* derivation and sort behind Home's list and the rail count, the presence renderings that keep present, absent and not determinable apart, the America/Chicago formatters, and the eight-state region. It consumes only `theme.css` tokens, so a token change restyles every surface and no surface carries a literal of its own. This EPIC is an EPIC of its own rather than a slice of each screen because the functions it holds are the design's one-definition correctness argument (DEC-0222).
**Actors:** Owner-operator (indirectly, through every screen); `ui-components`; `design-system/theme.css`; the consuming components `owner-shell`, `command-palette`, `setup-ui`, `home-ui`, `data-health-ui`, `owner-web-app`.
**Estimate:** L
**Out of Scope:** Any screen or route (E3 to E7); the layout-constants module `web/src/app/layout.ts`, which `owner-shell` owns (E3); the delivered `outcome-badge.tsx` and `result-outcome-badge.tsx`, replaced and deleted by E7 once every caller uses `StatusBadge`; any new theme token or design-system variant, which enter only through `design-system/intake.md`; the `chart`, `tabs` and `toggle-group` components and the variants UX design §3 lists as deliberately unused; a dark theme (STD-UI OQ-UI-2) or a density choice (STD-UI OQ-UI-4).
**Dependencies:** None inside CAP-003: this EPIC starts first, because E3 to E7 import from it. Cross-capability: tech stack v7 (`conforms-to`) already confirms `shadcn/ui` on Radix (OQ-TS-6) and all ten non-Radix packages (OQ-TS-10; capability OQ-4), so the packages are added as the first story needing each lands, each with its licence recorded (SEC-DEP-003). CAP-002 (`requires-runtime`): the owner fixed the order, CAP-002 lands first (capability OQ-2), and this EPIC takes over its `web/src/components/patterns/as-of-line.tsx` and generalises it to `AsOfLine` with the Research line composing it (component design 2.1); that one story is sequenced after CAP-002's `classification-ui` has merged, and nothing else in this EPIC waits on CAP-002. STD-UI v6 and the blueprint (`conforms-to`) are designed against, not waited for.
**Links:** system-design.md §1 (one definition of a problem, nothing undetermined shown as a value), §2 edges E7 to E10, §4.1 `ui-components`, §4.3, constraints 3, 4, 5, 12, 13; component-design-ui-components.md §2.1 to §2.7, §3, §4, §7; component-design-owner-shell.md §2.1 (`layout.ts`); ux-brief.md §12.2 (status tier table); ux-design.md §0.6, §0.7, §3.

## Goals

- Vendor the fifteen design-system components the UX design uses (`badge`, `button`, `card`, `checkbox`, `command`, `data-table`, `dialog`, `form`, `input`, `progress`, `radio-group`, `select`, `stepper`, `textarea`, `toast`) as shadcn/ui ships them, with `@/` imports rewritten to relative paths and no `tsconfig` or Vite alias added, so they are first-party code from the moment they are copied.
- Map every download state, result outcome, score state, check result and credential presence to exactly one blueprint §8 tier in one function, `tierOf`, with its STD-UI-1 v6 display label from `labelOf`, and render it through `StatusBadge` as label plus `aria-hidden` tier shape, never colour alone.
- Compose the data verdict once, in `worstDataTier`, over the problem set and the latest terminal download, and Home's tile badge once, in `dataTileBadge`, so the tile never reads better than the verdict and reads worse only when the score state is.
- Derive the *Needs you* list once, in `deriveNeedsYou` and `sortAttention`, so Home's list and the rail's Home count are the same array.
- Keep present, absent and not determinable apart with `Absent` and `NotDeterminable`, and render every instant, clock, session date, count and download name through one set of America/Chicago formatters.
- Give every data-bearing region STD-UI-23's eight states through `StateRegion`, which refuses at the type level a caller that omits a state without naming why.
- Extend `tailwind.config.js` with the colour and radius keys the vendored components reference, each mapped to a token `theme.css` already defines, adding no token.

## Non-Functional Requirements

- **Tokens only** (AC-26; STD-UI-29): no spacing, size or colour literal outside `theme.css` in any vendored component or pattern. The approved-specification layout dimensions (208 px rail, 1180 px measure, 260 to 300 px side column, 28 px, 16 px, 70ch) are not held here; they live in `owner-shell`'s `web/src/app/layout.ts` (E3). The `command` dialog's 560 px is shadcn/ui's own and not a call-site literal (UX design 1.1).
- **Accessibility** (AC-25; STD-UI-24): Radix supplies the dialog, radio, select, checkbox and progress keyboard contracts; cmdk the combobox and listbox; the stepper is a native `ol` with `aria-current="step"`; `button` `blocked` stays focusable and exposes its reason through `aria-describedby`; contrast 4.5:1 for text and 3:1 for large text and boundaries, with the chip and as-of pairs checked against `design-system/theme-validation.md`. Biome has no `jsx-a11y`, so this is enforced by review and Testing Library role queries (system design constraint 13).
- **Security:** no `dangerouslySetInnerHTML` in any vendored component or pattern, with the delivered `web/src/api/render.test.tsx` widened to `web/src/components/`; provider reasons render as text (AGT-PROHIB-003); no browser storage; the credential badge receives a boolean only (AC-4). Supply chain: only the ten packages tech stack v7 confirms plus the `@radix-ui/react-*` primitives, each recorded with its licence when added (SEC-DEP-003) and scanned with `package.json` (SEC-DEP-001).
- **Performance:** patterns are pure functions over at most a few hundred items; the `virtualised` `data-table` variant reuses CAP-001's windowed rendering over keyset pages so the DOM stays bounded at the 3000-stock list (STD-UI-30; DEC-0215). No bundle-size target is asserted because no governed document states one.
- **Volume:** the one table variant that reaches 3000 rows keeps CAP-001's windowing; no virtualisation library is added (DEC-0215).

## EPIC Acceptance Criteria

### From Capability

- [AC-9] Every item on Home MUST have exactly one action, items MUST be ordered by severity tier then recency, and an item MUST leave the list only when its cause is resolved, never because it was viewed. This EPIC delivers the derivation and sort both callers use.
- [AC-11] The Data health verdict MUST name how many followed stocks need attention with its severity tier. This EPIC delivers `worstDataTier`, the one function that composes it.
- [AC-12] No screen MUST present a partial or interrupted download, or a check built on one, as complete. This EPIC fixes `partial` as warning and `abandoned` as serious in the one tier function.
- [AC-16] The Home destination MUST carry the number of *Needs you* items, absent when zero. This EPIC delivers the derivation whose length is that count.
- [AC-19] Every user-visible label MUST use the display label STD-UI-1 defines and MUST NOT show the domain term beside it. This EPIC delivers `labelOf`, the one source of status labels.
- [AC-20] Every download outcome, check result and stock state MUST render as the single severity tier the blueprint's status map assigns it, with its label and its tier shape, never colour alone.
- [AC-24] Every data-bearing region MUST render each of STD-UI-23's eight states as designed, or record why one does not apply, and MUST NOT collapse never-populated into nothing-found. This EPIC delivers `StateRegion` and the presence renderings.
- [AC-25] Every operation MUST be completable by keyboard. This EPIC delivers the component contracts every screen relies on.
- [AC-26] Every surface MUST be built from the product's design-system components and consume its theme tokens, with no spacing, size or colour literal outside the theme.
- [AC-7] Home MUST show the first download's progress until scores exist. This EPIC delivers the `first_download` item variant that exists before the score read is served (DEC-0216).

### Derived

- [DAC-E1-1] `tierOf` and `labelOf` MUST implement every row of UX brief §12.2 verbatim: download `requested` / `running` / `cancelling` as *Queued* / *Downloading* / *Stopping* (neutral / active / warning); `succeeded` / `partial` / `failed` as *Complete* / *Partial* / *Failed* (good / warning / critical); `cancelled` / `abandoned` as *Cancelled by you* / *Interrupted* (neutral / serious); result `not_found` / `failed` as *Not found* / *Failed* (warning / critical); scores `building` / `not_current` / `failed` / `never_classified` / `current` as *Updating* / *Not reflecting the latest download* / *Score update failed* / *No scores yet* / *Current* (active / warning / critical / neutral / good); check `ok` / `exceptions` (good / warning); credential present / missing as *Found* / *Missing* (good / critical). `partial` MUST never map to good and `cancelled` never to critical. (traces to: AC-20, AC-12)
- [DAC-E1-2] `StatusBadge` MUST render the `badge` `status-<tier>` variant with the label as text and the tier shape (neutral hollow circle, active ringed dot, good filled circle, warning triangle, serious diamond, critical square) as an `aria-hidden` icon, so no information is carried by colour alone and greyscale rendering keeps every tier distinguishable. (traces to: AC-20)
- [DAC-E1-3] `worstDataTier` MUST return `null` whenever `latestTerminalDownload` is null, for `affectedCount` 0 and above 0 alike, and `dataTileBadge` MUST return `null` whenever the verdict is `null`, whatever the score state, so no surface renders *Yes* or any verdict tier before a download has ended. (traces to: AC-21, AC-11)
- [DAC-E1-4] Otherwise `worstDataTier` MUST answer good *Yes* when `affectedCount` is 0, warning *Mostly yes* when it is above 0 and below `followedCount`, critical *No* when every followed stock is affected (`affectedCount` ≥ `followedCount` > 0), critical *No* with the clause *, and the last download failed.* when the latest terminal download is `failed`, and serious *Mostly yes* with *, and the last download was interrupted.* when it is `abandoned`; the worst input wins by the one order critical, serious, warning, good, neutral, with active ranked alongside good, and the download clause is returned whenever the latest terminal download failed or was interrupted, whichever input wins. (traces to: AC-11)
- [DAC-E1-5] `dataTileBadge` MUST return the worse of the verdict tier and the score-state tier by the same order with the label of whichever wins, a tie going to the verdict, and a null or neutral or active score state MUST never worsen or displace the answer. (traces to: AC-8)
- [DAC-E1-6] `deriveNeedsYou` MUST produce each of the six kinds (`data_problems`, `download_not_complete`, `credential_missing`, `first_download`, `first_scores`, `score_failed`) exactly while its cause holds in the latest attention and summary reads, with the `first_download` variant present under a `404` summary only while `latest_terminal_download` is null, and the `first_scores` and `score_failed` kinds absent under a `404`; it MUST return no user-visible string. (traces to: AC-9, AC-7)
- [DAC-E1-7] `sortAttention` MUST order by tier (critical, serious, warning, good, neutral, with active sorting with good), then by `recordedAt` newest first, and MUST be stable for equal keys; the length of `sortAttention(deriveNeedsYou(...))` is the one value both `owner-shell` and `home-ui` use. (traces to: AC-9, AC-16)
- [DAC-E1-8] `Absent` MUST render an em dash in `--value-missing` with visually hidden text naming what is absent, never `0` and never blank; `NotDeterminable` MUST render `badge` `coverage-unknown` with *Not determinable* (or a caller's label), `--pattern-indeterminate` and its reason, never a dimmed absent and never a passed check. (traces to: AC-24, AC-8)
- [DAC-E1-9] `formatInstant` MUST render `YYYY-MM-DD HH:MM zone` (or with seconds when asked) in America/Chicago with the zone abbreviation the instant falls in, *CDT* or *CST*, built from `Intl.DateTimeFormat` parts and never a locale format; `formatClock` renders `HH:MM:SS zone`; `formatSessionDate` renders a session date unconverted; `formatCount` renders thousands separators; `formatDownloadName` renders *Download {YYYY-MM-DD HH:MM zone}* from `started_at`, else `requested_at`, which the owner confirmed as the permanent naming (capability OQ-1). (traces to: AC-25)
- [DAC-E1-10] `StateRegion` MUST take the delivered `ScreenState` union unchanged and one renderer per state, MUST refuse to type-check a call that omits a state without `{ notApplicable: "reason" }`, MUST render the two empty states as distinct copy and the error with its three parts and **Try again**, and MUST leave the unreachable kind to the shell. (traces to: AC-24)
- [DAC-E1-11] `tailwind.config.js` MUST gain only the keys the vendored components reference (`primary`, `primary-foreground`, `accent`, `accent-foreground`, `popover`, `popover-foreground`, `muted`, `ring`, `destructive`, `destructive-foreground`, `status-foreground`, `seq-1`, `borderRadius.DEFAULT`, `ringWidth.DEFAULT`), each in the delivered `hsl(var(--token) / <alpha-value>)` form resolving to a token `theme.css` already defines; the delivered `web/src/app/shell.tokens.test.tsx` MUST keep passing. (traces to: AC-26)
- [DAC-E1-12] No vendored component or pattern MAY contain a spacing, size or colour literal outside the theme, and no `package.json` dependency MAY be added beyond the ten packages tech stack v7 confirms and the `@radix-ui/react-*` primitives, each with its licence recorded when added. (traces to: AC-26)
- [DAC-E1-13] `AsOfLine` MUST be the generalisation of CAP-002's `web/src/components/patterns/as-of-line.tsx`, with CAP-002's Research as-of line composing it and CAP-002's `as-of-line.test.tsx` cases for that line still passing, so the blueprint's as-of line is built once. (traces to: AC-26)
- [DAC-E1-14] `dialog` `confirm` (Radix AlertDialog) MUST put **Cancel** first and focus it; `button` `blocked` MUST remain focusable and be described by its reason; `stepper` MUST set `aria-current="step"`; `progress` MUST expose `progressbar` labelled by its visible text; `command` MUST loop and restore focus on close. (traces to: AC-25)
- [DAC-E1-15] `dialog` `destructive` MUST NOT be used for stopping following or cancelling a download, because nothing is deleted (STD-UI-2), and `button` `disabled` MUST NOT be used where a precondition gates an action. (traces to: AC-25)
