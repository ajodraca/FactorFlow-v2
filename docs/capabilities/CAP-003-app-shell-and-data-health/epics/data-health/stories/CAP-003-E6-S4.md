# **Download Now**, **Stop Following** and **Follow a Different Symbol**

## User Story

As an owner-operator, I want to retry a failure with one full download that is safe to repeat, and for a symbol the provider does not recognise, to stop following it with its history kept or follow a different one, so that every fix on Data health is the one the delivered product supports and nothing is ever deleted.

## Description

Logical component: `data-health-ui`. Creates `web/src/screens/data-health/download-now.tsx` (one component around the delivered `startAcquisitionRun()`, used by the header, *Needs fixing* and the empty state's **Start the first download**, routine with no confirmation) and `stop-following-dialog.tsx` (E1-S7's `dialog` `confirm` with blueprint §9's wording, never `destructive`), and wires **Follow a different symbol** as a link to `/data/followed` with router state `{ focusAdd: true }`, as `component-design-data-health-ui.md` §2.7 specifies. A `202` with `queued_behind` null calls `refresh("attention")` so the download heads Recent downloads; `queued_behind` set reads the queued line; each `409` names its fix. **Stop following** on `200` closes the dialog, re-reads the aggregate, calls `refresh("attention")` and announces politely with no toast; `404` or `409` keeps the dialog open with the refusal. Focus returns to the row's **Stop following** or, when the row has left, to the *Needs fixing* heading.

Breakdown and ordering: DEC-0223.

## Technical Details

### API Contract

- Endpoint: `POST /api/acquisition-runs` (delivered, unchanged); Response: `202 { run_id, queued_behind }`; Errors: `409 history_depth_not_set`, `409 no_active_instruments`.
- Endpoint: `DELETE /api/instruments/{symbol}` (delivered, unchanged); Response: `200` retired; Errors: `404`, `409`.
- Both writes pass the delivered Origin check (same origin).
