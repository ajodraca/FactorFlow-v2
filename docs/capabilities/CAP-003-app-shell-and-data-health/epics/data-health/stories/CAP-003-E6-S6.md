# Data Health Journeys End to End: Trusting the Data and the Unrecognised Symbol

## User Story
As an owner-operator, I want Data health proven against the running product, so that a partial download is named, downloaded again and refreshed, and an unrecognised symbol is stopped with its history kept.

## Description
Writes `tests/e2e/data-health-trust.spec.ts` (a partial download: verdict *Mostly yes*, rows named, **Download now** starts a full download that heads Recent downloads with its progress, and the checks refresh once at its end; capability flow 2) and `tests/e2e/data-health-not-found.spec.ts` (an unrecognised symbol's row: **Stop following** confirmed, the row leaves and *Stopped following {SYMBOL}* is announced, its history still shows on `/data/coverage?symbol=`; **Follow a different symbol** navigates to `/data/followed`). The add-field focus on arrival is E7-S3's entry hint and is asserted there, since the delivered followed-stocks screen does not yet read `focusAdd` (backlog review v2 FINDING-2); this spec asserts the navigation and the router state.

Scheduled after the E6 closing story CAP-003-E6-S7, which registers `/data` and the Data health destination (DEC-0223 answer A).

Source: component-design-data-health-ui.md 7; capability flow 2; AC-14.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-11] Data health MUST open with the verdict naming how many followed stocks need attention.
- [AC-13] Each row MUST name the stock, what was being downloaded, the reason and the fix.
- [AC-14] An unrecognised symbol MUST offer stopping following and following a different symbol, never a download.
- [AC-15] **Download now** MUST start a download over the whole followed list.
- [AC-28] The checks MUST refresh once when the download ends, not on a timer.

### Derived
- [DAC-E6-S6-1] Given the Massive stub failing three symbols, When the download ends `partial`, Then the verdict reads *Mostly yes. 3 of {m} followed stocks need attention…*, *Needs fixing · 3* lists them, and **Download now** is in the header because a row is retryable. (traces to: AC-11, AC-13)
- [DAC-E6-S6-2] Given the stub not recognising one symbol, When its row's **Stop following** is confirmed by keyboard, Then `DELETE /api/instruments/{symbol}` is sent, the row leaves, the Data health chip decrements, and Coverage still lists the symbol as stopped following with its history. (traces to: AC-14)
