# Download Now and the Stop Following Dialog: the Two Recoveries Behind the Delivered Endpoints

## User Story
As an owner-operator, I want one routine action that downloads everything again and one confirmed action that stops following a symbol with its history kept, so that every fix Data health offers is one the product already knows how to do.

## Description
Creates `web/src/screens/data-health/download-now.tsx` (one component around the delivered `startAcquisitionRun()`, routine with no confirmation, used by the header, *Needs fixing* and the empty state's **Start the first download**: `202` with `queued_behind` null calls `refresh("attention")`; with it set the helper line reads *A download is running. This starts when it finishes.*; `409 history_depth_not_set` reads *Couldn't start the download: history depth isn't set.* with **Set history depth** to `/settings`; `409 no_active_instruments` reads *Couldn't start the download: no stocks are followed.* with **Follow stocks** to `/data/followed`; it always downloads the whole followed list, D-9) and `stop-following-dialog.tsx` (`dialog` `confirm` titled *Stop following {SYMBOL}* with the blueprint §9 wording verbatim, **Cancel** first and focused, then **Stop following**; `retireInstrument(symbol)`; `200` closes, calls the caller's aggregate re-read and `refresh("attention")` and announces *Stopped following {SYMBOL}* politely with no toast; `404` or `409` keeps the dialog open with *Couldn't stop following {SYMBOL}: {reason}.*; focus returns to the row's **Stop following** or, when the row has left, to the *Needs fixing* heading). Writes `download-now.test.tsx` and `stop-following-dialog.test.tsx`.

Source: component-design-data-health-ui.md 2.1, 2.7, 3, 4, 7; epic CAP-003-E6 NFR *Action tiers*, DAC-E6-11, DAC-E6-12.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-15] **Download now** MUST start a download over the whole followed list; when a download is already under way the product MUST accept the request and say it starts when the current one finishes.
- [AC-14] Stopping following MUST be offered as a fix, confirmed, with history kept.
- [AC-17] Starting a download and stopping following MUST go through the delivered endpoints with CAP-001's confirmations and refusals unchanged.
- [AC-25] The dialog MUST trap focus, put **Cancel** first and return focus on close.
- [DAC-E6-11] **Download now** outcomes MUST be as stated, with no confirmation and no per-stock retry. (traces to: AC-15)
- [DAC-E6-12] The stop-following dialog MUST be as stated, with `confirm` never `destructive`. (traces to: AC-14, AC-17)

### Derived
- [DAC-E6-S2-1] Given each `409` code, When rendered, Then the two reasons are never interchanged and each link targets its path; given a transport failure, Then *Couldn't start the download: {reason}.* with **Try again** (CAP-001 AC-23, AC-24). (traces to: DAC-E6-11)
- [DAC-E6-S2-2] Given a `409` on stop following, When rendered, Then the dialog stays open with the reason, `Esc` closes it, and the row is refreshed on close. (traces to: DAC-E6-12)
- [DAC-E6-S2-3] Given the Download now control, its helper lines and refusals, and the stop-following dialog rendered in every state this story defines, When its visible text and accessible names are scanned for *instrument*, *acquisition*, *acquire*, *run*, *runs*, *Retire*, *Retired*, *Provider credential* as whole words in any case (the DAC-E7-3 term list), Then none appears, and every label is the STD-UI-1 v6 display label from `labelOf` or this component's `copy.ts`, never the domain term beside it. (traces to: AC-19)
- [DAC-E6-S2-4] Given no status badge renders in these controls, so the one-tier rule is recorded as not applicable here, When rendered, Then each goes through `StatusBadge` with its label as text and its tier shape `aria-hidden`, a value no artifact can determine goes through `NotDeterminable`, and no state is conveyed by colour alone. - Consumes `POST /api/acquisition-runs` (`202` with `queued_behind`, `409 history_depth_not_set`, `409 no_active_instruments`) and `DELETE /api/instruments/{symbol}` (`200`, `404`, `409`) through the delivered `startAcquisitionRun` and `retireInstrument`, behind the delivered Origin check.
