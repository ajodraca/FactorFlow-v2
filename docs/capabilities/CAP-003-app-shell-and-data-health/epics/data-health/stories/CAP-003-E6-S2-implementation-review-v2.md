### IR-001 — The opener capture's reset of a leftover row-exit watch is unpinned

- **Severity**: MEDIUM
- **Scope**: late
- **Status**: OPEN
- **Acceptance criteria**: AC-25; data-health-ui §10 ("Polling and a row leaving announce politely and never move focus")
- **Tasks**: T005, T011, T013
- **Files**:
  - `web/src/screens/data-health/stop-following-dialog.tsx` l.72–79, specifically l.76 `watchRowExit.current = false;` in the opener `useLayoutEffect`
  - `web/src/screens/data-health/stop-following-dialog.test.tsx` T005 (l), (g2), (j)
- **Claim challenged**:
  - T011, Opener capture: "when it turns non-null, record `document.activeElement` as `opener` and set `watchRowExit` false."
  - T013: no non-equivalent mutant survives.
- **Observed evidence**:
  - The reviewer's mutant `rv2:open-watch-not-reset` (l.76 deleted) survives all 151 focused tests. The generated `:76:negate-boolean:1`, which sets the flag *true*, is killed by (l). The deletion differs: it matters only when a watch is still set at the next open.
  - (g2) shows when a watch is still set at the next open: after a successful stop whose row has not left yet, with focus back on that row's button.
  - Probe P3 drives this case:
    1. Stop FBXX with a `200`. The row stays, and focus returns to **Stop following FBXX**.
    2. Open GOOD's dialog and press **Cancel**. Focus returns to **Stop following GOOD**.
    3. Remove GOOD's row.
  - P3 expects the heading not to be focused. It passes on HEAD. With the mutant it fails, because focus moves to *Needs fixing*.
- **Expected evidence/behavior**:
  - Per T011, every open starts with no watch. Per T005 (l), after **Cancel** a row that leaves later does not move focus, and data-health-ui §10 says a row leaving never moves focus.
  - Step E.9 counts a mutant that changes plan-specified behaviour as not equivalent.
- **Impact**:
  - A regression that drops this one line would pass the suite. After a stop whose aggregate re-read is slow, an owner who opens another row's dialog and cancels could later have focus pulled to the heading when that row leaves. That is the unprompted focus move STD-UI-24 forbids.
  - The production code is correct today.
  - Line 76 is unchanged since the baseline's `reviewed_head` `c3f99962`, so v1 could have run this mutant. That makes it `late`: MEDIUM at most, and it does not make TC-COMP-162 `WEAK`.
- **Required remediation**: Add a test to `stop-following-dialog.test.tsx` that does the following, so that deleting l.76 is killed:
  1. Leave a watch set, with a successful stop whose row stays and focus back on that row.
  2. Open another row's dialog and cancel it.
  3. Remove that row, and assert that the heading does not take focus.

  This does not block the gate.
