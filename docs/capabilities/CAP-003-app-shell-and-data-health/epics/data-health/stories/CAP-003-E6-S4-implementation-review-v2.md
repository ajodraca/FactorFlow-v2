### IR-001 — Try again unmounts while focused, so keyboard focus falls to `<body>`

- **Severity**: LOW
- **Scope**: delta
- **Status**: OPEN
- **Acceptance criteria**: N/A (DAC-E6-17 is satisfied); constitution STD-UI-24
- **Tasks**: T014 (*Reads*), T013
- **Files**:
  - `web/src/screens/data-health/what-you-follow.tsx:59`: the rework's `setState({ kind: "loading" })`, which replaces `ReadFailure` with the skeleton body as soon as **Try again** is pressed.
  - `web/src/screens/data-health/recent-downloads.tsx:225–237`: the table replaces `ReadFailure` when a retry succeeds.
- **Claim challenged**: That the rework of v1 IR-002 leaves the card meeting the shared accessibility rules.
- **Observed evidence**:
  - A reviewer probe in a scratch clone of HEAD focuses **Try again** after a failed read and presses Enter. `document.activeElement` is `BODY` at once, and it is still `BODY` after the reads settle.
  - At the baseline, What you follow's button stayed mounted until the reads settled, so a retry that failed again kept focus. Now focus is lost on every activation. In Recent downloads, and at the baseline in both cards, focus was already lost when a retry succeeded.
  - No test checks focus after **Try again**.
- **Expected evidence/behavior**: STD-UI-24: "focus MUST be managed on dialogs and on content inserted into the page". The same epic's sibling has the same convention gap, graded LOW: CAP-003-E6-S2 v2 IR-003, "**Try again** unmounts while focused, so keyboard focus falls to `body`". DEC-0256 settled the same question for CAP-002-E1-S7 by moving focus to a control that every state keeps.
- **Impact**: A keyboard or screen-reader user who retries a failed card loses their place and starts again from the top of the document. The retry itself works, so AC-25's "completable by keyboard" holds.
- **Required remediation**: After **Try again**, move focus to a stable element that every state keeps, such as the card's `h2` made focusable with `tabIndex={-1}`, and pin it with a test. Alternatively, record at the design level (data-health-ui 10 or DEC-0314) that the `ReadFailure` convention accepts the loss. This does not block the gate and may follow it.
