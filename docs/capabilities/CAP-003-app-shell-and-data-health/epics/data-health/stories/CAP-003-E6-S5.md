# Recent Downloads and What You Follow

## User Story

As an owner-operator, I want the five most recent downloads with a running one's progress at the top, and a summary of what I follow with whether the market data key was found, so that I can see what the product has done and what it is working with.

## Description

Logical component: `data-health-ui`. Creates `web/src/screens/data-health/recent-downloads.tsx` (E1-S9's `data-table` `compact` with `history` semantics over the delivered `listAcquisitionRuns({ limit: 5 })`, columns *Started* as row header and link to `/data/downloads/{id}`, *Outcome* through `StatusBadge`, *Ended* or an em dash while running, *Result*; a running download heads the list with E1-S8's `progress` `determinate` from attention's `latest_download.progress`; re-read on each attention answer while `latest_download` is non-terminal and otherwise only on load; *checked {time}* in the card header) and `what-you-follow.tsx` (`card` `summary` over the delivered `listInstruments({ limit: 1 })` and `getHistoryDepth()` and `health.credential_present`), as `component-design-data-health-ui.md` §2.6 specifies. Each card's failed read keeps its header and renders the three-part error with **Try again**.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-4] *What you follow* MUST state whether the market data key was found and MUST NOT display its value.
- [AC-12] No region MUST present a partial or interrupted download as complete.
- [AC-17] The run list, instrument counts and depth MUST come from the delivered endpoints unchanged.
- [AC-25] Every polled region MUST show its last-updated time.
- [AC-20] Every download outcome MUST render through `StatusBadge` with label and shape.
- [DAC-E6-14] Recent downloads MUST be a `data-table` `compact` with `history` semantics over `listAcquisitionRuns({ limit: 5 })` with columns *Started* (the start time as row header, a link to the detail), *Outcome* (`StatusBadge`), *Ended* (or an em dash while running) and *Result* (*{written} of {named} stocks*; *Partial* as *{written} of {named} stocks, {failed} failed*; *Interrupted* as *FactorFlow restarted mid-download; {written} kept, the rest picked up next time*); a running download MUST head the list with its progress; the list MUST be re-read on each attention answer while `latest_download` is non-terminal and otherwise only on load. (traces to: AC-12, AC-25)
- [DAC-E6-16] *What you follow* MUST render *Followed stocks {active_count}*, *Stopped following {retired_count} (history kept)*, *History depth {y} years* or *not set* as a link to `/settings`, *Market data key* as `badge` *Found* / *Missing* / `coverage-unknown` *Not determinable* from `health.credential_present`, and **Manage followed stocks** (link to `/data/followed`). (traces to: AC-4, AC-17)
- [DAC-E6-17] A failed read MUST keep each card's header and replace its body with *Couldn't read {recent downloads / what you follow}: {reason}.* and **Try again**; no `request_id` MUST be shown. (traces to: AC-24)

### Derived

(traces to: DAC-E6-14)
- [DAC-E6-S5-2] Given a `partial` run with 1230 written of 1236 named and 6 failed, When rendered, Then the outcome badge is `status-warning` *Partial* and the result reads *1,230 of 1,236 stocks, 6 failed*; given `abandoned`, Then `status-serious` *Interrupted* with *FactorFlow restarted mid-download; {written} kept, the rest picked up next time*. (traces to: DAC-E6-14)
- [DAC-E6-S5-4] Given `active_count` 1236, `retired_count` 4, depth 7 and `credential_present` true, When rendered, Then the card reads *Followed stocks 1,236*, *Stopped following 4 (history kept)*, *History depth 7 years* linking to `/settings`, *Market data key* *Found* (good), and **Manage followed stocks** linking to `/data/followed`; given depth null, Then *not set*; given health unreachable, Then `NotDeterminable` and never *Missing*. (traces to: DAC-E6-16)
