# The Data Health Screen: Composition, the Honest Empty States and the On-Demand Refresh Rule

## User Story
As an owner-operator, I want Data health composed from its regions with the aggregate read only when it matters, so that the expensive read never runs on a timer and the screen never presents empty checks as passed.

## Description
Creates `web/src/screens/data-health/index.tsx` (`DataHealthScreen`): `useDataHealth()` for the aggregate (read on load, on **Try again**, once when attention's latest download turns terminal, after a successful **Stop following**, never on a timer; DAC-E6-15), the header with the verdict and its two actions, the four-column check-card grid with the fourth column empty, *Needs fixing*, Recent downloads and What you follow in the lower columns, capped at `LAYOUT.contentMaxWidth`. While attention's `latest_terminal_download` is null it renders, in place of the verdict, the cards and What you follow, one card with `h2` *No data has been downloaded yet.* and either *Download data for your {n} followed stocks to see whether it can be trusted.* with **Start the first download** (E6-S2's component) or *Follow some stocks first.* with **Open setup**, with *Needs fixing* still rendered when `affected_count` is above 0 and Recent downloads when any download exists (DAC-E6-6). When `never_acquired` is true but a download has ended, the two check cards render their null state, an `Absent` em dash with hidden *no data stored yet* (DAC-E6-7). Writes `data-health.test.tsx` (empty states, refresh rule).

Source: component-design-data-health-ui.md 2.1, 2.2, 3, 5, 7, 8, 10; epic CAP-003-E6 NFR *Latency and load*, *Layout*, DAC-E6-6, DAC-E6-7, DAC-E6-15.
