### IR-001 — *and {k} more* renders *k* without a thousands separator

- **Severity**: MEDIUM
- **Scope**: late
- **Status**: OPEN
- **Acceptance criteria**: DAC-E6-3, DAC-E6-4 (display convention only; AC-11)
- **Tasks**: T012, T014, T015
- **Files**: `web/src/screens/data-health/copy.ts:93-95` (`andMore(k: number)` interpolates `k` raw); `web/src/screens/data-health/daily-prices-card.tsx:101-105`; `web/src/screens/data-health/financials-card.tsx:52-56`
- **Claim challenged**: Each check card's as-of line renders its count as UX design 0.7 requires, like every other count on the card.
- **Observed evidence**: `andMore(more)` receives the raw number, and nothing on that path calls `formatCount`. A scratch probe on HEAD with `exception_count` 1,200 and five symbols renders *Prices to 2026-10-29 · AAA, BBB, CCC, DDD, EEE and 1195 more*. The same card's result line reads *1,200 without prices*. The financials card renders *… and 1095 more*. `exception_count` is the size of the distinct-stock exception union (data-health-reader l.416, l.425; DEC-0220), so it ranges up to the followed count, about 1,236 today and up to 3,000 per STD-UI-30. The delivered Home copy formats the same clause: `web/src/screens/home/copy.ts:126` and `:143` use `and ${formatCount(more)} more`.
- **Expected evidence/behavior**: UX design 0.7 says "Counts are whole numbers with thousands separators … (*1,236*)". *k* is a count of stocks. Plan T012 and T014 give `andMore(k)` without saying how *k* is formatted. The plan is silent, so the approved UX convention governs.
- **Impact**: After a partial first download, the trust screen shows two formats for counts on one line pair. No test fails, because no fixture has *k* ≥ 1,000. There is no data-integrity, security or behaviour effect: the value of *k* and its omission at 0 are correct.
- **Scope and severity rationale**: No line this finding concerns changed since the baseline's `reviewed_head` `436187a3`, so v1 could have raised it just as well. That makes it `late`. Step H allows a late finding to block only as CRITICAL, when it shows code that violates an acceptance criterion or core contract, or a security, privacy or data-integrity risk. DAC-E6-3 and DAC-E6-4 state what *k* is and when it is omitted, and both hold. The gap is the UX 0.7 display convention. That is a real production deviation, but not a CRITICAL one, so it is graded MEDIUM, the late maximum.
- **Required remediation**: Route *k* through `formatCount` in both cards, as Home does. For example, `andMore` could take the formatted string, as the other copy helpers do. Add one row per card with *k* ≥ 1,000 that asserts the separated form. This can be done in a later story or a follow-up rework. It does not hold this gate.
