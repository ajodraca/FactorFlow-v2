# Data Health Reads

**EPIC ID:** CAP-003-E2
**Capability:** CAP-003
**Summary:** Give the shell, Home and Data health the three server-side reads they need, computed from what CAP-001 already recorded and nothing else: `GET /api/attention`, the cheap aggregate the shell polls for the rail counts, Home's data tile and items and setup's progress; `GET /api/data-health`, the on-demand aggregate behind Data health's verdict, check cards and first *Needs fixing* page; and `GET /api/data-health/problems`, the keyset-paged rest of that list. A read-only Python module, `data-health-reader`, derives the one problem set (a followed stock whose latest recorded outcome for any data type is failed or not found), the latest and latest-terminal downloads with progress, the Daily prices and Company financials checks and the server-derived attention items; a FastAPI router, `data-health-api`, serves them in the domain vocabulary behind the delivered middleware and error envelope; and `ingestion-api` gains the one `include_router` line and the no-secrets test for the new routes. Nothing is written, no table is added and no provider is read. This is the only Python work in the capability and it is an EPIC of its own so that every story in it is single-component (DEC-0222).
**Actors:** `data-health-reader`; `data-health-api`; `ingestion-api` (application factory, middleware, envelope, pool); `coverage-service` (`read_coverage`, in process, unchanged); `market-data-store` (read only); `config.settings.credential_present`; consumers `owner-shell`, `data-health-ui`.
**Estimate:** M
**Out of Scope:** Any sentence, label or tier (composed in the interface, E1, E5, E6); the Factor scores check, which the interface reads from `classification-api`'s summary; any change to a delivered request or response model, route, refusal or middleware rule (system design constraint 2); any schema change, migration or index; any provider request; polling the aggregate or reading it from Home (DEC-0219 withdrawn).
**Dependencies:** None inside CAP-003: this EPIC is independent of E1 and can run in parallel with it; E3, E5 and E6 consume its routes. Cross-capability: CAP-001 (`requires-runtime`) supplies the tables read (`instrument`, `acquisition_state`, `run_instrument_result`, `acquisition_run`, `coverage_segment`, migrations 0001, 0003, 0004), `coverage-service`'s `read_coverage` and the application factory; all are delivered and this EPIC designs against them as documented, verified against a real store in the integration tests. CAP-002 (`requires-runtime`): the `include_router` line goes after `classification-api`'s two calls if they have landed, which the owner fixed (capability OQ-2); order among `/api` routers does not matter. The `SEC-ENC-001 host-local loopback exception` reliance is DEC-0050 as extended by DEC-0208.
**Links:** system-design.md §1, §2 blocks B9 to B12, B15, §3.3 box 1, §3.4 steps 2 to 8, §4.1, §4.2 (`GET /api/attention`, `GET /api/data-health`, `GET /api/data-health/problems`, `Data health queries`, `Problem and download read`, `Coverage page read`, `Router registration`), §4.4, constraints 1, 2, 3, 5, 7, 9, 10, assumptions 2, 3, 4; component-design-data-health-reader.md §2.1 to §2.8, §3, §4, §5, §7; component-design-data-health-api.md §2.1 to §2.4, §3, §4, §7; component-design-ingestion-api.md §2.1 to §2.3, §7.

## Goals

- Compute one problem set, `affected_count` = `problems.stock_count` = the distinct symbols of the *Needs fixing* rows, so every counted stock has a row and a fix.
- Serve `GET /api/attention` as a handful of indexed aggregates over at most 3000 active instruments, safe to poll every 10 seconds.
- Serve `GET /api/data-health` on demand by folding `read_coverage` pages into the Daily prices and Company financials checks, within 2 seconds at the 95th percentile with 3,000 followed stocks (AC-28).
- Page *Needs fixing* by keyset under the canonical bounds, refusing a bad bound or cursor rather than clamping it.
- Keep the module read-only by construction and the responses in the domain vocabulary, with no tier, no sentence and no secret.
- Register the router on the delivered application so the three routes inherit the request-id, Host and Origin middleware and the error envelope.

## Non-Functional Requirements

- **Latency** (AC-28; system design constraint 7): with 3,000 followed stocks, `GET /api/data-health` answers within 2 seconds at the 95th percentile, measured by `tests/integration/test_data_health_volume.py` over 20 timed requests after one warm-up through the in-process application. `GET /api/attention` is five aggregate statements plus one progress aggregate and is safe at the 10 second cadence (data-health-reader §5).
- **Volume** (STD-UI-30; CAP-001 AC-4): at most 3000 active instruments times four data types for the attention read; six `read_coverage` pages of 500 for the aggregate; `read_data_health` folds each page into running counts and keeps at most five exception symbols per check, so memory does not grow with the roster.
- **Security** (system design constraints 9, 10; SEC-INP-001, SEC-INP-002, SEC-ERR-001): loopback bind, Host and Origin checks and the delivered envelope inherited; `limit` bounded and `cursor` normalised and validated as a symbol before it reaches SQL as a bound parameter; `credential_present` a boolean and the key's value in no response; failures reach the delivered `internal_error` envelope with a fixed message and a `request_id`; no new dependency. Data classification: every new response element is Internal under SEC-DAT-001, no PII.
- **Read-only** (system design constraint 1): every statement is a `SELECT`; a unit test asserts `queries.py` and `reader.py` contain no `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `ALTER` or `DROP` token; no transaction is left open.
- **Operations:** no migration and no data step; rollback is redeploying the previous image (OPS-MIG-003); handlers log nothing beyond the delivered request-id stamping.

## EPIC Acceptance Criteria

### From Capability

- [AC-4] No new response MUST carry the market data credential's value; `credential_present` is a boolean only, and the delivered no-secrets test is extended to the three new routes.
- [AC-7] The attention read MUST carry the latest download's progress so setup and Home can show it.
- [AC-8] The attention read MUST carry `followed_count` and `prices_as_of` for Home's data tile.
- [AC-9] The server-derived attention items MUST exist exactly while their cause holds in the store, so an item leaves only when its cause is resolved.
- [AC-11] `GET /api/data-health` MUST carry the verdict counts (`affected_count`, `followed_count`) and the Daily prices and Company financials checks with the time each is current to.
- [AC-12] Run states and outcomes MUST be returned as recorded; a check built on a partial or interrupted download MUST carry its exceptions rather than read as clean.
- [AC-13] Every problem row MUST carry, per failure, the data type, the outcome, the reason reported, the attempts and the completion time, so the interface can name the stock, what was being downloaded, why it failed and its fix.
- [AC-14] A row whose failures are all `not_found` MUST be `retryable: false`, so the interface never offers a download for it.
- [AC-16] `problems.stock_count` on the attention read MUST be the same set as the *Needs fixing* rows, so the rail count and the rows never disagree.
- [AC-17] No delivered request or response model, route, status code or refusal MUST change; the new routes are additive.
- [AC-21] Before anything was acquired, both checks MUST be null rather than zero counts that could read as passed; `latest_terminal_download` MUST be null until a download has ended, which is the interface's empty-state trigger.
- [AC-28] With 3,000 followed stocks, `GET /api/data-health` MUST answer within 2 seconds at the 95th percentile, measured by the volume test.

### Derived

- [DAC-E2-1] A followed stock has a problem exactly when its `instrument.lifecycle` is `active` and any of its `acquisition_state` rows has `last_outcome` `failed` or `not_found`; each failure's `reason`, `attempts` and `completed_at` come from the `run_instrument_result` row matched on `(last_run_id, instrument_id, data_type)`; a retired stock with a failure is in no count and no row. (traces to: AC-13, AC-16)
- [DAC-E2-2] A problem MUST leave every read only when a later download records `written` for that data type or the stock is retired; nothing records that a row was viewed. (traces to: AC-9)
- [DAC-E2-3] `read_problems` MUST page by symbol with the `limit + 1` lookahead, returning `next_cursor` as the last kept symbol only when a further stock exists, so a full final page carries no cursor; `GET /api/data-health/problems` MUST take `limit` (default 50, maximum 500, from `api/bounds.py`) and `cursor`, MUST answer `422 validation_error` for a `limit` outside 1 to 500 or a cursor that is not a symbol, never clamping or ignoring either, and MUST NOT echo the submitted value. (traces to: AC-13)
- [DAC-E2-4] The Daily prices check MUST be `exceptions` when `absent_count`, `behind_count` or a known `gap_stock_count` is above zero, `not_determinable` when gap detection is unavailable and nothing else is wrong, and `ok` only when every part ran and found nothing; `gap_stock_count` MUST be `null`, never 0, when gap detection is unavailable, with `gap_detection.reason` carried. (traces to: AC-11, AC-24)
- [DAC-E2-5] `absent_count` MUST count active stocks whose prices (or fundamentals) presence is `absent` or `unknown` alike; `behind_count` MUST count stocks whose prices `covered_to` is earlier than `latest_session`, the latest prices `covered_to` over active stocks; the financials `problem_count` MUST count active stocks whose fundamentals `last_outcome` is `failed` or `not_found`; `exception_symbols` MUST be the first five symbols of each check's union and `exception_count` the number of distinct stocks in that union, because the groups overlap (DEC-0213, DEC-0220). (traces to: AC-11)
- [DAC-E2-6] `latest_download.progress.done` MUST count instruments with a `run_instrument_result` row for all four data types in that run and `total` MUST be `instruments_named`, returned as `null` while it is 0 (before a runner claims the download); `done` MUST never exceed `total`. (traces to: AC-7)
- [DAC-E2-7] `latest_download` MUST be the `acquisition_run` with the greatest `requested_at` and `latest_terminal_download` the run with the greatest `ended_at` among the five terminal states, with its recorded `state` and `failure_reason`; a running download MUST NOT displace the latest terminal one. (traces to: AC-12, AC-21)
- [DAC-E2-8] The attention `items` MUST be `data_problems` when `problems.stock_count` is above 0 (recency `newest_completed_at`), `download_not_complete` when `latest_terminal_download.state` is `failed` or `abandoned` (recency its `ended_at`, carrying its `run_id`), never for `partial` or `cancelled`, and `credential_missing` when `credential_present()` is false; items carry no tier and no copy. (traces to: AC-9)
- [DAC-E2-9] The three routes MUST answer `200` with the §4.2 shapes whenever the database answers, including on an empty store (`never_acquired` true, both checks `null`, zero counts on attention); a `psycopg.Error` MUST propagate to the delivered `500` `internal_error` envelope with `X-Request-Id`, and no partial aggregate MUST be returned as complete. (traces to: AC-21, AC-11)
- [DAC-E2-10] The router MUST be included by `create_app` with the delivered routers and before `_add_static_mount`, so a foreign `Host` gets `400 host_not_allowed` on all three routes, a foreign `Origin` on a `GET` is not refused, an unknown `/api` path still answers the `not_found` envelope, and every refusal carries a request id. (traces to: AC-17, AC-16)
- [DAC-E2-11] Nullable counts and dates (`gap_stock_count`, `prices_as_of`, `latest_session`, `as_of`, `total`) MUST serialise as `null`, never omitted and never `0`, so the interface can render not determinable and absent apart from zero. (traces to: AC-24)
- [DAC-E2-12] Field names MUST stay in the domain vocabulary (`instrument`, `acquisition_run`, outcome); no response field MUST be named *stock* or *download* and no response MUST carry a sentence or a tier. (traces to: AC-19)
- [DAC-E2-13] The delivered `tests/unit/test_api_no_secrets.py` MUST gain one parametrised test proving a populated `200` body of each of the three routes never contains the value of `FACTORFLOW_MASSIVE_API_KEY`. (traces to: AC-4)
- [DAC-E2-14] The volume test MUST seed 3000 active instruments with failures on 300, assert the counts, the keyset pages and bounded memory, and time `GET /api/data-health` through the in-process application to a 95th percentile of at most 2 seconds after one warm-up request. (traces to: AC-28)
- [DAC-E2-15] `read_data_health` MUST call `coverage-service`'s public `read_coverage(conn, lifecycle="active", cursor, limit=500)` unchanged, page by page to a null cursor, and MUST NOT catch a `ValueError` from it, which would be a programming error. (traces to: AC-11)
