# Data Health Reader Package: Models, Read-Only Queries and the Problem Set

## User Story

As an owner-operator, I want one read-only module that derives the set of followed stocks with problems from what CAP-001 recorded, so that the rail count, the verdict and every *Needs fixing* row come from the same set and a problem leaves only when its cause is resolved.

## Description

Logical component: `data-health-reader`. Creates the package `src/factorflow/data_health/` as `component-design-data-health-reader.md` §2.1 and §2.2 specify: `models.py` with every frozen dataclass of §2.2 (`Progress`, `LatestDownload`, `LatestTerminalDownload`, `Problems`, `AttentionItem`, `Attention`, `Failure`, `ProblemRow`, `ProblemPage`, `GapDetectionState`, `DailyPricesCheck`, `CompanyFinancialsCheck`, `DataHealth`), `queries.py` with `PROBLEM_ROWS_SQL` (§2.4, verbatim) and `PROBLEM_COUNT_SQL` as parameterised `SELECT` constants, and `reader.py` with `read_problems(conn, *, cursor, limit)` and the shared problem-set helper the later reads call; `__init__.py` exports `read_problems` now and gains `read_attention` and `read_data_health` in E2-S2 and E2-S3. The problem set is DEC-0201 (PROVISIONAL): an active instrument with any `acquisition_state.last_outcome` of `failed` or `not_found`, each failure's `reason`, `attempts` and `completed_at` joined from `run_instrument_result` on `(last_run_id, instrument_id, data_type)`. Every statement is a `SELECT`; the module leaves commit and rollback to the caller's `with pool.connection()` block (§3).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-13] Every problem row MUST carry, per failure, the data type, the outcome, the reason reported, the attempts and the completion time.
- [AC-14] A row whose failures are all `not_found` MUST be `retryable: false`.
- [AC-16] The problem set behind the count MUST be the same set as the *Needs fixing* rows.
- [AC-9] A problem MUST exist exactly while its cause holds in the store.
- [DAC-E2-1] A followed stock has a problem exactly when its `instrument.lifecycle` is `active` and any of its `acquisition_state` rows has `last_outcome` `failed` or `not_found`; each failure's `reason`, `attempts` and `completed_at` come from the `run_instrument_result` row matched on `(last_run_id, instrument_id, data_type)`; a retired stock with a failure is in no count and no row. (traces to: AC-13, AC-16)
- [DAC-E2-2] A problem MUST leave every read only when a later download records `written` for that data type or the stock is retired; nothing records that a row was viewed. (traces to: AC-9)
- [DAC-E2-3] `read_problems` MUST page by symbol with the `limit + 1` lookahead, returning `next_cursor` as the last kept symbol only when a further stock exists, so a full final page carries no cursor. (traces to: AC-13)

### Derived

- [DAC-E2-S1-1] Given `queries.py` and `reader.py`, When `tests/unit/test_data_health_sql_is_read_only.py` scans their source, Then no `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `ALTER` or `DROP` token is found, on the pattern `tests/unit/test_sql_is_append_only.py` established. (traces to: AC-17)
- [DAC-E2-S1-2] Given a seeded store with five problem stocks, When `read_problems` is called with `limit=2` three times following `next_cursor`, Then the pages hold 2, 2 and 1 rows, the third carries no cursor, and the rows are ordered by symbol with failures ordered by data type. (traces to: DAC-E2-3)
- [DAC-E2-S1-3] Given a stock with one `failed` and one `not_found` failure, When read, Then `retryable` is true; given a stock whose only failures are `not_found`, Then `retryable` is false. (traces to: AC-14)
- [DAC-E2-S1-4] Given a problem stock, When a later run records `written` for the failed data type, Then the row and the count no longer include it; When the stock is retired instead, Then likewise; When nothing else changes, Then it stays. (traces to: DAC-E2-2)
- [DAC-E2-S1-5] Given `PROBLEM_COUNT_SQL` and `PROBLEM_ROWS_SQL` over the same store, When both run, Then the count, the number of distinct row symbols, the first three symbols and `max(completed_at)` agree. (traces to: DAC-E2-1)
- [DAC-E2-S1-6] Given `read_problems` on a connection, When it returns, Then no transaction is left open by the module (the caller's block ends it) and `mypy src` passes with every dataclass frozen. (traces to: AC-17)
