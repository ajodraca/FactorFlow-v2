# data-health-reader Models, Queries and read_problems: the One Problem Set, Keyset-Paged

## User Story
As an owner-operator, I want one definition of a followed stock with a problem, paged by keyset, so that every counted stock has a row and a fix and nothing ever records that a row was viewed.

## Description
Creates the `data-health-reader` module: `src/factorflow/data_health/__init__.py`, `models.py` (the frozen dataclasses of data-health-reader 2.2 mirroring system design §4.2), `queries.py` (parameterised `SELECT` constants, one each, including `PROBLEM_ROWS_SQL` and `PROBLEM_COUNT_SQL`) and the `read_problems(conn, *, cursor, limit)` function in `reader.py` (data-health-reader 2.1, 2.4). A followed stock has a problem when its `instrument.lifecycle` is `active` and any `acquisition_state` row has `last_outcome` `failed` or `not_found`; each failure's `reason`, `attempts` and `completed_at` come from the `run_instrument_result` row matched on `(last_run_id, instrument_id, data_type)` (DEC-0201). Paging is by symbol with the `limit + 1` lookahead, `next_cursor` set only when a further stock exists; `retryable` is true when any failure is `failed`. Writes `tests/unit/test_data_health_sql_is_read_only.py` and `tests/integration/test_data_health_problems.py`. `read_attention` and `read_data_health` follow in E2-S2 and E2-S3 on these models and queries.

Source: component-design-data-health-reader.md 2.1, 2.2, 2.4, 2.8, 3, 4, 7; epic CAP-003-E2 DAC-E2-1, DAC-E2-2, DAC-E2-3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-13] Every problem row MUST carry, per failure, the data type, the outcome, the reason reported, the attempts and the completion time.
- [AC-14] A row whose failures are all `not_found` MUST be `retryable: false`.
- [AC-9] The problem set MUST exist exactly while its cause holds in the store.
- [AC-16] The set behind the rail count and the *Needs fixing* rows MUST be one set.
- [DAC-E2-1] A followed stock has a problem exactly when it is `active` and any `acquisition_state` row has `last_outcome` `failed` or `not_found`, with each failure's facts from the matched `run_instrument_result` row; a retired stock with a failure is in no count and no row. (traces to: AC-13, AC-16)
- [DAC-E2-2] A problem MUST leave every read only when a later download records `written` for that data type or the stock is retired. (traces to: AC-9)
- [DAC-E2-3] `read_problems` MUST page by symbol with the `limit + 1` lookahead, returning `next_cursor` as the last kept symbol only when a further stock exists. (traces to: AC-13)

### Derived
- [DAC-E2-S1-1] Given `queries.py` and `reader.py`, When `test_data_health_sql_is_read_only.py` runs, Then neither source contains an `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `ALTER` or `DROP` token, following `tests/unit/test_sql_is_append_only.py`'s pattern. (traces to: AC-17)
- [DAC-E2-S1-2] Given five problem stocks and `limit` 2, When `read_problems` pages, Then the pages hold 2, 2 and 1 stocks with cursors on the first two and none on the last, and a full final page carries no cursor. (traces to: DAC-E2-3)
- [DAC-E2-S1-3] Given a stock whose failures are all `not_found` and one with a `failed` failure, When read, Then `retryable` is false and true respectively; given a later run recording `written` for the failed data type, or the stock retired, Then the row leaves, and nothing else removes it. (traces to: AC-14, DAC-E2-2)
- [DAC-E2-S1-4] Given the `cursor` and `limit` parameters, When bound, Then they are psycopg query parameters, never interpolated (SEC-INP-002), and each function leaves commit and rollback to the caller's `with pool.connection()` block. (traces to: AC-17)

## Technical Details

### API Contract
- None served; the module is called in process by `data-health-api` (E2-S4).

### Data Changes
- None: no schema change, no migration, no index; reads use the delivered indexes `idx_instrument_active`, `idx_run_result_failures`, `idx_coverage_instrument` and the primary keys (data-health-reader 2.8).

### Implementation
- Python 3.12, `psycopg` 3 on the delivered pool, frozen dataclasses with full type hints (tech stack v7; SA-TYPE-001).
- Files: `src/factorflow/data_health/__init__.py`, `models.py`, `queries.py`, `reader.py`; `tests/unit/test_data_health_sql_is_read_only.py`; `tests/integration/test_data_health_problems.py` (pytest with `testcontainers[postgres]`, marked `postgres`).
- No delivered file is edited (DEC-0211). Rollback: redeploy the previous image (OPS-MIG-003).

### Validation
`uv run pytest` (or `uv run pytest -m 'not postgres'` when no container runtime is available, reported as an exclusion), `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src` (tech stack v7 validation commands).

### Dependencies
- None inside CAP-003: this is the first reader story.
- Cross-capability: CAP-001's tables (migrations 0001, 0003, 0004), `requires-runtime`, delivered.
