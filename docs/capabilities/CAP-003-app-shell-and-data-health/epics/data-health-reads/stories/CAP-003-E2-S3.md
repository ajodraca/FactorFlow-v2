# read_data_health: the Daily Prices and Company Financials Checks over coverage-service Pages

## User Story
As an owner-operator, I want the two data checks derived from one pass over the coverage pages, so that Data health's verdict counts and check cards rest on the same facts as the coverage table.

## Description
Adds `read_data_health(conn)` to `reader.py`: calls `coverage-service`'s public `read_coverage(conn, lifecycle="active", cursor, limit=500)` unchanged, page by page to a null cursor, folding each page into running counts and keeping at most five exception symbols per check (data-health-reader 2.5; DEC-0201, DEC-0213, DEC-0220). When `read_coverage` reports `never_acquired`, both checks are `None`. Daily prices: `absent_count` (presence `absent` or `unknown`), `behind_count` (`covered_to` earlier than `latest_session`, the latest prices `covered_to` over active stocks), `gap_stock_count` (`missing_days` above 0, `None` when gap detection is unavailable with `gap_detection.reason` carried), `exception_symbols` the first five of the union and `exception_count` its size; status `exceptions`, `not_determinable` or `ok` per the 2.5 flowchart. Company financials: `absent_count`, `problem_count`, `as_of` (latest `last_acquired_at` with `last_outcome` `written`, `None` when none), the union's symbols and count. `affected_count` equals `Problems.stock_count` and `problems` is the first page of 50 from `read_problems`. Writes `tests/unit/test_data_health_checks.py` and `tests/integration/test_data_health_checks.py`.

Source: component-design-data-health-reader.md 2.5, 3, 5, 7; epic CAP-003-E2 DAC-E2-4, DAC-E2-5, DAC-E2-15.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-11] `GET /api/data-health` MUST carry the verdict counts and the two checks with the time each is current to.
- [AC-12] A check built on a partial or interrupted download MUST carry its exceptions rather than read as clean.
- [AC-21] Before anything was acquired, both checks MUST be null rather than zero counts that could read as passed.
- [AC-24] A null part MUST stay null, never `0`.
- [DAC-E2-4] The Daily prices check MUST be `exceptions`, `not_determinable` or `ok` as stated, with `gap_stock_count` `null`, never 0, when gap detection is unavailable. (traces to: AC-11, AC-24)
- [DAC-E2-5] The count rules and exception unions MUST be as stated (DEC-0213, DEC-0220). (traces to: AC-11)
- [DAC-E2-15] `read_data_health` MUST call `read_coverage` unchanged, page by page, and MUST NOT catch a `ValueError` from it. (traces to: AC-11)

### Derived
- [DAC-E2-S3-1] Given a stock with presence `unknown`, When the checks run, Then it counts in `absent_count` and not in `behind_count`; given a stock both absent and failed for fundamentals, Then it counts in both counts and once in `exception_symbols` and `exception_count`; given a stock with gaps that is also behind, Then it counts once in Daily prices' `exception_count`. (traces to: DAC-E2-5)
- [DAC-E2-S3-2] Given an empty store, When read, Then `never_acquired` is `True`, both checks are `None` and `affected_count` is 0; given a store where a download ended and every request failed, Then `never_acquired` is `True` with `affected_count` and the problem rows populated (review v1 FINDING-10). (traces to: AC-21)
- [DAC-E2-S3-3] Given a retired stock with a failure, When read, Then it is in no count and no row; given 3000 active stocks, Then six `read_coverage` pages are requested and memory holds at most five symbols per check. (traces to: DAC-E2-1, AC-28)
