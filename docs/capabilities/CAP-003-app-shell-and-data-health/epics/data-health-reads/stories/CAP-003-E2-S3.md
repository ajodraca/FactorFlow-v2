# Data Health Aggregate: the Daily Prices and Company Financials Checks over Coverage Pages

## User Story

As an owner-operator, I want the two data checks derived from the coverage CAP-001 already computes, so that Data health can say whether prices and financials are present without asserting anything the store does not record.

## Description

Logical component: `data-health-reader`. Adds `read_data_health(conn)` to `reader.py` as `component-design-data-health-reader.md` §2.5 specifies: calls `coverage-service`'s public `read_coverage(conn, lifecycle="active", cursor, limit=500)` unchanged, page by page to a null cursor, folding each page into running counts and keeping at most five exception symbols per check; derives `DailyPricesCheck` and `CompanyFinancialsCheck` by the DEC-0213 count rules and DEC-0220's distinct `exception_count` (both PROVISIONAL); returns both checks `None` when `read_coverage` reports `never_acquired`; and composes `DataHealth` with `followed_count`, `affected_count` (E2-S1's problem count), and the first problem page of 50 from `read_problems`. The Factor scores check is not derived here (system design §3.4 note 4).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-11] `GET /api/data-health` MUST carry the verdict counts (`affected_count`, `followed_count`) and the Daily prices and Company financials checks with the time each is current to.
- [AC-12] A check built on a partial or interrupted download MUST carry its exceptions rather than read as clean.
- [AC-21] Before anything was acquired, both checks MUST be null rather than zero counts that could read as passed.
- [DAC-E2-4] The Daily prices check MUST be `exceptions` when `absent_count`, `behind_count` or a known `gap_stock_count` is above zero, `not_determinable` when gap detection is unavailable and nothing else is wrong, and `ok` only when every part ran and found nothing; `gap_stock_count` MUST be `null`, never 0, when gap detection is unavailable, with `gap_detection.reason` carried. (traces to: AC-11, AC-24)
- [DAC-E2-5] `absent_count` MUST count active stocks whose prices (or fundamentals) presence is `absent` or `unknown` alike; `behind_count` MUST count stocks whose prices `covered_to` is earlier than `latest_session`; the financials `problem_count` MUST count active stocks whose fundamentals `last_outcome` is `failed` or `not_found`; `exception_symbols` MUST be the first five symbols of each check's union and `exception_count` the number of distinct stocks in that union. (traces to: AC-11)
- [DAC-E2-15] `read_data_health` MUST call `read_coverage(conn, lifecycle="active", cursor, limit=500)` unchanged, page by page to a null cursor, and MUST NOT catch a `ValueError` from it. (traces to: AC-11)

### Derived

- [DAC-E2-S3-1] Given `tests/unit/test_data_health_checks.py` over the fold as a pure function of coverage rows, When a stock has presence `unknown`, Then it counts in `absent_count` and not in `behind_count`; When a stock has gaps and is behind, Then it counts once in `exception_count`; When a stock is both absent and failed for fundamentals, Then it counts in both counts and once in `exception_symbols`. (traces to: DAC-E2-5)
- [DAC-E2-S3-2] Given gap detection unavailable and every other part clean, When derived, Then `status` is `not_determinable` and `gap_stock_count` is `None`; given gap detection unavailable and `absent_count` 2, Then `status` is `exceptions` and `gap_stock_count` is still `None`. (traces to: DAC-E2-4)
- [DAC-E2-S3-3] Given an empty store, When `read_data_health` runs, Then `never_acquired` is true, both checks are `None`, `affected_count` is 0 and `problems.rows` is empty. (traces to: AC-21)
- [DAC-E2-S3-4] Given a store where one download ended and every request failed, When read, Then `never_acquired` is true, both checks are `None`, and `affected_count` and `problems.rows` are populated (review v1 FINDING-10). (traces to: AC-21, AC-13)
- [DAC-E2-S3-5] Given 1200 active stocks, When read, Then `read_coverage` is called three times with `limit=500` and successive cursors and once more is not needed when the last page's cursor is null, asserted by a spy on the unchanged function. (traces to: DAC-E2-15)
- [DAC-E2-S3-6] Given `as_of`, When derived, Then it is the latest fundamentals `last_acquired_at` whose `last_outcome` is `written` over active stocks, or `None`; `latest_session` is the max prices `covered_to` over active stocks, or `None`. (traces to: AC-11)
