# read_attention: Followed Count, Prices As-Of, Latest Downloads with Progress and the Server Items

## User Story
As an owner-operator, I want one cheap aggregate the shell can poll every 10 seconds, so that the rail counts, Home's tile and items, and setup's progress come from the same facts.

## Description
Adds `read_attention(conn)` to `reader.py` with its queries: Q1 `followed_count` (active instruments), Q2 `prices_as_of` (max prices `covered_to` over active stocks), Q3 the problem block (count, first three symbols, `newest_completed_at`, from `PROBLEM_COUNT_SQL`), Q4 `LATEST_DOWNLOAD_SQL` (the `acquisition_run` with the greatest `requested_at`, with `done` as instruments holding a `run_instrument_result` row for all four data types and `total` as `instruments_named`, `None` while 0), Q5 `LATEST_TERMINAL_SQL` (greatest `ended_at` among the five terminal states, with `failure_reason`), `credential_present()` from `config.settings`, and the three server item kinds of DEC-0203 (data-health-reader 2.3, 2.6, 2.7). `checked_at` is Q1's `now()`. No call to `coverage-service`. Writes `tests/unit/test_data_health_items.py` and `tests/integration/test_data_health_attention.py`.

Source: component-design-data-health-reader.md 2.3, 2.6, 2.7, 5, 7; epic CAP-003-E2 DAC-E2-6, DAC-E2-7, DAC-E2-8.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-7] The attention read MUST carry the latest download's progress.
- [AC-8] The attention read MUST carry `followed_count` and `prices_as_of`.
- [AC-9] The server-derived attention items MUST exist exactly while their cause holds in the store.
- [AC-12] Run states and outcomes MUST be returned as recorded.
- [AC-21] `latest_terminal_download` MUST be null until a download has ended.
- [DAC-E2-6] `progress.done` MUST count instruments with a result row for all four data types and `total` MUST be `instruments_named`, `null` while 0; `done` MUST never exceed `total`. (traces to: AC-7)
- [DAC-E2-7] `latest_download` MUST be the run with the greatest `requested_at` and `latest_terminal_download` the run with the greatest `ended_at` among the terminal states, with its recorded `state` and `failure_reason`; a running download MUST NOT displace the latest terminal one. (traces to: AC-12, AC-21)
- [DAC-E2-8] The items MUST be `data_problems` when `problems.stock_count` is above 0, `download_not_complete` when the latest terminal state is `failed` or `abandoned` (never `partial` or `cancelled`), and `credential_missing` when `credential_present()` is false; items carry no tier and no copy. (traces to: AC-9)

### Derived
- [DAC-E2-S2-1] Given an empty store, When `read_attention` runs, Then `followed_count` is 0, `prices_as_of`, `latest_download` and `latest_terminal_download` are `None`, `problems.stock_count` is 0 and `items` is empty. (traces to: AC-21)
- [DAC-E2-S2-2] Given a `running` download after a `partial` one, When read, Then `latest_download` is the running one and `latest_terminal_download` the partial one; given an `abandoned` latest terminal download, Then the `download_not_complete` item carries its `run_id` and `ended_at` as `recorded_at`. (traces to: DAC-E2-7, DAC-E2-8)
- [DAC-E2-S2-3] Given `credential_present()` false, When read, Then the `credential_missing` item has `recorded_at` equal to `checked_at` and `credential_present` is `False`; the key's value is never read by this module (AGT-PROHIB-001). (traces to: AC-4)
- [DAC-E2-S2-4] Given 3000 active instruments, When `read_attention` runs, Then it issues the five aggregate statements plus the progress aggregate and no per-instrument statement, so it is safe at the 10 s cadence (data-health-reader 5). (traces to: AC-28)
