# Attention Read: Downloads, Progress and the Server-Derived Items

## User Story

As an owner-operator, I want one cheap aggregate the shell can poll every ten seconds, so that the rail counts, Home's data tile and items and setup's progress all follow the store without the expensive coverage derivation.

## Description

Logical component: `data-health-reader`. Adds `read_attention(conn)` to `reader.py` and the statements it needs to `queries.py`, as `component-design-data-health-reader.md` §2.3, §2.6 and §2.7 specify: Q1 `followed_count` (active instruments), Q2 `prices_as_of` (max `prices` `covered_to` over active instruments), Q3 the problem block from E2-S1's `PROBLEM_COUNT_SQL`, Q4 `LATEST_DOWNLOAD_SQL` (greatest `requested_at`, with `done` as instruments having a `run_instrument_result` row for all four data types and `total` as `instruments_named`, `None` while 0), Q5 `LATEST_TERMINAL_SQL` (greatest `ended_at` among the five terminal states with `failure_reason`), `credential_present()` from `factorflow.config.settings`, and the three item kinds of DEC-0203 (PROVISIONAL). `checked_at` is Q1's `now()`. Items carry no tier and no copy (DEC-0200).

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-7] The attention read MUST carry the latest download's progress so setup and Home can show it.
- [AC-8] The attention read MUST carry `followed_count` and `prices_as_of` for Home's data tile.
- [AC-9] The server-derived attention items MUST exist exactly while their cause holds in the store.
- [AC-12] Run states and outcomes MUST be returned as recorded.
- [AC-21] `latest_terminal_download` MUST be null until a download has ended, which is the interface's empty-state trigger.
- [AC-4] `credential_present` is a boolean only; the key's value enters no field.
- [DAC-E2-6] `latest_download.progress.done` MUST count instruments with a `run_instrument_result` row for all four data types in that run and `total` MUST be `instruments_named`, returned as `null` while it is 0; `done` MUST never exceed `total`. (traces to: AC-7)
- [DAC-E2-7] `latest_download` MUST be the `acquisition_run` with the greatest `requested_at` and `latest_terminal_download` the run with the greatest `ended_at` among the five terminal states, with its recorded `state` and `failure_reason`; a running download MUST NOT displace the latest terminal one. (traces to: AC-12, AC-21)
- [DAC-E2-8] The attention `items` MUST be `data_problems` when `problems.stock_count` is above 0 (recency `newest_completed_at`), `download_not_complete` when `latest_terminal_download.state` is `failed` or `abandoned` (recency its `ended_at`, carrying its `run_id`), never for `partial` or `cancelled`, and `credential_missing` when `credential_present()` is false. (traces to: AC-9)

### Derived

- [DAC-E2-S2-1] Given an empty store, When `read_attention` runs, Then `followed_count` is 0, `prices_as_of`, `latest_download` and `latest_terminal_download` are `None`, `problems.stock_count` is 0 and `items` is empty apart from `credential_missing` when the key is unset. (traces to: AC-21)
- [DAC-E2-S2-2] Given a run with `instruments_named` 0, When read, Then `progress.total` is `None` and `done` is 0; given `instruments_named` 300 and 120 instruments with all four results, Then `done` is 120 and `total` 300. (traces to: DAC-E2-6)
- [DAC-E2-S2-3] Given a `succeeded` run that ended and a later `running` run, When read, Then `latest_download` is the running one and `latest_terminal_download` the succeeded one with `ended_at` set. (traces to: DAC-E2-7)
- [DAC-E2-S2-4] Given a latest terminal run `abandoned`, When read, Then one `download_not_complete` item carries that run's `run_id` and `ended_at`; given `partial` or `cancelled`, Then no such item exists. (traces to: DAC-E2-8)
- [DAC-E2-S2-5] Given `tests/unit/test_data_health_items.py` over the item rule as a pure function of the read values, When each cause is toggled, Then each kind appears and disappears with its cause alone. (traces to: DAC-E2-8)
- [DAC-E2-S2-6] Given `prices` coverage over active and retired instruments, When read, Then `prices_as_of` is the max `covered_to` over active instruments only and is a `date`. (traces to: AC-8)
