# ingestion-api: Register the data_health Router and Extend the No-Secrets Test

## User Story
As an owner-operator, I want the three new routes served by the delivered application behind its middleware and envelope, and proven never to carry the market data key, so that nothing about the API's posture changes.

## Description
Makes the two `ingestion-api` edits of ingestion-api 2.1: `src/factorflow/api/app.py` gains the import of `data_health` and `app.include_router(data_health.router)` after the delivered `include_router(coverage.router)` (line 461) and before `_add_static_mount` (line 465), after `classification-api`'s two calls if they have landed (order among `/api` routers does not matter); `tests/unit/test_api_no_secrets.py` gains the parametrised `test_data_health_routes_never_echo_credential` of ingestion-api 2.3 with its `stub_reader_functions` and `StubPool` helpers. No other `ingestion-api` file changes; `_resource_for_path` is not extended (ingestion-api 3). Every real-stack end-to-end story in E3 to E7 depends on this story, because the shell polls `GET /api/attention` on every route (backlog review v2 FINDING-1).

Source: component-design-ingestion-api.md 2.1 to 2.3, 3, 4, 7; epic CAP-003-E2 DAC-E2-10, DAC-E2-13.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-4] No new response MUST carry the market data credential's value; the delivered no-secrets test is extended to the three new routes.
- [AC-17] No delivered route, model, status code or refusal MUST change.
- [DAC-E2-10] The router MUST be included by `create_app` with the delivered routers and before `_add_static_mount`, so a foreign `Host` gets `400 host_not_allowed` on all three routes, a foreign `Origin` on a `GET` is not refused, an unknown `/api` path still answers the `not_found` envelope, and every refusal carries a request id. (traces to: AC-17, AC-16)
- [DAC-E2-13] `tests/unit/test_api_no_secrets.py` MUST gain one parametrised test proving a populated `200` body of each of the three routes never contains the value of `FACTORFLOW_MASSIVE_API_KEY`. (traces to: AC-4)

### Derived
- [DAC-E2-S5-1] Given `app.py`, When the change lands, Then its diff is the one import and the one `include_router` line, and the delivered `tests/integration/test_api_static_mount.py` and `tests/unit/test_api_host_origin.py` pass unchanged. (traces to: AC-17)
- [DAC-E2-S5-2] Given the new test, When it runs, Then each route answers `200` through `create_app` with the reader stubbed and the pool replaced, without a database and without waiting on the pool's 30 s checkout timeout, and `secret_value` is absent from `response.text`. (traces to: DAC-E2-13)
