# Volume Test: 3,000 Followed Stocks and the Two-Second Aggregate

## User Story

As an owner-operator, I want the data health aggregate proven to answer in bounded time at the roster size CAP-001 committed to, so that Data health opens promptly with 3,000 followed stocks.

## Description

Logical component: `data-health-reader`. Creates `tests/integration/test_data_health_volume.py` as `component-design-data-health-reader.md` §7 and DAC-E2-14 specify: seeds 3000 active instruments with failures on 300, asserts the counts, the keyset pages and bounded memory, and times `GET /api/data-health` through the in-process application built by `create_app` (E2-S5) to a 95th percentile of at most 2 seconds over 20 timed requests after one warm-up (AC-28, the owner's threshold of 2026-10-25). Memory is bounded because `read_data_health` folds each page into running counts (E2-S3); the test asserts the fold holds no per-stock list beyond the five exception symbols per check.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-28] With 3,000 followed stocks, `GET /api/data-health` MUST answer within 2 seconds at the 95th percentile, measured by the volume test.
- [AC-16] `problems.stock_count` MUST be the same set as the *Needs fixing* rows at volume.
- [DAC-E2-14] The volume test MUST seed 3000 active instruments with failures on 300, assert the counts, the keyset pages and bounded memory, and time `GET /api/data-health` through the in-process application to a 95th percentile of at most 2 seconds after one warm-up request. (traces to: AC-28)

### Derived

- [DAC-E2-S6-1] Given the seeded store, When `/api/attention` is requested, Then `followed_count` is 3000 and `problems.stock_count` is 300; When `/api/data-health` is requested, Then `affected_count` is 300 and `read_coverage` was called six times with `limit=500`. (traces to: AC-16, DAC-E2-14)
- [DAC-E2-S6-2] Given `limit=500`, When `/api/data-health/problems` is paged from the first page, Then the first page holds 50 rows (the aggregate's page), the `problems` route's pages hold at most 500, and the union of all pages is exactly the 300 problem symbols with no duplicate. (traces to: DAC-E2-14)
- [DAC-E2-S6-3] Given 20 timed requests after one warm-up, When their durations are sorted, Then the 95th percentile is at most 2.0 seconds and the test fails, naming the measured value, otherwise. (traces to: AC-28)
- [DAC-E2-S6-4] Given the fold's intermediate state captured by a spy, When the last page is folded, Then no collection in it holds more than five symbols per check. (traces to: DAC-E2-14)
