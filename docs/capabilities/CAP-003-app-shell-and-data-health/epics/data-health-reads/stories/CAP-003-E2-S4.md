# data-health-api Router and Response Models for the Three Reads

## User Story
As an owner-operator, I want the three reads served in the domain vocabulary with the delivered error envelope, so that the interface composes every sentence and tier itself from facts it can trust.

## Description
Creates `src/factorflow/api/routes/data_health.py` (the `APIRouter` with `GET /api/attention`, `GET /api/data-health`, `GET /api/data-health/problems` as data-health-api 2.3 lists them) and `src/factorflow/api/data_health_models.py` (Pydantic models mirroring system design §4.2 field for field plus each check's `exception_count`, data-health-api 2.4), following the `classification_models.py` precedent so no delivered file is edited. The problems route takes `limit` (`Query(default=DEFAULT_PAGE_SIZE, gt=0, le=MAX_PAGE_SIZE)` from `api/bounds.py`) and `cursor` (normalised with `instruments.symbols.normalise`, refused with `422 validation_error`, resource `data-health`, when not `is_valid`, never echoing the value). Each handler opens one pooled connection and delegates to the reader. Writes `tests/unit/test_api_data_health_models.py` and `tests/unit/test_api_data_health_routes.py` on a minimal `FastAPI()` app including the router; the delivered `500` envelope and the Host and Origin middleware are proved through `create_app` in E2-S6, after `ingestion-api` registers the router (E2-S5).

Source: component-design-data-health-api.md 2.1 to 2.4, 3, 4, 7; epic CAP-003-E2 DAC-E2-3, DAC-E2-9, DAC-E2-11, DAC-E2-12.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-11] `GET /api/data-health` MUST carry the verdict counts and the two checks.
- [AC-13] Every problem row MUST carry its failures' facts.
- [AC-17] No delivered request or response model, route, status code or refusal MUST change; the new routes are additive.
- [AC-19] Field names MUST stay in the domain vocabulary.
- [DAC-E2-3] `GET /api/data-health/problems` MUST take `limit` (default 50, maximum 500) and `cursor`, answer `422 validation_error` for a `limit` outside 1 to 500 or a cursor that is not a symbol, never clamping, and MUST NOT echo the submitted value. (traces to: AC-13)
- [DAC-E2-11] Nullable counts and dates MUST serialise as `null`, never omitted and never `0`. (traces to: AC-24)
- [DAC-E2-12] No response field MUST be named *stock* or *download* and no response MUST carry a sentence or a tier. (traces to: AC-19)

### Derived
- [DAC-E2-S4-1] Given each model, When serialised, Then every §4.2 field is present, timestamps are ISO-8601 with offset, session dates are `YYYY-MM-DD`, and `gap_stock_count`, `prices_as_of`, `latest_session`, `as_of` and `progress.total` serialise as `null` when absent. (traces to: DAC-E2-11)
- [DAC-E2-S4-2] Given `limit=0`, `limit=501` and `cursor=not a symbol`, When requested, Then each answers `422 validation_error`, the cursor refusal names resource `data-health` with the message *`cursor` must be a stock symbol.*, and no response body contains the submitted value. (traces to: DAC-E2-3)
- [DAC-E2-S4-3] Given each handler, When called, Then it calls its reader function once with one connection from `request.app.state.db_pool` and returns the reader's value through `from_reader` unchanged; a `psycopg.Error` raised by the reader propagates out of the handler uncaught (the delivered handler turns it into the `500` envelope, asserted in E2-S6). (traces to: DAC-E2-9)
- [DAC-E2-S4-4] Given `limit` and `cursor`, When they reach SQL, Then only as bound parameters after validation (SEC-INP-001, SEC-INP-002); `credential_present` is a boolean and no handler logs beyond the delivered request-id stamping. (traces to: AC-4)

## Technical Details

### API Contract
- `GET /api/attention`: no parameters; `200 AttentionResponse` (`checked_at`, `followed_count`, `prices_as_of`, `credential_present`, `problems {stock_count, symbols[<=3], newest_completed_at}`, `latest_download`, `latest_terminal_download`, `items[]`).
- `GET /api/data-health`: no parameters; `200 DataHealthResponse` (`checked_at`, `never_acquired`, `followed_count`, `affected_count`, `checks {daily_prices, company_financials}` each null exactly when `never_acquired`, `problems {rows, next_cursor}`).
- `GET /api/data-health/problems?limit=50&cursor=KO`: `200 ProblemPageResponse`; `422 validation_error` (delivered envelope) on a bad bound or cursor.
- Auth: none; loopback bind and the delivered Host and Origin middleware (DEC-0208). Errors: `400 host_not_allowed`, `500 internal_error` with `X-Request-Id`, all delivered.

### Data Changes
- None.

### Implementation
- Python 3.12, FastAPI, Pydantic as delivered (tech stack v7). Files: `src/factorflow/api/routes/data_health.py`, `src/factorflow/api/data_health_models.py`, `tests/unit/test_api_data_health_models.py`, `tests/unit/test_api_data_health_routes.py`.
- `api/models.py`, `api/bounds.py`, `api/errors.py` untouched; `factorflow.api.errors.error_response` used for the cursor refusal.
