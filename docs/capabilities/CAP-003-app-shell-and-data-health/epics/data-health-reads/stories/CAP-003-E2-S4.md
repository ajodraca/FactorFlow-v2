# Data Health API Router and Response Models

## User Story

As an owner-operator, I want the three reads served as JSON in the domain vocabulary with the canonical paging bounds, so that the shell and Data health read facts the interface words, and a bad page request is refused rather than quietly clamped.

## Description

Logical component: `data-health-api`. Creates `src/factorflow/api/routes/data_health.py` with the three `GET` handlers of `component-design-data-health-api.md` §2.3 (`/api/attention`, `/api/data-health`, `/api/data-health/problems`) and `src/factorflow/api/data_health_models.py` with the Pydantic response models of §2.4 (`AttentionResponse`, `DataHealthResponse`, `DailyPricesCheckResponse`, `CompanyFinancialsCheckResponse`, `ProblemRowResponse`, `ProblemPageResponse`), each with a `from_reader` classmethod over E2-S1 to E2-S3's dataclasses. Each handler opens one connection from the delivered `app.state.db_pool` and delegates; it holds no SQL and no derivation. `limit` is bounded by `Query(default=DEFAULT_PAGE_SIZE, gt=0, le=MAX_PAGE_SIZE)` from the delivered `api/bounds.py`; `cursor` is normalised with `factorflow.instruments.symbols.normalise` and refused with the delivered `error_response(422, "validation_error", ...)` naming `resource` `data-health` when `is_valid` fails, never echoing the value. No delivered file is edited (DEC-0211); registration on `create_app` is E2-S5's.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-11] `GET /api/data-health` MUST carry the verdict counts and the two checks with the time each is current to.
- [AC-13] Every problem row MUST carry, per failure, the data type, the outcome, the reason, the attempts and the completion time.
- [AC-17] No delivered request or response model, route, status code or refusal MUST change; the new routes are additive.
- [AC-19] Field names MUST stay in the domain vocabulary.
- [DAC-E2-3] `GET /api/data-health/problems` MUST take `limit` (default 50, maximum 500, from `api/bounds.py`) and `cursor`, MUST answer `422 validation_error` for a `limit` outside 1 to 500 or a cursor that is not a symbol, never clamping or ignoring either, and MUST NOT echo the submitted value. (traces to: AC-13)
- [DAC-E2-9] The three routes MUST answer `200` with the §4.2 shapes whenever the database answers, including on an empty store; a `psycopg.Error` MUST propagate to the delivered `500` `internal_error` envelope with `X-Request-Id`, and no partial aggregate MUST be returned as complete. (traces to: AC-21, AC-11)
- [DAC-E2-11] Nullable counts and dates (`gap_stock_count`, `prices_as_of`, `latest_session`, `as_of`, `total`) MUST serialise as `null`, never omitted and never `0`. (traces to: AC-24)
- [DAC-E2-12] Field names MUST stay in the domain vocabulary (`instrument`, `acquisition_run`, outcome); no response field MUST be named *stock* or *download* and no response MUST carry a sentence or a tier. (traces to: AC-19)

### Derived

- [DAC-E2-S4-1] Given each model built from a reader value with every nullable field `None`, When serialised, Then every §4.2 field is present and each nullable one is JSON `null`; timestamps carry an offset and session dates are `YYYY-MM-DD`. (traces to: DAC-E2-11)
- [DAC-E2-S4-2] Given `limit=0`, `limit=501` and `cursor=not a symbol`, When requested on a test application that includes the router, Then each answers `422 validation_error`; the cursor refusal names `resource` `data-health` and its message does not contain the submitted text. (traces to: DAC-E2-3)
- [DAC-E2-S4-3] Given the reader functions patched to record their calls, When each route is requested, Then its reader function is called exactly once with one connection and the response equals `Model.from_reader(value)`. (traces to: DAC-E2-9)
- [DAC-E2-S4-4] Given a reader raising `psycopg.Error`, When requested through an application with the delivered exception handlers, Then the answer is `500` with the `internal_error` envelope, a fixed message and an `X-Request-Id` header. (traces to: DAC-E2-9)
- [DAC-E2-S4-5] Given the serialised bodies, When their keys are collected recursively, Then none is `stock`, `download`, `tier`, `label` or `sentence`. (traces to: DAC-E2-12)
- [DAC-E2-S4-6] Given `AttentionResponse` with `credential_present` true, When serialised, Then the field is the boolean `true` and no field holds a string resembling the key. (traces to: AC-4)

## Technical Details

### API Contract

- Endpoint: `GET /api/attention`; Auth: none, loopback (DEC-0208); Request: none; Response: `200 AttentionResponse`; Errors: `500 internal_error`.
- Endpoint: `GET /api/data-health`; Request: none; Response: `200 DataHealthResponse` with the first 50 problem rows; Errors: `500 internal_error`.
- Endpoint: `GET /api/data-health/problems`; Request: `limit` (1 to 500, default 50), `cursor` (a symbol); Response: `200 ProblemPageResponse { rows, next_cursor }`; Errors: `422 validation_error`, `500 internal_error`.
- Response shapes are system design §4.2 field for field plus each check's `exception_count` (DEC-0220).

### Implementation

- New: `src/factorflow/api/routes/data_health.py`, `src/factorflow/api/data_health_models.py`, `tests/unit/test_api_data_health_routes.py`, `tests/unit/test_api_data_health_models.py`.
- The unit tests mount `data_health.router` on a FastAPI app built with the delivered exception handlers and a stub pool, so they run without a database and before E2-S5 registers the router on `create_app`.
