# Coverage at `/data/coverage`: Words, Table and the `?symbol=` Entry Hint

## User Story

As an owner-operator, I want the coverage table in the product's words, built from the design system, reachable with a symbol already filtered, so that **Full coverage table** and a problem row's symbol land me on the right stock with nothing CAP-001 accepted changed.

## Description

Logical component: `owner-web-app`. Takes over `web/src/screens/coverage/*` as `component-design-owner-web-app.md` §2.3 and §2.4 specify: labels in `copy.ts` per UX design 1.5 (*stock*, **Download now**, *Last downloaded*, *Stopped following*, the two blocked reasons with *Settings* a link to `/settings`, the queued sentence; *Coverage*, *gap*, *history depth*, *trading day*, *Covered from*, *Covered to*, *Depth*, *Reference*, *Prices*, *Fundamentals*, *Corporate actions* unchanged); the table rebuilt on E1-S9's `data-table` `virtualised` with v5's row expansion, `coverage-table.tsx`'s windowing now in the vendored component; presence through `badge` `coverage-*`; the lifecycle filter through `select` `inline`; states through `StateRegion`; `?symbol={SYMBOL}` seeding the filter on load and the filter updating or clearing the query with `replace`; starting a download routing to `/data/downloads/{run_id}`; every internal link at the new paths. The delivered `coverage/*.test.tsx` follow (§2.6) and `entry-hint.test.tsx` is new. No request, query parameter, confirmation or refusal changes (AC-17). The route exists from E3-S3.

Breakdown and ordering: DEC-0223.
