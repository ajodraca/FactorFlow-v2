# Coverage Under the Shell: Display Labels, the Virtualised Table, ?symbol= Seeding and Links to the New Paths

## User Story
As an owner-operator, I want the coverage table at `/data/coverage` in the product's words, reached with a stock already filtered from Data health, so that a problem row leads straight to the stock's coverage.

## Description
Takes over `web/src/screens/coverage/*` (owner-web-app 2.1, 2.3, 2.4): *instrument* becomes *stock* throughout, **Start acquisition run** becomes **Download now**, *Last acquired* becomes *Last downloaded*, *Retired* becomes *Stopped following*, the blocked reasons (*History depth is not set. Set it in Settings before downloading.* with *Settings* a link to `/settings`; *No stocks are followed. Follow stocks before downloading.*, depth first) and the queued sentence; `Coverage`, `gap`, `history depth`, `trading day`, `Covered from`, `Covered to`, `Depth`, `Reference`, `Prices`, `Fundamentals`, `Corporate actions` stay. The table becomes `data-table` `virtualised` with the per-row expansion CAP-001 v5 specified, its hand-built windowing removed from `coverage-table.tsx` in favour of the vendored component (DEC-0215). `?symbol={SYMBOL}` seeds the symbol filter on load; editing or clearing the filter updates or clears the query with `replace`; a seeded symbol matching nothing renders the nothing-found state with its reset. Starting a download routes to `/data/downloads/{run_id}`. Writes `entry-hint.test.tsx`; the delivered coverage tests follow (owner-web-app 2.6).

Source: component-design-owner-web-app.md 2.1, 2.3, 2.4, 2.5, 2.6, 5, 7; UX design 1.5; epic CAP-003-E7 DAC-E7-1, DAC-E7-4, DAC-E7-6, DAC-E7-9, DAC-E7-11.
