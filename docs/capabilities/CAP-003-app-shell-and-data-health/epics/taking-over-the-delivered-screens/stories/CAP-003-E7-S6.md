# Settings at `/settings`: **Open Setup** and the *Market Data Key* Region

## User Story

As an owner-operator, I want Settings to offer a way back into setup and to state whether the market data key was found in the product's words, so that I can re-check my configuration and never see the key's value.

## Description

Logical component: `owner-web-app`. Takes over `web/src/screens/settings/*` as `component-design-owner-web-app.md` §2.3 specifies: under the `h1` *Settings*, *Walk through setup again to check the market data key, history depth and followed stocks.* with **Open setup** (`button` `outline`, a link to `/setup`); the *Provider credential* region becomes *Market data key* on `card` `summary`: *Found* or *Missing* through `StatusBadge`, never the value; when missing, *Set the environment variable `FACTORFLOW_MASSIVE_API_KEY` to your Massive API key, then restart FactorFlow.*; while health is unreachable `coverage-unknown` *Not determinable*, never *Missing*; the history depth form unchanged in behaviour, rebuilt on `form` `stacked` and `input` `numeric`. Reads `credential_present` from `useShell().health`. The delivered `settings/*.test.tsx` follow (§2.6). Settings renders at `--measure-prose` inside the shell.

Breakdown and ordering: DEC-0223.
