# Research `SHELL_ROUTES` Targets Migrated to the New Paths

## User Story

As an owner-operator, I want the three links CAP-002's Research screens make into the market data surfaces to point at the new paths directly, so that nothing in Research depends on the legacy redirects and nothing breaks when they are removed.

## Description

Logical component: `owner-web-app`. Edits exactly three targets in the `SHELL_ROUTES` map of `web/src/screens/research/copy.ts`, the one edit CAP-002's approved `component-design-classification-ui.md` §2.2 assigns to the shell capability and DEC-0211 gives to this component: `/runs/:runId` to `/data/downloads/:id`, `/runs` to `/data`, `/instruments` to `/data/followed`. Nothing else in the file changes and no CAP-002 screen is touched (AC-27).

Recorded departure (DEC-0224): system design §4.1 and open question 6 map the `/runs` target to `/data/downloads`, while `component-design-owner-web-app.md` §2.1 and DAC-E7-2 map it to `/data`; the link is *Open Data health* and Data health is served at `/data`, and the precedence ladder ranks the epic criterion above the design prose, so this story implements `/data` and the system design is corrected separately by the owner (specification review v3 FINDING-10; epics backlog review v1 FINDING-3).

Sequencing: the owner fixed CAP-002 to land first (capability OQ-2). This clone does not yet hold `web/src/screens/research/copy.ts`, so this story is implementable only after CAP-002's `classification-ui` has merged; that is a cross-capability sequencing, not a dependency on a CAP-003 story. If the file is absent when this story is scheduled, the story stops and reports rather than creating it.

Breakdown and ordering: DEC-0223.
