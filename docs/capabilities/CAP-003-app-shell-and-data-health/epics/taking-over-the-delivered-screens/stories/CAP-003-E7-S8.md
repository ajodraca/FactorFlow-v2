# Migrate the Three SHELL_ROUTES Targets in CAP-002's research/copy.ts

## User Story
As an owner-operator, I want the three links the Research screens make into the data side to point at the new paths directly, so that nothing breaks when the legacy redirects are removed.

## Description
Changes exactly three targets in the `SHELL_ROUTES` map of `web/src/screens/research/copy.ts` and nothing else in that file (owner-web-app 2.1; DAC-E7-2): `/runs/:runId` to `/data/downloads/:id` (the download's start time in the Research as-of line), `/runs` to `/data` (*Open Data health*), `/instruments` to `/data/followed` (the followed-stocks link in refusals). CAP-002's tests under `web/src/screens/research/` that assert these targets follow; no non-test file other than `copy.ts` changes (backlog review v2 FINDING-3). The edit is this capability's because DEC-0211 gives every file under `web/src/screens/` to `owner-web-app` and CAP-002's approved `component-design-classification-ui.md` v3 §2.2 assigns the migration to the shell capability (review v1 FINDING-13).

**Recorded departure from the system design (DEC-0224, second opinion agreed, triage accepted; backlog review v3 FINDING-3).** `system-design.md` §4.1 (*Existing components this design changes*) and open question 6 state the `/runs` target as `/data/downloads`; `component-design-owner-web-app.md` §2.1 and DAC-E7-2 state `/data`. This story implements `/data`: the link is named *Open Data health* and Data health is served at `/data` (system design §4.2 *Screen registration*), so `/data/downloads` would land the owner on Downloads instead of the screen the link names, and the precedence ladder ranks the epic criterion above design prose. The system design is approved and is not edited by this run; §4.1 and OQ-6 are flagged for correction at its next revision. DEC-0224's `blocks` names this story ID.

**Sequencing.** The owner fixed the order, CAP-002 lands first (capability OQ-2); this clone does not yet hold `web/src/screens/research/` (backlog review v3, *Repository facts*), so this story is scheduled after `classification-ui` has merged. Its link test follows the three links to their screens, so it hard-depends on the stories that register them: E3-S4 (`/data/downloads/:id`, `/data/followed`) and E6-S7 (`/data`).

Source: component-design-owner-web-app.md 1, 2.1; epic CAP-003-E7 DAC-E7-2; DEC-0224; CAP-002 component-design-classification-ui.md v3 §2.2.
