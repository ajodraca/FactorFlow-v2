# Downloads at `/data/downloads`: Words, the *Started* Column and Outcomes Through `StatusBadge`

## User Story

As an owner-operator, I want the downloads list named by start time with every outcome in the product's tier words, so that no raw identifier appears and a partial or interrupted download never reads as complete.

## Description

Logical component: `owner-web-app`. Takes over `web/src/screens/runs/index.tsx`, `run-table.tsx`, `run-controls.tsx`, `cancel-run.tsx` and their tests as `component-design-owner-web-app.md` §2.3 specifies: *Runs* becomes *Downloads*; the first column is *Started*, the start time with the zone as the link to `/data/downloads/{id}` named *Download started {time}, open details*, replacing the run id link (no raw `run_id` on any surface, DAC-E7-10); *Instruments written* and *Instruments failed* become *Stocks downloaded* and *Stocks failed*; the empty and nothing-found copy say *download*; outcomes render through E1-S2's `StatusBadge` (*Queued* neutral, *Downloading* active, *Stopping* warning, *Complete* good, *Partial* warning, *Failed* critical, *Cancelled by you* neutral, *Interrupted* serious); the table is E1-S9's `data-table` `history`; the outcome filter is `select` `inline`; **Download now** and the queued sentence as on Coverage; the 10 second poll while any download is non-terminal is unchanged. The list's callers of `outcome-badge.tsx` are switched to `StatusBadge` here; the file itself is deleted by E7-S5 once the detail and the shell's status region (E3-S5) no longer import it.

Breakdown and ordering: DEC-0223.
