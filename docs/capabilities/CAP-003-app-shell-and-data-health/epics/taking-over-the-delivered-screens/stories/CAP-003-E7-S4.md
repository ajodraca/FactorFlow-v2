# Downloads Under the Shell: the Started Column, StatusBadge for the Eight States and the Retired outcome-badge

## User Story
As an owner-operator, I want the downloads list at `/data/downloads` naming each download by when it started and showing its outcome in the one tier language, so that a partial download never looks complete anywhere.

## Description
Takes over `web/src/screens/runs/index.tsx`, `run-table.tsx`, `run-controls.tsx`, `cancel-run.tsx` and their tests (owner-web-app 2.1, 2.3; the directory keeps its name): *Runs* becomes *Downloads*; the first column is *Started*, the start time with the zone as the link to `/data/downloads/{id}`, replacing the run id link so no raw `run_id` appears (DAC-E7-10); *Instruments written* and *Instruments failed* become *Stocks downloaded* and *Stocks failed*; the empty and nothing-found copy say *download*; the eight outcomes render through `StatusBadge` (*Queued* neutral, *Downloading* active, *Stopping* warning, *Complete* good, *Partial* warning, *Failed* critical, *Cancelled by you* neutral, *Interrupted* serious); **Download now** keeps the queued sentence; the table becomes `data-table` `history`; the 10 second poll while any download is non-terminal is v5's, unchanged, with its last-updated time shown. Replaces every caller of `web/src/screens/runs/outcome-badge.tsx` with `StatusBadge` and deletes it with `outcome-badge.test.tsx` (DAC-E7-5; `detail/result-outcome-badge.tsx` is E7-S5's).

Source: component-design-owner-web-app.md 2.1, 2.3, 2.6, 5, 7; UX design 1.7; epic CAP-003-E7 DAC-E7-1, DAC-E7-4, DAC-E7-5, DAC-E7-10, DAC-E7-11.
