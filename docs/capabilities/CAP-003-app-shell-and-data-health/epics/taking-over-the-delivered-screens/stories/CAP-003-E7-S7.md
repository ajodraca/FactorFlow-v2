# The Eleven Delivered End-to-End Specs and acquisition.ts Follow the New Paths and Labels

## User Story
As an owner-operator, I want every journey CAP-001 accepted proven again at the new paths in the new words, so that the takeover changed nothing I rely on.

## Description
Updates `tests/e2e/first-run.spec.ts`, `diagnose-failure.spec.ts`, `cancel-run.spec.ts`, `cancel-in-progress.spec.ts`, `coverage-empty.spec.ts`, `coverage-expansion.spec.ts`, `instrument-changes.spec.ts`, `instruments-add-retire.spec.ts`, `run-detail.spec.ts`, `runs-start-cancel.spec.ts`, `unrecognised-instrument.spec.ts` and `tests/e2e/support/acquisition.ts` (owner-web-app 2.1, 2.6): `page.goto("/coverage" / "/instruments" / "/runs")` become `/data/coverage`, `/data/followed`, `/data/downloads`; locators by the old labels become the new labels; the behaviour each spec proves is unchanged (AC-17). `acquisition-stack-stub.spec.ts` is not in owner-web-app's list and is untouched. The specs run against the real stack, so they depend on the data-health router being registered: the shell polls `GET /api/attention` on every route (backlog review v2 FINDING-1).

Source: component-design-owner-web-app.md 2.1, 2.6, 7; epic CAP-003-E7 NFR *Behaviour preserved*, DAC-E7-1, DAC-E7-12.
