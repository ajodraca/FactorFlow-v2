### IR-001 — The last-updated time renders in the shell's delivered form, not UX design 0.7's `YYYY-MM-DD HH:MM zone` through ui-components' `formatInstant`

- **Severity**: HIGH
- **Scope**: delta (`instrument-table.tsx:5` and `255–257` were added by the rework, commit `555b7757`). It is also the unmet form clause of v1 IR-001's remediation
- **Status**: OPEN
- **Acceptance criteria**: AC-24 (capability AC-24: "render each of STD-UI-23's eight states as designed"), AC-26 (capability AC-26: built from the design system)
- **Tasks**: T018 (the populated renderer); the v1 IR-001 rework (cycle 4)
- **Files**: `web/src/screens/instruments/instrument-table.tsx:5` (`import { formatTimestamp } from "../../app/status-region"`), `:255–257`; `web/src/screens/instruments/instrument-table.test.tsx:7`, `293–326`
- **Claim challenged**: Cycle 4 says the line uses "the timestamp form the Coverage and Downloads screens use". The rework's hand-off mutant `manual:3` describes `formatTimestamp` as "UX design 0.7's timestamp form (America/Chicago with the zone shown)".
- **Observed evidence**:
  - **The form.** The populated renderer writes `Last updated {formatTimestamp(new Date(populated.fetchedAt))}`. `formatTimestamp` (`web/src/app/status-region.tsx:72–92`) prints seconds and the IANA name. The reviewer probe renders *Last updated 2026-03-02 09:04:05 America/Chicago* where UX design 0.7's form is *2026-03-02 09:04 CST*, and *2026-10-15 17:46:10 America/Chicago* where it is *2026-10-15 17:46 CDT*.
  - **The designed formatter exists and is unused.** `formatInstant` in `web/src/components/patterns/format.ts:47–53` (CAP-003-E1-S6, `status: docs-sync`, at the review base since `330bc559`) renders exactly 0.7's form. Home, Setup and Data health already use it.
  - **The test cannot see the form.** The new case builds its expected text with the same helper (`instrument-table.test.tsx:7`, `303`, `313`, `322–325`). It proves the time comes from the read and moves on a re-read, which is correct. But it asserts whatever `formatTimestamp` prints, so a wrong form passes.
  - **A new importer of a module scheduled for deletion.** This line makes the screen import `web/src/app/status-region.tsx`. DAC-E3-15 requires CAP-003-E3-S6 to delete that module (`status: planning`). E3-S6's T015 repoints the remaining importers by `grep`, and its T007 (b) fails while any remain. So the line does not break E3-S6, but it adds work there and stays on the delivered form after repointing. The sibling takeover plans move the other way: CAP-003-E7-S2 (T019, T021), CAP-003-E7-S4 and CAP-003-E7-S5 each remove their `status-region` import and render through `formatInstant`.
  - **The precedent v1 named was wrong.** `coverage/index.tsx:191` and `runs/index.tsx:147` are CAP-001's delivered lines, not yet taken over on this branch.
- **Expected evidence/behavior**:
  - UX design 0.7, *Conventions stated once*: "timestamps are America/Chicago with the zone shown, *CDT* or *CST* as the instant falls, in the form `YYYY-MM-DD HH:MM zone`", and "`--text-xs` timestamps".
  - Ui-components design 2.5: "`formatInstant(date, { seconds })` renders `YYYY-MM-DD HH:MM zone` … The delivered `formatTimestamp` in the shell's health module renders the zone as *America/Chicago*; it is kept for the delivered tests that assert it, and every CAP-003 surface uses `formatInstant` (system design assumption 5; UX design 0.7)."
  - UX design 1.6 States: "last-updated time".
  - v1 IR-001's remediation: "Use UX design 0.7's timestamp form".
- **Impact**: Followed stocks, which Data health's **Follow a different symbol** opens, shows a timestamp in a different shape from every other CAP-003 surface. The shape has seconds and *America/Chicago* where the rest of the product shows *CDT* or *CST*, which is the inconsistency 0.7 states its conventions once to prevent. STD-UI-5 itself is met (an ISO date and a visible zone), so no time is wrong; the designed rendering is not followed. The test gives false assurance about the text, and the new import adds an importer for E3-S6 to repoint.
- **Required remediation**:
  - Render the last-updated time through `formatInstant` from `../../components/patterns/format`, keeping the read's `fetchedAt`, `font-numeric` and `text-xs`.
  - Drop the `app/status-region` import.
  - Pin the designed text with a literal, for example a fixed instant asserted as `Last updated 2026-03-02 09:04 CST`, keeping the redraw and re-read assertions.
  - The import makes CAP-003-E1-S6 (already implemented at the review base) a direct dependency the plan lists as context only. Record that as a plan deviation.
  - If the coder holds that the delivered formatter should stand, that contradicts ui-components 2.5 and UX design 0.7, so it is a question for the owner, not a provisional decision.
