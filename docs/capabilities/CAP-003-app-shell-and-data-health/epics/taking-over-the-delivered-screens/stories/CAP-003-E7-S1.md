# Export `requestJson` from the API Client

## User Story

As an owner-operator, I want the shell's new reads and the palette's universes read to reuse the product's one request function, so that every call carries the same error mapping and no second request path exists.

## Description

Logical component: `owner-web-app`. Adds the `export` keyword to `requestJson` in `web/src/api/client.ts` (line 154 of the delivered file, not exported today), the one-line change DAC-E7-12 conditions on CAP-002 not having added it first (DEC-0064). DEC-0211 gives `web/src/api/client.ts` to `owner-web-app`, so the export is this epic's even though `owner-shell`'s `shell-client.ts` (E3-S1) and the palette's `universes.ts` (E3-S4) are its first consumers; that is why those two stories in the earlier epic E3 depend on this one (DEC-0223). Nothing else in the file changes; `web/src/api/client.coverage.test.ts`, `client.runs.test.ts` and `render.test.tsx` stay unchanged. If CAP-002 has merged and already exported it when this story is scheduled, the story is a no-op and says so.

Breakdown and ordering: DEC-0223.
