### IR-001 — Step 2's blur-then-change validation timing is unpinned: `onBlur` and `onChange` both survive

- **Severity**: MEDIUM
- **Scope**: late. `step-history-depth.tsx:56` and the step 2 validation tests (`step-history-depth.test.tsx:471-503`) are unchanged since the baseline's `reviewed_head` `410a5225`, and v1 did not mutate the mode. Under step H a late survivor is MEDIUM at most and does not make T012 `WEAK`.
- **Status**: OPEN
- **Acceptance criteria**: DAC-E4-4 (step 2's field behaviour), via UX design §1.2 Step 2
- **Tasks**: T012, T017
- **Files**: `web/src/screens/setup/step-history-depth.tsx:56` (`mode: "onTouched"`); `web/src/screens/setup/step-history-depth.test.tsx:471-503`
- **Claim challenged**: T017: "`mode: "onTouched"` is the form contract's blur-then-change rule (CAP-003-E1-S2)"; T012 (d) "Blur validation".
- **Observed evidence**: In this review's mutation run, `step-history-depth.tsx:manual:review2-mode-onblur` (`"onTouched"` → `"onBlur"`) and `…:review2-mode-onchange` (`"onTouched"` → `"onChange"`) both pass every focused suite and `tsc`. Each validation test types a value, then tabs or clicks Continue, and only then asserts. No test asserts that no error shows before the field is left, or that a shown error clears when the value is corrected before the next blur.
- **Expected evidence/behavior**: `design-system/components/input/design-spec.md:47-48`: "Validation runs on blur, not on every keystroke … for numeric entry that is constant. - **Impact**: The code is correct today. A regression to `onChange` would show *History depth must be a whole number of years from 1 to 50.* mid-typing in the numeric field, which the input spec forbids. A regression to `onBlur` would leave that error on screen while the owner types a valid value, until they leave the field. Either would ship green.
- **Required remediation**: Add step 2 cases that fail under both modes. For example: type `0` and assert no `alert` before blur; then blur, see the alert; then type a valid value without blurring and assert the alert is gone. No production change is needed.
