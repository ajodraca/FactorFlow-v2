# `SetupDraftProvider`: Session Drafts Above the `/setup` Route

## User Story

As an owner-operator, I want what I typed in setup kept while I move between steps or leave and come back during a session, so that going back or looking at another screen never discards unsaved input.

## Description

Logical component: `setup-ui`. Creates `web/src/screens/setup/draft.tsx` with `SetupDraftProvider` and `useSetupDrafts()` as `component-design-setup-ui.md` §2.2 specifies: `SetupDrafts` holds `yearsText`, `source` (`"paste"` | `"later"` | null), `pasted` and `unposted` in React state only, never browser storage (system design §4.4; DEC-0202 as the owner amended it on 2026-10-25). This story has no screen: the provider is delivered first so that `owner-shell`'s frame (E3-S5) can mount it inside `ShellProvider` and outside the route map, which is the interleaving the epics backlog review v1 FINDING-2 asked to be stated (DEC-0223). `draft.test.tsx` proves survival across a route change with the provider above a memory router holding placeholder routes.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-3] Going back to an earlier step MUST keep every value entered in later steps.
- [DAC-E4-2] `SetupDraftProvider` MUST hold `yearsText`, `source`, `pasted` and `unposted` in React state only, mounted by the shell above the `/setup` route, so the drafts survive navigating away and back within the session; nothing MUST be written to `localStorage` or `sessionStorage`, and a freshly mounted provider starts empty. (traces to: AC-3)

### Derived

- [DAC-E4-S1-1] Given the provider above a memory router with a `/setup` consumer and a `/home` placeholder, When `yearsText` *7*, `source` *paste* and a pasted list are set on `/setup`, the router navigates to `/home` and back, Then `useSetupDrafts()` returns the same three values. (traces to: DAC-E4-2)
- [DAC-E4-S1-2] Given `localStorage` and `sessionStorage` spied, When every draft is set and the provider unmounts, Then neither store was written or read. (traces to: DAC-E4-2)
- [DAC-E4-S1-3] Given a freshly mounted provider, When read, Then `yearsText` and `pasted` are empty strings, `source` is null and `unposted` is empty. (traces to: DAC-E4-2)
- [DAC-E4-S1-4] Given `useSetupDrafts()` called outside the provider, When invoked, Then it throws an error naming the missing provider rather than returning undefined. (traces to: AC-3)
