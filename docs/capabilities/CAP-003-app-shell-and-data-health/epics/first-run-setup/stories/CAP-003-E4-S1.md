# Setup Drafts, Step State and the Setup Copy Catalogue

## User Story
As an owner-operator, I want every value I enter in setup kept for the session and each step's done flag re-derived from the server, so that going back or leaving never discards my input and never shows a step as done that is not.

## Description
Creates `web/src/screens/setup/draft.tsx` (`SetupDraftProvider`, `useSetupDrafts`: `yearsText`, `source`, `pasted`, `unposted` in React state only, never browser storage; DEC-0202 as the owner amended it), `web/src/screens/setup/use-setup-state.ts` (`SetupState`: `done` per step from `health` having answered, `GET /api/settings/history-depth` returning years, `GET /api/instruments?lifecycle=active&limit=1` returning `active_count` above 0, and `attention.latest_download` non-null in any state; `current` the first step not done, re-derived on every visit; `step4` `ready` or `blocked` while `active_count` is 0; `goTo`, `setDraft`) and `web/src/screens/setup/copy.ts`, every owner-facing string of UX design 1.2 and setup-ui 2.3 (setup-ui 2.1, 2.2). The provider is owned here and mounted by the shell in CAP-003-E4-S6 (DEC-0223). Writes `draft.test.tsx` and `use-setup-state.test.ts`.

Source: component-design-setup-ui.md 2.1, 2.2, 3, 7; epic CAP-003-E4 DAC-E4-1, DAC-E4-2.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC
- [AC-3] Going back to an earlier setup step MUST keep every value entered in later steps.
- [AC-2] Until a download has been requested, including after *Add later*, `/` MUST keep opening setup: step 4's done flag is `latest_download` non-null.
- [DAC-E4-1] Each step's done flag MUST follow its server fact, the current step MUST be the first not done, re-derived on every visit, and done steps MUST be links. (traces to: AC-3)
- [DAC-E4-2] `SetupDraftProvider` MUST hold the four drafts in React state only, mounted by the shell above the `/setup` route; nothing MUST be written to `localStorage` or `sessionStorage`, and a freshly mounted provider starts empty. (traces to: AC-3)

### Derived
- [DAC-E4-S1-1] Given `SetupDraftProvider` above a memory router, When the owner navigates from `/setup` to `/home` and back within the session, Then unsaved years text, radio choice and pasted text survive, and `localStorage` and `sessionStorage` hold nothing. (traces to: DAC-E4-2)
- [DAC-E4-S1-2] Given a depth read that fails, When the state derives, Then step 2 is not done and the state carries the read's error for the step to render *Couldn't read history depth: {reason}* with **Try again**; given `active_count` 0 with step 4 current, Then `step4` is `blocked`. (traces to: DAC-E4-13, AC-21)
- [DAC-E4-S1-3] Given `copy.ts`, When scanned for the DAC-E7-3 terms as whole words, Then none appears, and the plan-limit note states 5 years as copy, not a validation (setup-ui 3). (traces to: AC-19)
