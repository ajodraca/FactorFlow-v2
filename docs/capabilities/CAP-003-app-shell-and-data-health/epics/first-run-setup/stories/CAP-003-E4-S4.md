# Setup Step 4 and the Setup Screen: Start the First Download, Its Progress, the Blocked State and the Two Exits

## User Story
As an owner-operator, I want to start the first download from setup and watch its progress, or leave setup with nothing started and two honest exits, so that the first run ends where the product's own screens begin.

## Description
Creates `web/src/screens/setup/step-download.tsx` (step 4: the summary card restating the key badge, *{y} years* and *{n}* followed stocks; **Start download** calling the delivered `startAcquisitionRun()`, on `202` with `queued_behind` null calling `refresh("attention")` and rendering `progress` `determinate` *{done} of {total} stocks* (`indeterminate` while `total` is null), *Started {start time}*, *checked {time}* from attention's `checkedAt` and *You can leave; this keeps running.*; with `queued_behind` set *A download is running. This starts when it finishes.*; each `409` naming its step with **Go to step 2** or **Go to step 3**; *Progress can't be read right now* while attention fails; the blocked state after *Add later*: **Start download** `button` `blocked` described by *No stocks are followed. Follow stocks before downloading.*, **Go to Home** to `/home` and **Manage followed stocks** to `/data/followed`, neither rendering once `active_count` is above 0) and `web/src/screens/setup/index.tsx` (`SetupScreen`: the two-column layout inside the 1180 px main region, loads, re-derives steps, reads the drafts, exactly four steps; setup-ui 2.1, 2.3, 10). Writes `step-download.test.tsx` and `setup.test.tsx` (back keeps drafts).

Source: component-design-setup-ui.md 2.1, 2.3, 5, 7, 8, 10; epic CAP-003-E4 NFR *Freshness*, DAC-E4-8 to DAC-E4-12.

- [AC-15] When a download is already under way the product MUST accept the request and say it starts when the current one finishes.
- [AC-21] After *Add later*, setup MUST let the owner leave with no download started.
- [AC-24] Every setup region MUST render each of the eight states as designed or record why one does not apply.
- [AC-25] The polled progress MUST show its last-updated time; every setup operation MUST be completable by keyboard.
- [AC-26] Setup MUST be built from `ui-components` and consume theme tokens only.
- [DAC-E4-8] After *Add later* step 4 MUST render **Start download** `blocked`, focusable, described by its reason, sending no request, with **Go to Home** and **Manage followed stocks**, neither rendering once `active_count` is above 0; on each return the steps are re-derived. (traces to: AC-21, AC-2)
- [DAC-E4-9] **Start download** outcomes MUST be as stated for `202` with and without `queued_behind` and for each `409`. (traces to: AC-7, AC-15)
- [DAC-E4-10] **Start download** MUST NOT be blocked by a missing key. (traces to: AC-17)
- [DAC-E4-12] Step 4's summary card MUST restate the three facts, and the progress region while attention fails MUST read *Progress can't be read right now* beside the running state, never a frozen bar. (traces to: AC-24, AC-4)

- Consumes `POST /api/acquisition-runs` (`202` with `queued_behind`, `409 history_depth_not_set`, `409 no_active_instruments`) through the delivered `startAcquisitionRun`; `attention.latest_download.progress` through `useShell()`.

- None: no schema, migration, index or browser storage.
