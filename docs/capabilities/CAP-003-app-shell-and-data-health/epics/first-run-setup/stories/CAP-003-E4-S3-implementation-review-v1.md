### IR-004 — A post still in flight moves the owner after they have left step 3

- **Severity**: MEDIUM
- **Scope**: initial
- **Status**: OPEN
- **Acceptance criteria**: AC-3 (setup is a visible multi-step operation; Back changes the current step); DAC-E4-6 ("leave the step current")
- **Tasks**: T017
- **Files**: `web/src/screens/setup/step-stocks.tsx:180-214` (`post` calls `state.goTo(lines.length > 0 ? 3 : 4)` or `state.goTo(3)` after `await postInBatches`), `:230` (`onBack={() => state.goTo(2)}`, with no posting guard); `web/src/screens/setup/use-setup-state.ts:158` (`goTo` is a stable `useCallback` that sets the visit's `override`)

### IR-005 — Continue is unmounted and remounted when it switches between `blocked` and `default`

- **Severity**: LOW
- **Scope**: initial
- **Status**: OPEN
- **Acceptance criteria**: DAC-E4-7; AC-25
- **Tasks**: T016, T017
- **Files**: `web/src/screens/setup/step-card.tsx:81-94`
- **Claim challenged**: `continueBlocked` is additive and leaves the footer unchanged in use.
- **Observed evidence**: The blocked branch is a Fragment (`<p id={reasonId}>` plus `<Button variant="blocked">`). - **Required remediation**: Keep a single `Button` element and switch its `variant` and `aria-describedby`, rendering the reason `<p>` conditionally beside it. Alternatively, show with a test that a click survives the toggle.
