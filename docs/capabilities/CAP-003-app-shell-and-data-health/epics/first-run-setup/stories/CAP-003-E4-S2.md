# Setup Screen Scaffold: Step State, Stepper, Step Card and Step 1 (Market Data Key)

## User Story

As an owner-operator, I want setup to show its four steps, my position and what remains, opening on the first step not done and stating whether the market data key was found, so that I know where I am and never see the key's value.

## Description

Logical component: `setup-ui`. Creates `web/src/screens/setup/index.tsx` (`SetupScreen`), `use-setup-state.ts` (step derivation over the server facts and the drafts, §2.2), `step-list.tsx` (E1-S8's `stepper` `vertical` inside a `nav` *Setup steps*), `step-card.tsx` (the step card composition of §10: *Step {n} of 4*, the question as `h2`, the explanation at `LAYOUT.explanationMeasure`, the footer with **← Back** and **Continue**), `step-market-data.tsx` (step 1) and `copy.ts`, as `component-design-setup-ui.md` §2.1 specifies. Steps 2 to 4 render placeholders from `copy.ts` here and are filled by E4-S3 to E4-S5. Done flags come from the server on every visit: health answered, `GET /api/settings/history-depth` returns years, `GET /api/instruments?lifecycle=active&limit=1` returns `active_count` above 0, `attention.latest_download` non-null (DAC-E4-1). Layout reads the 1180 px cap, the 260 to 300 px column, the 28 px dot and 70ch from `LAYOUT` (AC-26). The `/setup` route is registered by E3-S7.

Carries AC-19 and AC-20 for this screen (review v1 FINDING-4): every string lives in `copy.ts` in the display vocabulary and the key presence renders through `badge` and `NotDeterminable`.

Breakdown and ordering: DEC-0223.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-3] Setup MUST show its steps, the owner's position and what remains.
- [AC-4] Setup MUST state whether the market data credential was found and, when it is missing, which environment variable to set, and MUST NOT display its value.
- [AC-24] Every setup region MUST render each of the eight states as designed or record why one does not apply.
- [AC-25] Every setup operation MUST be completable by keyboard.
- [AC-26] Setup MUST be built from `ui-components` and consume theme tokens only.
- [AC-19] Every user-visible label MUST use the display label STD-UI-1 defines.
- [AC-20] Every status MUST render as its single tier with label and shape.
- [DAC-E4-1] Step 1 is done when health has answered, step 2 when `GET /api/settings/history-depth` returns years, step 3 when `GET /api/instruments?lifecycle=active&limit=1` returns `active_count` above 0, and step 4 when `attention.latest_download` is non-null in any state; the current step MUST be the first not done, re-derived on every visit, and done steps MUST be links. (traces to: AC-3)
- [DAC-E4-3] Step 1 MUST render `badge` `status-good` *Found* or `status-critical` *Missing*, and when missing *Set the environment variable `FACTORFLOW_MASSIVE_API_KEY` to your Massive API key.* and *Restart FactorFlow after setting it.*; while health is unreachable it MUST render `coverage-unknown` *Not determinable* with its reason; **Continue** MUST always be available on step 1. (traces to: AC-4)
- [DAC-E4-11] Setup MUST show exactly four steps with the paper trading step absent. (traces to: AC-3)
- [DAC-E4-13] A failed depth or count read MUST show *Couldn't read {history depth / the followed list}: {reason}* with **Try again** in that step only. (traces to: AC-24)

### Derived

- [DAC-E4-S2-1] Given health answered, years set, `active_count` 0 and no download, When `/setup` renders, Then steps 1 and 2 are done and links, step 3 is current with `aria-current="step"`, step 4 is to do, and focus is on step 3's `h2`. (traces to: DAC-E4-1)
- [DAC-E4-S2-2] Given `credential_present` false, When step 1 renders, Then the `StatusBadge` reads *Missing* at the critical tier, the two sentences name `FACTORFLOW_MASSIVE_API_KEY` and the restart, and the document contains no string longer than the variable name that resembles a key. (traces to: DAC-E4-3)

- [DAC-E4-S2-4] Given the step list, When rendered, Then it is a `nav` *Setup steps* holding an `ol` of exactly four items whose titles are *Market data*, *How far back*, *Stocks to follow* and *Download data*, with done steps saying *done* in text. (traces to: DAC-E4-11, AC-25)
- [DAC-E4-S2-5] Given `GET /api/settings/history-depth` failing, When rendered, Then step 2's card body reads *Couldn't read history depth: {reason}* with **Try again** and the other steps render normally. (traces to: DAC-E4-13)
- [DAC-E4-S2-6] Given every string in `copy.ts`, When scanned, Then none contains *instrument*, *acquisition*, *acquire*, *run* or *Provider credential* as a whole word. (traces to: AC-19)

## Technical Details

### API Contract

Consumes `GET /api/settings/history-depth` (delivered `getHistoryDepth`), `GET /api/instruments?lifecycle=active&limit=1` (delivered `listInstruments`) and `useShell()` (`health.credential_present`, `attention.latest_download`). Exposes `SetupScreen`.

### Implementation

- New: `web/src/screens/setup/index.tsx`, `use-setup-state.ts`, `step-list.tsx`, `step-card.tsx`, `step-market-data.tsx`, `copy.ts`, `use-setup-state.test.ts`, `setup.test.tsx`, `step-market-data.test.tsx`.
- The `h1` is *Get set up* with `tabIndex={-1}` for the shell's focus rule.
