# Step 4: Start the First Download, Its Progress and the Blocked State After *Add Later*

## User Story

As an owner-operator, I want to start the first download from setup, watch its progress while I stay and leave whenever I like, and, if I followed no stocks yet, see why I cannot start and where to go, so that setup ends in a running download or an honest exit.

## Description

Logical component: `setup-ui`. Creates `web/src/screens/setup/step-download.tsx` as `component-design-setup-ui.md` §2.3 and §10 specify: the `card` `summary` restating the key presence badge, *{y} years* and *{n}* followed stocks; **Start download** calling the delivered `startAcquisitionRun()`; on `202` with `queued_behind` null, `refresh("attention")` then `progress` `determinate` *{done} of {total} stocks* (`indeterminate` while `total` is null) from `attention.latest_download.progress`, *Started {start time}*, *checked {time}* from the read's `checkedAt` at the shell's 10 s cadence, and *You can leave; this keeps running.*; with `queued_behind` set, *A download is running. This starts when it finishes.*; each `409` naming its step. While `active_count` is 0 (after *Add later*), **Start download** is `button` `blocked` described by *No stocks are followed. Follow stocks before downloading.* with **Go to Home** (`/home`) and **Manage followed stocks** (`/data/followed`), neither rendering once `active_count` is above 0 (DEC-0202 as amended). While attention fails the progress region reads *Progress can't be read right now* beside the running state. The screen opens no interval.

Breakdown and ordering: DEC-0223.

## Technical Details

### API Contract

- Endpoint: `POST /api/acquisition-runs` (delivered, unchanged); Request: none; Response: `202 { run_id, queued_behind }`; Errors: `409 history_depth_not_set`, `409 no_active_instruments`.
- Progress and the done flag come from `useShell().attention.latest_download` (E2-S2's shape through E3-S2).
