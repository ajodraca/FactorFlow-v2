# Step 2: History Depth

## User Story

As an owner-operator, I want to state how far back history should go and have it saved through the product's existing setting, so that the download requests the depth I chose and a bad value is corrected in place.

## Description

Logical component: `setup-ui`. Creates `web/src/screens/setup/step-history-depth.tsx` as `component-design-setup-ui.md` §2.3 and §10 specify: `form` `stacked` with `input` `numeric` and the suffix *years*, the explanation *Whole years, 1 to 50.*, the plan-limit note *Your provider plan holds 5 years. A deeper depth is requested as stated; the provider returns what it holds.* (copy, not a validation), **Continue** saving through the delivered `setHistoryDepth` (`PUT /api/settings/history-depth`), a `422` rendered as the field error *History depth must be a whole number of years from 1 to 50.* with the value kept, and the typed text held in the drafts' `yearsText` so going back keeps it. On `200` the step's done summary reads *{y} years of history* and step 3 becomes current.

Breakdown and ordering: DEC-0223.

- [DAC-E4-S3-2] Given *60* typed, When the server answers `422`, Then the field shows the error text linked by `aria-describedby`, the input still reads *60*, and step 2 stays current. (traces to: DAC-E4-4)
- [DAC-E4-S3-3] Given *8* typed, no save, and **← Back** then step 2 reopened, When rendered, Then the input reads *8* from `drafts.yearsText`. (traces to: AC-3)

## Technical Details

### API Contract

- Endpoint: `PUT /api/settings/history-depth` (delivered, unchanged); Request: `{"years": n}`, 1 to 50; Response: `200 { years }`; Errors: `422` beyond the range.
- Endpoint: `GET /api/settings/history-depth` (delivered) for the done flag, read by E4-S2.
