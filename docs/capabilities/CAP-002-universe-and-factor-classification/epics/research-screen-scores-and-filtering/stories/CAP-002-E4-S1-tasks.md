# Tasks: CAP-002-E4-S1 — Classification Fetch Layer, Response Types and the requestJson Export

**Story**: `repos/factorflow-v2/FactorFlow-v2/docs/capabilities/CAP-002-universe-and-factor-classification/epics/research-screen-scores-and-filtering/stories/CAP-002-E4-S1.md`
**Component**: `FactorFlow-v2` (web interface, `web/src/`)
**Branch**: `usr/alvaro-de-jodra/CAP-002-E4-tasks`
**Date**: 2026-10-17

## Summary

Delivers the typed fetch layer every CAP-002 screen reads through: response types that mirror `classification-api` section 2.7 (`web/src/api/classification-types.ts`), a client with one function per universe and classification endpoint that maps the snake_case wire to camelCase and keeps decimal-string scores and `YYYY-MM-DD` dates as strings (`web/src/api/classification-client.ts`), and the one-keyword edit that exports `requestJson` from the delivered `web/src/api/client.ts` (DEC-0064, DEC-0086). An error envelope reaches the caller as a `ClassificationApiError` carrying code, operation, resource and reason without any prose being parsed, and `neverClassified`, `set` and `later` are one shape on both the list and the summary read, so the never-populated state (AC-22) and the not-current state (AC-20) are expressible before any screen exists. No screen, hook or copy is built here.

### Open Gaps

1. **Operation and reason on the error (DAC-E4-S1-2). PROVISIONAL — awaiting owner confirmation (2026-10-17). Recorded as DEC-0143.** The envelope has `code`, `message`, `resource`, `request_id`; it has no `operation` or `reason` field, and classification-api section 2.5 says the *message prose* names the operation, resource and reason, which the interface must not parse. Adopted: `operation` is a stable identifier the client itself assigns per function (a `ClassificationOperation` literal union, kebab-case of the function name, for example `"create-universe"`, `"list-classifications"`); `reason` is the envelope `code` (the code is the contract, section 2.5), `null` when absent; `resource` is the envelope's `resource` when it is one of the four `ClassificationResource` values (`universe`, `universe-member`, `classification`, `classification-set`, classification-api section 2.5). Otherwise it is the resource the endpoint belongs to (the per-function list in T011). That covers a body that is not an envelope, and an envelope that carries any other value, as a `422` `validation_error` raised through the delivered validation handler does: the path's last segment, classification-api section 2.3 (CAP-002-E1-S6's own `validation_error` for a malformed member symbol carries `universe-member`, DEC-0100, and is kept). Derivation: DAC-E4-S1-2 names the four values, only `code` and `resource` exist on the wire, `copy.ts` (a later story) maps code and operation to the display sentence (classification-ui section 2.4). Follow-up: classification-ui section 2.4 should name the operation identifiers when next revised. Owner-directed fix (cross-plan review 2026-10-18, E4-F10): `ClassificationApiError.resource` is normalised to a `ClassificationResource`. The envelope value is kept only when it is one of the four values of classification-api section 2.5. Any other value is replaced by the operation's own resource listed in T011, including the path-segment resources (`universes`, `members`, `classifications`, `summary`, `history`, or an offending path value) that a `422` `validation_error` carries under section 2.3. No raw envelope string is kept; T003 and T007 pin both branches. — Derivation: section 2.5 lists the four resources the interface labels (DEC-0149). Section 2.3, by contrast, sends validation errors with the path segment and forbids editing `_VALIDATION_ERROR_RESOURCES` (CAP-002-E1-S6 T019, CAP-002-E3-S5 Open Gap 8). Passing the envelope value through would therefore leave CAP-002-E4-S2's `RESOURCE_LABELS[resource]` undefined for CAP-002-E4-S8's over-long-name refusal and for every other validation error. Normalising in the one fetch layer keeps the union true for every consumer without changing an approved artifact; DEC-0143 is amended to match.
2. **Reading `resource` and `symbols` without editing `toApiError`. PROVISIONAL — awaiting owner confirmation (2026-10-17). Recorded as DEC-0143.** The delivered `ApiError` does not retain the envelope's `resource` or the `instrument_not_acquired` `symbols` list (classification-api section 2.5), the create dialog (TC-COMP-006, E1-S7) must name every unfollowed stock, and DAC-E4-S1-1 permits no edit to `client.ts` beyond the keyword.
