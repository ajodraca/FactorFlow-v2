# Tasks: CAP-002-E4-S9 — Research Screen: Results Pane, Never-Populated State and Set History Dialog

**Story**: `repos/factorflow-v2/FactorFlow-v2/docs/capabilities/CAP-002-universe-and-factor-classification/epics/research-screen-scores-and-filtering/stories/CAP-002-E4-S9.md`

## Summary

Delivers the Research screen itself, in `web/src/screens/research/`: `index.tsx` (the default export `ResearchScreen`, which CAP-002-E4-S10 routes to), `results-pane.tsx` (the Results card: banner, `h1`, as-of line, **Save these {n} as a universe…**, table, selection tray, the STD-UI-18 footnote, and the two table bodies, never-populated and nothing-found) and `set-history-dialog.tsx` (**Earlier sets…**, DEC-0073, DEC-0078). It composes what E4-S4 to S8 built and builds none of it again: the poll hook, banner and as-of line (S4), the Filters pane and `useResearchQuery` (S5), the results table (S6), the tray and inspector (S7), and the Save and Add dialogs with the notices (S8). `ResearchScreen` holds the one `useResearchQuery`, the one `useScoreSetPoll` (its `onNewSet` bumps the table's `refreshKey` once), `selected` and `checked` by symbol, the first-page result, and the one `useNotices`/`NoticeRegion`. The `h1`, the Save control's count and set id, and the as-of line's set describe the rows on screen (`matchCount` and `set` from the list result); the banner and the first set's Updating or Score update failed state come from the poll's summary. Before any set exists the body states that no stocks have been scored, shows the first set's state from `later` and the latest download's state, and is a different body from *No stocks match these filters.* with **Clear filters**. Sort, thresholds, scope, hide-incomplete and search live in the URL and are restored on reload and back. Seven prerequisites (E4-S1, S2, S4, S5, S6, S7 and S8) must be on the branch and are read before coding; none is on it when this plan is written.
