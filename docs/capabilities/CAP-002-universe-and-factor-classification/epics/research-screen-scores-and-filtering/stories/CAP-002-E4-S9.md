# Research Screen: Results Pane, Never-Populated State and Set History Dialog

## User Story

As an owner-operator, I want the Research screen at /research showing every followed stock's value, growth and momentum classification, so that I can see what is scored and whether it is current.

## Description

Delivers `web/src/screens/research/index.tsx`, `results-pane.tsx` (banner, h1, as-of line, Save as universe, table, STD-UI-18 footnote), `set-history-dialog.tsx` (DEC-0073, DEC-0078) and the never-populated state, composing the patterns, filters pane, table, tray, inspector and dialogs built by CAP-002-E4-S4 to S8. This is the `ResearchScreen` the composition story routes to.

Source: `component-design-classification-ui.md` sections 2.3 to 2.6, 7; `ux-design.md` sections 1.1, 1.2.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-9] Every classified factor MUST be shown as a standardised score together with a percentile rank from 0 to 100. (display side)
- [AC-11] Classifications for up to 3000 actively acquired stocks MUST be up to date within 5 minutes of the acquisition run ending. (the UI must render at that volume without degrading)
- [AC-12] The product MUST NOT show a score or percentile on a factor for a stock unless every input that factor needs is present and current, and MUST instead show the stock as not classified on that factor with the missing or outdated input named.
- [AC-14] When fewer than 30 stocks qualify on a factor, the product MUST NOT show scores or percentiles on that factor, and MUST state that there are not enough stocks to rank and how many qualified.
- [AC-16] The user MUST be able to sort stocks by any factor's score or percentile, filter them with thresholds on one or more factors at once, and view chosen stocks side by side, both across all classified stocks and within a single universe. (the sort, filter and selection controls)
- [AC-20] Until a new set of classifications is complete, the product MUST show the previous set marked as not reflecting the latest acquisition, and MUST NOT show a half-finished set as current. When classification fails, the product MUST also show the failure and its reason.
- [AC-21] The user MUST be able to see when the current classifications were produced and which acquisition run they reflect.
- [AC-22] Before any classification has been produced, the product MUST state that no stocks have been classified rather than presenting an empty list as complete.
- [DAC-E4-2] Before any score exists, the results body MUST state that no stocks have been scored, rather than an empty table, and MUST show the first set's Updating or Score update failed state from the same `later` block a populated screen would use. (traces to: AC-22)
- [DAC-E4-3] The results heading MUST read the server's `match_count`, never the number of rows loaded into the table, and sort, thresholds, scope, hide-incomplete and search MUST survive a reload and back navigation because they live in the URL. (traces to: AC-16)
- [DAC-E4-4] While a later set is building, the current set MUST stay displayed with a warning banner and an "Updating" mark; when the attempt fails, the banner MUST read the recorded reason and offer nothing to retry; on completion the table MUST refresh exactly once, announced, with sort, filters, selection and checked rows preserved. (traces to: AC-20, AC-21)

### Derived

- [DAC-E4-S9-1] Given a never-populated store, When the screen renders, Then the body reads No stocks have been scored yet with the first set's Updating or Score update failed and the download's state, and is distinct from No stocks match these filters with Clear filters. (traces to: DAC-E4-2)
- [DAC-E4-S9-2] Given a result, When the heading renders, Then the h1 shows the server's `matchCount`, not the loaded row count. (traces to: DAC-E4-3)
- [DAC-E4-S9-3] Given a reload or back navigation, When the screen loads, Then thresholds, scope, hide-incomplete, search and sort are restored from the URL. (traces to: DAC-E4-3)
- [DAC-E4-S9-4] Given Earlier sets, When activated, Then the history dialog opens listing sets by download start time and focus returns to the control on close. (traces to: AC-21)
- [DAC-E4-S9-5] Given the footnote, When rendered, Then the statement that absence judges presence and currency, not provider correctness, appears once (STD-UI-18). (traces to: AC-12)
