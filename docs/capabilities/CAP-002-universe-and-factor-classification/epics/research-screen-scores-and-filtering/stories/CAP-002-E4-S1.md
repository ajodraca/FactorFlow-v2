# Classification Fetch Layer, Response Types and the requestJson Export

## User Story

As an owner-operator, I want one typed fetch layer for the universe and classification endpoints, so that every screen reads the API's envelope and errors the same way.

## Description

Delivers `web/src/api/classification-client.ts` and `web/src/api/classification-types.ts` (types mirroring classification-api section 2.7, snake_case on the wire mapped to camelCase) and makes the one edit to the delivered `web/src/api/client.ts`: the `export` keyword on `requestJson` (DEC-0064).

Ordering decision: the `requestJson` export is made here, in the story whose module first imports it, and not in the shell composition story, because `classification-client.ts` cannot compile without it (DEC-0086). CAP-002-E4-S10 keeps the rest of the shell composition.

Source: `component-design-classification-ui.md` sections 2.1, 2.2, 2.4.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-16] The user MUST be able to sort stocks by any factor's score or percentile, filter them with thresholds on one or more factors at once, and view chosen stocks side by side, both across all classified stocks and within a single universe. (the sort, filter and selection controls)
- [AC-20] Until a new set of classifications is complete, the product MUST show the previous set marked as not reflecting the latest acquisition, and MUST NOT show a half-finished set as current. When classification fails, the product MUST also show the failure and its reason.
- [AC-22] Before any classification has been produced, the product MUST state that no stocks have been classified rather than presenting an empty list as complete.
- [DAC-E4-3] The results heading MUST read the server's `match_count`, never the number of rows loaded into the table, and sort, thresholds, scope, hide-incomplete and search MUST survive a reload and back navigation because they live in the URL. (traces to: AC-16)

### Derived

- [DAC-E4-S1-1] Given `client.ts`, When the export is added, Then only the `export` keyword changes and every delivered client test still passes. (traces to: AC-16)
- [DAC-E4-S1-2] Given an API error envelope, When the fetch layer receives it, Then it surfaces the code, operation, resource and reason to the caller without parsing prose. (traces to: AC-22)
- [DAC-E4-S1-3] Given a response with `set` null and `later` populated, When typed, Then the types express `neverClassified`, `set` and `later` as one shape. (traces to: AC-22)
- [DAC-E4-S1-4] Given every response in classification-api section 2.7, When mapped, Then each field has a typed counterpart and decimal-string scores stay strings until formatted. (traces to: DAC-E4-3)
