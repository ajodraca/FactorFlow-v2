# Not-Current Banner, As-Of Line and the Score-Set Poll with Refresh-Once

## User Story

As an owner-operator, I want to know whether the scores I see are current, and see them refresh once when a new set completes, so that I never act on a stale or half-built result unknowingly.

## Description

Delivers `web/src/components/patterns/not-current-banner.tsx`, `as-of-line.tsx` and `web/src/screens/research/use-score-set-poll.ts`. The poll reads the summary every 10 seconds from first load, including before any set exists, while `later.state` is `building` or the latest download is non-terminal, and stops otherwise (STD-UI-25). On completion it refreshes once, announced, preserving sort, thresholds, scope, hide-incomplete, search, selection and checked rows by symbol.

Source: `component-design-classification-ui.md` sections 2.3, 2.6, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-20] Until a new set of classifications is complete, the product MUST show the previous set marked as not reflecting the latest acquisition, and MUST NOT show a half-finished set as current. When classification fails, the product MUST also show the failure and its reason.
- [AC-21] The user MUST be able to see when the current classifications were produced and which acquisition run they reflect.
- [AC-22] Before any classification has been produced, the product MUST state that no stocks have been classified rather than presenting an empty list as complete.
- [DAC-E4-2] Before any score exists, the results body MUST state that no stocks have been scored, rather than an empty table, and MUST show the first set's Updating or Score update failed state from the same `later` block a populated screen would use. (traces to: AC-22)
- [DAC-E4-4] While a later set is building, the current set MUST stay displayed with a warning banner and an "Updating" mark; when the attempt fails, the banner MUST read the recorded reason and offer nothing to retry; on completion the table MUST refresh exactly once, announced, with sort, filters, selection and checked rows preserved. (traces to: AC-20, AC-21)

### Derived

- [DAC-E4-S4-1] Given `later` null, When the banner renders, Then none appears; given `building`, Then a `status-warning` banner reads Not reflecting the latest download with Updating on the as-of line. (traces to: DAC-E4-4)
- [DAC-E4-S4-2] Given a failed attempt, When the banner renders, Then it reads Score update failed with the recorded reason, keeps the previous set and offers nothing to retry. (traces to: DAC-E4-4)
- [DAC-E4-S4-3] Given the as-of line, When rendered, Then it reads Scores from {time} from the download started {time} in America/Chicago linked to run detail, with no number or UUID. (traces to: AC-21)
- [DAC-E4-S4-4] Given a failed poll, When it errors, Then the banner stays and a Try again control is offered. (traces to: DAC-E4-4)
- [DAC-E4-S4-5] Given the poll reports a new complete set, When it arrives, Then exactly one announcement and one reload occur and no second reload follows. (traces to: DAC-E4-4)
- [DAC-E4-S4-6] Given a never-populated store, When the poll runs, Then it polls from first load and the first completion renders the populated state. (traces to: DAC-E4-2)
