# Virtualised Results Table with Server-Side Sort and Selection

## User Story

As an owner-operator, I want a results table that stays responsive at 3000 stocks with server-side sorting and independent selection and checking, so that I can scan every followed stock and pick some.

## Description

Delivers `web/src/screens/research/results-table.tsx`, the virtualised data-table composition shared by the Research screen and universe members. Sorting is a request with `sort` and `order`; the column header states the qualified count once for a factor below 30 stocks; selection (row activation, arrows with a 150 ms debounced single stock read) and checking (checkbox, Space) are independent and checked rows survive sort, filter, scope and refresh.

Source: `component-design-classification-ui.md` sections 2.5, 5, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-9] Every classified factor MUST be shown as a standardised score together with a percentile rank from 0 to 100. (display side)
- [AC-11] Classifications for up to 3000 actively acquired stocks MUST be up to date within 5 minutes of the acquisition run ending. (the UI must render at that volume without degrading)
- [AC-12] The product MUST NOT show a score or percentile on a factor for a stock unless every input that factor needs is present and current, and MUST instead show the stock as not classified on that factor with the missing or outdated input named.
- [AC-14] When fewer than 30 stocks qualify on a factor, the product MUST NOT show scores or percentiles on that factor, and MUST state that there are not enough stocks to rank and how many qualified.
- [AC-16] The user MUST be able to sort stocks by any factor's score or percentile, filter them with thresholds on one or more factors at once, and view chosen stocks side by side, both across all classified stocks and within a single universe. (the sort, filter and selection controls)
- [DAC-E4-1] A scored factor cell MUST show a whole-number percentile and a bar; an incomplete factor MUST show "Incomplete" and name the input that fell short; a factor below 30 qualifying stocks MUST show "Not enough to rank" in every cell of that column with the count stated once in the header. (traces to: AC-9, AC-12, AC-14)

### Derived

- [DAC-E4-S6-1] Given a factor with fewer than 30 qualifying stocks, When the table renders, Then the header carries {n} qualified, 30 needed, every cell is Not enough to rank and the column's sort control is absent. (traces to: AC-14)
- [DAC-E4-S6-2] Given a sort activation, When made, Then a request with `sort` and `order` is issued, `aria-sort` follows, focus does not move and the new match count is announced. (traces to: AC-16)
- [DAC-E4-S6-3] Given a stock incomplete on one factor, When the table renders, Then two percentiles and one Incomplete appear and incomplete rows sort last, described in the header. (traces to: AC-12)
- [DAC-E4-S6-4] Given Click or Enter selects and Space on the checkbox checks, When used, Then selection (`aria-selected`) and checking never interfere. (traces to: AC-16)
- [DAC-E4-S6-5] Given 3000 rows, When rendered, Then the DOM does not grow with the result size (virtualised). (traces to: AC-11)
