# Tasks: CAP-002-E4-S4 — Not-Current Banner, As-Of Line and the Score-Set Poll with Refresh-Once

**Story**: `repos/factorflow-v2/FactorFlow-v2/docs/capabilities/CAP-002-universe-and-factor-classification/epics/research-screen-scores-and-filtering/stories/CAP-002-E4-S4.md`

## Summary

Delivers the score-set state every scored CAP-002 surface shows: `web/src/components/patterns/not-current-banner.tsx` (the `status-warning` *Not reflecting the latest download* banner while a later set builds, the `status-critical` *Score update failed* banner with the recorded reason and no retry, nothing otherwise), `web/src/components/patterns/as-of-line.tsx` (*Scores from {time} from the download started {time}* with the start time as the link to run detail, the *Updating* badge and *checked {time}* while a set builds, the *Complete*/*Partial* outcome badge, *Could not check for newer scores.* with **Try again**, and one polite live region that announces the completion, *Updating* and a failed poll) and `web/src/screens/research/use-score-set-poll.ts` (polls `getClassificationSummary` from first load every 10 seconds while `later.state` is `building` or the shell health reports a non-terminal `most_recent_run`, and on a new set announces once and calls the host's `onNewSet` once). No screen, table or dialog is built here: E4-S9 composes these three into the Research screen and owns the never-populated body (DAC-E4-S9-1), the set-history dialog and the table reload that `onNewSet` triggers; UX design 1.2 also places the banner and the line on universe detail, Compare and Stock evidence, but no story mounts them there (CAP-002-E1-S8's plan Open Gaps, DEC-0175, DEC-0184), so CAP-002-E4-S9 is their only planned consumer.

## Notes

### Resolved Conflicts

1. **"Offers nothing to retry" (DAC-E4-4, DAC-E4-S4-2) against a **Try again** control (DAC-E4-S4-4).** They concern different failures: a failed classification attempt (the recorded `failureReason`; the scheduler does not retry it, so the banner has no control, STD-UI-2) and a failed status read (a transport failure of the summary call; the owner can re-ask). Established by UX design 1.2 ("Failure", "Error" state) and the test coverage matrix note 7 (`tests/coverage-matrix.md` line 319). The banner has no control; **Try again** lives in the as-of line (design 2.6: "adds *Could not check for newer scores.* with **Try again** under the as-of line") and, in the never-populated state, which renders no as-of line, in E4-S9's never-populated body (Open Gap 3, DEC-0155 as amended). No gap.
2. **"A new `set`, `later` null" (design 2.6, UX 1.2) against detecting completion on `setId` alone.** Completion is a `set.setId` change; the extra "later null" condition is a rationale of the common case and would miss a set that completes while another already builds, or the first set arriving. The two coincide in every sequence the tests name. Settled by the precedence ladder (the AC says "a new complete set" and "exactly one", DAC-E4-S4-5); recorded as DEC-0153.
3. **Banner time as `17:46 CDT` (UX 1.2 examples) against the as-of line's `2026-10-15 17:46 CDT`.** STD-UI-5 requires a time with its zone; S2 ships one formatter. Open Gap 4.
4. **Banner for a never-scored store.** UX design 1.2 says the never-scored condition "replaces the results body rather than heading it" with "no as-of line", and classification-ui 2.6 renders *Updating* or *Score update failed* inside that body from `later`. Hence the banner and the line render nothing when `set` is null; the body is E4-S9's (DAC-E4-S9-1). Established by the designs; no gap.
5. **The story cites classification-ui sections 2.3, 2.6, 7.** Section 2.3 holds the cadence, section 2.6 the behaviour and the as-of line text, section 7 the testing; the banner wording is in UX design 1.2. The story's source line should add UX design 1.2 at its next revision. Not a conflict.
