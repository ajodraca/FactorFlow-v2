# URL Query Model, Display Formatting and the Owner-Facing Copy Catalogue

## User Story

As an owner-operator, I want filters that live in the URL and strings and numbers formatted one way everywhere, so that filters survive reload and every screen speaks the same words.

## Description

Delivers `web/src/api/research-query.ts` (URL query to `ResearchQuery` and back: the twelve bounds, scope, `hide_incomplete`, `symbol`, sort, order; invalid keys dropped), `web/src/screens/research/format.ts` (DEC-0063 precision, sign, dates, America/Chicago zone) and `web/src/screens/research/copy.ts` with the full message catalogue of `classification-ui` section 2.8 keyed by error code and state, including the `SHELL_ROUTES` map. Later stories import strings from this catalogue and do not add to it unless a design message is missing.

Source: `component-design-classification-ui.md` sections 2.4, 2.8, 7; `ux-design.md` section 0.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-9] Every classified factor MUST be shown as a standardised score together with a percentile rank from 0 to 100. (display side)
- [AC-16] The user MUST be able to sort stocks by any factor's score or percentile, filter them with thresholds on one or more factors at once, and view chosen stocks side by side, both across all classified stocks and within a single universe. (the sort, filter and selection controls)
- [DAC-E4-1] A scored factor cell MUST show a whole-number percentile and a bar; an incomplete factor MUST show "Incomplete" and name the input that fell short; a factor below 30 qualifying stocks MUST show "Not enough to rank" in every cell of that column with the count stated once in the header. (traces to: AC-9, AC-12, AC-14)
- [DAC-E4-3] The results heading MUST read the server's `match_count`, never the number of rows loaded into the table, and sort, thresholds, scope, hide-incomplete and search MUST survive a reload and back navigation because they live in the URL. (traces to: AC-16)

### Derived

- [DAC-E4-S2-1] Given any `ResearchQuery`, When encoded and decoded, Then it round-trips equal, each threshold sentence maps to exactly one of the twelve bounds and an invalid key is dropped, not sent. (traces to: DAC-E4-3)
- [DAC-E4-S2-2] Given a save payload built from the query, When constructed, Then it is the twelve bounds, `hide_incomplete` and `symbol`. (traces to: DAC-E4-3)
- [DAC-E4-S2-3] Given scores, percentiles, ratios, rates and amounts, When formatted, Then `+1.27`, `-0.45`, `0.00` unsigned; percentile `84` without sign or `%`; ratios 2 dp; rates `+12.40%`; timestamps in America/Chicago with zone; dates unconverted. (traces to: AC-9)
- [DAC-E4-S2-4] Given `copy.ts`, When scanned, Then no owner-facing string contains instrument, acquisition run, not classified, retire, or a bare score where percentile or standardised score is meant (STD-UI-1). (traces to: DAC-E4-1)
