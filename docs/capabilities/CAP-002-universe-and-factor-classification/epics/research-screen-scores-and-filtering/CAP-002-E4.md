# Research Screen: Scores and Filtering

**EPIC ID:** CAP-002-E4
**Jira Key:** N/A
**Capability:** CAP-002
**Summary:** Deliver the Research screen (the product UX blueprint's S03) at `/research`, the owner's one entry point to see every followed stock's value, growth and momentum classification, filter and sort it server-side, and know at a glance whether the scores shown are current. This EPIC owns the single seam that composes CAP-002 into the delivered CAP-001 shell: one appended rail destination, Research, and the five `/research/*` routes every CAP-002 screen needs, registered once and changing no delivered behaviour, label or route. A cell that is not a measured value says so in text, shape and token, never colour alone, because this is the first FactorFlow surface that renders a derived number.
**Actors:** Owner-operator, classification-ui, classification-api (classification routes), owner-web-app (the delivered shell, composed into)
**Estimate:** L
**Out of Scope:** Computing classifications (E2); serving them (E3); universe write operations (E1), though this EPIC's Save-as-universe and Add-to-universe dialogs call them; the Compare and Stock evidence pages (E5).
**Dependencies:** E3 (`GET /api/classifications`, `/summary`, `/sets`). E1 (`POST /api/universes`, `POST .../members` — the Save-as-universe and Add-to-universe dialogs this screen hosts write through E1's API). This EPIC owns the one shell-composition seam (`shell.tsx`'s appended `DESTINATIONS` entry, `routes.tsx`'s five `Route` elements, `client.ts`'s `requestJson` export, and the four delivered shell tests whose navigation-item count moves from four to five) that registers every `/research/*` route at once; E1's and E5's screens render inside routes this EPIC's composition story creates, so both depend on it.
**Links:** system-design.md section 4.2 (Screen registration; Router registration; Scheduler start consumer; constraint 18 cadence); component-design-classification-ui.md sections 2.1 to 2.6; ux-design.md sections 0, 1.1, 1.2; PRODUCT-UX-S03.

## Goals

- Show every followed stock's value, growth and momentum classification, sorted and filtered server-side, with the match count the server computed, never a client-side count.
- Say plainly when nothing has been scored yet, and keep that visibly distinct from a filter that matched nothing.
- Show, without a page reload, when the previous set is not current because a newer one is building or the latest attempt failed, naming the recorded reason.
- Refresh exactly once, announced, when a new set completes, preserving sort, filters, scope, selection and checked rows.
- Let the owner save a reviewed result as a universe or add it to one, from the same filtered view the match count describes.
- Compose into the delivered shell with one appended destination and one set of shared routes, without changing any delivered behaviour, label or route.

## Non-Functional Requirements

- **Honesty in rendering (AC-12, AC-14, AC-20, AC-22, AC-23):** a cell that is not a measured value says so in text, shape and token, never colour alone; nothing renders beyond a recorded row.
- **Volume (AC-11, STD-UI-30):** 3000 rows render, sort, filter and scroll in a virtualised table without the DOM growing with the result size.
- **Polling cadence (STD-UI-25):** the summary poll runs every 10 seconds from first load, including before any set exists, while a later set is `building` or the latest download is non-terminal, and stops otherwise.
- **Accessibility (STD-UI-24, WCAG 2.1 AA):** every operation is keyboard-reachable; polled updates and the match count are announced politely; blocked controls stay focusable with their reason exposed through `aria-describedby`.
- **Composition discipline (AGT-SCOPE-002):** exactly one rail destination, five routes, one export and four counted-assertion edits touch delivered files; no other delivered behaviour, label or route changes.

## EPIC Acceptance Criteria

### From Capability

- [AC-2] The user MUST be able to save the result of a threshold filter as a named universe, and that universe's membership MUST NOT change afterwards unless the user changes it. (the Save-as-universe dialog this screen hosts)
- [AC-5] The product MUST refuse to create or save a universe with no members, and MUST refuse to remove a universe's last member. (the zero-match blocked state this screen renders)
- [AC-9] Every classified factor MUST be shown as a standardised score together with a percentile rank from 0 to 100. (display side)
- [AC-11] Classifications for up to 3000 actively acquired stocks MUST be up to date within 5 minutes of the acquisition run ending. (the UI must render at that volume without degrading)
- [AC-12] The product MUST NOT show a score or percentile on a factor for a stock unless every input that factor needs is present and current, and MUST instead show the stock as not classified on that factor with the missing or outdated input named.
- [AC-14] When fewer than 30 stocks qualify on a factor, the product MUST NOT show scores or percentiles on that factor, and MUST state that there are not enough stocks to rank and how many qualified.
- [AC-16] The user MUST be able to sort stocks by any factor's score or percentile, filter them with thresholds on one or more factors at once, and view chosen stocks side by side, both across all classified stocks and within a single universe. (the sort, filter and selection controls)
- [AC-20] Until a new set of classifications is complete, the product MUST show the previous set marked as not reflecting the latest acquisition, and MUST NOT show a half-finished set as current. When classification fails, the product MUST also show the failure and its reason.
- [AC-21] The user MUST be able to see when the current classifications were produced and which acquisition run they reflect.
- [AC-22] Before any classification has been produced, the product MUST state that no stocks have been classified rather than presenting an empty list as complete.

### Derived

- [DAC-E4-1] A scored factor cell MUST show a whole-number percentile and a bar; an incomplete factor MUST show "Incomplete" and name the input that fell short; a factor below 30 qualifying stocks MUST show "Not enough to rank" in every cell of that column with the count stated once in the header. (traces to: AC-9, AC-12, AC-14)
- [DAC-E4-2] Before any score exists, the results body MUST state that no stocks have been scored, rather than an empty table, and MUST show the first set's Updating or Score update failed state from the same `later` block a populated screen would use. (traces to: AC-22)
- [DAC-E4-3] The results heading MUST read the server's `match_count`, never the number of rows loaded into the table, and sort, thresholds, scope, hide-incomplete and search MUST survive a reload and back navigation because they live in the URL. (traces to: AC-16)
- [DAC-E4-4] While a later set is building, the current set MUST stay displayed with a warning banner and an "Updating" mark; when the attempt fails, the banner MUST read the recorded reason and offer nothing to retry; on completion the table MUST refresh exactly once, announced, with sort, filters, selection and checked rows preserved. (traces to: AC-20, AC-21)
- [DAC-E4-5] "Save these {n} as a universe…" MUST be blocked at zero matches and, when confirmed, MUST post the same thresholds, `hide_incomplete`, search prefix and set id the results header counted, so the created universe's member count equals that header's count. (traces to: AC-2, AC-5)
- [DAC-E4-6] The rail MUST gain exactly one Research destination and the five `/research` routes MUST register at the delivered seam, with the four delivered shell tests' navigation-item-count assertions moving from four to five and no other assertion in those files changing. (traces to the composition constraint, AGT-SCOPE-002; not a capability AC)
