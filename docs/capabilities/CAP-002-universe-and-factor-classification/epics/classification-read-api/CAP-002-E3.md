# Classification Read API: Scoring, Currency and Evidence

**EPIC ID:** CAP-002-E3
**Jira Key:** N/A
**Capability:** CAP-002
**Summary:** Serve one definition each of "current," "a filter match," and "a current stock," so every reader of classification data — the Research screen, a universe's filter snapshot, and the shell capability's future Home and Data health screens — sees the same answer computed from the same rows. Sorting, filtering and counting always run in SQL over the whole set, never a loaded page, so a result at 3000 stocks is never silently wrong. Before any set exists, or while a newer one is building or has failed, the read says so explicitly, with the previous set's currency and the newer attempt's state and reason carried beside it, never an empty table standing in for either. It also owns the one API-side composition point: mounting this capability's two routers and starting the classification scheduler's loop in the application lifespan, once.
**Actors:** classification-reader, classification-api, research-store, market-data-store (`instrument`, `acquisition_run`), universe-service (`membership_as_of` for universe scope), ingestion-api (`app.py`, the delivered composition root)
**Estimate:** L
**Out of Scope:** Computing the classifications being read (E2 — this EPIC starts E2's scheduler loop at the composition seam, DAC-E3-13, but does not define it); writing universe membership (E1, though this EPIC's `evaluate_filter` is what E1's filter-save calls); rendering any screen (E4, E5).
**Dependencies:** E2 (the `classification_set`, `factor_input` and `factor_classification` rows this EPIC reads; and `run_classification_loop` with `ClassificationSettings`, which this EPIC's composition story starts in `_lifespan`). The composition story is the last API story to land: the approved `app.py` edit imports `routes/universes.py` (E1's router story), `routes/classifications.py` (this EPIC's router story) and the scheduler module (E2's scheduler story), so it depends on all three and nothing depends on it at build time; until it lands, E1's and this EPIC's endpoints exist but are not mounted. E1 (`universe-service`'s `membership_as_of.sql`, imported rather than restated, for universe-scoped reads and the stock-memberships read — SA-DUP-001). The relationship with E1 is reciprocal at the story level, not the EPIC level: E1's own replay and schema stories land first, then this EPIC's `evaluate_filter` and list read, then E1's filter-save story, which calls `evaluate_filter`. That ordering is deliberate, as it is for CAP-001's provider-client and acquisition-runner EPICs.
**Links:** system-design.md sections 3.3, 4.2 (`GET /api/classifications`, `/summary`, `/sets`, `/sets/{set_id}`, `/stocks/{symbol}`, `/stocks/{symbol}/history`); component-design-classification-reader.md sections 2.2 to 2.7; component-design-classification-api.md section 2.3 (the edit to `app.py`), sections 2.4 to 2.7 (classifications routes, error mapping, response shapes), sections 4 and 7 (`test_api_no_secrets.py`); system-design.md section 4.2 (Router registration; Scheduler start) and section 8 question 4 (DEC-0084).

## Goals

- Resolve the current set as the latest set in state `complete`, and report any newer `building` or `failed` set beside it as `later`, in one shape before and after the first set.
- Serve a sorted, threshold-filtered, searched list of scored stocks over all followed stocks or one universe, with the match count computed over the whole result, never the page.
- Define `evaluate_filter` exactly once, so the list read and a universe's saved snapshot never disagree about what matched.
- Define what `hide_incomplete` excludes, so it hides only a stock whose incompleteness is an input reason, never an unranked or a retired stock.
- Serve 2-to-6-stock comparison that never drops a stock because it is incomplete.
- Serve one stock's inputs, their dates, its universe memberships, and its classification history exactly as recorded.
- Serve the one small summary a 10-second poll can afford: set state, per-factor counts and the current-stock count, with no stock rows.
- Mount this capability's two routers (`universes`, `classifications`) and start the classification scheduler task in the application lifespan, once, in the one delivered API file CAP-002 edits, so every endpoint of E1 and this EPIC is reachable and AC-10's refresh actually runs.

## Non-Functional Requirements

- **Correctness (STD-UI-15):** every value returned is a stored row; nothing is recomputed by this EPIC's components.
- **Performance at volume (AC-11, STD-UI-30):** the list query, its match count and its sort each run over one set's indexed rows (`idx_factor_classification_set_factor_score`/`_percentile`), never a client-side scan of 3000 rows.
- **Injection safety (SEC-INP-002):** `sort` resolves through a fixed allowlist of column expressions, never interpolated from the request.
- **Consistency (SA-DUP-001):** `current_set`, `evaluate_filter` and the current-stock rule are each defined exactly once in this EPIC's reader and reused by every caller, including `universe-service` today and the future shell capability.
- **Honesty (AC-20, AC-22):** a page or summary before any complete set exists says so explicitly, carrying the first set's `building` or `failed` state, never an empty table standing in for it.
- **Composition discipline (AGT-SCOPE-002; DEC-0064, DEC-0084):** the API side touches exactly two delivered files — `src/factorflow/api/app.py` (two `include_router` calls; one lifespan task created and cancelled beside the reclaim task) and `tests/unit/test_api_no_secrets.py` (the same no-credential assertion over the new routes) — and no other delivered route, model or behaviour changes.

## EPIC Acceptance Criteria

### From Capability

- [AC-9] Every classified factor MUST be shown as a standardised score together with a percentile rank from 0 to 100. (serve side: the read this EPIC returns)
- [AC-10] Classifications MUST be brought up to date without user action after every acquisition run that ends as succeeded or partial, and MUST NOT be recomputed after a run that ends as failed, cancelled or abandoned. (start side: the lifespan task that runs E2's scheduler loop; the loop itself and what it does are E2's)
- [AC-13] An input MUST be treated as outdated when it is a fundamental whose latest reported period ended more than 6 months before the classification date, or a price that is not from the latest trading day the product holds. (the current-stock summary rule derived from this)
- [AC-16] The user MUST be able to sort stocks by any factor's score or percentile, filter them with thresholds on one or more factors at once, and view chosen stocks side by side, both across all classified stocks and within a single universe.
- [AC-17] For any classification, the user MUST be able to see the inputs it was built from and the date on which each input was known.
- [AC-18] Every classification MUST be retained with the date it was produced and MUST NOT be overwritten, and the user MUST be able to see a stock's earlier classifications.
- [AC-20] Until a new set of classifications is complete, the product MUST show the previous set marked as not reflecting the latest acquisition, and MUST NOT show a half-finished set as current. When classification fails, the product MUST also show the failure and its reason. (serve side)
- [AC-21] The user MUST be able to see when the current classifications were produced and which acquisition run they reflect.
- [AC-22] Before any classification has been produced, the product MUST state that no stocks have been classified rather than presenting an empty list as complete.
- [AC-23] A value or growth classification MUST be marked as possibly reflecting restated data when any fundamental behind it was acquired as historical backfill, for a period already reported before acquisition of that stock began, and the mark MUST be retained with that classification in its history. (read-through side)

### Derived

- [DAC-E3-1] `current_set` MUST resolve to the latest set in state `complete`, and `later` MUST carry the most recent set newer than it (`building` or `failed`) or the first set while none is complete; `not_current` MUST be true exactly when `later` is non-null. (traces to: AC-20, AC-21)
- [DAC-E3-2] `evaluate_filter` MUST be the one predicate used by the list read, by compare, and by `universe-service`'s filter snapshot, covering the twelve threshold bounds, `hide_incomplete` and the symbol prefix identically for all three callers. (traces to: AC-16)
- [DAC-E3-3] A threshold on a factor MUST exclude only a stock classified on that factor that fails the bound; a stock incomplete or unranked on that factor MUST stay listed and counted. (traces to: AC-12 via the shared predicate, AC-16)
- [DAC-E3-4] `hide_incomplete` MUST exclude a stock only when its `not_classified` reason on any factor is `input_missing`, `input_outdated` or `input_not_computable`, never `not_enough_stocks` and never `retired`. (traces to: AC-14, AC-15 via the shared predicate)
- [DAC-E3-5] The unscoped list MUST be active instruments only; a universe scope or a compare request MUST keep retired members, rendered with their `retired` reason. (traces to: AC-15, AC-16)
- [DAC-E3-6] `match_count` MUST be the count over the whole filtered scope (lifecycle scope, thresholds, search, `hide_incomplete`), computed once per request and identical on every page of the same query. (traces to: AC-16)
- [DAC-E3-7] Compare MUST accept 2 to 6 symbols, never fewer or more, and MUST return every requested symbol that names a known instrument, with an unrecognised one reported in `unknown_symbols` rather than silently dropped. (traces to: AC-16)
- [DAC-E3-8] A stock's evidence read MUST return every `factor_input` row of the current set with its value, `as_of` and `known_on`, and the active universes the stock currently belongs to. (traces to: AC-17)
- [DAC-E3-9] A stock's history read MUST return only `complete` sets' results, newest first, exactly as each was recorded. (traces to: AC-18)
- [DAC-E3-10] A stock MUST be reported current in the summary exactly when none of its `factor_input` rows in the current set is `missing` or `outdated`; `not_computable` MUST NOT count against currency. (traces to: AC-13)
- [DAC-E3-11] The summary and the list read MUST carry the same `set` and `later` shape, including before any set exists, so every consumer — this capability's screens and the future shell capability's — reads one rule. (traces to: AC-20, AC-22)
- [DAC-E3-12] The restatement mark MUST be carried on every read that returns a factor cell: list, compare, evidence and history. (traces to: AC-23)
- [DAC-E3-13] `create_app` MUST include the `universes` and `classifications` routers before the Host/Origin and request-id middleware and the static mount are added, and `_lifespan` MUST create the classification scheduler task from `ClassificationSettings()` beside the reclaim task and cancel both on shutdown; `tests/unit/test_api_no_secrets.py` MUST carry its no-credential assertion over the new routes; no other delivered API file changes. (traces to: AC-10, AC-16)
