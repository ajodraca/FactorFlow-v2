NON-BLOCKING
1. Two mutant kills depend on PostgreSQL tie order (test_reader_evidence.py:100-135). Dropping the input-order or factor-order key,
   or the cells-from-any-stock mutant, leaves rows tied in the sort, and the result order for ties is not guaranteed. Because the
   reader keeps the last cell per factor in a dict, this can't be fully avoided. The RED log shows ties kept the order rows were
   stored in, and inserting AAPL first is what makes the leak visible. The tests are deterministic against the correct code, so
   this affects only how firmly those mutants are killed.
2. The docstring overstates (test_reader_evidence.py:426). "Cannot fail without the tiebreaker" should read "is not guaranteed to
   fail". Without the tiebreaker the result is simply unspecified.
3. The YAML reason overstates slightly (tdd-evidence.yaml:101). "No stored state can distinguish it" is too strong: the uniqueness
   rule is enforced by the service at write time, not by a database constraint, and this very test inserts such data directly.
   "No state the product can write" would be exact.
4. The YAML fix was made in cycle-1's record rather than in "the next cycle's evidence" as v1 asked. That is acceptable provided
   the rework-1 cycle record lists the same disposition.
