Is the new reason faithful? Yes.
- DEC-0057 (2): names must be unique among active universes, compared exactly after trimming; a retired universe's name may be reused.
- Universe-service design section 3 (line 445) states the same rule. Writes are serialised by an advisory lock (DEC-0065).
- stock_memberships.sql excludes retired universes with NOT EXISTS ... 'retired'.
- Equal names are therefore unreachable. ORDER BY n.name uses the default collation, which never ties two different strings.
  With ties impossible among the active universes the read returns, removing u.universe_id from the sort cannot change any
  result built from data the service writes.
- The reason is scoped correctly. It says "unreachable in product data". The test builds equal names with direct inserts, which
  the reason doesn't contradict.

Note (bookkeeping, not spec drift): IR-004 said to correct the reason "in the next cycle's evidence". The commit instead rewrote
the reason inside cycle-1, which cycle-1's reviews had already judged. Since the YAML is excluded from the fingerprinted patch,
the review evidence isn't invalidated. But cycle-1 no longer shows the reason that was actually reviewed, so the rework-1 cycle
entry should mention the change.

Minor wording, also not drift: the docstring phrase "this holds but cannot fail without the tiebreaker" is ambiguous.
