# Reader Foundation: Current Set, Later Attempt and Summary

## User Story

As an owner-operator, I want one definition of the current set, any newer attempt and a cheap summary, so that every screen reads the same currency answer, before and after the first set.

## Description

Delivers `src/factorflow/classification/reader.py` (module skeleton, `current_set`, `summary`, shared set and later blocks), `sql/current_set.sql` and `sql/summary.sql`. The current set is the latest set in state `complete`; `later` is the most recent newer `building` or `failed` set, or the first set while none is complete; `not_current` is true exactly when `later` is non-null. The summary carries per-factor counts and the current-stock count with no stock rows.

Source: `component-design-classification-reader.md` sections 2.1, 2.3, 2.4, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-13] An input MUST be treated as outdated when it is a fundamental whose latest reported period ended more than 6 months before the classification date, or a price that is not from the latest trading day the product holds. (the current-stock summary rule derived from this)
- [AC-20] Until a new set of classifications is complete, the product MUST show the previous set marked as not reflecting the latest acquisition, and MUST NOT show a half-finished set as current. When classification fails, the product MUST also show the failure and its reason. (serve side)
- [AC-21] The user MUST be able to see when the current classifications were produced and which acquisition run they reflect.
- [AC-22] Before any classification has been produced, the product MUST state that no stocks have been classified rather than presenting an empty list as complete.
- [DAC-E3-1] `current_set` MUST resolve to the latest set in state `complete`, and `later` MUST carry the most recent set newer than it (`building` or `failed`) or the first set while none is complete; `not_current` MUST be true exactly when `later` is non-null. (traces to: AC-20, AC-21)
- [DAC-E3-10] A stock MUST be reported current in the summary exactly when none of its `factor_input` rows in the current set is `missing` or `outdated`; `not_computable` MUST NOT count against currency. (traces to: AC-13)
- [DAC-E3-11] The summary and the list read MUST carry the same `set` and `later` shape, including before any set exists, so every consumer — this capability's screens and the future shell capability's — reads one rule. (traces to: AC-20, AC-22)

### Derived

- [DAC-E3-S1-1] Given a `complete` set and a newer `building` set, When `current_set` is read, Then `set` is the complete one, `later` the building one and `not_current` true. (traces to: DAC-E3-1)
- [DAC-E3-S1-2] Given only a `building` or `failed` first set, When read, Then `never_classified` is true, `set` is null and `later` carries that set with its `failure_reason` when failed. (traces to: DAC-E3-11)
- [DAC-E3-S1-3] Given no set at all, When read, Then `never_classified` is true and `later` is null, in the same shape as every other state. (traces to: AC-22)
- [DAC-E3-S1-4] Given a stock with a `missing` or `outdated` input in the current set, When the summary counts current stocks, Then it is not current; a `not_computable` input does not count against currency. (traces to: DAC-E3-10)
- [DAC-E3-S1-5] Given the summary read, When it is executed, Then it returns counts only and no stock rows and runs from indexed set rows. (traces to: AC-13)
- [DAC-E3-S1-6] Given each returned value, When inspected, Then it is a stored row; nothing is recomputed by the reader (STD-UI-15). (traces to: AC-21)
