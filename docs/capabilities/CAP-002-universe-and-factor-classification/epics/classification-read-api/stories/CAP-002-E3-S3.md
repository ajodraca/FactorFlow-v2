# Compare, Stock Evidence and Stock Memberships Reads

## User Story

As an owner-operator, I want 2 to 6 stocks side by side and one stock's inputs, dates and universe memberships, so that I can explain any result.

## Description

Adds to `reader.py` `compare`, `stock_evidence` and the memberships read, plus `sql/stock_evidence.sql` and `sql/stock_memberships.sql` (active universes holding the instrument, via E1's membership replay).

Source: `component-design-classification-reader.md` sections 2.5, 2.6, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-16] The user MUST be able to sort stocks by any factor's score or percentile, filter them with thresholds on one or more factors at once, and view chosen stocks side by side, both across all classified stocks and within a single universe.
- [AC-17] For any classification, the user MUST be able to see the inputs it was built from and the date on which each input was known.
- [DAC-E3-7] Compare MUST accept 2 to 6 symbols, never fewer or more, and MUST return every requested symbol that names a known instrument, with an unrecognised one reported in `unknown_symbols` rather than silently dropped. (traces to: AC-16)
- [DAC-E3-8] A stock's evidence read MUST return every `factor_input` row of the current set with its value, `as_of` and `known_on`, and the active universes the stock currently belongs to. (traces to: AC-17)
- [DAC-E3-12] The restatement mark MUST be carried on every read that returns a factor cell: list, compare, evidence and history. (traces to: AC-23)

### Derived

- [DAC-E3-S3-1] Given 2 to 6 symbols, When compare runs, Then every symbol naming a known instrument is returned, including an incomplete or retired one; fewer than 2 or more than 6 is rejected. (traces to: DAC-E3-7)
- [DAC-E3-S3-2] Given an unrecognised symbol, When compare runs, Then it is reported in `unknown_symbols` and not silently dropped. (traces to: DAC-E3-7)
- [DAC-E3-S3-3] Given a stock, When evidence is read, Then every `factor_input` row of the current set is returned with value, `as_of`, `known_on` and `restated_possible`, with the active universes it belongs to in name order. (traces to: DAC-E3-8)
- [DAC-E3-S3-4] Given a retired stock, When compared or read as evidence, Then it keeps its row with the `retired` reason. (traces to: AC-15)
- [DAC-E3-S3-5] Given no current set, When evidence is read, Then `set` is null and the shape matches the populated shape. (traces to: DAC-E3-8)
