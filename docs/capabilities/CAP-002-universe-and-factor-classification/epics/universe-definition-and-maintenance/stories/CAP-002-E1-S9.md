# Universe Detail Screen: Summary Header, Rename, Add Stocks and Retire

## User Story

As an owner-operator, I want a universe detail page where I can rename, add stocks and retire, so that I maintain a universe without editing the data store.

## Description

Delivers `web/src/screens/research/universes/detail/index.tsx`, `summary-header.tsx` (inline rename, Add stocks, Retire), `add-stocks-dialog.tsx` and `retire-dialog.tsx`, mounting the tabs from CAP-002-E1-S8. This is the `UniverseDetailScreen` the shell composition story routes to.

Source: `component-design-classification-ui.md` sections 2.7, 7; `ux-design.md` section 1.4.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-4] The user MUST be able to add and remove members, rename a universe and retire a universe without editing the data store directly, and renaming MUST NOT change the universe's history.
- [AC-5] The product MUST refuse to create or save a universe with no members, and MUST refuse to remove a universe's last member.
- [AC-6] Removing a member or retiring a universe MUST retain the dated record of membership, and the user MUST be able to see which stocks belonged to a universe on any past date.
- [DAC-E1-4] Universe names MUST be unique among active universes after trimming; a retired universe's name MAY be reused by a later create or rename. (traces to: AC-4)
- [DAC-E1-6] Adding a symbol that is already a current member MUST report it as `already_member` rather than raising, and MUST append no event for it. (traces to: AC-4)
- [DAC-E1-7] Removing a universe's sole member MUST be refused with `last_member`, offering retirement as the alternative; retiring MUST append one `retired` event, after which the universe's members and events remain readable and every further write to it is refused with `universe_retired`. (traces to: AC-5, AC-6)

### Derived

- [DAC-E1-S9-1] Given inline rename, When Enter is pressed Then `PATCH` is sent and Esc cancels; `universe_name_in_use` attaches as a field error and an empty trimmed name is a field error. (traces to: DAC-E1-4)
- [DAC-E1-S9-2] Given Add stocks with an already-current symbol, When the response arrives, Then `already_member` is reported politely and not as an error. (traces to: DAC-E1-6)
- [DAC-E1-S9-3] Given an uncovered symbol, When Add stocks is submitted, Then the whole-request refusal names every symbol. (traces to: AC-4)
- [DAC-E1-S9-4] Given Retire, When the dialog opens, Then it uses the `confirm` variant and, after `200`, the header shows Retired and the actions leave. (traces to: DAC-E1-7)
- [DAC-E1-S9-5] Given a retired universe, When the page renders, Then members and history remain readable and `universe_retired` wording is shown for any attempted write. (traces to: AC-6)
