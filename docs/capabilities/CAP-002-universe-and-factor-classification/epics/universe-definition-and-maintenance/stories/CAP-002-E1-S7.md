# Universes List Screen and Create-by-Hand Dialog

## User Story

As an owner-operator, I want a Universes list and a dialog to create a universe from pasted symbols, so that I can see my universes and build one without leaving the app.

## Description

Delivers `web/src/screens/research/universes/index.tsx`, `universe-table.tsx` and `create-dialog.tsx` (UX design sections 1.3, 2.7 of `classification-ui`). Active universes show by default, retired ones are separated by the lifecycle select; never-populated and nothing-found states are distinct; the origin line renders each clause only when it applies. Bulk symbol parsing reuses `web/src/screens/instruments/parse-bulk-symbols.ts` by import.

The route that renders this screen is registered by CAP-002-E4-S10.

Source: `component-design-classification-ui.md` sections 2.1, 2.7, 7; `ux-design.md` section 1.3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] The user MUST be able to create a named universe by selecting its members from the stocks acquisition covers, and MUST NOT be able to add a stock that acquisition does not cover.
- [AC-3] The user MUST be able to hold more than one named universe at a time, and a stock MUST be able to belong to more than one universe.
- [AC-5] The product MUST refuse to create or save a universe with no members, and MUST refuse to remove a universe's last member.
- [DAC-E1-1] `create_by_hand` and `add_members` MUST refuse the whole request when any named symbol lacks an `instrument` row with at least one `coverage_segment`, naming every uncovered symbol, and MUST write nothing. (traces to: AC-1)

### Derived

- [DAC-E1-S7-1] Given no symbol parses or more than 1000 do, When the create dialog is shown, Then the submit control is `blocked` with its reason and stays focusable. (traces to: AC-5)
- [DAC-E1-S7-2] Given a response with `instrument_not_acquired`, When the dialog receives it, Then it names every uncovered symbol, links to the followed-stocks page and keeps the owner's list. (traces to: DAC-E1-1)
- [DAC-E1-S7-3] Given a `201`, When the create succeeds, Then the app navigates to the new universe's detail without a toast. (traces to: AC-1)
- [DAC-E1-S7-4] Given active and retired universes, When the list renders, Then retired ones appear only under the lifecycle select with a `secondary` badge reading Retired. (traces to: AC-3)
- [DAC-E1-S7-5] Given a universe saved from a filter, When its origin line renders, Then it names the filter, `search "AA"` and `stocks with an incomplete score hidden` only when they applied. (traces to: AC-3)
- [DAC-E1-S7-6] Given no universe exists, When the list renders, Then the never-populated state is distinct from a lifecycle filter that matches nothing. (traces to: AC-3)

## Technical Details

### Implementation

- React, TypeScript, shadcn/ui on Radix, no `dangerouslySetInnerHTML` anywhere (existing `web/src/api/render.test.tsx`).
- Tests (Vitest and React Testing Library, beside the sources): `web/src/screens/research/universes/universes.test.tsx`, `web/src/screens/research/universes/create-dialog.test.tsx`.

### Validation

`npm run test`, `npm run lint`, `npm run format`, `npx tsc --noEmit`, `npm run build`.
