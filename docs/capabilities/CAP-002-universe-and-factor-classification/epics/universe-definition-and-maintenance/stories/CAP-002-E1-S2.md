# Universe Replay: Current State, Membership As Of a Date and Event History

## User Story

As an owner-operator, I want to see a universe's members today and on any past date, and its event history, so that a later backtest can see exactly which stocks belonged to a universe on any date.

## Description

Delivers the read half of `universe-service`: `src/factorflow/universes/replay.py` (`membership_as_of`, `current_state`), `sql/current_state.sql`, `sql/membership_as_of.sql`, `sql/events_page.sql`, `sql/list_universes.sql`, and `src/factorflow/universes/__init__.py`. Membership is replayed from the append-only event log, never read from a maintained row.

`membership_as_of.sql` is later imported, not restated, by `classification-reader` (CAP-002-E3-S2, SA-DUP-001).

Source: `component-design-universe-service.md` sections 2.1, 2.5, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-6] Removing a member or retiring a universe MUST retain the dated record of membership, and the user MUST be able to see which stocks belonged to a universe on any past date.
- [AC-15] A stock retired from acquisition MUST NOT be classified or counted in any peer set, and MUST be shown in its universes as not classified because it is retired. (membership side: a retired instrument remains a member and is never excluded from a universe for that reason)
- [DAC-E1-8] Membership as of a given America/Chicago date MUST equal exactly the members implied by every `member_added`/`member_removed` event recorded on or before that date; a date before the universe's `created` event MUST return no members, flagged `as_of_before_creation`, with the creation date. (traces to: AC-6)
- [DAC-E1-9] A symbol acquisition covers but whose `instrument.lifecycle` is `retired` MAY be added or MAY already be a member; it MUST remain a member, replaying with `lifecycle: retired`, rather than being excluded for that reason. (traces to: AC-15)

### Derived

- [DAC-E1-S2-1] Given a stock added and removed on the same `recorded_on` date, When membership is read as of that date, Then it is not a member; a stock added on D is a member as of D and every later date until removed. (traces to: DAC-E1-8)
- [DAC-E1-S2-2] Given a date before the universe's `created` event, When membership is read as of it, Then it returns no members, `as_of_before_creation: true` and the creation date. (traces to: DAC-E1-8)
- [DAC-E1-S2-3] Given an instrument whose `lifecycle` is `retired`, When it is a current or past member, Then replay returns it with `lifecycle: retired` rather than excluding it. (traces to: DAC-E1-9)
- [DAC-E1-S2-4] Given a universe with more events than one page, When `list_events` is read, Then events are ordered by `event_id DESC` with a stable cursor across pages. (traces to: AC-6)
- [DAC-E1-S2-5] Given all SQL in this module, When statements are inspected, Then every one is parameterised and loaded once at import from a `.sql` file (SEC-INP-002). (traces to: DAC-E1-10)

## Technical Details

### Implementation

- Python with `psycopg` 3; SQL in `.sql` files loaded once at import, as `src/factorflow/coverage/sql/` does (no ORM).
- Tests: `tests/unit/test_universe_replay.py` (replay semantics on in-memory event sequences), `tests/integration/test_universe_as_of.py`, `tests/unit/test_universe_sql_safety.py` (created here: every statement parameterised, no `UPDATE` or `DELETE`; CAP-002-E1-S3 and S4 add their statements to the same scan).

### Data Changes

None. Reads `universe`, `universe_event`, `instrument`.

### Validation

`uv run pytest -m postgres`, `uv run pytest -m 'not postgres'`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`.

### Dependencies

- **CAP-002-E1-S1**, the `universe` and `universe_event` tables the replay queries read.
