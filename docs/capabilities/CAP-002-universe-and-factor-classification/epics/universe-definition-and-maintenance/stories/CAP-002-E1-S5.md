# Universe from a Filter Result: Snapshot with Provenance

## User Story

As an owner-operator, I want to save a reviewed factor-filter result as a universe whose members never change afterwards, so that I can study exactly the stocks I reviewed.

## Description

Adds `create_from_filter` to `src/factorflow/universes/service.py`. Inside the write transaction it calls the reader's `evaluate_filter` with the owner-reviewed `Thresholds` against the named `classification_set`, refuses when that set is no longer the current complete set, and records `filter_provenance` on the `created` event so the origin line renders from the event alone.

This story hard-depends on a story in a later epic (CAP-002-E3-S2, which defines `evaluate_filter` and `Thresholds`), deliberately: E1's snapshot must call the same predicate the list read uses (S03-7).

Source: `component-design-universe-service.md` sections 2.3, 2.4, 7; `component-design-classification-reader.md` section 2.3.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-2] The user MUST be able to save the result of a threshold filter as a named universe, and that universe's membership MUST NOT change afterwards unless the user changes it.
- [AC-5] The product MUST refuse to create or save a universe with no members, and MUST refuse to remove a universe's last member.
- [DAC-E1-2] `create_from_filter` MUST evaluate the owner-reviewed `Thresholds` object against the named `classification_set` inside the writing transaction and refuse with `classification_set_changed` when that set is no longer the current complete set. (traces to: AC-2)
- [DAC-E1-3] A `created` event taken from a filter MUST carry `filter_provenance` with the bounds, `hide_incomplete`, the symbol prefix, the `set_id` and the set's `classification_date`, so the origin line renders from the event alone. (traces to: AC-2)

### Derived

- [DAC-E1-S5-1] Given thresholds, `hide_incomplete` and a prefix, When `create_from_filter` runs, Then the members equal `evaluate_filter`'s result for that set and the same `Thresholds`. (traces to: DAC-E1-2)
- [DAC-E1-S5-2] Given a newer complete set than the named `set_id`, When the snapshot is requested, Then `ClassificationSetChanged` (`classification_set_changed`) is raised and nothing is written. (traces to: DAC-E1-2)
- [DAC-E1-S5-3] Given thresholds that match no stock, When the snapshot is requested, Then `EmptyUniverse` is raised. (traces to: AC-5)
- [DAC-E1-S5-4] Given a saved snapshot, When `get_universe` reads it, Then the `Origin` carries the bounds, `hide_incomplete`, `symbol` (null without a search), `set_id` and the set's `classification_date`, equal to `filter_provenance` on the event. (traces to: DAC-E1-3)
- [DAC-E1-S5-5] Given a stock incomplete on one factor for an input reason that the bounds admit, When `hide_incomplete` is false it is a member and when true it is not. (traces to: DAC-E1-2)
- [DAC-E1-S5-6] Given a later set that changes which stocks match, When the universe is read, Then its members are unchanged. (traces to: AC-2)
