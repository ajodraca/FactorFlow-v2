# Universe Creation by Hand and Adding Members with Coverage Check and Write Lock

## User Story

As an owner-operator, I want to create a named universe from covered stocks and add stocks to it, with the whole request refused if any stock is not covered, so that a universe only ever holds stocks the product actually follows.

## Description

Delivers `src/factorflow/universes/service.py` (typed exceptions, `UNIVERSE_WRITE_LOCK_KEY`, `create_by_hand`, `add_members`, `get_universe`, `list_universes`, `list_events`) and `sql/coverage_check.sql`. Every write takes one transaction advisory lock before its checks (DEC-0065) so concurrent creates cannot both find a name free. `create_from_filter`, `rename`, `remove_member` and `retire` are CAP-002-E1-S5 and S4.

The maximum universe name length is an open owner question (`[REQUIRES INPUT: maximum universe name length in characters]`, system design section 8 question 2); this story does not invent a number and the check is added when the owner answers, tracked in the EPIC's open questions.

Source: `component-design-universe-service.md` sections 2.3, 2.4, 3, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] The user MUST be able to create a named universe by selecting its members from the stocks acquisition covers, and MUST NOT be able to add a stock that acquisition does not cover.
- [AC-3] The user MUST be able to hold more than one named universe at a time, and a stock MUST be able to belong to more than one universe.
- [AC-5] The product MUST refuse to create or save a universe with no members, and MUST refuse to remove a universe's last member.
- [AC-15] A stock retired from acquisition MUST NOT be classified or counted in any peer set, and MUST be shown in its universes as not classified because it is retired. (membership side: a retired instrument remains a member and is never excluded from a universe for that reason)
- [DAC-E1-1] `create_by_hand` and `add_members` MUST refuse the whole request when any named symbol lacks an `instrument` row with at least one `coverage_segment`, naming every uncovered symbol, and MUST write nothing. (traces to: AC-1)
- [DAC-E1-4] Universe names MUST be unique among active universes after trimming; a retired universe's name MAY be reused by a later create or rename. (traces to: AC-4)
- [DAC-E1-5] Two concurrent creates naming the same universe name MUST serialise through the write lock so that exactly one universe is created and the other is refused with `universe_name_in_use`. (traces to: AC-3, AC-4)
- [DAC-E1-6] Adding a symbol that is already a current member MUST report it as `already_member` rather than raising, and MUST append no event for it. (traces to: AC-4)
- [DAC-E1-9] A symbol acquisition covers but whose `instrument.lifecycle` is `retired` MAY be added or MAY already be a member; it MUST remain a member, replaying with `lifecycle: retired`, rather than being excluded for that reason. (traces to: AC-15)

### Derived

- [DAC-E1-S3-1] Given a batch containing one symbol with no `instrument` row or no `coverage_segment`, When `create_by_hand` or `add_members` runs, Then `InstrumentNotAcquired` names every uncovered symbol and nothing is written. (traces to: DAC-E1-1)
- [DAC-E1-S3-2] Given no symbols, When `create_by_hand` runs, Then `EmptyUniverse` is raised and nothing is written. (traces to: AC-5)
- [DAC-E1-S3-3] Given a successful create of n symbols, When the events are read, Then there is one `created` and n `member_added` events appended in one `executemany`, and replay returns the n members with `member_since`. (traces to: AC-1)
- [DAC-E1-S3-4] Given an active universe already named X after trimming, When a second create or rename names X, Then `UniverseNameInUse` is raised; after the first is retired the name is accepted. (traces to: DAC-E1-4)
- [DAC-E1-S3-5] Given two connections creating the same name at once, When both run, Then they serialise on `UNIVERSE_WRITE_LOCK_KEY` and exactly one succeeds. (traces to: DAC-E1-5)
- [DAC-E1-S3-6] Given a symbol already a current member, When `add_members` runs, Then it is returned in `already_member` and no event is appended for it. (traces to: DAC-E1-6)
- [DAC-E1-S3-7] Given a covered symbol whose lifecycle is `retired`, When it is named, Then it is accepted and replays with `lifecycle: retired`. (traces to: DAC-E1-9)
- [DAC-E1-S3-8] Given a universe of 3000 members created in three calls, When it is created and replayed, Then the result is correct within the test's own budget (`slow` marker). (traces to: AC-1)

## Technical Details

### Implementation

- Every write: acquire the advisory lock, check, append events, commit. Dependency on `replay.current_state` for current members.
- Tests: `tests/integration/test_universe_create.py`, `tests/integration/test_universe_volume.py` (`slow`); statements covered by `tests/unit/test_universe_sql_safety.py`.

### Data Changes

None beyond the `0005` tables.

### Dependencies

- **CAP-002-E1-S2**, `replay.current_state`, used to find current members and `already_member`.
