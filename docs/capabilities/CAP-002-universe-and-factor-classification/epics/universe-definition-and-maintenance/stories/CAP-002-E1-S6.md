# Universes Router, Request Models, Error Mapping and Mount in the Application

## User Story

As an owner-operator, I want the universe operations reachable as local HTTP endpoints, so that the interface can create, read and maintain universes.

## Description

Delivers `src/factorflow/api/routes/universes.py` (`GET/POST /api/universes`, `GET/PATCH/DELETE /api/universes/{id}`, `GET /api/universes/{id}/events`, `POST /api/universes/{id}/members`, `DELETE .../members/{symbol}`), the universe models in the new `src/factorflow/api/classification_models.py`, `src/factorflow/api/classification_bounds.py` and the universe error mapping, and adds `app.include_router(universes.router)` to the delivered `src/factorflow/api/app.py`.

Ordering decision: the router is mounted in the story that builds it, as CAP-001 did, so this story's route and integration tests build the app through `create_app()` and pass without waiting for another story (DEC-0086; backlog review v3 FINDING-11). CAP-002-E3-S6 keeps the scheduler start and the no-secrets extension. The single `include_router` line moves from E3's composition story to this one; the resulting `app.py` is the same.

`MAX_UNIVERSE_NAME_LENGTH` is an open owner question; the constant is declared with `[REQUIRES INPUT]` semantics as classification-api section 2.1 states and is not given an invented value.

Source: `component-design-classification-api.md` sections 2.1, 2.3 (the `include_router` insertion only), 2.4 to 2.7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-1] The user MUST be able to create a named universe by selecting its members from the stocks acquisition covers, and MUST NOT be able to add a stock that acquisition does not cover.
- [AC-4] The user MUST be able to add and remove members, rename a universe and retire a universe without editing the data store directly, and renaming MUST NOT change the universe's history.
- [AC-5] The product MUST refuse to create or save a universe with no members, and MUST refuse to remove a universe's last member.
- [AC-6] Removing a member or retiring a universe MUST retain the dated record of membership, and the user MUST be able to see which stocks belonged to a universe on any past date.
- [DAC-E1-1] `create_by_hand` and `add_members` MUST refuse the whole request when any named symbol lacks an `instrument` row with at least one `coverage_segment`, naming every uncovered symbol, and MUST write nothing. (traces to: AC-1)
- [DAC-E1-4] Universe names MUST be unique among active universes after trimming; a retired universe's name MAY be reused by a later create or rename. (traces to: AC-4)
- [DAC-E1-6] Adding a symbol that is already a current member MUST report it as `already_member` rather than raising, and MUST append no event for it. (traces to: AC-4)
- [DAC-E1-7] Removing a universe's sole member MUST be refused with `last_member`, offering retirement as the alternative; retiring MUST append one `retired` event, after which the universe's members and events remain readable and every further write to it is refused with `universe_retired`. (traces to: AC-5, AC-6)

### Derived

- [DAC-E1-S6-1] Given `POST /api/universes` with symbols, When any is uncovered, Then the response is the error envelope naming the operation, the resource and every uncovered symbol, and nothing is written. (traces to: DAC-E1-1)
- [DAC-E1-S6-2] Given a refusal (`universe_name_in_use`, `last_member`, `universe_retired`, `empty_universe`, `classification_set_changed`, `instrument_not_acquired`), When it is raised by the service, Then error mapping returns the documented status and code with no stack trace or credential in the body. (traces to: AC-5)
- [DAC-E1-S6-3] Given `POST .../members` with a current member, When it is called, Then `already_member` is reported in the 200 body, not as an error. (traces to: DAC-E1-6)
- [DAC-E1-S6-4] Given a request beyond the bounds in `classification_bounds.py`, When it is validated, Then it is rejected before the service is called. (traces to: AC-1)
- [DAC-E1-S6-5] Given the application is built with `create_app()`, When `GET /api/universes` is called through `TestClient`, Then the route is mounted behind the Host and Origin and request-id middleware and ahead of the static mount. (traces to: AC-4)
- [DAC-E1-S6-6] Given `DELETE .../members/{symbol}` on the sole member, When called, Then `last_member` is returned and nothing is written. (traces to: DAC-E1-7)

## Technical Details

### API Contract

- Endpoints as above, snake_case on the wire; response shapes `UniverseResponse`, `UniverseListResponse`, `UniverseEventsResponse`, `AddMembersResponse`, `RemoveMemberResponse`, `RetireUniverseResponse` per classification-api section 2.7.
- Auth: none beyond the delivered local-only posture; Host/Origin middleware (H9) applies unchanged.

### Implementation

- FastAPI, Pydantic. The only delivered file edited is `src/factorflow/api/app.py` (one `include_router` call, before the middleware and static mount are added); `tests/unit/test_api_no_secrets.py` is edited by CAP-002-E3-S6.
- Tests: `tests/unit/test_api_universes_routes.py`, `tests/unit/test_api_classification_models.py`, `tests/unit/test_api_classification_error_mapping.py`, `tests/integration/test_api_universes.py`, `tests/integration/test_api_classification_host_origin.py` (universes cases).

### Validation

`uv run pytest -m postgres`, `uv run pytest -m 'not postgres'`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`.

### Dependencies

- **CAP-002-E1-S4**, rename, remove and retire the routes call.
