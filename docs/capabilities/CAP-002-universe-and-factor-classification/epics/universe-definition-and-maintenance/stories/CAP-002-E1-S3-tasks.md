# Tasks: CAP-002-E1-S3 — Universe Creation by Hand and Adding Members with Coverage Check and Write Lock

**Story**: `docs/capabilities/CAP-002-universe-and-factor-classification/epics/universe-definition-and-maintenance/stories/CAP-002-E1-S3.md`
**Component**: `FactorFlow-v2` (module `universe-service`, first write half)
**Branch**: `usr/alvaro-de-jodra/CAP-002-E1-tasks`
**Date**: 2026-10-17

## Summary

Deliver the first write path of `universe-service`: `src/factorflow/universes/service.py` (the typed exceptions, `UNIVERSE_WRITE_LOCK_KEY`, `create_by_hand`, `add_members`, `get_universe`, `list_universes`, `list_events`, plus re-exports of the dataclasses CAP-002-E1-S2 defines in `replay.py`, DEC-0093) and `src/factorflow/universes/sql/coverage_check.sql`. Every write runs in `with conn.transaction():` and takes `pg_advisory_xact_lock(UNIVERSE_WRITE_LOCK_KEY)` as its first statement, so two concurrent creates cannot both find a name free. A request naming any uncovered symbol is refused whole (`InstrumentNotAcquired`, every uncovered symbol, sorted), an empty create is refused, an active universe's trimmed name cannot be reused, and a symbol already a member is reported as `already_member` with no event. A covered symbol whose lifecycle is `retired` is accepted and replays as a member with `lifecycle: retired`. The module issues `INSERT` only. `create_from_filter`, `rename`, `remove_member` and `retire` are CAP-002-E1-S4 and CAP-002-E1-S5; CAP-002-E1-S5 needs CAP-002-E3-S2's `evaluate_filter`, which this story does not import; `classification-ui` (CAP-002-E1-S8) shows the refusals through the API.
