# Universe Definition and Maintenance

**EPIC ID:** CAP-002-E1
**Jira Key:** N/A
**Capability:** CAP-002
**Summary:** Let the owner define a named universe from instruments acquisition already covers, either by hand or by saving a reviewed factor-filter result as a one-time snapshot, and maintain it over time, adding and removing members, renaming and retiring, without ever touching the data store directly. A universe is never empty: creating or saving one with no members is refused, and removing the last member is refused in favour of retirement. Every change is an appended, dated event, so a later backtest can see exactly which stocks belonged to a universe on any past date, and a stock retired from acquisition stays a member, shown as not classified because it is retired, rather than disappearing. Delivers the Universes list and Universe detail screens.
**Actors:** Owner-operator, universe-service, research-store, classification-api, classification-ui, market-data-store (coverage check, read-only)
**Estimate:** L
**Out of Scope:** Computing value, growth or momentum classifications (E2); serving scored lists, comparison or evidence (E3); the Research screen's scoring display (E4); the Compare and Stock evidence pages (E5); the mapping from Massive payload keys to factor inputs, which does not touch this EPIC.
**Dependencies:** E3 (`classification-reader`'s `evaluate_filter` and its current-set rule, which `create_from_filter` calls inside its own write transaction to take the filter snapshot, AC-2); E4 (the one shell-composition seam — `shell.tsx`'s appended rail destination, `routes.tsx`'s five routes, and `client.ts`'s `requestJson` export — registered once, which this EPIC's Universes screens render inside). CAP-001's `instrument` and `coverage_segment` tables are `requires-runtime` per capability section 5.1: this EPIC is designable and most of it buildable now against CAP-001's documented contract, with the coverage check verified against a real store. Within E1 itself, the filter-snapshot story (which calls E3's `evaluate_filter`) is ordered after E1's own replay and schema stories, and after E3's `evaluate_filter` lands — a deliberate cross-EPIC ordering, not a cycle.
**Links:** system-design.md sections 3.2 (universe writes), 4.1, 4.2 (`POST`/`GET`/`PATCH`/`DELETE /api/universes*`, "Universe operations"), 4.4 (`universe`, `universe_event`), 5.13, 5.14; component-design-universe-service.md sections 2.2 to 2.5; component-design-research-store.md section 2.3 (migration `0005`); component-design-classification-api.md sections 2.4, 2.6 (universes routes and error mapping); component-design-classification-ui.md sections 2.1 (Universes screens), 2.7 (Save/Add/Remove/Retire dialogs); ux-design.md sections 1.3, 1.4.

## Goals

- Let the owner build a named universe by hand from instruments acquisition covers, refusing the whole request when any named symbol is not covered.
- Let the owner save a reviewed factor-filter result as a one-time snapshot universe whose membership never drifts afterwards, even as later classifications change which stocks would match.
- Guarantee a universe is never empty: refuse creation or a filter save with no members, and refuse removing a universe's last member, offering retirement instead.
- Let the owner add members, remove members, rename and retire a universe without editing the data store, with renaming changing nothing else about the universe's identity or history.
- Keep a retired instrument a member of every universe it belonged to, shown as not classified because it is retired, rather than removed or hidden.
- Serve current and as-of membership, and the universe's event history, by replaying the append-only event log, never from a maintained row.

## Non-Functional Requirements

- **Concurrency:** every write acquires one transaction advisory lock (`UNIVERSE_WRITE_LOCK_KEY`, DEC-0065) before its checks, so two concurrent creates cannot both find a name free; correctness does not depend on one owner-operator never doing two things at once.
- **Point-in-time integrity (C5):** `universe_event` is append-only; no `UPDATE` or `DELETE` statement anywhere in the repository names it, and a static repository test asserts this the day the module exists.
- **Consistency with the read side:** the filter snapshot evaluates the owner-reviewed `Thresholds` object (the twelve bounds, `hide_incomplete`, the *Find a stock* prefix) through `classification-reader`'s `evaluate_filter`, the same predicate the list read uses, so a saved universe is exactly what the owner reviewed (S03-7).
- **Sizing:** a universe may hold every active instrument (3000); a create with 1000 symbols appends 1001 rows in one `executemany`; replay is one indexed range scan over a universe's own events.
- **Presentation (STD-UI-19, STD-UI-2):** every refusal names the operation, the resource and the reason; removing a member and retiring a universe use `confirm` dialogs, never `destructive`.

## EPIC Acceptance Criteria

### From Capability

- [AC-1] The user MUST be able to create a named universe by selecting its members from the stocks acquisition covers, and MUST NOT be able to add a stock that acquisition does not cover.
- [AC-2] The user MUST be able to save the result of a threshold filter as a named universe, and that universe's membership MUST NOT change afterwards unless the user changes it.
- [AC-3] The user MUST be able to hold more than one named universe at a time, and a stock MUST be able to belong to more than one universe.
- [AC-4] The user MUST be able to add and remove members, rename a universe and retire a universe without editing the data store directly, and renaming MUST NOT change the universe's history.
- [AC-5] The product MUST refuse to create or save a universe with no members, and MUST refuse to remove a universe's last member.
- [AC-6] Removing a member or retiring a universe MUST retain the dated record of membership, and the user MUST be able to see which stocks belonged to a universe on any past date.
- [AC-15] A stock retired from acquisition MUST NOT be classified or counted in any peer set, and MUST be shown in its universes as not classified because it is retired. (membership side: a retired instrument remains a member and is never excluded from a universe for that reason)

### Derived

- [DAC-E1-1] `create_by_hand` and `add_members` MUST refuse the whole request when any named symbol lacks an `instrument` row with at least one `coverage_segment`, naming every uncovered symbol, and MUST write nothing. (traces to: AC-1)
- [DAC-E1-2] `create_from_filter` MUST evaluate the owner-reviewed `Thresholds` object against the named `classification_set` inside the writing transaction and refuse with `classification_set_changed` when that set is no longer the current complete set. (traces to: AC-2)
- [DAC-E1-3] A `created` event taken from a filter MUST carry `filter_provenance` with the bounds, `hide_incomplete`, the symbol prefix, the `set_id` and the set's `classification_date`, so the origin line renders from the event alone. (traces to: AC-2)
- [DAC-E1-4] Universe names MUST be unique among active universes after trimming; a retired universe's name MAY be reused by a later create or rename. (traces to: AC-4)
- [DAC-E1-5] Two concurrent creates naming the same universe name MUST serialise through the write lock so that exactly one universe is created and the other is refused with `universe_name_in_use`. (traces to: AC-3, AC-4)
- [DAC-E1-6] Adding a symbol that is already a current member MUST report it as `already_member` rather than raising, and MUST append no event for it. (traces to: AC-4)
- [DAC-E1-7] Removing a universe's sole member MUST be refused with `last_member`, offering retirement as the alternative; retiring MUST append one `retired` event, after which the universe's members and events remain readable and every further write to it is refused with `universe_retired`. (traces to: AC-5, AC-6)
- [DAC-E1-8] Membership as of a given America/Chicago date MUST equal exactly the members implied by every `member_added`/`member_removed` event recorded on or before that date; a date before the universe's `created` event MUST return no members, flagged `as_of_before_creation`, with the creation date. (traces to: AC-6)
- [DAC-E1-9] A symbol acquisition covers but whose `instrument.lifecycle` is `retired` MAY be added or MAY already be a member; it MUST remain a member, replaying with `lifecycle: retired`, rather than being excluded for that reason. (traces to: AC-15)
- [DAC-E1-10] No statement issued by this EPIC's components against `universe` or `universe_event` MAY be an `UPDATE` or `DELETE`; a repository test MUST assert it over every `.sql` file and Python source under the tree. (traces to: AC-6)
