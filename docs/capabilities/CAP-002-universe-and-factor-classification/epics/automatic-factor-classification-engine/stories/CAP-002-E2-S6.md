# Possibly-Restated Mark for Value and Growth Classifications

## User Story

As an owner-operator, I want value and growth classifications marked when they rest on backfilled fundamentals, so that I know when a number may have been restated.

## Description

Wires the backfill flag from `statements.sql` through `factor_input` into `factor_classification.restated_possible`: a statement whose `provider_filing_date` precedes the instrument's first fundamentals `observed_on` marks its inputs and the value or growth classification. Momentum is never marked.

Source: `component-design-factor-engine.md` sections 2.4, 2.5, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-23] A value or growth classification MUST be marked as possibly reflecting restated data when any fundamental behind it was acquired as historical backfill, for a period already reported before acquisition of that stock began, and the mark MUST be retained with that classification in its history.
- [DAC-E2-11] A value or growth classification built on any statement whose `provider_filing_date` precedes the instrument's first fundamentals `observed_on` MUST carry `restated_possible`, appended with the classification and never with a momentum classification. (traces to: AC-23)

### Derived

- [DAC-E2-S6-1] Given a statement filed before the instrument's first fundamentals observation, When inputs and classifications are written, Then its inputs and the value and growth classifications carry `restated_possible`. (traces to: DAC-E2-11)
- [DAC-E2-S6-2] Given a momentum classification for the same stock, When written, Then it is never marked. (traces to: DAC-E2-11)
- [DAC-E2-S6-3] Given a marked classification in a completed set, When a later set is built, Then the earlier row's mark is unchanged. (traces to: AC-23)
