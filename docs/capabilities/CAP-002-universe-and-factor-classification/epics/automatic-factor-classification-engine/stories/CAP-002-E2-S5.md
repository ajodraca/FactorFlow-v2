# Peer Sets, Composite Score and Percentile Classification

## User Story

As an owner-operator, I want each factor scored and ranked only against stocks whose inputs are all present, with a floor of 30 stocks, so that every score is like for like and honest about when it cannot be ranked.

## Description

Adds `sql/peer_sets.sql` (insert into `classification_set_factor`), `sql/classify.sql` (z-scores with the sample standard deviation, equal-weight mean, re-standardisation, `percent_rank() x 100`, and `not_classified` rows with reasons) and the classification stage in `engine.build`. Arithmetic is PostgreSQL window functions (`avg`, `stddev_samp`, `percent_rank`), no numeric library (DEC-0052, DEC-0053). Universes are never read.

Source: `component-design-factor-engine.md` sections 2.5, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-8] A stock's classification on a factor MUST be measured against all actively acquired stocks that qualify on that factor, and MUST be identical in every universe the stock belongs to.
- [AC-9] Every classified factor MUST be shown as a standardised score together with a percentile rank from 0 to 100. (compute side: the score and percentile this EPIC writes)
- [AC-12] The product MUST NOT show a score or percentile on a factor for a stock unless every input that factor needs is present and current, and MUST instead show the stock as not classified on that factor with the missing or outdated input named.
- [AC-14] When fewer than 30 stocks qualify on a factor, the product MUST NOT show scores or percentiles on that factor, and MUST state that there are not enough stocks to rank and how many qualified.
- [AC-15] A stock retired from acquisition MUST NOT be classified or counted in any peer set, and MUST be shown in its universes as not classified because it is retired. (compute side: exclusion from every peer set)
- [DAC-E2-2] A factor's peer set MUST be exactly the active instruments whose inputs for that factor are all `present`; a stock's score and percentile on a factor MUST be identical whether or not it belongs to any universe. (traces to: AC-8)
- [DAC-E2-3] The composite MUST be formed by z-scoring each input over the peer set with the sample standard deviation, averaging with equal weight, re-standardising, and ranking with `percent_rank() × 100`; zero dispersion in any step MUST contribute zero rather than dividing by zero. (traces to: AC-9)
- [DAC-E2-7] A factor MUST be ranked only when at least 30 stocks qualify; below that, every active stock MUST be `not_classified` with reason `not_enough_stocks` and the qualifying count stated. (traces to: AC-14)
- [DAC-E2-8] A retired instrument MUST be excluded from every peer set and recorded `not_classified` with reason `retired` on all three factors, with no `factor_input` rows written for it. (traces to: AC-15)

### Derived

- [DAC-E2-S5-1] Given a hand-built peer set, When the composite is computed, Then z-scores, the equal-weight mean, re-standardisation to mean 0 and sd 1 and `percent_rank x 100` match `test_composite_arithmetic.py`; a zero-dispersion input contributes 0; `hypothesis` property tests hold over random peer sets. (traces to: DAC-E2-3)
- [DAC-E2-S5-2] Given a stock with two of three value inputs present, When peer sets are formed, Then it is outside the value peer set and is classified on growth and momentum. (traces to: DAC-E2-2)
- [DAC-E2-S5-3] Given 29 qualifying stocks, When a factor is classified, Then `ranked` is false, every active stock is `not_classified` with `not_enough_stocks` and `reason_detail` `29 of 30 stocks qualified`, and no score is written; at 30 it ranks. (traces to: DAC-E2-7)
- [DAC-E2-S5-4] Given a retired instrument, When the build runs, Then it is in no peer set, is `not_classified` with reason `retired` on all three factors and has no `factor_input` rows. (traces to: DAC-E2-8)
- [DAC-E2-S5-5] Given a stock in zero, one or several universes, When classified, Then its scores are identical; no universe table is read. (traces to: DAC-E2-2)
- [DAC-E2-S5-6] Given an input `not_computable`, When the factor is classified, Then the stock is `not_classified` with `input_not_computable` and the reason input named. (traces to: AC-12)
