# Value and Growth Inputs from Quarterly Fundamentals

## User Story

As an owner-operator, I want book-to-price, earnings yield, free-cash-flow yield and revenue and EPS growth derived for every active stock with the date each was known, so that value and growth classifications rest on defined, dated inputs.

## Description

Adds `sql/statements.sql` (latest observation per period and statement, quarterly only, with the backfill flag column), `sql/value_inputs.sql`, `sql/growth_inputs.sql`, `sql/insert_inputs.sql`, the fundamentals-side currency rule and the corresponding stage in `engine.build`. Trailing-twelve-month sums use four quarters, prior year the four before; market capitalisation is `close(L) x shares_outstanding(P1)`; the outdated-price rule applies to price-dependent value inputs.

Verification against a real acquisition run waits on the owner's payload-key answer (see CAP-002-E2-S2); this story's tests declare their own payload keys.

Source: `component-design-factor-engine.md` sections 2.4, 7.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-7] Every value, growth and momentum classification MUST be computed from exactly the inputs, periods and equal weights defined for that factor in Section 2.
- [AC-12] The product MUST NOT show a score or percentile on a factor for a stock unless every input that factor needs is present and current, and MUST instead show the stock as not classified on that factor with the missing or outdated input named.
- [AC-13] An input MUST be treated as outdated when it is a fundamental whose latest reported period ended more than 6 months before the classification date, or a price that is not from the latest trading day the product holds.
- [DAC-E2-1] Each of the eight named inputs MUST be derived exactly per the trailing-twelve-month sums, prior-year comparison, most-recent balance sheet, and read-time split-and-dividend adjustment of unadjusted bars this capability's factor definitions and the system design fix, with no step the capability does not define. (traces to: AC-7)
- [DAC-E2-6] A fundamental input MUST be `outdated` when its latest reported period ended more than 6 months before the classification date; a price-dependent input MUST be `outdated` when the stock's latest bar precedes the latest trading day held across active instruments. (traces to: AC-13)
- [DAC-E2-9] Every input used by a classification set MUST be selected exactly as it existed when that set's build transaction ran; a fundamental or price recorded after a set completes MUST NOT alter any row of that set. (traces to: AC-19)

### Derived

- [DAC-E2-S3-1] Given eight quarters, When `revenue_growth` is derived, Then it equals the ratio of the four-quarter sum to the prior four minus one and `as_of` is the latest period. (traces to: DAC-E2-1)
- [DAC-E2-S3-2] Given seven quarters, When growth inputs are derived, Then they are `missing` with `detail.periods_found` listing seven and value inputs are unaffected. (traces to: AC-12)
- [DAC-E2-S3-3] Given `fiscal_period = 'FY'` rows, When TTM sums are formed, Then annual rows enter no sum. (traces to: DAC-E2-1)
- [DAC-E2-S3-4] Given two observations of one period, When selected, Then the one with the later `observed_on` is used, `known_on` equals it and the earlier row is untouched. (traces to: DAC-E2-9)
- [DAC-E2-S3-5] Given a latest period end 6 months and a day before the classification date, When currency is decided, Then the input is `outdated`; at exactly 6 months it is `present`. (traces to: DAC-E2-6)
- [DAC-E2-S3-6] Given a stock whose latest bar precedes the latest trading day held, When value inputs are decided, Then they are `outdated`; growth inputs are unaffected. (traces to: DAC-E2-6)
- [DAC-E2-S3-7] Given a prior-year revenue or EPS base of zero or less, or non-positive shares, When inputs are derived, Then they are `not_computable` and the factor is not classified with that reason input (DEC-0055). (traces to: DAC-E2-1)
