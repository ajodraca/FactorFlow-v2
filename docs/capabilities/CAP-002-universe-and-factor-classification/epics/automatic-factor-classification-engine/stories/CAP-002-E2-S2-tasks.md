# Tasks: CAP-002-E2-S2 — Factor Engine Build Transaction: Constants, Set Context, Completion, Failure and Timeout

**Story**: `docs/capabilities/CAP-002-universe-and-factor-classification/epics/automatic-factor-classification-engine/stories/CAP-002-E2-S2.md`
**Component**: `FactorFlow-v2`
**Branch**: `usr/alvaro-de-jodra/CAP-002-E2-tasks`
**Date**: 2026-10-17

## Summary

Creates the `factorflow.classification` package and the build spine of the factor engine: `constants.py`, `line_items.py` (seven line items, every key `REQUIRES_INPUT`), `engine.build(conn, set_id, timeout_seconds) -> BuildResult` and the three statements `set_context.sql`, `complete_set.sql` and `fail_set.sql`. `build` runs an ordered list of stages (empty in this story; CAP-002-E2-S3 and CAP-002-E2-S4 register their input stages above the `_classification_stage` that CAP-002-E2-S5 registers last, DEC-0121) inside one `REPEATABLE READ` transaction with a local `statement_timeout`, completes the set in that transaction, and on any exception rolls back every row of the attempt and records the set `failed` with the exception class and message in a new transaction, so no reader can see half a set. Four tests prove the transaction behaviour (TC-COMP-166, 167, 090, 159), one safety test proves the package is isolated from ingestion and append-only (TC-COMP-160), and one strict-xfail test keeps the unresolved payload-key question from being forgotten (TC-COMP-059). No factor is computed here.
