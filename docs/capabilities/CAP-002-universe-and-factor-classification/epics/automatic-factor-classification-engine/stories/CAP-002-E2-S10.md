# Momentum Requires Corporate-Actions Coverage of Its Window

## User Story

As an owner-operator, I want a stock whose corporate actions were never acquired over a momentum window to be shown as not classified on momentum, with the input named, so that no momentum score silently treats a stock as if it never split or paid a dividend.

## Description

Closes CAP-002 release blocker B3 (DEC-0397, DEC-0398). `sql/momentum_inputs.sql` joins `corporate_action` with an outer join, so a stock whose corporate actions were never acquired gets a return computed as if it had no split and no dividend. In production on 2026-11-07, 31 of 42 momentum-classified stocks had no corporate-action rows because the provider rate-limited that data type, and all 31 were scored, against AC-7 and AC-12.

This story makes a momentum input `return_k` depend on the instrument's `corporate_actions` coverage. The input is computed only when one `coverage_segment` of that data type contains the window `(S_k, E]` (`covered_from <= S_k + 1`, `covered_to >= E`). Otherwise it is `missing` with `detail.cause = "corporate_actions_not_covered"`, and its `last_acquisition` names `corporate_actions`. A covered input records the segment that contains its window. The rule, the `detail` shapes, the per-cause data type and the order of missing causes are factor-engine design v4 section 2.4. The coverage contract is CAP-001's released behaviour (DEC-0398): a successful fetch, an empty one included, covers the range the runner requested, and a failed or `not_found` fetch covers nothing.

The engine test seeds record no coverage today, so after this change every momentum input they build would be `missing`. Two seeds gain `corporate_actions` coverage by default, mirroring a successful acquisition: `tests/integration/engine_support.py::add_instrument`, which every engine seed module and engine test imports (`engine_momentum_support`, `engine_inputs_support`, `engine_classify_support`, `engine_proof_support`, `engine_restatement_support`), and `tests/integration/engine_proof_support.py::populate_volume`, which inserts its roster in bulk and is used by the volume and latency tests and the CAP-002 integration automation (`classification_cycle_support.seed_roster`). The default is one segment per instrument from 2000-01-01 to 2099-12-31, which contains every fixture window. `add_instrument` takes `corporate_actions_covered: bool = True`; the new cases pass `False` and insert the segments they need. No other seed changes.

Source: `component-design-factor-engine.md` v4 sections 2.3 step 5, 2.4, 3, 6, 7, 8 (criterion 14); `system-design.md` v5 constraint 8; DEC-0397, DEC-0398, DEC-0243, DEC-0241.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-7] Every value, growth and momentum classification MUST be computed from exactly the inputs, periods and equal weights defined for that factor in Section 2.
- [AC-12] The product MUST NOT show a score or percentile on a factor for a stock unless every input that factor needs is present and current, and MUST instead show the stock as not classified on that factor with the missing or outdated input named.
- [DAC-E2-1] Each of the eight named inputs MUST be derived exactly per the trailing-twelve-month sums, prior-year comparison, most-recent balance sheet, and read-time split-and-dividend adjustment of unadjusted bars this capability's factor definitions and the system design fix, with no step the capability does not define. (traces to: AC-7)
- [DAC-E2-13] A momentum input MUST be `missing`, with cause `corporate_actions_not_covered`, unless one `corporate_actions` coverage segment of the instrument contains its whole window `(S_k, E]`; an absent corporate-action row MUST be read as "no split or dividend" only inside covered dates. (traces to: AC-7, AC-12)

### Derived

- [DAC-E2-S10-1] Given a stock with every boundary bar and no `corporate_actions` coverage, When the set is built, Then `return_3m`, `return_6m` and `return_12m` are `missing` with `detail.cause = corporate_actions_not_covered`, `detail.window_months`, `detail.E`, `detail.S` and `detail.corporate_actions_coverage = []`, a null value and a null `known_on`, and the stock is `not_classified` on momentum with reason `input_missing` naming `return_3m`. (traces to: DAC-E2-13, AC-12)
- [DAC-E2-S10-2] Given that stock and an `acquisition_state` row for `corporate_actions` ending `failed`, When the inputs are written, Then each missing momentum input's `detail.last_acquisition` has `data_type = corporate_actions` and `outcome = failed`. (traces to: AC-12)
- [DAC-E2-S10-3] Given one `corporate_actions` segment from exactly `S_k + 1` to exactly `E`, When the set is built, Then `return_k` is `present`; given a segment starting on `S_k + 2`, or ending on `E - 1`, Then `return_k` is `missing` and `detail.corporate_actions_coverage` lists that segment, while a window the segment does contain stays `present`. (traces to: DAC-E2-13)
- [DAC-E2-S10-4] Given a segment containing the window and no corporate-action rows in it, When the set is built, Then the input is `present`, its value is the price return `close(E) / close(S_k) - 1`, and `detail.corporate_actions_covered_by` is that segment's `{covered_from, covered_to}`; an `outdated` input records it the same way. (traces to: DAC-E2-13, AC-7)
- [DAC-E2-S10-5] Given no `S_k` bar and no coverage, When the set is built, Then the input names the boundary and its `last_acquisition` names `prices`; given no coverage and an unusable payload in the window, or no coverage and a non-positive `E` close, Then the cause is `corporate_actions_not_covered` (owner's order, DEC-0397). (traces to: DAC-E2-13, AC-12)
- [DAC-E2-S10-6] Given stocks seeded with the default coverage, When the set is built, Then every delivered statement of status, value, `as_of`, `known_on`, cause and data type in `tests/integration/test_engine_inputs_momentum.py` (splits, dividends, boundaries, currency, unusable payloads, `price_not_positive`) holds as delivered, and the volume, latency and integration-automation builds seeded through `populate_volume` classify as delivered. The one change to a delivered expectation is DAC-E2-S10-4's key: the two tests that compare a whole present or outdated `detail` (`test_every_window_is_present_with_bars_on_every_boundary` and `test_a_stale_latest_bar_makes_all_three_momentum_inputs_outdated`) add `corporate_actions_covered_by` with the default segment to their expected `detail`, and nothing else. Value and growth inputs are unaffected by coverage. (traces to: DAC-E2-1)
- [DAC-E2-S10-7] Given the acquisition runner and a provider stub whose corporate-actions fetch succeeds with no action, When an instrument is acquired, Then one `corporate_actions` coverage segment over the range requested is recorded; given a fetch that fails, or one that ends `not_found`, Then no segment is recorded and an existing one is unchanged. This pins the coverage contract momentum relies on (DEC-0398). (traces to: DAC-E2-13)

## Technical Details

### Implementation

- `src/factorflow/classification/sql/momentum_inputs.sql`: a `covered` test on the `win` relation (one `EXISTS` probe of `idx_coverage_instrument` per stock and window), a `corporate_actions_coverage` array per instrument for the `detail` of an uncovered window, the containing segment for a covered one, the new cause placed right after a missing boundary and ahead of `price_not_positive` and `corporate_action_payload_unusable` in `statused` and in the `detail` `CASE` (DEC-0397), and `missing_data_type = 'corporate_actions'` for it. Read-only; no migration (`coverage_segment` exists since `0003`).
- Tests: `tests/integration/test_engine_inputs_momentum.py` for DAC-E2-S10-1 to DAC-E2-S10-5, written first and failing against the delivered SQL; `tests/integration/test_runner_acquires.py` for DAC-E2-S10-7, which passes against the delivered runner and stays as a guard. The seed changes are the two the Description names. DAC-E2-S10-7 adds test functions to a CAP-001 test module, as factor-engine design v4 section 7 places them; it changes no CAP-001 code, design or delivered assertion, which is what DEC-0398's "No CAP-001 change" excludes, and system design section 8 question 4's list governs CAP-002's edits to delivered product files and tests at its first delivery, not this guard.
- `docs/reference/classification-engine.md`: the new cause, its `detail`, the per-cause data type and the cause order, at doc sync.

### Validation

`uv run pytest -m postgres`, `uv run pytest -m 'not postgres'`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`.

### Rollout and rollback

No migration and no setting. After deployment, the first set built treats every uncovered stock as not classified on momentum (factor-engine design v4 section 6). Rollback is the 0.2.0 image.
