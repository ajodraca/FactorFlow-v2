# Stock Evidence Screen with Factor Cards and Three-Part Insufficient-Evidence Statements

## User Story

As an owner-operator, I want to open a stock and see every input, its date and exactly why a factor is not scored, so that a result I cannot explain never passes for one I can.

## Description

Delivers `web/src/screens/research/stocks/index.tsx` and `factor-card.tsx`, mounting the history tab built by CAP-002-E5-S2. Each factor card lists inputs with value, `as_of` and `known_on`; an incomplete factor gets a three-part statement naming the missing or outdated input, the rule (the 6-month rule against the scores' date) and the recovery path when one exists; per-input status follows DEC-0077. A retired stock reads Not followed. This is the `StockEvidenceScreen` the shell composition story routes to.

Source: `component-design-classification-ui.md` sections 2.5, 10, 7; `ux-design.md` section 1.6.

## Acceptance Criteria (Given/When/Then)

### From Capability / EPIC

- [AC-13] An input MUST be treated as outdated when it is a fundamental whose latest reported period ended more than 6 months before the classification date, or a price that is not from the latest trading day the product holds. (evidence-statement side)
- [AC-15] A stock retired from acquisition MUST NOT be classified or counted in any peer set, and MUST be shown in its universes as not classified because it is retired. (display side: Compare and evidence render it as not followed)
- [AC-17] For any classification, the user MUST be able to see the inputs it was built from and the date on which each input was known.
- [AC-23] A value or growth classification MUST be marked as possibly reflecting restated data when any fundamental behind it was acquired as historical backfill, for a period already reported before acquisition of that stock began, and the mark MUST be retained with that classification in its history. (display side)
- [DAC-E5-2] Stock evidence MUST show every input with its value (where present), `as_of` and `known_on`, and MUST name the specific missing or outdated input behind an incomplete factor with the recovery path when one exists. (traces to: AC-17, AC-13)
- [DAC-E5-3] A stock no longer followed MUST render "Not followed" on every factor in Compare and evidence, keeping its earlier classifications visible rather than disappearing. (traces to: AC-15)
- [DAC-E5-5] The restatement mark MUST render on every percentile it applies to across Compare and Stock evidence, with the meaning sentence stated once per screen. (traces to: AC-23)

### Derived

- [DAC-E5-S3-1] Given an outdated fundamental, When the card renders, Then it names the period end, the 6-month rule against the scores' date and the next-download recovery. (traces to: DAC-E5-2)
- [DAC-E5-S3-2] Given a factor where the provider holds no data, When the card renders, Then no recovery is offered. (traces to: DAC-E5-2)
- [DAC-E5-S3-3] Given the screen, When rendered, Then the STD-UI-18 sentence appears once and the restatement meaning appears beside the first mark. (traces to: DAC-E5-5)
- [DAC-E5-S3-4] Given a retired stock, When the screen renders, Then each factor reads Not followed while earlier classifications stay in the history tab. (traces to: DAC-E5-3)
- [DAC-E5-S3-5] Given an unknown symbol, When the screen loads, Then a not-found state is shown, not an empty card set. (traces to: AC-17)
