# Expedited Change: Honour the Massive base URL and the ratios endpoint signature

## Request and Outcome

The owner asked directly: "fix the MassiveClient defects with $expedited-change". Two defects in `src/factorflow/ingestion/massive/client.py`:

1. `MassiveClient` builds `massive.RESTClient(...)` without `base=`, so `MassiveSettings.base_url` (`FACTORFLOW_MASSIVE_BASE_URL`) has no effect and every request goes to the SDK's built-in host. Outcome: the configured base URL is the host every request (including `next_url` pages and the `vx` sub-client's IPO call) is sent to.
2. `_financial_page` calls all four financial SDK methods with `tickers=`, `period_end_gte=` and `period_end_lte=`. The installed SDK's `list_financials_ratios` (massive 2.8.0) accepts `ticker=` (singular), has no period parameter and no `**kwargs`, so the call raises `TypeError`. Outcome: the ratios endpoint is called with `ticker=<symbol>` only, and the three statement endpoints keep their existing (correct) parameters.

## Eligibility and Risk

`python3 scripts/classify-lane.py --none` (run in `ai-agents`) returned `expedited`; every signal was answered no. Risk is medium: today `fetch_financials` can never succeed (the ratios `TypeError` is classified retryable, so every instrument spends three governor attempts and ends `ProviderUnavailable`), and the base URL cannot be pointed at a stub, which DEC-0025's acquisition e2e stack depends on.

Signal answers, with the close calls stated:

- `multi-component`: no. Only FactorFlow-v2 changes.
- `acceptance-criteria`: no. AC-3 is unchanged; the fix restores it.
- `public-contract`: no. No published FactorFlow interface changes. The outbound request to Massive changes to match the provider's real contract, which is consumed, not published.
- `product-behaviour`: no. Both fixes restore behaviour the approved designs already specify (`component-design-runtime-config.md` section 2.2 lists `FACTORFLOW_MASSIVE_BASE_URL`; `component-design-massive-client.md` section 2.5 requires all four financial endpoints, constrained by ticker).
- `persistent-schema`: no. No migration or DDL.
- `authn-authz`: no. The `Authorization: Bearer` mechanism is unchanged.
- `privacy-secrets` (close call): no. Honouring `base_url` means the API key goes to the configured host. That host is already an approved, operator-set variable whose default (`https://api.massive.com`) equals the SDK's default, so an unconfigured deployment sends the key exactly where it does today.
- `deployment-topology` (close call): no. No variable is added, removed or re-defaulted; an existing, documented runtime setting becomes effective.
- `unknown-risk`: no. The change is confined to the SDK construction and one request-argument helper in one module; both are covered by the tests below.

## Documentation Impact

Two statements in `component-design-massive-client.md` need synchronizing through `$doc-sync`: the section 2.2b construction snippet omits `base=settings.base_url`, and the section 11 interface table says the ratios endpoint takes the same request ("as above") and has the "Same shape and constraints" as the statement endpoints. The SDK shows ratios takes `ticker`, not `tickers`, and has no `period_end` or `filing_date` filter.

Open, and outside this change's scope (for the owner):

- **Ratios response shape.** The SDK's `FinancialRatio` model carries `ticker`, `cik`, `date` and ratio values. It has no `tickers`, `period_end`, `filing_date`, `fiscal_year` or `timeframe`, and `FinancialStatement` requires all of those. If the live endpoint matches the SDK, any non-empty ratios response now fails validation as `ProviderContractViolation` rather than as the earlier `TypeError`/`ProviderUnavailable`. Deciding how ratios are modelled and stored, and whether to bound them by `date` client-side, changes the component design and `fundamental_observation` semantics. That belongs in the standard lane and was not attempted here.
- `tests/e2e/support/massive_stub.py` accepts either `ticker` or `tickers` and serves statement-shaped ratios rows, so the e2e stack does not exercise the real ratios shape.
- The `# Implements TC-INT-023` annotation (integration automation task T011) is still held. This change does not add it.
