**Product-behaviour close call.** I agree with the author's "no", for the following reasons:

- **The design asks for something the SDK cannot do.** Section 2.5 asks for all four financial endpoints to be constrained by ticker *and* period, and section 11 says ratios has the "Same shape and constraints". In massive 2.8.0, `list_financials_ratios` has no period, date or filing-date parameter and no `**kwargs`. That is not the approved behaviour being changed. It is a design statement that could never be implemented, and the gap was hidden by a bare mock.
- **The observable outcome is the same or better.** A user sees the per-instrument, per-data-type outcome:
  - Before (base `src`): every instrument's fundamentals ended `failed`. The `TypeError` raised inside our own code was classified retryable, so it used three governed attempts and then raised `ProviderUnavailable`.
  - After, with a non-empty ratios response: still `failed`. I confirmed this with a scratch probe, which fed a `FinancialRatio`-shaped row through an autospecced client and got `ProviderContractViolation` after **1** send. `outcomes.classify_provider_error` maps both classes to the same `failed`.
  - After, with an empty ratios response: `written`, which is what AC-3 asks for.
- **The owner-visible reason text changes.** In `compose_failure_reason`, the kind changes from provider-unavailable to contract-violation. The new kind is accurate, and the old one was a symptom of the defect. Nothing branches on the kind: the runner treats both identically, and `CredentialRejected` is unaffected.
- **No partial writes.** `fetch_financials` returns only after all four endpoints are collected, so a ratios failure writes nothing.

**Unknown-risk.** The ratios call is now unbounded by date, so `follow_pages` fetches every ratios page for the symbol, once per run. The first uncovered range that fails raises, so later ranges are not fetched. The page count for the live endpoint is unverified. The SDK's filters (`price`, `market_cap`, `dividend_yield` and similar, with no date filter) suggest a per-ticker snapshot rather than a long history, but that is an inference. Even in the worst case, each page is one governed permit under the existing rate limiter. The cost is run time for that instrument's fundamentals, not new failure modes or a new surface. The blast radius is known and bounded, and the record already carries the bound decision as an owner follow-up.
