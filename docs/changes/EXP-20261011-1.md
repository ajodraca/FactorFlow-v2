# Expedited Change: A fully written run finalises as succeeded

## Request and Outcome

The owner directed this change on 2026-10-11, before finishing CAP-001's E2E automation: "Fix defects first". Automation tasks T008 (TC-E2E-001) and T009 (TC-E2E-005) require a run to end `succeeded`, and no run could.

Root cause, in code CAP-001-E4-S5 delivered:

- `finalise` in `src/factorflow/runs/journal.py` awards `succeeded` only when `instruments_named > 0` and the run wrote four successful results per named instrument (run-journal design section 2.5, rule 3).
- `acquisition_run.instruments_named` is `NOT NULL DEFAULT 0` (`migrations/0004_runs.sql`), and nothing under `src/` ever set it. `ingestion_main.claim_fn` snapshots the roster, but its size was never stored.
- So every run with at least one successful result ended `partial`. CAP-001-E3-S7's implementation review v1 recorded this as a pre-existing follow-up for the owner ("no run can reach `succeeded`").

The runner tests did not catch it because TC-COMP-183 and TC-COMP-184 accepted `state in ("succeeded", "partial")`.

Outcome: `AcquisitionRunner.execute_claimed` records the size of the roster snapshot it was given, through a new journal function, before it works the roster. A run in which every named instrument writes or keeps all four data types finalises `succeeded`. Any run with a missing, failed, not-found or skipped result stays `partial` (AC-9).

## Eligibility and Risk

`python3 scripts/classify-lane.py --none --json` returned `expedited`, with exit 0. Every signal was answered no, so `lane_signals` is empty.

Risk is medium: the change is small, but it decides which runs are reported `succeeded`, and AC-9 forbids reporting `succeeded` for a run in which any named instrument failed. The rule itself is unchanged: `finalise` still requires four successful rows per named instrument and no unsuccessful row. The change only supplies the count the rule was written against. A run that skips an instrument (no symbol row) or is unknown to the provider still has fewer successful rows than `instruments_named * 4`, so it stays `partial`.
