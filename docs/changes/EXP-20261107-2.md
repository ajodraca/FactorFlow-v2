# Expedited Change: Idle the classification scheduler in the universes API tests

## Request and Outcome

CI run 42343440472 on PR #176 failed in
`tests/integration/test_api_universes.py::test_a_malformed_source_is_a_validation_error[extra1-filter]`
with `psycopg.errors.UniqueViolation: duplicate key value violates unique constraint
"classification_set_run_id_key"`, raised in `seed_classified` -> `seed_set`
(`tests/integration/test_universe_filter_snapshot.py:83`). The same race is on `main`.

Cause: the module's `client` fixture enters `TestClient(create_app())`, so the app lifespan
(`src/factorflow/api/app.py`, `run_classification_loop`) runs the real classification
scheduler. `seed_set` commits a succeeded `acquisition_run` on an autocommit connection and
then inserts its `classification_set`. A scheduler poll that falls between the two claims the
run (`qualifying_run.sql` selects any succeeded or partial run with no set) and inserts its
own set, so the seed's insert violates the unique `run_id`.

Outcome: the `client` fixture replaces the scheduler with the idle stand-in that
`tests/integration/api_classification_support.py` already uses for the same reason, so no
set is created behind a test's back. No test in the module relies on the live scheduler.
