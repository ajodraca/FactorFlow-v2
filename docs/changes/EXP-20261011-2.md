# Expedited Change: The status region shows how the last run ended

## Request and Outcome

The owner directed this change on 2026-10-11, before finishing CAP-001's E2E automation: "Fix defects first". Automation task T013 (TC-E2E-011) requires the status region to report "the most recent run outcome", and it could not.

Root cause:

- `ux-design.md` section 0 and `component-design-owner-web-app.md` section 2.2 specify that the status region reports two facts from `GET /api/health`: whether the product is answering, and how the most recent acquisition run ended (AC-18).
- CAP-001-E1-S5 built the region when `most_recent_run` was always `null`. It implemented only the null branch ("No run recorded") and left the populated branch as a placeholder, "Most recent run recorded", for CAP-001-E7-S3.
- CAP-001-E7-S3 populated `most_recent_run` on the API (`ingestion-api`) and widened the TypeScript type, but did not change the region. So the region says a run exists without saying how it ended.

Outcome: when `most_recent_run` is present, the run-outcome line reads "Last run" followed by the run's outcome badge, the same `OutcomeBadge` the Runs screen and Run detail use: its word, its tier icon and its `status-*` variant. `data-outcome` carries the recorded state. The null branch is unchanged.

## Eligibility and Risk

`python3 scripts/classify-lane.py --none --json` returned `expedited`, with exit 0. Every signal was answered no, so `lane_signals` is empty.

Risk is low: the change is one render branch in one component, reusing an existing badge. If it were wrong, the region would misstate the last run's outcome. The badge renders the state exactly as the API reports it and never upgrades it (its own contract), and the tier mapping is the one the Runs screen already uses, so a `partial` run reads as a warning and never as good (AC-9).

Signal answers:

- `multi-component`: no. Only FactorFlow-v2 changes.
- `acceptance-criteria`: no. No acceptance criterion or test case changes.
- `public-contract`: no. The API is untouched; the interface reads a field it already receives.
- `product-behaviour` (close call): no. The approved behaviour is that the region reports how the most recent run ended (ux-design section 0, AC-18). This change implements it where a placeholder stood. Nothing relied on the placeholder text.
- `persistent-schema`, `authn-authz`, `privacy-secrets`, `deployment-topology`: no.
- `unknown-risk`: no. The blast radius is the status region's run-outcome line on every screen, plus one E2E assertion that counted badges page-wide (see Changed Files).

Deliberately out of scope: ux-design section 6 also says the region "links to that run's detail directly". That link is a separate missing behaviour, not needed for TC-E2E-011, and is left as a follow-up for the owner.
