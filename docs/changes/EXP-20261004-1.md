# Expedited Change: Show a settled cancel in the run summary immediately

## Request and Outcome

Resolve the failed PR #83 end-to-end check for CAP-001-E7-S4 AC-26. When a queued run is cancelled, the detail summary must show one `Cancelled` outcome as soon as the cancel API succeeds, while the detail refetch supplies the remaining fields.

## Eligibility and Risk

`python3 scripts/classify-lane.py --none` returned `expedited`. Every signal was answered no: the fix stays in one component repository; it does not add or materially change acceptance criteria, a published contract, approved product behavior, persistent schema, authentication or authorization, privacy or secrets, or deployment topology. The affected state flow and tests are known. Risk is medium because the owner can briefly see contradictory run states after a successful cancel.

Root cause: `CancelRunControl` renders the settled API state immediately, but `RunDetailView` handles `onRunChanged` only by starting a refetch. Before that GET resolves, `RunSummaryCard` still renders the prior `requested` state, so both `Requested` and `Cancelled` badges occur in the same summary. The Playwright `getByTestId("outcome-badge")` locator in `tests/e2e/cancel-run.spec.ts:48` then fails strict mode. The CI evidence is `https://github.com/ajodraca/FactorFlow-v2/actions/runs/37247328958/job/111569016387`.

Pattern analysis: the existing unit test in `web/src/screens/runs/run-detail.test.tsx:444-466` waits for the refetch to finish, so it misses the interval when both badges render. Hypothesis test: hold the refetch unresolved and assert the summary has one `Cancelled` badge. The new focused test failed against unchanged production code with two badges (`Requested` and `Cancelled`), confirming the root cause before implementation.

Pre-commit test review: the new case changes only the queued-cancel test fixture, leaves the second GET unresolved while making its assertion, and resolves it afterward. It therefore cannot pass by waiting for the GET. Spec drift check: its one-badge `Cancelled` assertion sharpens existing AC-26 and adds no new product behavior.

## Scope and Traceability

- `web/src/screens/runs/detail/index.tsx`: apply the authoritative cancel result to the summary's local run state before refetching.
- `web/src/screens/runs/run-detail.test.tsx`: hold the refetch pending and assert that the summary immediately contains exactly one settled outcome badge.
- This record and its independent review. Traceability: CAP-001-E7-S4 AC-26, AC-19, DAC-E7-S4-3 and the owner's 2026-10-04 request to fix PR #83.
