# Expedited Change: The e2e URL assertions follow the Downloads path

## Request and Outcome

CAP-003-E3-S4 moved the download pages from `/runs` and `/runs/{id}` to `/data/downloads` and `/data/downloads/{id}`. The old paths now redirect with `replace` (AC-18). Six delivered e2e assertions still expect the address to end in `/runs/{uuid}`, so 12 specs fail on FactorFlow-v2 PR #190 (CI run 44880663516, job 136777461376). Each one fails at the same kind of assertion: after **Start acquisition run**, the address is `/data/downloads/{uuid}`.

E3-S4's approved plan leaves these specs red until CAP-003-E7-S7. The owner decided not to carry a red e2e suite on main that long (DEC-0403). The outcome is that the six assertions expect `/data/downloads/`, and the e2e suite passes again. Each spec still proves the same behaviour.

## Eligibility and Risk

`python3 scripts/classify-lane.py --list` lists the signals. None was answered yes, so the lane is `expedited`. The close calls:

- **product-behaviour: no.** No product code changes. The tests now follow the behaviour E3-S4 already delivered under its approved story.
- **acceptance-criteria: no.** No criterion changes. AC-17 (behaviour preserved) is what the edit keeps true.
- **multi-component: no.** Only `tests/e2e` in FactorFlow-v2 changes.

The edit takes part of the scope CAP-003-E7-S7 owns: DAC-E7-12 makes E7-S7 update the e2e specs. DEC-0403 records the owner's decision to pull these six assertions forward. Everything else E7-S7 lists stays with it: the `page.goto` paths, the label locators and the `href` assertions.

Risk is **low**. The worst case is a wrong URL pattern, and that fails visibly in CI. It cannot pass silently, because each pattern stays anchored with `$` and still requires a 36-character id.

## Scope and Traceability

These files may change, and only in their `toHaveURL` assertions that name `/runs/`:

- `tests/e2e/support/acquisition.ts` (`startRun`, line 152).
- `tests/e2e/cancel-run.spec.ts` (line 43).
- `tests/e2e/runs-start-cancel.spec.ts` (line 26).
- `tests/e2e/diagnose-failure.spec.ts` (lines 54, 106, 107). The negative assertion at 106 moves too. Otherwise it would compare against a path the app no longer shows and pass for the wrong reason.

Three things are deliberately not changed:

- **`href` assertions.** `runs-start-cancel.spec.ts:31` and `research-after-download.spec.ts:116` keep `/runs/{id}`. The delivered Downloads table and CAP-002's `SHELL_ROUTES` still render those links until the E7 takeover stories move them.
- **`page.goto("/runs" | "/coverage" | "/instruments")`.** These keep working through the legacy redirects. They belong to E7-S7.
- **The depth-field locator in `acquisition.ts:122`.** It belongs to E7-S7 once CAP-003-E7-S1 lands.

Traceability: owner instruction in chat, 2026-11-21. Also DEC-0403; CAP-003-E3-S4-tasks.md *Other Notes* ("The e2e red window"); backlog review v4 FINDING-5; CAP-003-E7-S7 DAC-E7-12; and the PR #190 CI failure.
