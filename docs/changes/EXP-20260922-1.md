# Expedited Change: Correct CAP-001 dependency ordering

## Request and Outcome

Audit CAP-001's 28 implementation task plans against the scheduler graph using concrete file producers and consumers, correct every confirmed missing hard edge, and classify cited non-edges where evidence is needed. At minimum, record that CAP-001-E4-S6 depends on CAP-001-E4-S5 because E4-S6 imports and modifies the acquisition runner that E4-S5 creates. The resulting graph must prevent future scheduling from treating that implementation prerequisite as optional.

The audit covered all 28 existing CAP-001 task plans on `main`. Concrete prerequisite checks, imports, and file modifications established ten missing hard edges:

| Story | Added dependency | File-level evidence |
| --- | --- | --- |
| CAP-001-E2-S2 | CAP-001-E2-S1 | Uses E2-S1's `factorflow.instruments` package and `service.py` in integration coverage. |
| CAP-001-E3-S1 | CAP-001-E3-S2 | Imports provider models from `ingestion/massive/models.py`. |
| CAP-001-E3-S1 | CAP-001-E3-S3 | Imports provider taxonomy from `ingestion/massive/errors.py`. |
| CAP-001-E3-S1 | CAP-001-E3-S4 | Imports and invokes `RateLimitGovernor` from `ingestion/rate_limit.py`. |
| CAP-001-E3-S5 | CAP-001-E3-S2 | Updates the Massive package initializer created by E3-S2. |
| CAP-001-E4-S6 | CAP-001-E4-S5 | Imports and updates E4-S5's `ingestion/runner.py` seam. |
| CAP-001-E5-S3 | CAP-001-E5-S2 | Extends E5-S2's `runs/journal.py` request and claim boundary. |
| CAP-001-E5-S4 | CAP-001-E4-S3 | Updates the observation writer transaction. |
| CAP-001-E5-S4 | CAP-001-E4-S5 | Updates the acquisition runner's heartbeat checkpoint. |
| CAP-001-E5-S4 | CAP-001-E4-S6 | Requires the typed one-instrument result transaction before adding reclaim guards. |

The other 22 plans required no graph change: CAP-001-E1-S1 through E1-S6; E2-S1, E2-S3 and E2-S4; E3-S2 through E3-S4; E4-S1 through E4-S5 and E4-S7; and E5-S1, E5-S2, E5-S5 and E5-S6. Their non-edge references are reverse consumers, soft parallel contracts, contextual ownership notes, or prerequisites already guaranteed transitively by an existing hard edge.

E4-S6's E5-S2 mention is contextual rather than a new direct edge. E5-S2 created the base journal module, but E4-S5 now supplies the argument-free finaliser and runner seam and already hard-depends on E5-S2. The E4-S6 task plan records that classification explicitly and corrects its stale finalisation ownership note.

The capability remains on dependency contract version 1. Migrating all historical plans to version 2 would rewrite 28 implementation records without changing the corrected schedule; new or materially replanned stories will acquire classifications through the updated planning workflow.
