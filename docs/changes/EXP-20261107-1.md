# Expedited Change: Bind the Massive payload keys and read shares from the income statement

## Request and Outcome

The owner answered system design section 8 question 1 on 2026-11-06 and 2026-11-07. The answer is recorded in DEC-0295, system design v4 and factor-engine design v3, which the owner re-approved on specification review v5. This change implements that answer in the factor engine. The observable outcomes:

- The seven line items carry real Massive payload keys, and `line_items.unresolved()` is empty. Value and growth inputs are therefore derived from acquired statements instead of being `missing` with `line_item_mapping_unresolved`.
- Market capitalisation, for all three value inputs, is the latest close times the `diluted_shares_outstanding` of the single most recent quarterly income statement. That figure is never summed across a trailing window.
- Capital expenditure is read as a magnitude, so FCF is OCF minus `|purchase_of_property_plant_and_equipment|` whatever sign a record carries.
- Book equity is `total_equity_attributable_to_parent` less `preferred_stock`. An absent or JSON-null `preferred_stock` reads as zero. Any other non-numeric value makes book equity absent.

## Eligibility and Risk

`python3 scripts/classify-lane.py --none` returned `expedited`, with no signal answered yes. The close calls:

- **product-behaviour: no.** Value and growth becoming classifiable once the keys are supplied is the behaviour the approved designs already specify: factor-engine v3 §2.4, and v1 onward said "turns on by itself when the owner resolves the keys". This change implements approved behaviour. It does not change it.
- **acceptance-criteria: no.** AC-7 to AC-14 are unchanged.
- **public-contract: no.** The `factor_input.detail` keys keep their names.
- **persistent-schema: no.** No migration.

Risk is **medium**, not low. A wrong rule here would write wrong values into append-only classification sets. The integration tests below pin each rule.

## Scope and Traceability

These files may change:

- `src/factorflow/classification/line_items.py`: the seven keys, `magnitude` and `less_key` (DEC-0295; factor-engine v3 §2.4).
- `src/factorflow/classification/engine.py`, `_line_item_parameters`: bind the two new fields.
- `src/factorflow/classification/sql/value_inputs.sql`: shares from income statement P1, capex magnitude, preferred deduction.
- `tests/unit/test_line_items_resolved.py`: TC-COMP-059 now passes, so the strict xfail goes.
- `tests/unit/test_line_items.py`, `tests/unit/test_engine_line_item_params.py` and `tests/unit/test_restatement_sql_static.py`: unit tests that pinned the unresolved keys or the bound parameter set.
- `tests/integration/engine_inputs_support.py`, `tests/integration/engine_proof_support.py` and `tests/integration/test_engine_inputs_fundamentals.py`: the fixtures follow the shares move, plus factor-engine v3 §7's new cases.
- `tests/integration/test_engine_currency.py`, `tests/integration/test_engine_inputs_momentum.py` and `tests/integration/test_engine_restatement.py`: expectations that encoded the superseded statement set or the unresolved keys.

**JSON-null preferred stock.** DEC-0295 reads a JSON-null `preferred_stock` as zero. This deliberately departs from DEC-0116 (4), which reads null as absent, and applies to this one deduction field only. The owner decided it on specification review v5 FINDING-3 when re-approving the designs, and the design prose is amended at their next revision (review v1 ER-002).

**Rework after review v1.** ER-001: `test_an_old_income_statement_dates_every_value_input` restores the case where the income statement is the oldest of the latest periods, so the shares source dating all three value inputs is tested. ER-004: the market-capitalisation test docstring names the income statement. ER-005: this scope list now names every changed file. ER-003 (DEC-0295 uncommitted in the harness) is the owner's to commit with the run's records. The rest of ER-004, `docs/reference/classification-engine.md`, is left for `$doc-sync`.

Traceability: DEC-0295; system design v4 §5 constraint 8 and §8 question 1; factor-engine v3 §2.4 and §7; specification review v4 FINDING-4 to FINDING-6 and v5 FINDING-3.
