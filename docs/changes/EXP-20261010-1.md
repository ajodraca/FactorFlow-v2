# Expedited Change: Find the non-loopback address AC-14's binding test needs without hostname resolution

## Request and Outcome

The owner directed this change, with a fixed scope of two findings from CAP-001-E1-S6 implementation review v6 (`docs/capabilities/CAP-001-market-data-acquisition-foundation/epics/runnable-foundation/stories/CAP-001-E1-S6-implementation-review-v6.md`):

- **IR-604 (MEDIUM).** `tests/integration/test_api_binding.py::_find_non_loopback_ipv4` resolves the hostname. On a host whose `/etc/hosts` maps the hostname to `127.0.0.1` it returns `None`, so `test_server_binds_to_loopback_only` (TC-COMP-014 / AC-14) skips even though the host owns non-loopback IPv4 addresses. Its docstring wrongly says it enumerates interfaces.
- **IR-605 (LOW), docstring part only.** `probe_schema_version`'s docstring in `src/factorflow/api/routes/health.py` says it returns `None` when the `applied_migrations` table does not exist. It raises instead.

Planned outcome:

- The helper finds a non-loopback IPv4 address the host owns without a name lookup, using the standard library only. The test skips only when no such address can be found. The docstring says what the helper does.
- `probe_schema_version`'s docstring describes its real behaviour. Its code does not change.
