# Expedited Change: Find the non-loopback address AC-14's binding test needs without hostname resolution

## Request and Outcome

The owner directed this change, with a fixed scope of two findings from CAP-001-E1-S6 implementation review v6 (`docs/capabilities/CAP-001-market-data-acquisition-foundation/epics/runnable-foundation/stories/CAP-001-E1-S6-implementation-review-v6.md`):

- **IR-604 (MEDIUM).** `tests/integration/test_api_binding.py::_find_non_loopback_ipv4` resolved the hostname with `getaddrinfo`. On a host whose `/etc/hosts` maps the hostname to `127.0.0.1`, it returned `None`. `test_server_binds_to_loopback_only` (TC-COMP-014 / AC-14) then skipped, even though the host owns non-loopback IPv4 addresses. The helper's docstring wrongly said it enumerated interface addresses.
- **IR-605 (LOW), docstring part only.** `probe_schema_version`'s docstring in `src/factorflow/api/routes/health.py` said it returns `None` when the `applied_migrations` table does not exist. In fact the query raises.

Outcome:

- **IR-604.** The helper now asks the kernel's routing table instead of the resolver. It connects a UDP socket to `198.51.100.1:9` (TEST-NET-2, RFC 5737), which sends no packet, and reads the chosen local address with `getsockname()`. That address is assigned to one of the host's interfaces.
  - It uses the standard library only, with no new dependency.
  - It returns `None`, and the test skips, only when `connect()` fails (no IPv4 route off the host) or the address is loopback or unspecified.
  - The docstring and the skip message now describe this.
  - The test's assertions are unchanged.
- **IR-605.** The docstring now says:
  - `None` means the table exists but is empty.
  - A missing table raises `psycopg.errors.UndefinedTable`, which propagates.
  - `get_health` catches it and reports `"unreachable"`.

  The function's code is unchanged.

Why the UDP route lookup and not `if_nameindex` with an ioctl: the route lookup is portable and needs no platform-specific ioctl number or `struct` packing. `SIOCGIFADDR` (`0x8915`) is Linux-only.

Known limit, recorded so a reviewer can weigh it: a host whose non-loopback interfaces carry no route to an off-host destination (no default route, only on-link subnets) also yields `None` and skips. Such a host does not match "genuinely has no non-loopback IPv4". It is a narrower and much rarer case than IR-604's, and the skip message names the cause. The containerised hosts IR-604 describes have a default route. The GitHub-hosted CI runners have one too.
